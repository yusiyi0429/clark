# 讨论中的修改

本页讲复盘生成后，负责人提意见、改稿和分歧怎么处理。确认权见 contracts.md。

## 改稿

从当前版本开始改，只改意见涉及的内容和直接受影响的内容。按意见的性质分开处理：

| 意见 | 怎么改 |
|---|---|
| 补了新证据（含负责人具体陈述） | 按 method.md 第 2 节核对来源、事实范围和本期归属，再重判受影响的结果和判定 |
| 对原因有不同解释 | 两种解释都写出来，各附证据；说明什么证据能分出对错 |
| 认为承诺口径不对 | 找本月有效的确认记录；找到了按它改，找不到就保留原口径并写明分歧 |
| 只改文字 | 只改表达，判定、证据和缺口不变 |

改完再把整份复盘从头读一遍：判定理由、事实证据各行和下期输入，凡是和这次改动对不上的句子，在同一次修改里一起改掉。改的是事实（比如补了使用记录），判定理由和其他行里说“缺这条记录”的地方一定要跟着改；改完判定可能也要变，变了按上一段重判。例：原因改成“明华 10/14、10/15 用过两次”，那一行的 status 和判定理由就不能再写“缺明华的使用记录”。

改动判定时，在变更记录里写原判定、新判定和依据。

## 人工纠正

收到“这件事已经实现”“原文漏了实际使用”等纠正时，先定位当前卡片、事实行和原承诺；对照新陈述重新判断，不能只重复原判定。证据采信、冲突与补问标准统一按 method.md 第 2 节“负责人陈述”。

- 能修正的，出一张有具体改文的修订卡，以消息或批注 ID 作为来源。事实证据注明陈述人；同时改正受影响的 status、判定理由、总体判定和下期输入，其他行保持原样。不要只回复“收到”或只加一句报告而保留已失效的“缺记录”结论。
- 还不能修正的，说清是哪条标准尚不满足、哪一个具体冲突或关键信息影响结论；最多先追问一个关键问题。已经得到的陈述和来源继续保留，不要求负责人重复提供。
- 能读取相关记录时，先核对；读不到时如实说明读取范围。按陈述判断不等于已检索本体，不声称找到或核验了没有读过的记录。需要补记本体的另列缺口，出修订候选不以写回成功为前提，也不自动写外部系统。

个人复盘仍由本人、私人 Agent、Nexus 三方讨论：本人补事实、纠正判断；私人 Agent 帮忙找材料和说明意见；Nexus 按上述规则形成修订候选。有权的人按既有规则确认，Nexus 不替人确认。已锁定的卡仍遵守现有锁定规则，有新情况到单元复盘提出。

## 负责人和上级意见不同

先对四件事：说的是不是同一个对象、同一个承诺范围、同一个标准、同一个截止时间。对齐后仍不同，两边的判断和依据都写进复盘，标明谁的意见，交有权确认的人决定。只有双方都认可的内容才写成共识。

CEO 的意见写成“CEO 反馈”；CEO 确认后的判定按确认版本呈现。

## 个人复盘改动对单元复盘的影响

Mission 复盘（个人复盘）的修订被接受后，Nexus 对比这个 Mission 改前和改后，判断所属单元复盘要不要跟着改。

**有实质影响**，有下面任一种就要改单元复盘（出一张单元复盘修订卡）：
1. 单元复盘事实证据里这个 Mission 那一行的 status 要变。这一行的 status 照搬 Mission 复盘的判定，Mission 判定变了，这一行就跟着变。
2. 那一行的 evidence 或 gap 引用的事实变了，原句已经不对。例如原写“缺明华的使用记录”，Mission 复盘已补上 10/14、10/15 两次使用。
3. 单元的判定或判定理由依据的就是这一行：这一行变了，单元判定可能要升或降，或者判定理由里的说法不再成立。按 method.md 第 4 节重判，不变就只改理由里对不上的话。
4. 单元复盘下期输入里对应这一行的那条要跟着变：已经不需要了（比如补齐后达成），要换类型，或者 Mission 新出了没了的事要加一条。仍按每行事实最多 1 条。

**影响不大**，不改单元复盘：
- Mission 复盘只改了措辞、改短、换了说法；
- 补的细节不影响这一行的 status，单元复盘这一行的一句话结果仍然对；
- 改的是单元复盘没有引用的内容（比如某个 Task 行的证据编号）。

拿不准时看一句话：单元复盘里有没有哪一句因为这次改动变成错的。有就改，没有就不动。

**要改时只改受影响的部分**：这个 Mission 那一行，和因它而对不上的判定、判定理由、下期输入；别的 Mission 行和别的内容原样保留。改法按上面“改稿”一节，写成人话（reader-format.md）。

程序调用时返回 {"impact":true|false,"reason":"一句话","patch":{...}}。reason 写清是上面哪一种，或为什么影响不大。patch 只在 impact 为 true 时给，只放要改的字段（verdict、verdictReason、facts、nextInputs 里的哪几个）；facts 和 nextInputs 给改完后的整个数组。

## 回查上下层

- 个人复盘改动对单元复盘的影响按上一节判断。
- 单元复盘改了判定，同样回查公司复盘：公司复盘里这个单元那一行和公司判定，按上一节同样的标准看。
- 只回查受影响的单元和那几条判断，不改别的内容。
- 上层改了，也检查是否引用过下层的旧说法。
