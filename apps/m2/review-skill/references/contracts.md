# 复盘对象、承诺基线与确认权

本页定义复盘谁、对照什么、谁确认。怎样判定见 method.md，各层写什么见 quality-bars.md。业务方的新口径优先于本页。

## 复盘对象

和拆解用同一套单元：Company LTO → 战场 LTO／能力域 LTO → RU 的月度 PO → Mission → Task。

- **Mission 复盘（个人复盘）**：一个 Mission 一份，页面上按负责人归在一起。对照这个 Mission 本月的成果、成功标准和时间。它下面每个 Task 是一行事实证据。
- **RU 复盘（责任单元复盘）**：一个战场或能力域一份，只复盘 PO。对照本 RU 本月的 PO：成果、成功标准、完成定义。它下面每个 Mission 是一行事实证据。
- **公司复盘**：全公司一份。对照公司本月的方向或目标，以及公司 LTO。每个责任单元是一行事实证据。
- **Task 不单独复盘。** Task 是所属 Mission 复盘里的事实行。

战场对客户和业务结果负责；能力域对可复用的能力和它在哪里被用上负责。复盘时各看各的承诺：战场看客户和业务状态变了没有，能力域看能力交出去、被用上了没有。

## 承诺基线

- 判定对照**本月有效的承诺**：月初确认的版本，加上月中经有权人确认的变更。变更从确认那天起生效，之前的部分仍按原承诺看。
- 讨论意见、口头解释、事后反馈，都不改变承诺。
- 资料里找不到承诺时，写明“未找到本月承诺”，按资料里能找到的最接近的目标判定，并在判定理由里写清用的是哪一份。

## 一个结果算一次

- 一个结果按主归属算在一个单元里。能力域交给战场的东西，能力域算“交出去、被用上”，战场算“客户和业务变了没有”，两边各写自己的部分。
- 同一个人在不同单元承担的结果，分别在各单元里评。
- 同一条证据可以支持几个判断，但同一项交付、收入或使用案例只计一次。

## 确认权

- **Mission 复盘（个人复盘）**：只由 Mission 负责人自己确认。所属 RU 的 DRI 不签字，但要提交洞察。
- **RU 复盘**：RU DRI 和 CEO 确认同一版本。CEO 本人兼任这个 RU 的 DRI 时，也按两个位置各确认一次，和拆解一样。
- **公司复盘**：CEO 确认。
- **确认顺序**：个人复盘在复盘生成后 24 小时内由本人确认；单元复盘要等本单元的个人复盘都确认后才能确认，48 小时内完成；公司复盘在各单元复盘确认后由 CEO 确认。时限和顺序由程序和页面管，Nexus 提醒时照这个说。
- **握手覆盖判定、事实证据和下期输入。** 分析洞察不握手：参与者各自提交，公开前只有本人看得到自己写的，公开后所有人可见；Nexus 综合也不握手。
- 质量检查通过、复盘被确认、结果达成，是三件不同的事。复盘写得准、被确认了，判定仍可以是未达成。
- 确认后的整份复盘（判定、事实证据、下期输入、公开的洞察和 Nexus 综合）是下月拆解的参考输入。确认后再改，形成新的候选版本，不覆盖已确认的内容。
