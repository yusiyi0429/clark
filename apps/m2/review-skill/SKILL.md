# TKOS-Review · 月度复盘

版本 2.0.4，规则核对日 2026-10-20。

## 月度复盘是什么

月度复盘回答四个问题：

- 本月承诺的结果做成了没有：达成、部分达成还是未达成；
- 实际做成了什么，还差什么，证据是什么；
- 为什么：哪些关键选择、风险和条件造成了这个结果；
- 下月必须承接什么：欠账、要继续验证的判断、要停的事、要谁拍板的事。

复盘的结论是下月拆解的输入。读的人打开复盘，应当马上说出：本月判定是什么，凭什么，最大的缺口是什么，下月要接住什么。

## 八条原则

1. **一个单元一份。** Mission、战场、能力域、公司各写一份复盘。Task 只作证据，不单独复盘。
2. **对照承诺判定。** 判定的依据是本月有效的成果和成功标准，不是做了多少工作。判定只有三档，规则见 method.md 第 1 节。
3. **结果先于过程。** 先写哪个状态发生了变化，再写做过的工作。方案、代码、测试、演示、会议是过程；本月承诺的是真实使用时，过程再多也算不上达成。
4. **下结论。** 每份复盘都给出一档判定。证据缺了，就按已有证据判，并在受影响的地方写清缺哪条证据。
5. **原因讲到能改变下次选择。** 写风险什么时候看得见、当时怎么选的、哪些事自己能决定却没做、哪些是外部条件。原因要具体到事和人，单次结果只说明这次的事，个人评价另走绩效流程。
6. **上层看自己的承诺。** RU 复盘看 PO 有没有兑现；公司复盘看公司目标有没有兑现、各单元的结果合起来是否成立。上层判定按上层承诺单独给出。
7. **下月输入要能被接住。** 每条下月输入写清类型、要接住什么、为什么，并编号，让下月拆解逐条表态。下月的 PO、Mission 和 Task 由拆解来写。
8. **一开始就写成人话。** 分析在不展示的 analysis 里做；给人看的字段第一遍就按 reader-format.md 写：一句一事、先说结论、写看得见的事实。

## 聊天中使用

1. 确定入口：复盘哪个单元、哪个月、事实截止到什么时候，是起草、审查还是修改。
2. 找齐本月有效承诺和截止前的证据。缺什么，在相应判断旁写明。
3. 按 method.md 判定和分析，按 quality-bars.md 和 reader-format.md 写。修改已有版本时，先读当前正文，只改要求的部分和直接受影响的内容。
4. 需要核对证据时间或数字时，用 scripts/ 里的两个脚本：audit_evidence.py 查证据是否在截止时间内、有没有重复；compare_metrics.py 核对指标差异。

## 边界

- 只产出候选和待决事项。确认状态、关闭 Mission、发消息、写外部系统，都由人或已授权的流程来做。
- 判定、复盘被确认、Mission 关闭、个人绩效是四件不同的事，分开表达。
- 本次明确的业务决定优先于本技能的默认做法。
- 维护本技能前先读 [MAINTAINING.md](MAINTAINING.md)。
