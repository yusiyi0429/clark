# TKOS-Review · 月度复盘

版本 2.1.2，规则核对日 2026-10-26。

## 月度复盘是什么

每份复盘三段：

- **判定**：本月承诺的结果做成了没有：达成、部分达成还是未达成，一句话说为什么。
- **事实证据**：一行一项，逐项写做到了什么、没做到什么、证据是什么、表面上为什么没做到。个人复盘一行一个 Task，责任单元复盘一行一个 Mission，公司复盘一行一个责任单元。
- **分析洞察**：参与者站在公司管理层的角度写，生成复盘时不写。公开后由 Nexus 综合，见 quality-bars.md 和 round-stages.md 的“Nexus 综合洞察”。

判定和事实证据要握手确认；洞察不握手。整份复盘（判定、事实、公开的洞察和 Nexus 综合）交给下月拆解作参考。

## 八条原则

1. **一个对象一份。** 每个 Mission 一份（个人复盘），每个战场和能力域的 PO 一份（责任单元复盘），公司一份。Task 不单独复盘，是 Mission 复盘里的事实行。
2. **对照承诺判定。** 判定的依据是本月有效的成果和成功标准，不是做了多少工作。判定只有三档，规则见 method.md 第 1 节。
3. **结果先于过程。** 方案、代码、测试、演示、会议是过程；本月承诺的是真实使用时，过程再多也算不上达成。
4. **下结论。** 每份复盘都给出一档判定。证据缺了，就按已有证据判，在那一行写清缺哪条证据。
5. **事实和分析分开。** 事实证据只写发生了什么、证据在哪、表面上为什么没做到；不写分析、评价和建议。分析是洞察的事。
6. **一项不漏。** 该列的每个 Task、Mission 或单元都有一行，没开始的也写“未开始”。
7. **洞察看共性。** 洞察不讲某个 Mission 具体为什么没做成，而是看原因合起来反映出公司在目标、理念、机制、流程上的什么问题，一个问题配一条建议。
8. **一开始就写成人话。** 分析在不展示的 analysis 里做；给人看的字段第一遍就按 reader-format.md 写。

## 聊天中使用

1. 确定入口：复盘哪个单元、哪个月、事实截止到什么时候，是起草、审查还是修改。
2. 找齐本月有效承诺和截止前的证据。缺什么，在相应判断旁写明。
3. 按 method.md 判定和分析，按 quality-bars.md 和 reader-format.md 写。修改已有版本时，先读当前正文，只改要求的部分和直接受影响的内容。
4. 需要核对证据时间或数字时，用 scripts/ 里的两个脚本：audit_evidence.py 查证据是否在截止时间内、有没有重复；compare_metrics.py 核对指标差异。

## 边界

- 只产出候选和待决事项。确认状态、关闭 Mission、发消息、写外部系统，都由人或已授权的流程来做。
- 判定、复盘被确认、Mission 关闭、个人绩效是四件不同的事，分开表达。
- 本次明确的业务决定优先于本技能的默认做法。
- 维护本技能前先读 [MAINTAINING.md](MAINTAINING.md)。
