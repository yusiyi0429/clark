# 各层合格标准

生成后、交付前按本页自查本次涉及的层级。对象定义见 contracts.md，拆解方法见 method.md。

## 验收（各层通用）

- **成果写届时为真的状态，验收写查什么证据、怎样算成立、什么不算。** 不能把“完成初稿”的验收写成“初稿完成”，也不能用“完整、合理、质量好”代替判断依据。
- **验收必须证明本层承诺的结果真的发生。** 交付节点（文件交了、功能上线了）和结果成立（下游能做什么、什么问题改善了）分开。每条验收反问一次：“东西全交了、记录也有，但内容错误或下游用不了，还能判通过吗？”能的话，补质量、实际使用或效果的口径和取证安排，不靠降低目标让它通过。
- **以下写法都判为验收太松：**
  - 用“或”把失败也列为通过，如“确认或退回”“录用或暂缓”；
  - 负责人自己确认就算数；
  - 拿内部场景、模拟、演示或本人试用代替真实使用，却没有单独标为降级结果；
  - 只要求交文件、开会、有版本号。
  失败或降级的情况写成“未通过时怎么办”，不算通过。
- **验收的严格程度匹配本期承诺的状态**：首次使用看真实完成一次约定工作并取得反馈；持续使用看跨多次业务活动的使用记录；自主运行看不依赖团队代做。能力建设看是否有效支撑约定的下游，不强求每项证明收入。
- **数字要有来源。** 业务要求、有效基线或已确认决定支持的阈值才写成正式标准；合理的建议阈值标为候选并说明依据；真实未知的关键阈值写清由谁按什么依据核定，不编造，也不空着整个验收。
- **取证要有人负责。** 验收需要的使用记录、反馈、确认回执，写清谁收集、何时核对。

## LTO

跨多个周期仍有意义的经营结果或能力状态，不是项目清单。六个月边界清楚，一个主归属；RU LTO 说明对公司结果的具体贡献；实现逻辑解释因果阶段，不罗列未来的 Task。

## PO

- 一个 RU、一个月、唯一有效版本的上级 LTO；时间边界是整月。
- 成果是本月末应达到的结果状态，不是 Mission 清单。
- 存在必要性回答为何本月必须做、所选路径和暂缓代价、与其他 RU 一起如何推进公司目标（写法见 method.md 第 3 节）。
- 责任边界写清本 RU 负责到哪里、其他 RU 负责什么。
- 预计 LTO 推进写到什么阶段，不虚构百分比或实际进度。
- 上级 LTO 的每项要求、上期复盘的每条缺口都有着落：本月承接、写明暂缓及影响，或注明由哪个 RU 承接。
- 能力域 PO 的供给与战场使用的关系写具体；只有技术测试时不声称已证明经营效果。

## Mission

- **有独立的端到端结果。** 删掉它，PO 会出现明确缺口；否则合并或降为 Task。Mission 组合不是项目阶段换个名字。
- **先选本期要到的状态**（可演示、可供使用、首次真实使用、多轮使用并迭代、持续采用、业务效果），再写交付、推动和验收。接通数据不等于真实使用，多轮使用不自动证明持续采用。
- **核心路径**解释如何兑现结果，不抄操作步骤；**关键取舍**写主动不做什么、为什么；**约束与依赖**只留会改变打法、启动或通过的条件，写提供者、必要状态、需要时点和未满足的后果。
- **里程碑**是少量可观察的结果状态，可以由多个 Task 共同支撑；“开评审会”“提交方案”不是里程碑。数量按需要，通常少于 Task。
- 子项全部完成仍可能兑现不了 Mission 时，补联合交付或真实使用的验证。
- 实际承载条件要写到：哪个产品版本或业务流程、谁使用、需要哪些真实数据和权限；演示版转正式使用、试行转制度运行要有人承接交接。

## Task

- 有可独立验收的工作结果，不是动作串或任务说明。责任边界写清与相邻 Task 的分工。
- 说明让执行者看出具体的工作对象、要解决的专业问题和产出。整套 Task 换一个行业名称仍原样可用时，说明漏掉了决定成败的专业内容。
- 涉及统计、比较、筛选时，写清算哪些对象、用哪个日期和范围、怎么去重、公式和缺失值怎么处理；已有业务规则直接采用。
- 依赖写清真正要等的前置交付，以及到什么程度就能开始（见 feasibility.md）。

## Activity

只用 Agent Activity、Human Activity、Human Checkpoint 三类，一个主要执行主体。拿到必要信息就能做；“研究→讨论→改稿→确认”藏着多次交接，应该分开；“打开文件、复制文字”是工具步骤，应该合并。Human Checkpoint 承接真实判断权，写清判断对象、通过和退回的证据与后果；普通参与不自动变成审批。

## 交付前

先修掉能用现有信息解决的问题。剩下的按“对象／字段 → 具体问题 → 对上层结果的影响 → 修正方式或需要补的输入”列出。结构合格、内容合格、条件可行、正式确认、真实结果达成是不同的结论，分开说。
