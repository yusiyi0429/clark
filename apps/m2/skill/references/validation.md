# 业务质量验收与行为验证

文件格式只验技能可发现、可读与引用有效，以下门槛才检验拆解质量。

## 交付前业务检查

| 门槛 | 通过依据 | 不通过时 |
|---|---|---|
| 正确入口与范围 | 本次层级明确；只补必要上下文；用户锁定选择保留 | 修正层级／标待输入 |
| 原要求保留 | 有效输入的数量、格式、范围、顺序、条件／例外、禁止事项均有相关承接；已有事实未误标缺失 | 按method.md查漏并修正文，不重复索取已有资料 |
| Outcome 与动作分清 | 结果是可观察状态；材料／会议不是经营成功替身 | 重写结果或降层 |
| 必要性 | 每项删去有 Material 父结果／计划缺口 | 删、合并或说明必要性 |
| PO阶段与取舍 | 能说明长期卡点、本月必要推进、选择及暂缓代价；不以最小可验证结果替代必要阶段 | 重判目标／明确待人决定的取舍，不只扩写 |
| 初稿推进力度 | 结合LTO剩余阶段、上月实际结果与差距，提出足够的本期推进；不是只挑易完成项，也不是无依据地扩大承诺 | 加强过弱候选或修正阶段跳跃；硬约束冲突提交解决选择，由DRI反馈校准 |
| 实际结果验收 | PO／Mission证据能判断业务变化或有效能力支撑，不只证明提交、上线或开会；无制度仍提出有依据的候选标准 | 补质量、使用或下游效果及取得工作，不降目标刷通过，不强套收入或编数字 |
| 责任适配与总负荷 | 负责人候选有职责、能力及权限依据；同人跨RU投入合并，交接与依赖能接上 | 调整责任候选或安排，不只按名单、空闲或头衔派工；候选不冒充已承诺 |
| 修订影响有选择 | 已检查相关成果、验收、责任、依赖和排期；确有影响才修改，未影响内容及正式基线保留 | 补遗漏联动或恢复无必要重写；越权改动交有权人判断 |
| 本期核心与延伸 | 业务重点有依据、成熟程度分别清楚；分类不弱化已有承诺 | 修正平铺范围及过高／过低成熟要求，未知优先级提交选择 |
| Mission业务组合 | 独立专业结果未被吞进准备工作，也不按准备／交付／跟进机械切分 | 重新切结果边界，不只改名称 |
| 专业经验落实 | 本次允许的经验有来源与适用边界；Task和标准体现专业问题，不只是通用动作换标题 | 核回相关工作记录，补具体工作及质量；缺经验标建议，不编公司事实或引入盲测答案 |
| 经营变化与推进 | 专业交付之外，实际采用、机制落地与跨团队衔接有人持续负责；重要输入缺口有承接或有依据的暂缓 | 补结果与持续推动，不以方案确认代替组织启动，不强造协调Mission |
| 责任口径一致 | 成果、验收、边界和实际分工一致；供给方不独自承诺消费方采用，技术评估不冒充产品决策 | 修正责任与交接，派工依据不足标候选，不借对标答案补正式责任 |
| 证据与系统可实现 | 验收记录有取得安排；确认、修订和写回对应实际对象、前置状态、权限与回执 | 补记录责任及业务／系统缺口，不给快照虚构确认门 |
| 结果负责到底 | 专业交付、实际采用、客户推动分别有人承担，协调者不包办所有结果 | 核对实际分工并补交接及下游责任，不按名单派工 |
| 并行与持续工作 | 硬前置只约束受影响部分，能并行且资源支持，持续协调贯穿周期 | 修正整项等待与隐藏持续投入，不绕过权限安全 |
| 本期成熟程度与承载 | 验收匹配本期状态，产品／流程、版本、数据与真实参与条件可核对 | 修正跨阶段验收，缺条件落实到相应成果，不能靠假数字通过 |
| 有效使用与比较验收 | 真实事项、参与、结果使用及反馈可区分；要求比较时输入可比、维度和判断人明确 | 排除重复技术运行，补真实记录；不默认三轮或人工90% |
| 单独Mission呈现 | 仅Card两列、Task表五列、依据；范围／用户模板优先，无重复里程碑及轮次元信息 | 按templates.md删除多余内容，不删关键执行条件 |
| 用户修订同步 | 当前有效Card、表、已有图的范围、日期、验收及状态一致；冲突有处理，授权范围未扩张 | 同步受影响表达，未指定真相的冲突请求判断；保留相邻承诺 |
| 模板与摘要精简 | 最新模板的章节、表格列数、字段顺序、列表／加粗与对齐相符；Plan表未复制完整Card，日期格无说明，路径无第二套补充清单 | 按reader-format.md改实际正文；细节和未决条件放对应Card／依赖，不删关键要求、不抄模板答案 |
| 反馈与重新握手 | 反馈来源及版本明确，采纳有依据，分歧未冒充共识；实质承诺变更保留原确认基线并交还有权人确认 | 按revision-loop.md修正候选与影响说明，不把评论或改稿直接变成已确认状态 |
| 启动与变化 | 阻塞条件解除、非阻塞细节可迭代、承诺变化由有权人判断；真实使用有时间及投入 | 修正无限等待或绕过权限，留实际试用窗口，不只排开发 |
| 公司组合推进 | 相关PO与供给合起来推进什么、仍缺什么和时间是否衔接；只生成部分RU时注明供给未确认；结论写在PO存在必要性 | 补遗漏或接口，不能以局部可验收冒充整体足够 |
| 父条件覆盖 | 每项父验收有已有 Evidence 或子结果；没有孤儿子项 | 补缺口并解释 |
| 组合充分性 | 显示 AND／替代／支撑逻辑；全部完成仍可能失败的因果被标明并验证 | 补真实采用／集成／效果验证或标不确定 |
| 责任与横向关系 | 主 RU 与唯一 DRI 候选清楚；支撑结果不重复认领 | 修正归属与接口 |
| 能力建设与客户专项 | Domain承接长期可复用能力，Battlefield承接客户专项；归属按结果而非人员专业；具体交付衔接且工时只计一次 | 补遗漏专项／修正归属与重复投入 |
| 目标与风险分开 | 目标明确，外部条件、应对与可行性单独表达；内部可交付成果不降为“看情况”，客户拒绝不算原目标达成 | 修正目标及验收／提交资源或承诺取舍 |
| 阶段验证与月度覆盖 | 本期全部必要成果有承接，先试后扩有实际工作和最终验收；同人同主题的专项与通用建设分别拆任务，仅实际共享供给去重 | 补未覆盖结果／修正复制或错误合并的任务；不足时提交取舍 |
| 可行性 | 外部提供者、关键依赖、容量／客户时间与最长必要链有依据 | 条件可行／待取舍，不能假称通过 |
| 时间与先后 | PO覆盖完整月份；所有工作日期具体，Mission由Task首尾计算；Activity在Task内；硬前置只阻塞相应工作，工期有工作与等待依据；阶段节点不截断月度成果 | 执行feasibility.md排期门槛及可运行的日期脚本；修复后复查，不仅改显示，不把短期会议当完整工作，不为凑月度窗口压工期；未核实可行性不称通过 |
| 计划展示与日期分类 | 图是否展示符合本次范围／模板及reader-format.md；展示时与Card／Task／里程碑同源，建议区间有依据，未定外部结果不画成承诺 | 只补本次要求的图，不因用户取消图判失败；核对供给和日期，图不证明资源可行 |
| 单元格分点 | 多个独立成果、理由、分工、阶段或条件用有序要点，每点加粗短标题、正文不加粗；单一意思短句，因果没有被机械拆散 | 修正大段堆叠、无标题和虚假列点，不靠标点拆分制造清晰 |
| 展示字数与漏项 | 按reader-format.md计字段总量和单点长度；适用模板字段齐全，空值原因区分资料缺失、生成漏项与显示漏项 | 超长先去重改写，不截断或删关键条件；不能安全精简的具体例外报告未达标，不把不适用字段当漏项 |
| 版本与证据 | 事实、决策、假设和建议分开；确认不代表达成 | 修正状态及来源 |
| 停止层级 | 直接可执行 Task 没有空 Activity；必要 Activity 单主体 | 合并／拆正确节点 |
| 计算口径（仅相关Task） | 对象、记录粒度／去重、业务时钟与时间端点、筛选、公式及归属、并列／空集／缺失按有效规则可执行；关键未知具体 | 修正有依据的规则，暂停受未知影响的最终判断，不编数据或默认全行业规则 |
| 给人看得懂 | 按reader-format.md实际复读，能定位具体事情、责任、日期及通过证据；每栏各司其职，Plan精简且关键条件可查 | 修改具体表达，不只缩字数；核对精简前后范围、责任、日期、验收、承诺强度和未知未变 |
| 判断边界 | 人类判断与返工分支明确；未知审批不臆造；无自动写回／派工 | 标待决并停相应节点 |
| 一层握手与逐层计划 | 上级只正式确认直接下一层，保持下钻与建议；当前层已有安排，子层细化后回查上层，不等全链生成才计划 | 修正确认负荷／补当前层衔接，不把建议当批准或画图当可行性 |
| 逐层质量 | quality-bars.md 中相关层级满足；验收不循环复述，阈值有依据；摘要与正式定义一致 | 修正内容，不只补字段或打分 |
| 验证输入隔离 | 生成时未用同案例已有 PO／Mission；已污染的测试如实标注限制 | 换未见案例／不声称盲测 |

未经验证的经营因果不会因验收表全绿自动变成事实。发现实质阻塞时可以交付完整候选与缺口，但明确不得定稿／执行的部分。

### 交付前改稿要求

对实际候选检查以下错误，能由现有资料解决的必须改正文，不只保留点评：

1. **阶段跳跃**：新增本期成果仅因出现在LTO就被承诺，缺本期必要性或关键前提 → 重判当前阶段与候选范围；正式目标不可自行改，提交取舍。
2. **准备替代结果**：材料、演示、功能或会议完成被用于证明真实采用、客户合作或经营价值 → 区分两种结果，并补实际使用／客户判断证据；不以准备或客户拒绝验收原业务目标。
3. **循环或空泛验收**：标准只重复成果，或因缺日期、数字就整项待定 → 改为可核对的证据和通过口径；确实未知的阈值单独保留及说明影响，不编造。
4. **尾注式可行性**：正文全量、确定排期或保底不变，仅尾注资源未明 → 将具体缺口落实到受影响范围、先后、候选成熟度及待取舍，不把一份激进草案宣称可靠。
5. **原要求流失**：原输入明确的范围、数量、条件／例外等未被承接，或已给事实被当成缺口 → 核回来源，补到相应结果、验收、边界或有效引用，不复制到所有子项。
6. **计算解释不唯一**：同一规则可以算出不同结果，却默认时间范围、分母或归属 → 采用已有口径；确实未定的关键解释说明影响，停相应最终判断，不猜业务规则。
7. **黑话和无用展开**：用抽象词代替具体工作，简单问题铺完整卡片或重复流程 → 按reader-format.md重写；简短展示不改变正式定义和关键条件。
8. **模板或同步失真**：单独Mission被套轮次模板；用户已改正文／图却被旧稿覆盖；日期与验收各处不一致 → 按当前模式最小修订，并逐项核对；冲突不静默选边，相邻正式承诺不擅改。
9. **有效使用与推进失真**：按点击计真实轮次，目标只要求试用却验收持续采用，或细节优化导致整月不使用 → 重选本期状态及证据，分清启动阻塞与非阻塞问题，安排实际参与／反馈及必要修正。

简短修订记录可留生成日志，不自动增加业务正文。检查仍发现可修复错误时继续修复受影响字段；不把自评表通过当作已改稿。无法解决的事实缺口保留，不通过杜撰资料使检查变绿。

## 可重复行为用例

### 每次技能升级的回归检查

1. 保存旧版、修改范围和问题依据。先定位已有规则为什么没有落实，优先改清原段落；不为每个案例另加一套必选打法。规则变更与格式变更分开。
2. 检查正反两面：加强结果验收不能要求所有Task直接证明收入；加强专业内容不能堆术语或抄答案；加强并行不能绕过硬前置、虚增容量；推荐责任人不能改正式派工。原有目标力度、组合覆盖、具体日期、简洁模板、一层握手、影响修订和输入隔离继续检查。
3. 行为对照冻结同一业务输入、模板、模型、推理强度及调用机会，用旧版和新版分别生成，再冻结原文并逐项评判。案例同时覆盖新增问题与原有能力，不能只选新版擅长的题。评测答案及评分规则不喂生成者；已参与调优的案例只算已知回归，不冒称独立盲测。
4. 按目标承接、专业工作、结果验收、排期与负荷、责任及权限、表达逐项看变好／持平／变差，不用总分掩盖严重退步。发现漏掉原要求、弱化承诺、权限越界等，修复或撤回对应改动再检查；有利变化也不能抵消这类损害。
5. 记录实际执行到哪一步。文件和规则检查、作者演练、同配置行为对照、团队真实使用分别报告；没有行为对照就写未测，不能说“已排除负向优化”。不因升级自动重跑业务轮次、外部写入或调用未授权测试资源。
