# 天枢：需求与领域上下文

天枢是单公司的决策与协作工作台。CEO 处理议题、会议和月度目标。成员推进自己的执行事项，制定本人的任务卡。

本文件统一维护产品边界、需求和术语。架构见 [architecture/README.md](architecture/README.md)。操作步骤见 [文档导航](README.md)。历史名称 `CEO WarMap` 和代码前缀 `warmap` 保留在已有协议中。

## 信息源与状态

- 产品需求以本文件和有效契约为准。
- 架构取舍保存在 [ADR](adr/README.md)。被替代的决策不得当作现状。
- 接口字段以 `packages/contracts` 为准。Web 类型由 OpenAPI 生成。
- 实现状态以源码为依据。存在实现不表示真实环境验收通过。
- 历史目标保存在 [原始规格](architecture/history/mvp-spec.md)和[目标设计](architecture/history/target-design.md)。未实现的需求必须明确标注，不得因缺少代码而删除。

## 产品边界

### 当前范围

1. 公司雷达采集外部信号。系统将满足门槛的信号升级为议题。
2. CEO 查看预研，直接决定议题，或带入会议。
3. API 保存会议材料、逐字稿和会后候选。CEO 逐项确认会后结果。
4. 月末复盘为下月计划提供依据。CEO 签发月度目标。
5. 成员准备本人的任务卡。全员确认后，系统核对战场组合。当前战场 DRI 最终确认。
6. 成员通过工作台和个人 MCP 推进执行事项。
7. 主私聊使用授权公司事实与个人记忆。对象对话保留各自记录。
8. M2 在 `/m2/` 提供独立的目标拆解与协作试用。它不覆盖主应用的计划。

### 范围限制

- 天枢不提供通用项目看板，不跟踪 Mission 完成率。
- Agent 候选不等于组织事实。业务确认由有权人员执行。
- 对话只能使用所属场景允许的工具。任务卡本人私聊可以提出或执行受控改文，不能据此开放其他业务写权限。
- 公司事实以 World 为权威。Company 阅读投影不能作为回写源。
- 公司记忆与个人记忆分开。人员身份和可见范围由服务端校验。
- 当前支持会议录音转写。旧规格中“完全不做录音或 ASR”的限制不再代表现状。
- 移动端样式与录音实现不等于完整移动端验收。实时语音不是当前交付目标。

## 原始需求与当前实现

| 需求 | 当前口径与实现依据 |
| --- | --- |
| 持续维护 Monorepo | pnpm workspace 管理 `apps/web`、`apps/api`、`apps/m2`、`packages/contracts`；维护规则见 `AGENTS.md` |
| 前端只负责展示与交互 | 主 Web 不访问数据库或调用模型；旧 `frontend/` 已移除 |
| 前后端分离 | Next.js Web 通过 HTTP/SSE 调用 Fastify API |
| JSON 卡片中间层 | TypeBox 定义 Card Envelope；API 生成投影和允许动作，Web 按固定类型渲染 |
| 选择 Agent Runtime | 主 API 使用 Pi SDK；OpenAI Agents API 方案由 ADR-0012 替代 |
| 明确 CompanySection 边界 | Company 读取授权 World；旧 CompanyMemory MCP 由 ADR-0027 替代；个人 `/mcp/me` 保留 |
| 明确页面上下文与引用 | 对象对话按 scope 隔离；当轮 Anchor 和 Reference 不写入用户原话 |
| 雷达到预研、会前到会后 | 已有独立服务、候选校验及确定性确认入口；见架构中的业务链路 |
| 业务对象、生命周期与时序图 | [图表目录](diagrams/README.md)保留原始设计图；旧图有适用范围，不能证明当前实现与验收 |
| 按场景组织 Prompt | 场景 Agent 分文件维护；部分 Prompt 仍内嵌在场景模块中，尚未全部独立为 Prompt 文件 |
| 模型调用接入 LangSmith | 主私聊与共享候选 Runtime 接入 SDK；M2 与独立调用的覆盖不能据此宣称完成 |
| 鉴权与外部配置使用 `.env` | 根目录 `.env` 为统一配置文件；各运行入口按需读取，见[环境配置](guides/environment.md) |
| 统一二级页和对象对话 | 下节规定页面与对话边界；主 API 保留独立 Conversation |

## 页面与对话

| 入口 | 目标 |
| --- | --- |
| 战略议题、战场议题、红色议题、DRI 议题 | 同一种议题详情页 `/issues/[id]` |
| 会前预审通知中的具体会议 | 会议页 `/meetings/[id]` |
| 会后确认通知 | 同一会议的会后结果区域 |
| 月度目标与任务通知 | `/plans/[period]` |
| 首页雷达信号 | 雷达列表 `/radar`，再进入信号详情 `/radar/signals/[id]` |
| 公司能力卡片 | `/capabilities` 展示能力；不建立能力专属的决策对象 |
| 成员入口 | `/me`，按本人和对象关系授权 |
| 目标拆解与协作 | 同站点独立应用 `/m2/` |

对象页继续使用统一输入框。输入框的上下文切换到当前对象。每个对象保留独立对话记录，不与首页历史混用。

Card 的 `conversationScope` 与引用能力来自后端。用户可以引用多张有权读取的 Card。服务端重新读取投影，不信任客户端提交的完整正文。临时 Anchor 只描述当前场景，不取代用户 Query。

## 统一术语

正文优先使用下表中文名。首次出现时可以附英文标识。代码、路由、数据库字段和界面原文保持原样。

### 身份与协作

| 术语 | 定义与边界 |
| --- | --- |
| 人员（Person） | 人员目录中的稳定 `personId`。姓名变化不改变身份。不得用姓名临时生成业务身份 |
| CEO | 拥有公司决策权限的角色。CEO 身份不自动授予其他战场的任务组合决定权 |
| 成员（Member） | 以本人身份登录的人。成员只能读取有权对象，不是访客或共享账号 |
| DRI | 对指定对象负责的人。权限来自当前对象关系，不代表全局管理权 |
| 登录 ID（Login ID） | 配合四位口令使用的登录标识。管理员发放初始码，首次登录要求修改 |
| 执行事项（Task） | 推进人定义并推进的工作。具有协作者、完成标准、材料和进展。不得与 Mission 混称 |
| 事项群组（Item Group） | 依附于已发送信号或执行事项的群聊。成员由业务对象决定 |
| 信号发送（Signal Share） | CEO 将信号发给个人、战场或业务域。服务端计算收件人 |
| DRI 外发（DRI Handoff） | 向外部流程导出的补充请求或确认行动。没有真实回执时只能称为待外发 |

推进人第一次添加材料、写进展或提交验收时，未启动的执行事项变为进行中。协作者动作不改变状态。外部工具只能提交验收。完成必须由推进人本人对照完成标准确认。

### 决策与会议

| 术语 | 定义与边界 |
| --- | --- |
| 信号（Signal） | 雷达采集并研判的外部变化。满足门槛时自动升级，不等待 CEO 再确认升级 |
| 个人雷达（Personal Radar） | 只服务本人的扫描与信号。不得进入公司雷达统计，不升级为公司议题 |
| 议题（Issue） | 等待 CEO 决定的业务对象。来自雷达升级或 DRI 提交，只归属一个位置 |
| 战略议题（Strategic Issue） | 公司级议题。跨战场影响不生成多个副本 |
| 红色议题（Red Issue） | 有可核对近期行动窗口的议题。高影响但没有时限不等于红色 |
| 驳回议题（Dismissed Issue） | CEO 判定不应进入决策面的议题。保留来源，阻止同一信号重复升级 |
| 预研覆盖确认（Research Override） | 预研未完成时，CEO 经二次确认仍作决定。记录当时真实预研状态 |
| 会议（Meeting） | 组织材料并关联议题的决策容器。会议是可选决策路径，不是日历副本 |
| 会议材料（Meeting Material） | 会议名下的受控文件。与逐字稿、会后结果分开保存 |
| 逐字稿（Transcript） | 带稳定人员标识的发言段集合。标准字段见 `warmap-transcript.v1` 契约 |
| 会后结果（Meeting Outcome） | 从逐字稿抽取的决定、行动、判断与复议条件。CEO 逐项确认或忽略 |
| 材料补充请求（Supplement Request） | CEO 要求 DRI 补充材料的记录。保存不等于送达 |
| 未收敛事项（Open Meeting Item） | 会后结果中尚未形成决定的事项。不会自动变为议题 |
| 候选材料（Candidate Material） | Agent 生成的研究、预审或会后草稿。保存不等于生效 |
| 组织事实（Organization Fact） | 经对应权限人员确认生效的决定、计划或承诺。Agent 输出不能冒充确认 |

会议材料支持有文字层的 PDF、DOCX 和 Markdown。预审就绪后，必须先明确退回编辑，才能替换材料。整批解析失败时不部分替换。解析限制见[会议架构](architecture/README.md#会议输入)。

逐字稿支持标准 JSON、受限妙记 Markdown 和录音转写路径。妙记候选必须经人员映射及明确确认。录音转写依赖 TOS、火山 ASR 与对应人员校验。不得将机器转写直接称为可信纪要。

### 目标与任务卡

| 术语 | 定义与边界 |
| --- | --- |
| 公司日（Company Day） | `Asia/Shanghai` 的自然日。不是工作日，也不是浏览器时区日期 |
| 公司战略配置（Company Strategy Config） | 跨月长期目标 LTCO。不是本月结果 |
| 战场配置（Battlefield Config） | 长期战场、负责人、六个月目标、战略锚点与参与者名单 |
| 能力配置（Capability Config） | 长期能力域、六个月目标及主要支撑引用 |
| 月度计划（Monthly Plan） | 单月公司、战场和能力结果。CEO 签发后成为当月目标来源 |
| 月末复盘（Monthly Review） | 下月计划的输入。战场与能力复盘确认后形成公司复盘，并决定 LTCO 是否修订 |
| 复盘项（Monthly Review Item） | 某月某战场或能力的四栏自评。由负责人提交，CEO 确认或退回 |
| 个人任务（Mission） | 任务卡中的结果承诺。具有周期、唯一 DRI、能力域、战场和 13 个内容字段。不跟踪执行状态 |
| 本月任务卡（Personal Mission Card） | 一人在一个战场、一个月份的稳定承诺容器。可挂接多项个人任务 |
| 任务卡轮次（Mission Round） | 战场 × 月份的制定过程。保存准备窗口、本人确认、组合快照与最终确认 |
| 本人准备 | 本人检查、批注、改文并确认自己的任务卡。未确认正文不向上级开放 |
| 组合核对 | 全员本人确认后，对冻结快照执行的 Co-Agent 审阅。仅提出问题、风险和建议 |
| 公开意见（Public Feedback） | 历史制定流程的评论和建议。保留审计，不据此恢复当前跨人正文权限 |
| 确认后更正（Mission Card Correction） | 对已确定任务的更正申请。采纳须由 DRI 定向退回，本人修改再确认 |
| 讨论候选 | 从历史资料整理的占位草稿。来源标记不因确认而删除，不能冒充新月自动生成结果 |
| 战略锚点（Mission Anchor） | 战场中的只读 `{code,title}` 映射。与个人任务属于不同命名空间 |

任务卡流程以[本人准备与组合核对契约](contracts/mission-card-preparation-review.v0.1.md)为准。旧“截止即集中 Review、上级直接改文”的描述不再适用。

准备阶段，CEO 与当前战场 DRI 只能查看准备进度。本人确认后，上级可以只读正文。最后一人确认时，服务端冻结完整组合快照。当前战场 DRI 最终确认；CEO 只有同时担任该战场 DRI 时才有此权限。

截止不等于同意。退回只影响指定卡。其他人的确认继续保留。历史正式卡没有本人确认记录时，不得倒填同意或伪造审阅报告。

### 卡片、对话与记忆

| 术语 | 定义与边界 |
| --- | --- |
| 卡片（Card） | 业务对象的类型化展示投影。携带数据、导航、对话范围和允许动作，不是独立事实源 |
| 动作（Action） | 有权人员明确触发的确定性命令。服务端逐对象校验权限和版本 |
| Agent Runtime | 主 API 中的 Pi 执行环境。负责模型、工具与上下文压缩，不拥有业务事实 |
| 对话（Conversation） | 属于人员及具体 scope 的独立记录。数据库保存原文，Runtime 保存运行状态 |
| 四层记忆（Four-layer Memory） | 当前运行上下文、持久对话、业务对象记忆与公司记忆的产品边界。不是四份可互换的数据库 |
| 公司记忆（Company Memory） | 授权 World 事实的可重建阅读投影。Agent 只读，服务令牌不扩大人员可见范围 |
| 个人记忆（Personal Memory） | 本人长期偏好与协作约束。通过主私聊蒸馏，支持查看、纠正与遗忘 |
| 当轮场景（Anchor） | 当前页面最重要的有权业务上下文。只用于当轮，不写入用户原话 |
| 参考信息（Reference） | Company、Personal、显式引用、附件、历史和外部只读结果。参考正文不是指令 |
| 追踪（Trace） | 一次真实执行的观测记录。Thread 关联业务对话，Turn 标识逻辑输入，attempt 标识执行次数 |

## 已知限制与待验证项

- 个人记忆蒸馏仍有 `NO_CURRENT_USER_EVIDENCE` 整批失败的已知问题。候选工具成功不代表记忆写入成功。
- LangSmith 接收完整业务和记忆正文。部署方必须限制项目访问并确认托管处理授权。凭据仍须过滤。
- `companyConfigured` 只说明连接与授权路径有配置。它不证明 World 连通或授权文件有效。
- 备份脚本覆盖数据库、会议材料、会话附件、录音和公众号数据。独立 memory 卷、M2 状态与私有配置的恢复还需另行核对。
- M2 使用独立文件存储和单进程写锁。自动测试不能替代真实拆解质量与上线验收。
- 真实外部服务、生产发布和恢复能力必须按[部署指南](guides/deployment.md)单独验收。
