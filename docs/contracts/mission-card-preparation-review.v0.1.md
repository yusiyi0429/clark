# Mission Card 本人准备与组合核对

本次用户确认的口径优先于旧公开讨论流程。方法对照 [Co-Agent Design 当前说明](https://github.com/TokenkingOS/Co-Agent-Design/blob/a123af49/docs/CURRENT-VERSION.md)；正式字段与起草要求沿用 [Mission Card 起草口径](./mission-card-writing.v0.1.md)，飞书正文 revision 26。模板示例不是公司正式任务数据。

## 状态与权限

CEO 签发月度目标后，系统为每个战场的参与者起草任务卡（CEO 不拿卡），整个战场起草成功后自动交给本人确认；有人起草失败时轮次停在草稿，失败的人在 CEO 与战场 DRI 的准备进度里可见，由战场 DRI 重试，重试全部成功后同样自动交给本人（[ADR-0026](../adr/0026-draft-mission-cards-on-plan-sign.md)）。任务本人检查结果、验收、边界、依赖与取舍。准备阶段只向本人展示正文、批注、私聊上下文；CEO 与当前战场 DRI 能看准备进度，不能读尚未确认的正文。普通同事即使在历史 `member_ids` 中也不能读别人任务卡。

只有本人能批注、提出修改或让私聊 Agent 改正文。本人确认后正文被冻结，上级可以只读原文和历史。取消本人确认同步增加对象版本并撤回上级正文可见性。最后一人确认时，同一事务冻结所有本人已确认卡，建立唯一组合核对快照，后台 Co-Agent 自动审阅。

完整组合报告只向 CEO 与当前战场 DRI 展示；普通本人只能读自己的正文及核对状态。DRI 最终确认 Mission 组合；CEO 签核月度目标，不因 CEO 身份获得其他战场的 Mission 决定权。CEO 同时是该战场实际 DRI 时使用相同负责权限。

## 备注和立即修改

`POST /api/mission-cards/{id}/annotations` 显式传 `intent: note|edit`。省略时为 note，兼容旧客户端但不会暗中修改。

- note：立即保存原文，不排队，不阻断本人确认；之后本人可以选择 retry 交给 Agent。
- edit：明确进入队列。清楚的改法立即修改，保留批注原文和修订前后版本；歧义以问题和选项澄清。
- queued、applying、needs_clarification、failed 的本人 edit 阻断确认。可以回答、重试，或以 resolve 写明“保留备注，暂不修改”；原意、问题、回答和原因均保留。

重复 clientId 的创建依据不可变 initial_intent 校验，不因后续 note 转 edit 改变原请求语义。所有写入复核本人身份、阶段、sourceRound、源版本与完整原字段；旧窗口生成的改法不能套进新窗口。历史外人建议仅保留审计，不计入当前有效意见或阻断本人确认。

## 自动组合核对

快照包含签核目标及版本、战场、全员本人确认时间、所有任务原字段及版本、原始批注、每次澄清、保留备注、全部修订、历史公开意见、更正申请与决定。后台不另取变化中的正文。

报告为简短摘要和带准确来源的问题、风险、建议。源必须属于快照，任务来源版本必须一致；批注/修订/更正引用可指定字段和版本，逐字引用必须实际存在，不能混用来源类型。无事实依据时提出问题，不编造人、数字、期限或资源。模型不写已确认正文、不代人确认，不将模型输出视为人的同意。

持久状态 queued/running/completed/failed 支持重启恢复和 DRI 显式重试；数据库阶段锁与独立 claim token 防止并发重复、旧窗口及晚到结果覆盖当前报告。正常关闭重排队；超时/失败保留全部已确认正文及历史。

## 退回与最终更正

`POST /api/mission-rounds/{id}/return-cards` 接收 `cardIds`、`reason`、当前 `version`，仅战场 DRI 可用。组合审阅或正式确认阶段如需改正文，只退回受影响卡，清除这些人的当前确认，其他本人确认保持；本人修改再确认后形成新的完整快照。旧报告、正式确认来源及更正历史不删除。

正式确认后的本人更正申请只保留意见，不直接写文；DRI 可拒绝并留原因，采纳必须通过定向退回。`correctionAccess.canApply=false`，`canReject` 独立投影。已过月份保持只读。

历史正式 confirmed 没有本人确认时间的记录仍按原正式确认允许上级读，不倒填本人同意，不伪造 Co-Agent 报告。此类历史组合不能使用定向退回；返回明确 LEGACY_CONFIRMATION_REQUIRES_NEW_DRAFT，需单独重新起草。旧 reviewing 无本人确认可退回重新准备，所有缺本人确认者必须真实确认。

## 截止与数据

截止未完成不默认为同意，不触发组合核对；进度明确保留未完成名单，DRI 可延长确认，保留已确认者。最后确认可以在有效延长或定向退回的新窗口完成。

数据来自服务器与数据库。迁移 054 只增字段并兼容现有审计，不导入演示数据、不重写既有正文、不重新审阅历史正式确认。自动化测试仅使用随机 warmap_test_ 数据库。
