# CEO WarMap 联调与部署方案

## 1. 目标

把各技术分片整合为一个可重复部署、可观察、可备份、可回滚的单机 MVP，并在不破坏当前 CEO WarMap 参考界面的前提下切换到新 Web。

## 2. 环境分层

| 环境 | 数据 | 外部 Provider | 用途 |
|---|---|---|---|
| local | 可删除 fixture | 默认 stub，可单独开真实模型 | 模块开发 |
| integration | 固定集成数据 | stub + 可控 Pi 模型 | API／Web 联调 |
| staging | 脱敏真实样本 | 真实 Search、公众号、模型、MCP | 上线验收 |
| production | 真实数据 | 真实 Provider | 单 CEO 使用 |

禁止 staging 和 production 共用 PostgreSQL、Session secret 或 service token。

## 3. Docker Compose

长期服务：

```text
edge      Caddy · 唯一公网入口与 TLS 终止
web       Next.js
api       Fastify + Pi + Scheduler + MCP
postgres  PostgreSQL
```

网络：

- 只有 Caddy 暴露 80/443，HTTP 自动跳转 HTTPS；
- Caddy 将 `/` 路由到 Web，将 `/api/*` 与 `/mcp/company-memory` 路由到 API；
- Web、API、PostgreSQL 只在 Compose 内网；
- DRI service API、Conversation SSE、multipart Transcript 和 MCP 都经 Caddy，不经过 Next rewrite；
- MCP 与 DRI API 继续要求各自 service token；
- Caddy 负责证书申请/续期和流式请求透传。

持久卷：

- PostgreSQL data；
- 不为 Web/API 创建业务文件卷；
- CompanyMemory Markdown 若仍为种子，通过只读挂载提供；
- 备份输出先写临时目录，再加密上传到异机位置。

## 5. 构建

### Web 镜像

- 使用 pnpm frozen lockfile；
- 只复制 workspace 所需包；
- 构建后检查 bundle 不包含服务端 key 名值、旧 seed 和旧业务模块；
- 使用非 root 用户运行。

### API 镜像

- 固定 Pi SDK、Fastify、TypeBox 和 PostgreSQL driver 版本；
- 不复制用户 `~/.pi`；
- 不安装 Shell、浏览器、ffmpeg、ASR 或录音依赖；
- Prompt 作为只读构建产物；
- 使用非 root 用户运行。

### 数据库

- 固定 PostgreSQL major；
- 启用必要 extension 前写 migration；
- 不依赖手工进入容器改 schema。

## 6. Migration

部署顺序：

1. 备份当前数据库；
2. 启动 PostgreSQL；
3. 以 advisory lock 执行 migration；
4. migration 失败则停止 API 上线；
5. API 启动后验证 schema version；
6. Web 最后切换。

Migration 只向前执行。MVP 不建设自动 down migration；回滚使用旧镜像加部署前数据库备份。

## 7. 联调数据

集成环境提供一套固定 fixture：

- 一条普通 Signal；
- 一条可自动升级的 Signal；
- 一条 dismissed Issue；
- 一条 DRI Issue；
- 一场 scheduled Meeting；
- 一份合法与一份非法 Transcript；
- 一个含多个 review item 的 MeetingOutcome；
- 一个 draft MonthlyPlan；
- global、Issue、Meeting 三个 Conversation。

fixture 只通过 API seed command 写入 integration 数据库，不编译进 Web。production 禁止执行 seed command。

## 8. 分片联调顺序

### 8.1 Contracts

- API OpenAPI snapshot 生成；
- Web client 重新生成；
- CI 确认生成文件无 diff；
- Card kind 全部有 renderer。

### 8.2 Auth 与 Card

- 登录、Cookie、logout；
- 首页 Card query；
- Action HMAC、version conflict、幂等；
- 未登录页面跳 access。

### 8.3 Pi／Conversation／MCP

- API 启动不读取用户 Pi 配置；
- Chat 无搜索问题不调用 Tool；
- 外部事实问题调用 Search；
- MCP 返回 section、passage 和 person；
- global 与对象 scope 不串话；
- runtime entries 重启恢复；
- compaction 不删除原始消息。

### 8.4 Radar／Issue

- scheduled/manual 使用同一管线；
- Signal 去重；
- 自动升级；
- red 时间门；
- Research ready/failed/retry；
- CEO 决定、Override、Receipt、dismissed。

### 8.5 Meeting／Outcome

- Meeting create/import；
- Preflight 保存；
- Supplement Request 状态；
- Transcript 整份校验；
- Outcome 引文和 speaker；
- 每项 confirm/dismiss；
- effectRef 精确撤回；
- pending_export。

### 8.6 MonthlyPlan

- 月初唯一创建；
- DRI feedback；
- sign；
- 战场背面；
- Radar 基础 anchors。

### 8.7 Web 视觉

- scope 内页面视觉 diff；
- scope 外新增状态人工走查；
- 稳定 URL 直达／刷新／回退；
- keyboard、Escape、focus、reduced-motion；
- 无语音、录音、深研和旧入口。

## 9. 真实 Provider 验收

### Web Search

- 使用一个真实 query；
- 结果包含 title、URL、excerpt；
- Pi 可完成一次自主 Tool loop；
- 记录调用数和 usage；
- 8 次保护可通过 stub 单独测试，不用真实烧满。

### 公众号

- 配置一个真实账号；
- 按账号拉取最新文章；
- 保存规范化 URL 与发布时间；
- 与 Web Search 结果进入同一 Signal 管线；
- 不把 `site:mp.weixin.qq.com` 验收为账号订阅。

### 模型

- light、heavy、compaction 各执行一次；
- Tool schema、submit_candidate、compaction 均成功；
- 模型失败不自动换档。

### CompanyMemory MCP

- Markdown 模式读取目录、段落和人员；
- 所有返回带 sourceRef 和 updatedAt；
- 未授权调用返回 401；
- 不暴露写 Tool。

## 10. Health 与 Smoke

### Web health

验证：

- 进程存活；
- BUILD_SHA；
- 不访问 API 上游。

### API health

报告布尔状态或安全摘要：

- database；
- Pi Runtime；
- model slots；
- Search；
- WeChat；
- MCP；
- scheduler last tick；
- BUILD_SHA。

不返回 key、端点完整凭据或 CompanyMemory 内容。

### 上线 smoke

1. 登录；
2. 首页 Card；
3. global Chat；
4. Issue Card；
5. Radar 状态；
6. Meeting 页面；
7. MonthlyPlan 页面；
8. API health；
9. MCP 鉴权；
10. 写操作使用专门 staging 对象，不修改 production 真实对象。

## 11. 备份与恢复

### 备份

由宿主机 cron 执行 `infra/backup/backup.sh`；API 镜像不安装备份 Shell 工具。备份目标为独立 SSH/SFTP 主机目录，使用 age 公钥加密。每天执行：

1. `pg_dump` 自定义格式；
2. 校验 dump 非空；
3. 使用独立备份密钥加密；
4. 上传到服务器外存储；
5. 保存 checksum、时间和 schema version；
6. 保留至少 7 天；
7. 删除本机明文临时文件。

### 恢复验收

`infra/backup/restore.sh` 接收加密备份、checksum 和目标 DATABASE_URL，不覆盖现有数据库。上线前至少一次：

- 新建空 PostgreSQL；
- 解密并恢复；
- 执行 schema 检查；
- 抽查 Issue、Transcript、MeetingOutcome、MonthlyPlan、Conversation messages、Pi entries；
- 恢复后创建 Pi Session 并继续一次对象 Conversation；
- 记录恢复耗时和结果。

Docker volume 不计为备份。

## 12. Cutover

### 12.1 前置门槛

- 新 Web 全部目标 URL 可用；
- 四条业务链通过；
- 真实 Provider 验收完成；
- 视觉回归通过；
- 用户确认像素级结果；
- 备份恢复通过；
- production env 和 health 通过；
- Web bundle 无旧业务与密钥；
- Caddy TLS、SSE、multipart、DRI service API 和 MCP 路由验收通过。

### 12.2 切换

1. 保持旧 frontend 只读运行；
2. 部署新 PostgreSQL、API、Web 和 Caddy edge；
3. production 只导入正式数据，不导入旧 demo；
4. 切换入口到新 Web；
5. 观察 health、错误、Agent usage；
6. 完成 CEO smoke；
7. 冻结观察窗口后删除旧 frontend 源目录。

### 12.3 回滚

观察窗口内：

- 路由切回旧只读前端；
- 停止新 API 写入口；
- 保留新数据库用于排查；
- 若 schema／数据损坏，恢复部署前备份；
- 不尝试把新数据写回旧 demo store。

旧 frontend 删除后，源码恢复依赖根仓库 Git 历史，不保留运行时兼容目录。

## 13. 发布后观察

最少观察：

- API 5xx；
- 401/403 异常；
- PostgreSQL 连接；
- Agent failed/aborted；
- Search calls 和超时；
- Radar last success；
- scheduler tick；
- MCP latency；
- Conversation 恢复次数；
- backup success。

不因为单个失败立即自动重跑模型。先在对象页面展示并由 CEO 决定是否重试。

## 14. 删除旧前端

最终删除包括旧页面、业务 API、Agent、data store、research、recording、ASR、TTS、ontology、graphknowledge、scan、models、memory adapter、旧 prompts、旧 scripts、seed 和 localStorage 兼容代码。

删除后验证：

- 根 workspace 和 Caddy 配置无 `frontend` 引用；
- Docker/CI 不构建旧目录；
- 新 Web bundle 不包含旧对象字符串和 demo 数据；
- 所有目标 URL 正常；
- 文档只指向 apps/web 与 apps/api；
- 无兼容重定向或双写。

## 15. 完成条件

- integration 与 staging 联调清单全部通过；
- production smoke 通过；
- 所有外部来源真实可用；
- 备份恢复有证据；
- 用户通过像素级 UI 验收；
- 旧 frontend 已删除；
- 没有 Redis、队列、对象存储、多 Runtime 或其他未请求基础设施。
