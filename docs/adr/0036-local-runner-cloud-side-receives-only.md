# 本机程序在云端的那一侧：设备令牌、只收上报、联网搜索走服务器

本机程序（ADR 0028–0033）在本人电脑上跑 Claude Code 等执行方。云端这一侧要回答三件事：本机凭什么身份报、报来的东西怎么收、执行方要联网搜索时怎么办。设计见 V2 设计第 4、5、18 节，本机程序那一侧见 `docs/technical/local-runner/RFC.md`。

## 决策

1. **设备令牌是一种个人令牌。** `personal_tokens.client` 加 `local`（迁移 228）。配对时网页调 `POST /api/me/local-devices`，云端发一把只给这台电脑的令牌；同一台电脑再配对，旧令牌立刻吊销。它不占每人 5 把的名额、不在设置页列，不能当登录态，只能调 `/api/local-runner/*`，以后在 `/mcp/me` 上只读。
2. **只收上报，云端从不指挥本机。** `POST /api/local-runner/sync` 收本机程序契约的 `LocalSyncBatchRequest`。一条一个事务：幂等键收过的直接回 accepted；不是本人的卡或专题、文件对不上、种类不收的永久拒收（本机不再重发）；意外出错的不进回执，本机稍后重发。状态和计划按本机序号只往前走。开工、插话、退回都由本人在网页上点，经网页交给本机。
3. **专题的版本号由本机编。** 本机从交代里的 `latestVersion` 往下编号；号在云端已经有了（两处同时写同一个专题）时把这一版排到最后，不丢；飞书地址先按本会话自己的本机号对回。
4. **联网搜索走服务器上的博查。** 第三方模型下 Claude Code 自带的搜索可能静默失效（见 `.scratch/next-phase/实测_第三方模型下的联网搜索_2026-11-06.md`），所以 `/mcp/me` 加只读工具 `web_search`，钥匙只在服务器。每人每分钟 10 次、每天 200 次（上海时间），每真搜一次记一行 `web_search_calls`（只记谁、哪种客户端、何时、成没成、几条结果，不记搜了什么），按次算钱。

## 和 10/29 下线的本机采集器有什么不同

本机采集器是在本人电脑上主动收集本人做过的事、报给云端。本机程序只跑本人在网页上点了「开工」的那张卡或那个专题，只报这一次执行的状态、计划、产出、花费和交回；对话全文只在本机。云端不能让本机做任何事，也拿不到本机上别的东西。

## 后果

- 设备令牌泄露的影响限于这个人：只能往他自己的卡和专题报东西、只读 `/mcp/me`。吊销设备即吊销令牌。
- 交出的文件存在 API 的材料卷里，按扩展名白名单收；HTML 预览用和材料预览一样的 CSP，其他类型 `sandbox`。
- 博查有费用：上限挡住失控的循环；并发时同一个人可能多出一两次。
- `web_search` 挂进 `/mcp/me` 工具列表、`local` 令牌在 `/mcp/me` 只读放行，要改共享文件 `mcpMe.ts`、`mcpOAuth.ts`，等 V1 合进来以后做；在那之前 `local` 令牌连 `/mcp/me` 一律 401。
