# 本机会话越界的路径：标红交本人定，不自动拒绝

2026-11-06 决定。适用于 `apps/local` 拉起的 Claude Code 会话。

## 背景

本机程序原先只检查会话的工作目录在不在本人允许的文件夹里（RFC 已知问题第 2 条）；会话里 Read、Write、Bash 写到外面的绝对路径，网页上看不出来。

11/06 用假网关驱动真 Claude Code 2.1.318 实测（假网关按脚本让「模型」发工具调用，不调真模型，见 RFC 附录 G）：

- 工作目录外的 Read、Write、Glob、Grep、`cat <外面的文件>`，Claude Code 自己都会发权限请求（`can_use_tool`，原因写着「Path is outside allowed working directories」，Bash 还带 `blocked_path`）；工作目录内的读和 `ls` 直接放行。仓库设置里写 `allow: ["Read", "Bash(cat:*)"]` 或 `additionalDirectories` 也没让越界的读免批。
- 越界请求附带的放行建议很宽：Read 是「本会话放行整个外面的目录」，Write 是「本会话改成 acceptEdits + 把外面的目录加进工作目录」，Bash 那条的 `destination` 是 `localSettings`，会写进仓库的 `.claude/settings.local.json`。原先「这张卡都允许」把建议原样回给 Claude Code，点一下就可能永久放开。

## 考虑过的做法

| 做法 | 好处 | 问题 |
|-|-|-|
| A. 越界就自动拒绝 | 最省心 | Bash、PowerShell 只能从命令里猜路径，猜错就误拒正常命令；读别的仓库、`~/.gitconfig`、临时文件这些正当需要没有办法放行；模型被拒后会绕着试别的写法 |
| **B. 标出越界路径，交本人定（采用）** | 不误伤；本人看得到越界在哪 | 每次越界都要点一次；Bash 认路径认不全，靠 Claude Code 自己先把越界请求拦下来 |
| C. 再挂一个 SDK 钩子（`initialize` 里注册 PreToolUse），越界就强制 `ask` | 仓库里写了越界放行规则时也能拉回网页（实测可用） | 实测各种情况 Claude Code 本来就会问；剩下的缺口是仓库自己写越界放行规则，这和仓库里的 hooks 能直接跑命令是同一个信任问题（ADR 0030），多一层钩子并不改变「允许的文件夹只放信得过的仓库」这条边界。先不做，留作以后不再信任项目配置时的选项 |

## 决定

- 每个权限请求带 `outsidePaths`：这一步要碰的、不在允许范围里的路径。允许范围是本会话的工作目录加本人允许的文件夹，每次现查（会话途中移除了文件夹，之后就算越界）。
  - Read、Write、Edit、MultiEdit、NotebookEdit、Glob、Grep 按字段取路径；相对路径按工作目录算，`..` 会被解开。
  - Bash、PowerShell 从命令里认：引号里的绝对路径、`~`、`$HOME`/`$env:USERPROFILE`、带 `..` 的相对路径、重定向目标；每段命令的程序本身、`/dev/null`、网址不算。Windows 上 Git Bash 的 `/c/...` 换成盘符，`/tmp` 这类算越界。再加上 Claude Code 自己给的 `blocked_path`。
  - 路径先解开符号链接和目录链接（Windows 的 junction）再比；还不存在的路径（要新建的文件）按最深一层已存在的上级来解，免得借工作目录里一个指向外面的链接写出去。相对路径一律按工作目录解开再查，命令里不带分隔符的普通词只在它是链接时才查。
- `outsidePaths` 非空时：网页标红并写明越界的路径；`canAllowForSession` 为 false，只能「只允许这一次」，网页硬传 `allowForSession` 也不生效。本机不自动拒绝。
- 「这张卡都允许」还要看建议本身：建议要加进工作目录的目录、放行规则里的路径（`//c/…`、`~/…`）、放行的命令里认出的路径，有一处越界也不给。这一层不靠切词准不准，挡的是真正有害的「一点就永久放开」（第二轮评审后加）。
- 「这张卡都允许」只在本会话内有效：回给 Claude Code 的放行建议一律改成 `destination: "session"`，不写进仓库或本人的设置文件。
- 允许的文件夹不能选：整个磁盘、主目录和它的上级（选了等于全放开，越界检查失效）、Claude 配置目录 `~/.claude` 和本机程序数据目录（里面有登录凭据和钥匙），以及它们的上级。选了回 400，提示能直接给人看；这条规矩之前加进来的旧条目也不再算数。会话途中本人移除了工作目录所在的文件夹，之后连工作目录里的路径也算越界。

## 代价

- Bash 认路径是尽力而为：拼出来的路径（变量、命令替换）认不出，`/usr/bin/env` 这类当参数的程序路径会被标红。标红只是提示，真正的闸门是 Claude Code 自己的越界检查加本人逐次批准。
- 越界的读每次都要点一次；常用的外部目录应该直接加进允许的文件夹。
- 仓库里写了越界放行规则时，那一步不会来问（见做法 C）。
