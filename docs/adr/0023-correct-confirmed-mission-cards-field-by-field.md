# 已确定个人卡按字段更正，每次经拍板人并留痕

2026-10-01 更新：直接采纳写回及 CEO 通用拍板权限已由 [本人准备与组合核对口径](../contracts/mission-card-preparation-review.v0.1.md) 替代。正式确认后的实质修改必须由本战场 DRI 定向退回本人，再次本人确认和组合核对；原更正申请、决定与版本仍保留。以下内容记录原实现，不作为当前写入授权。

日期：2026-09-27。依据：用户对 GAP-04 的委托（「已确定的个人卡发现错了怎么改……你也来思考一下怎么做更好，然后给我解释一下，然后去实现就好」），设计见 `.scratch/onboarding/design-gap04-corrections.md`。本 ADR 补全 ADR-0022 第 8 条留给 GAP-04 的「已确定后的纠错与再修订」。

整轮确认之后，个人卡是本月的组织承诺。它仍会有错：写错的数字、客户改了日期、某项任务本月不做了。只能等下个月会让错的承诺挂一整月；重开整轮讨论会让已经对齐的其他人重新表态，代价过大。

## 决策

1. **只改一个字段，不重开整轮**。确认后的修改单位是「某项个人任务的某个字段」，与讨论期修改建议的粒度相同。不撤回整张卡、不删个人任务、不重开 48 小时窗口。某项任务本月不做了，就更正它的预期结果或边界，并写明原因。
2. **拍板人点头才生效**。非拍板人（实际上就是卡的 Owner）提「更正申请」：改后的文字加原因。当前拍板人（CEO 或本战场 DRI，按当前身份复查）逐条采纳或不采纳，不采纳必须写原因。拍板人自己发现的错可以直接更正，同样要写原因，立即生效。
3. **每次都留痕、看得见**。更正单独存在 `mission_card_corrections`，保存原文、新文、原因、提出人、处理人、时间和写回后的 Mission 版本。看得到卡的人都看得到更正记录。卡的状态行写「已确定 · … · 更正 N 处」。拍板人有待处理的申请时，这一轮重新出现在通知里，写「N 条更正申请待你处理」。
4. **写回与整轮确认共用一条路径**。采纳或直接更正时锁定该 Mission，经同一个字段白名单写回，列表字段按行拆分，版本加 1。申请之后字段又被改过（当前文字不等于申请时的原文）的申请标为「原文已变化」，不能直接采纳，避免覆盖别人刚做的更正。
5. **月份过了就只读**。只有轮次月份不早于公司时区当前月份的卡可以更正，月底提前确定的下月卡也可以。月份过了，卡保持当时的承诺与更正记录，要改的放进下个月的个人卡。
6. **讨论期不变**。未确定时仍走公开意见、集中 Review 和整轮确认；更正只在确定之后开放。挂卡 Mission 的 `mission.edit` 仍然锁定，提示改为在个人卡上申请更正。

## 不做

- 申请人收到处理结果的通知、撤回申请。
- 重开已确定的整轮、跨月结转的自动化。

需要时再定。

卡片的私人 Agent 对话读到的是本人看得到的整张卡，所以也读得到更正记录；它不能提交或处理更正。
