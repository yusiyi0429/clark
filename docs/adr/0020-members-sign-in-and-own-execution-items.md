# 成员以自己的身份登录，并拥有自己的执行事项

> 2026-11-06：第 4 条里的「不做看板」由 [ADR-0034](0034-execution-board-cards-are-execution-items.md) 修订，其余不变。

天枢内测要让 CEO 把雷达信号发给具体的人、战场或业务域，收件人在自己的通知栏收到，可以把它转成自己的执行事项，并与相关同事在事项群组里讨论。这需要每个成员以自己的身份登录，因此 WarMap 不再只是「单 CEO」的应用。本 ADR 推翻 ADR-0001 中「单公司、单 CEO」与「不承担任务执行」的部分，以及目标设计 v0.3 的非目标「项目管理和任务执行」「DRI 工作台或多人协作」、「/access 单 CEO 登录」与「单 CEO MVP 不保存已读」。设计全文见 `.scratch/member-workspace/spec.md`。

## 决策

1. **每人一个登录 ID + 自设 4 位口令**：登录 ID 取姓全拼 + 名的首字母（`sun-mingze → sunm`），推不出或重名时由管理员指定。初始码由 `access:issue` 脚本随机生成、私下分发，首次登录必须改成自己的口令。同一 ID 连续输错 5 次锁 15 分钟。不接飞书等 OA 登录，取消原来的 CEO 共用长密码。
2. **会话只记录「是谁」**：签名 cookie 里是 `{pid, v, exp}`，身份（CEO／成员）每次按 company-people seed 现算。`v` 与凭据表里的 `session_version` 比对，口令被修改或重置后，旧会话立即失效。有效期默认 30 天。
3. **一个应用、按身份与对象关系分流**：CEO 与成员共用同一个 Next 应用和同一个 API。成员页面在 `/me`，不能进入 CEO 的决策页面及其专用接口（雷达列表、议题、会议、月度计划、Mission 总览与配置）。API 分两道闸门：`requirePerson`（任何有效会话）与 `requireCEO`（成员一律 403）；成员相关的接口还要校验这个人与对象的关系。[ADR-0022](./0022-persist-monthly-mission-card-rounds.md) 增加本月 Mission Card 边界：个人卡成员读取相关卡页、轮次摘要并发表公开意见，CEO 或当前战场 DRI 通过新动作端点整理、开放、逐条处理、重开和整轮确认；确认后公开意见与承诺只读，私人 Agent 仍只读问答、不改变承诺。这个边界不开放 CEO 的决策材料，也不放宽原 `/api/actions/execute` 的 CEO 限制。
4. **成员执行工作台范围刻意很窄**：本 ADR 的初始范围为「发送信号」「执行事项」「事项群组」与按人的通知，不做项目管理、看板、执行事项与 Mission／个人任务的挂接、成员与智能体的对话或外部推送；本月 Mission Card 的后续扩展以 ADR-0022 为准。（2026-11-06 修订：「不做看板」由 [ADR-0034](0034-execution-board-cards-are-execution-items.md) 取代——V2 在一个 Task 下把本人的执行事项排成四列，跨 Task 只给 worker 列表；仍不做项目管理。）被拉进执行事项的人直接加入、可以自己退出，不需要「接受邀请」（与概念版 SSOT DRI-05a 不同）。
5. **DRI Handoff 不变**：机器令牌的导入导出边界（`/api/dri/*`）照旧，与站内的「发送」是两回事。

## 后果

- 需要维护人员 seed 与凭据的对应关系。新增人员后要运行发码脚本；有人离开时从 seed 删除即可，凭据随之失效。
- 部署从「单 CEO 内网工具」变为成员可访问的公网站点：入口 `mvp.tkos.ai` 跳转到已备案的 `mvp.tokenkingos.com`，由主机 Nginx 终止 HTTPS。
- 4 位口令的强度靠按 ID 锁定来弥补，只适合内测；正式推广前需要重新评估（例如接入企业 IM 登录）。
