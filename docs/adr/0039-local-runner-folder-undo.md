# 普通文件夹里改、删前留一份：影子快照为主，改前拷一份补漏

2026-11-11 决定（本人定；方案和实测见共享笔记「兜底_普通文件夹留一份_方案和实测_1111」，试验脚本在分支 `claude/folder-undo-863d1b` 的 `.scratch/folder-undo/`）。适用于 `apps/local` 拉起的、不在 git 工作树里做的会话。

## 背景

卡在 git 仓库里做时有工作树和分支（ADR 0038），改坏了能推翻。普通文件夹（不是 git 仓库）和「此电脑」里，执行方直接改本人的真文件，改坏了找不回。不写代码的同事的文件夹几乎都是这种。11/11 的审视里，本人被看不懂的批准逼得开了「全部放行」，那个文件夹正好没有任何回头路。

## 决定

- **影子快照**（工作目录是本人的普通文件夹时）：本机数据目录 `undo/repos/<文件夹哈希>.git` 是影子仓库，`--work-tree` 指向那个文件夹。不读本人的 git 设置；`git add` 直接写包。
  - 开工时在后台先数一遍、留第一份，开工请求不等；每一轮开始前（执行方报 `agent_info`）、结束后（`turn_end`）各留一份，结束时记下这一轮变了哪些。
  - 不进快照：目录联接和符号链接（git 会顺着跟到外面）、套着的 git 仓库、32MB 以上的文件、`node_modules` 这类目录。文件夹自己的 `.gitignore` 不管（`add -f`）。
  - 超过 3 万个文件或 3GB、在同步盘里（OneDrive 等，整份留会把云端占位文件全下载下来）、盘不够（剩余 < 要留的 × 2 + 5GB）、没留成：降级成「只改前拷一份」，出一行提示，不弹窗问本人。
- **改前拷一份**（所有不在工作树里的会话）：批准通道里放行之前（本机自己放行和转给本人之前都先过一遍），改文件工具要改的已有文件不在快照里（工作目录以外、大文件、快照还没好）时，拷到 `undo/sessions/<会话>/files/`。每个文件只拷第一次。
- **命令等快照**：开工那份或这一轮开头那份还在留时，命令的批准请求等它，最多 10 秒；改文件工具不等（先拷一份）。
- **兜底范围**（`PathScope.covered`）：本机自己的目录、快照管得住的、拷过一份的。「全部放行」时，没有兜底的地方已有文件要被删、挪、覆盖照样问（第四类）；「自动」在有兜底的地方放行删、挪的命令。
- **恢复**（`POST /v1/sessions/:id/files/restore`）：回到「这个会话第一次动它之前」——快照这一路是它第一次变了的那一轮开始前那份，拷的这一路是第一次拷的那份；会话新建的删掉。恢复前先给现在的样子再留一份。一轮在跑时不让恢复。
- **留多久**：会话最后一次活动后 14 天；总量超过 20GB 或盘剩余空间的 10%（取小的）时从最旧的清起。本机程序启动时清。影子仓库没有会话挂着了整个删掉，不跑 `git gc`。
- 不用执行方自带的回退：Claude Code 的文件检查点实测只恢复主会话改文件工具改的（命令、子 agent 改的都不管）；Codex 的 undo 只在 git 仓库里、只在它自己的界面里。

## 代价

- 第一份要时间：满载下约「文件数 × 1.1 毫秒 + 大小 ÷ 20MB/s」，3GB 最坏几分钟；这段时间里命令最多等 10 秒，之后按没兜底处理（删挪覆盖照样问）。
- 降级的文件夹里，用命令、脚本改的已有文件不受保护（只有删、挪、写的命令会被问，脚本里改的认不出）。
- 套着的 git 仓库、大文件、跳过的目录只在改文件工具改它们时有拷贝。
- 同步盘按路径认（Node 读不了文件的「占位」属性），认不全。
- 被别的程序独占的文件留不住（执行方这时也改不了它）；Excel 开着时恢复失败，要关掉再点。
- 占盘：Word、Excel 本来就压缩过，留一份约等于原大小。
- 合回以前、或「此电脑」里命令写的工作目录以外的文件，没有兜底。
