# 本人审核任务卡，并在全员完成后汇总

日期：2026-09-30。依据：用户确认以 `feat/mvp-member-workspace` 为基础移植 `feat/mission-card-self-review` 的审核流程，并保留现有批注与 Agent 改写。整合范围见 `.scratch/mission-card-integration/spec.md`。

## 决策

1. 左侧正文保持阅读界面。直接批注在选区旁输入、所有能访问任务卡的人可见；引用并对话进入右侧私聊。现有 `edit_mission_card`、批注队列和 `mission_card_revisions` 为统一改写与留痕路径，不增加第二个编辑工具或重复的修改历史表。
2. 只有在下发审核后、当前卡尚未完成本人审核时允许即时改写。私聊、直接批注、澄清回答及队列写回使用相同服务端规则。完成审核后需先取消确认；已经汇总则需重新开放审核。已确定任务沿用 ADR-0023 的正式更正路径。
3. 增加 `personal_mission_cards.owner_confirmed_at`。只有本人能完成或取消自己的审核，完成时核对所读卡的全部 Mission 版本。普通本人确认不改变整场审核动作的签名版本；重新开放审核时清空所有人的确认。
4. 全员指该战场当月全部任务卡的负责人。最后一人完成审核与创建汇总快照在同一事务中提交。拍板人仍可提前汇总，弹确认前读取最新任务卡进度，并使用当前可用的汇总操作与尚未完成人员名单；读取失败或权限、阶段变化时停止并说明。
5. 排队修改、正在修改、待澄清或失败的批注阻止完成审核和手动汇总。不能处理的批注可明确选择「保留备注，暂不修改」，填写原因并保留原批注及澄清历史；纯保存备注不阻断审核。
6. 候选改写带读取时的审核标识，不能在关闭并重新开放后继续写入。公开建议的提交时原文与当前入库正文不一致时，禁止采纳和最终确认，避免旧建议覆盖新正文。重开时尚未提交的旧建议保留输入，用户明确重新核对后才绑定当前审核与正文版本。
7. 所有切人和审核操作收进统一的二级页头；审核期间仅显示蓝色「审核中」或绿色对号「已完成审核」。保留任务视图下拉、禁用的执行拆分、淡问号和与开启执行事项共用的五页案例引导。

继续沿用任务卡阶段、集中 Review、跨人员依赖核对、整场确认和已确定后的更正。批注原文、澄清回答、暂不修改的原因及改写前后记录可供最终审阅，私聊记录仍仅本人可见。
