# 卡在自己的 git 工作树里做：分支是交付物，合回由本人点

2026-11-06 决定（本人选了「每张卡一个工作树」，没选「同一个文件夹排队」）。适用于 `apps/local` 拉起的卡（`subject.kind = card`）的会话。

## 背景

本机最多同时跑 3 个会话。以前卡直接在本人选的文件夹里做：同一个仓库的几张卡改同一份文件，互相覆盖；验收员也分不清哪处改动是哪张卡的。

## 决定

- **在哪做**：本人选的文件夹在 git 仓库里，而且在某个分支上、至少有一个提交时，本机在点「开工」那一刻（排着队也一样）开一个工作树：
  - 位置是 `<数据目录>/worktrees/<cardId>`，加进允许的范围。本人选的是仓库里的子文件夹时，会话的 cwd 是工作树里对应的子文件夹。
  - 新建分支 `tianshu/<卡 id 去掉符号后的前 8 位，小写>-<标题里的英文和数字>`，中文标题就只有 id；名字被占了就加 `-2`、`-3`。
  - 从主文件夹所在分支的最新提交开出来，记下 `baseBranch`、`baseCommit`。
  - 会话摘要的 `workspace` 写明在哪做（契约 `LocalWorkspace`）。
- **不带过去的东西**：主文件夹里没提交的改动不带进工作树，开工时的 `notice`（`workspace`）说明这一点。`.gitignore` 里的文件（`.env`、`node_modules`）这一轮也不复制。追加的系统提示词告诉执行方：工作树是新的，要装依赖就自己装，缺钥匙问本人；不要切换分支，不要改主文件夹。
- **交回**：`hand_back` 时本机先 `git add -A`，有改动就提交到卡的分支，提交说明是「交回：<卡标题>」。交回事件和同步条目带这个提交（`commit`、`git { branch, baseBranch, baseCommit, commit }`）。
  - 提交加 `--no-verify`，不跑仓库的提交钩子：新开的工作树没装依赖，钩子多半跑不起来，会挡住交回。
  - 本人没配 git 的名字和邮箱时，用「天枢本机程序」。
  - 验收没过以后接着在同一个工作树、同一个分支上改。
- **验收**：验收员在卡的工作树里只读地做。交代后面由本机接上 `baseCommit` 到交回那个提交的改动：`--stat` 全列，补丁最多 4 万字，超出的部分请它读文件。结论 `LocalVerdict.commit` 记下验的是哪个提交。
- **合回**：本机从不自动合，验收过的分支就是交付物。
  - 网页上本人点了，才调 `POST /v1/sessions/:id/merge`，在主文件夹里 `git merge --no-ff` 卡的分支，说明是「合回天枢卡「标题」（分支）」。
  - 只在主文件夹正在 `baseBranch` 上、而且干净（没提交的改动和没加进 git 的文件都算不干净）时合。
  - 合不了就回原因，主文件夹原样不动：`base_not_checked_out`、`dirty`（带文件）、`conflict`（带冲突文件；已 `git merge --abort`）。
  - 卡这边合不了时回 409：卡不在工作树里、卡或它的验收员还在跑、工作树里有交回以后的改动、已经合回过。
  - 合成后先让还开着的进程（一轮做完在等回复的卡、本人续上的验收员）退出，再清掉工作树，分支保留；摘要里记 `mergedCommit`。
- **清理**：
  - 合回成功后清掉工作树。
  - 卡还没开始就取消了（排队时停下或强停、启动途中被强停），而且工作树没有别的会话在用，也清掉。分支都保留。
  - 正在做的卡被强停时不清：强停以后说一句还能续。
  - 本机程序启动时，对卡用过的每个仓库跑一次 `git worktree prune`。
  - 开工没开起来（没装 Claude Code 等），不留记录，也删掉刚开的工作树和分支。
- **同一张卡再开工**：这张卡上一个会话的工作树还在（没合回），就接着用它和它的分支；还有会话在做或在排队就拒绝（409）。上一个工作树已清掉时新开一个分支。
- **不是 git 仓库**（或不在分支上、还没有提交）：就在文件夹里做（`workspace.kind = folder`）。
  - 同一个文件夹同时只做一张卡：另一张正占着位置（开工中、进行中、等批准）时排队，状态事件的原因是「这个文件夹不是 git 仓库，同时只做一张卡，等另一张这一轮做完」。
  - 那张一轮做完（空闲）就让出来。文件夹按本人选的路径算，子文件夹算另一个。
- 专题、规划员仍用本机程序自己的目录，不变。验收员不占文件夹。

## 没选的做法

- 同一个文件夹排队（本人没选）：几张卡就只能一张张做，3 个位置等于 1 个。
- 验收员另开一个停在交回提交上的工作树：最准，但每次验收都要开、删一个工作树，本人续上验收员时也得留着。现在验收员在卡的工作树里做，交代里的改动以提交为准；这期间本人让卡接着改，验收员读到的文件可能比提交新。

## 代价

- 每个工作树是一份完整的检出：大仓库开工慢、占盘。子模块不初始化。Windows 上路径可能太长（数据目录本身就深）。
- 强停后没再合回的卡，工作树一直留着，现在没有「丢掉这张卡」的操作，要等合回或手动删。
- 交回提交不跑钩子，钩子要管的检查只能在合回以后、本人自己的流程里跑。
- 合回以后卡的会话续不上了（工作目录已清）。合回的结果只在本机，没有同步给云端。
- 不是仓库的文件夹：空闲的卡不占文件夹，本人给它说一句（或云端送回改法）时，可能和另一张同时改这个文件夹。
