# 月末复盘是下月计划的起点，LTCO 决定后才生成草案，1 日兜底

日期：2026-09-28。依据：当天「M1B 模拟演练」会议共识（飞书妙记 `obcna7spi9pmwkx5249koooy`），以及用户选定的范围（先做复盘与 LTCO 决定，复盘只到战场 / 能力域，能力域加负责人，月末自动开启，LTCO 确认后生成草案、1 日兜底）。Spec：`.scratch/monthly-review/spec.md`。

会议认为，现在的月度流程直接从“LTCO → PCO”开始，漏掉了上一个战略周期末的复盘与检视：上个月“一晃而过”，只有一份笼统的总结报告，没有逐项的差距分析和反馈，组织的经验沉淀不下来。复盘和拆解是每个检视周期的标准管理节点，结构和参与人对称：先自下而上复盘，再自上而下拆解。

## 决策

1. **新增月度复盘对象**。每月一份 `monthly_reviews`，每个战场和能力域各一项 `monthly_review_items`，由注册表负责人负责；负责人为空时挂到 CEO 名下代复盘。已签发的 MonthlyPlan 保持不可改，复盘只保存目标（PCO）的快照。
2. **负责人自评，co-agent 评估，CEO 逐项确认**。起草 Agent 先写四栏自评（达成情况、差距、原因、下月调整），负责人和自己的 agent 对话修改（agent 只能提建议，负责人点「采用」才写入），或直接编辑后提交。提交后偏差评估 Agent 对照公司视角给出偏差点和追问。CEO 确认或打回，打回必须写原因。评估失败不阻塞确认。
3. **复盘与 LTCO 决定分开**。全部项确认后，汇总 Agent 给出 5 条关键经营判断和一条 LTCO 修订建议。CEO 先确认公司复盘，再在单独的页面决定 LTCO 保持不变或采用修订。LTCO 主要由战略决定，复盘只是输入之一，所以 Agent 默认倾向不改。
4. **LTCO 决定后立即生成下月计划草案，1 日兜底**。`decide_ltco` 为下个月创建 MonthlyPlan 并启动草案生成，草案输入带上已确认的复盘。下月计划已存在时不重复创建。1 日的定时生成保留，复盘拖延时流程不会卡住，只是草案少了复盘输入。
5. **月末自动开启**。每月倒数第 3 天（Asia/Shanghai）自动创建当月复盘。CEO 也可以提前手动开启，上线当月就用这个方式。
6. **通知是状态的投影**。负责人和 CEO 的待办由复盘当前状态现算，不写通知表，和 Mission Card 轮次一致。
7. **能力域有负责人**。`capability_config.owner_id` 与战场的 `owner_id` 相同：空串显示为“待指派”。

## 不做

- Mission 层复盘（mission owner 和 DRI 之间），第一版只到战场 / 能力域。
- 月末周期进度入口、PCO 与 Mission 同屏、卡片级锁定、纪要三页签、co-agent 主动介入。
- 复盘结果写回 CompanyMemory，以及飞书推送。

月底试用、收集体验反馈之后再定。
