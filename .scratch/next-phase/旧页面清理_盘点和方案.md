# 旧页面清理：盘点和方案（2026-11-10）

> 只是盘点和方案，一行代码都没改。**动手要等两件事：11/13 新首页上正式之后，并且本人选定下面「要你定的」几项。**
> 盘点基于 `claude/new-home-integration` @ `232ee159`。行号都是这个提交上的。

## 0. 先说结论

1. **新首页现在还链到旧页面**，和设计稿 §15「新首页里不链到旧页面」不符。直接删 `(member)` 会让这些地方 404：执行事项行、等你里的会议/Mission Card、伙伴对话里的待办/复盘卡片、记忆页的出处、管理员入口、子会话复核里的「去技能页添加」。所以**顺序必须是：先移植或改链接，再删**。
2. **旧成员页离不开旧外壳**。`(member)/me/layout.tsx` 套的是 `MemberWorkspace`（旧首页 + 通知栏），里面的详情页都调 `useWorkspace()`，没有外壳会直接抛错（`components/shell/WorkspaceContext.tsx:60-63`）。所以「保留几个旧详情页、只删别的」做不到，要留就得给它换壳。好消息：新首页的 `HomeShell` 自己就提供 `WorkspaceContext`（`components/home/HomeShell.tsx:443-446`、`:603`），旧详情屏幕可以直接挂进新首页展示区。
3. **V2 那 7 页还有人在链**：新首页的子会话复核里有 `/me/team`（`components/topics/Review.tsx:81`），卡片会话找不到时有 `/me/month`（`components/cards/CardSession.tsx:113`），飞书推送「技能」那一类推的是 `/me/team`（`apps/api/src/homePush.ts:77`）。V2 的页面本身可以删，但 `V2Shell.tsx`、`MonthLanes.tsx`、`PluginsPage.tsx`、`ChatPane.tsx` 这几个文件新首页还在用其中一部分，只能删文件里的一部分。
4. **`/me` 本身不能删**：它现在是跳转页（`app/(member)/me/page.tsx`，→ `/me/work`，`?planTask=` → `/me/work/tasks/:id`），飞书、微信、MCP、M2 都还在往 `/me` 和 `/me?planTask=` 发（见 §3）。要从 `(member)` 挪出来留着。
5. **规模**：
   - 能直接删的网页代码：旧路由 32 个文件 355 行（`(member)` 24 个 269 行、`(v2)` 8 个 86 行），只给旧页面用的组件和样式 60 个文件 约 5,900 行，对应测试 11 个整文件 约 620 行 + 15 个测试要删其中几段。
   - 其中「执行事项详情」那一串（约 1,300 行）要看本人定的是移植还是不要（§8 问题 1）。
   - 文件里删一部分的 9 个，第二轮还会冒出一小批（§4.3）。
   - API：只给旧页面用的接口 15 条，在 `routes/me.ts`、`routes/myRadar.ts`；模块 `memberBattlefields.ts`（44 行）整个删，`battlefieldProgress.ts`、`planMarks.ts` 删一部分；另有约 20 处生成旧地址的代码要改成新地址。

## 1. 怎么盘的（可复现）

- 从 `apps/web/src/app` 下每个页面、布局、样式入口出发，按 import（静态、`import()`、CSS `@import`）建依赖图，`@/` 按 tsconfig 解析，测试文件不算入口。
  - 「只给旧页面用」= 从 `(member)`、`(v2)` 能走到，从别的入口（`(work)`、`(ceo)`、`config`、`access`、`welcome`、`oauth`、根布局）都走不到。
  - 「也被新首页/CEO 用」= 两边都走得到，并逐个记下从哪个保留入口走到的。
- 再按「从哪个文件导入了哪些名字」细到符号，找出文件还在、但其中某个导出只剩旧页面在用的（§4.2）。
- 链接：全仓库搜 `"/me…"` 这类字符串，再用依赖图筛出新首页（`(work)` 入口）真的走得到的那些，最后逐处看代码，确认会不会真的画出来（例如 `HomeShell` 只 `import type { Account }` 自 `AccountMenu`，那 `AccountMenu` 里的 `/me/memory` 在新首页就不会出现）。
- API 接口：从 `apps/api/src` 抽出所有路由，和网页（分旧/保留）、`apps/desktop`、`apps/local`、`apps/m2`、API 内部（伙伴 `inject` 调用）里的路径字符串对一遍。
- 盲区：
  - 运行时拼出来的地址只能靠读代码；已经搜过 `${…}/me`、`hrefOf`、`base` 这几种写法。
  - 外部系统（Chat 服务、Nexus、本体）有没有存天枢的旧地址，仓库里看不到。
