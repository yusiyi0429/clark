# Task 交付物（第一版）实施计划

**目标**：选中 Mission、再选中 Task 后，右边换成这个 Task 的交付物面板：传版本（文件、图片、链接、一句现状）→ 后台评审 Agent 按验收标准逐条评、出报告 → 每一条都达到才能「交付」→ 交付后伙伴写这一版的说明。孙铭泽 10/29 晚要求先做出这一版给他验收，之后再改。

**依据**：`spec.md` 5.2–5.4；样子 `Task页面样子_2026-10-29.html`，并按 10/29 晚的两条意见改：「交给 Co-Agent」改叫「交付」；画面更简洁，少一点框。

**契约**（已写好，见 `packages/contracts/src/deliverables.ts`、`homePlan.ts`、`openapi.ts`）：`TaskDeliverableResponse`、`DeliverableVersion`、`DeliverableItem`、`DeliverableReview`、`ReviewCriterion`、`DeliverableNote`、`TaskDeliverableStatus`，`HomePlanTask` 多了可选的 `responsibleId`、`deliverable`；路由前缀 `/api/plan-tasks/{taskId}/deliverable`。

## 这一版不做（第二批）

- Co-Agent 的评判（到没到节点、进展 0/1、风险）和 Mission 进展更新：溪南那边的接口还没定。
- 写进本体：斯一还没定写入方式。
- 飞书文档链接用本人飞书授权读正文：这一版飞书链接一律标「飞书文档请导出后上传」。
- 「说说现状」走对话、由 Agent 追问后存版本：这一版先在面板里写一段现状，存成一个版本。
- 版本说明的输入只用两版交付物和评审报告；对话、日进展、会议事件以后再接。

## 我定的

- 负责人：读本体 Task 的负责人（`identity.responsible.principals[0].principal_id`，没有再看 `attributes.responsible`），按本体实例配置的 `people` 反查天枢的人。本体没登记时，这个 Mission 的负责人（首页只列本人的 Mission，就是看的人）可以传版本、交付，面板上负责人写「未登记」。
- 评审标准：Task 有验收标准用验收标准（basis=acceptance）；没有就用完成定义当唯一一条（basis=definition）；两样都没有不评（basis=none），面板只显示「没有可对照的标准」。
- 一个版本 = 一次「评审这一版」：可以沿用上一版里的几样（keep），再加文件、链接、一句话。版本号从 1 起。
- 只有最新一版能交付；交付前要评审完、每一条都达到（有异议的条目不能交付）。交付后可以撤回，撤回会清掉版本说明。
- 评审模型：`REVIEW_MODEL`、`REVIEW_BASE_URL`、`REVIEW_API_KEY`、`REVIEW_THINKING` 都配了就走 TokenHub；没配时用现在的 `PI_BASE_URL` / `PI_API_KEY` / `HEAVY_MODEL`（本机先这样跑）。版本说明用同一个模型。

## 前端（我做）

- `HomePlan` → `MissionDetail`：选中的是真 Task 时，右边画 `TaskDeliverable`，执行事项三栏收进底部「▸ 我的事项 N」；选「全部」「未归入 Task」照旧。
- `TaskList`：每张卡写名字、计划日期和状态小标（未开始 / 评审中 / 迭代中 · 50 / 可以交付 / 已交付），去掉「已完成 a / b」和进度线。
- `TaskDeliverable`：一块面板、少框：负责人一行 → 报告结论（圆环 + 一句）→ 标准逐条（✓◐✗、理由，展开看依据和怎么补、「我不同意」）→ 交付物（版本切换、文件小条）→ 底部动作（传新版本、说说现状、还差几条、交付）。评审中显示阶段和「已用 / 约」；交付后显示伙伴的版本说明和「已交付 · N 分钟 · 撤回」。
- 不写说明句；用现有主题变量和组件；手机宽度一列。
