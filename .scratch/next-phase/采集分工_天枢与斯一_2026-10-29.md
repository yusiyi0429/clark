## 1. 一句话

按「谁来触发」分工：**每天定时的归斯一，天枢里发生的归天枢**。
- 读本机会话只留一份脚本，用斯一那份。
- 写本体每一类只有一个写入方，不出现第三个。
- 天枢不再定时收任何东西。

## 2. 已经定了的三件（10/29 19:10）

1. 以天枢为触发点的收集有四种：说说现状、交付物证据、确认后的跟进、补齐本体缺口。
2. 日进展照旧：斯一的 skill 在本人电脑上直接写本体，天枢只读来给 DRI agent。设计稿第 10 节第 2 问（「老二」是谁）就此关掉。
3. 天枢发起的收集在本机按请求收：天枢挂一个请求，本机每几分钟看一眼，有请求就叫起本人的 Codex/Claude 去读、起草，本人在天枢确认。原文不出本机。

## 3. 两条线

| | 每天定时（斯一） | 天枢发起（天枢） |
|-|-|-|
| 什么时候 | 每天 20:30，或本人说「写今天的进展」 | 本人在天枢里点了，或到了天枢定的检查点 |
| 收什么 | 一天的进展、卡点、协同、洞察，四段，内容先不变 | 只收这次请求要的那一件：某个 Task 的现状、某一版的证据、某件确认过的事做到哪、某个缺口的依据 |
| 谁去收 | 本人电脑上的 Codex/Claude（skill） | 本人电脑上的 Codex/Claude（天枢收集器叫起） |
| 原文 | 不出本机 | 不出本机，只交回草稿 |
| 本人确认 | 不单独确认：装了 skill 就算同意，快照标「未经确认」 | 每次都要在天枢里确认才存 |
| 写到哪 | 本体，用本人凭证。天枢每天 21:30 读一次给 DRI agent，第二天第一次打开时再补读一次 | 天枢；其中三种再进本体（第 4 节） |

## 4. 天枢发起的收集

| 场景 | 什么时候发起 | 收什么 | 确认后存在哪 | 进不进本体，谁写 |
|-|-|-|-|-|
| 说说现状 | 本人在 Task 面板点「说说现状」 | 本人最近在 Codex/Claude 里做这个 Task 的记录，加上昨天的日进展，起草三行现状 | 天枢：交付物的一版「现状说明」，存下就开始评审 | 不进 |
| 交付物证据 | 本人上传新版本时点「从我电脑里找」（我定的） | 和这个 Task 相关的产出清单：文档、PR、截图、测试记录。本人勾选带哪些 | 天枢：挂在这一版上 | 版本本身不进。**提交**时进（设计稿 5.4），天枢写；开关默认关，写法待斯一定 |
| 确认后的跟进 | 本人在天枢确认了会上决策、接手了执行事项以后，到检查点再收：截止前一天，以及本人打开这件事时（我定的） | 只收这几件事做到哪、会不会延期 | 天枢：给本人和他的 DRI agent | 只有状态变化进：完成、延期、改截止、取消。先找负责人确认，再照现在天枢会议写入的做法写（本人点头，天枢以服务主体写）。谁来写还待定：分工会上说「进展由 Co-Agent 写」，和溪南、斯一一起定 |
| 补齐本体缺口 | 天枢的「任务数据质量」发现某个 Task 缺验收标准或缺来源 | 本人电脑里能证明这一项的依据 | 天枢：补齐草稿，本人逐项确认 | 进。用本人凭证、经斯一的工具写，这一步是现有设计。变的只是把「复制给个人 Agent」换成自动发起 |
| 本机盘点（已有） | 本人在上手页或设置里点「扫描」 | 本机的定时任务、记忆文件，以及会话里出现过的飞书文档 | 天枢：只有本人能看 | 不进。另外不再每天自动盘点（我定的） |

几点补充：
- 跟进不是本人当场点的。所以接手一件事时先问一句「到期前要我从你电脑里看一眼吗」，同意了才发跟进请求（我定的）。
- 说说现状：先用昨天的日进展起个头，本机草稿到了再补一句，人不用干等。

## 5. 不适合从天枢出发的收集

**要进本体的**

| 信息 | 为什么不从天枢出发 | 由谁、怎么收 |
|-|-|-|
| 每天的进展、卡点、协同、洞察 | 按天收、覆盖全部工作；那个时候人不在天枢里 | 斯一的日进展 skill，每天 20:30 |
| 会议结论，以及会后执行事项的草稿 | 原料在会议里，不在本人电脑上 | Nexus：会中接管，会后整理并写本体；改动、冲突和执行事项由 Nexus 提取，交给本人的 DRI agent 推到天枢工作台。本人处理改动、接手执行事项这两步在天枢里做（孙铭泽 10/29 晚定，设计稿 5.6） |
| Mission、Task 的定义和体验验收标准 | 是敲定 Mission Card 时产出的，不是收来的 | 溪南的 M2 |
| 进度评判结论 | 由 Co-Agent 站在公司立场判，不能从本人这边收 | 溪南的 Co-Agent |
| 在云端干的活（ChatGPT 网页、飞书文档） | 本机没有记录，收集器读不到 | 日进展：在 ChatGPT 里连上天枢说一句，或者 DRI agent 每天晚上问一句（设计稿 5.1）。现状和证据：本人在对话里说，或者手动上传 |

**不进本体的**

| 信息 | 为什么 | 怎么处理 |
|-|-|-|
| 当天的过程细节、流水账 | 会上定了：不记「做了什么」 | 不收。原文留在本机，skill 读完只留下四段 |
| 和工作无关的会话、个人项目的会话 | 隐私 | 永远不读，按目录白名单过滤 |

## 6. 本机怎么按请求收（我定的）

```
天枢：本人点了，或到了检查点
  → 记一条请求：谁、哪种、哪个 Task 或事项、时间范围、目的

本机收集器：系统定时任务，每 2 分钟问一次「有我的请求吗」，不读任何东西
  └ 有请求 → 在后台叫起本人的 Codex 或 Claude Code（命令行），只给它三样：
             天枢 MCP、斯一的读取脚本、只读权限
      └ 它只读白名单目录里、请求时间范围内的会话，起草，交回天枢

天枢：显示「你的电脑在收… 已用 0:42 / 约 2 分钟」
  → 出草稿 → 本人改、确认 → 存
```

- 原文不出本机，只交回草稿。草稿不确认就不存。
- 电脑不在线：显示「你的电脑不在线」，同时给出「说一句」和「上传」两条路。当天没收成就作废。
- 用的是本人自己的 AI 订阅，只在有请求时才跑，一天几次。
- 后台那次 AI 运行不写本体。要写本体的，等本人在天枢确认以后再写：
  - 事件类由天枢服务端写；
  - 补齐类由收集器直接调斯一的工具、用本人凭证写，这一步不再经过 AI。
- 现有采集器就地改造：
  - 停掉每 30 分钟检查、约每 3 小时上传、服务端每 5 分钟整理；
  - 装过的人（你本机、王创峰）跑一次更新命令。

**要实测的**：
- 本机要有 Codex 或 Claude Code 的命令行；
- 后台运行的权限要预先配好，不能弹确认框；
- Windows 和 macOS 各跑一遍。

## 7. 怎么不重复

- **读**：只留斯一那份读取脚本。他那份已经能按目录白名单过滤，天枢那份不能。天枢 `tools/collector/` 里那份删掉，收集器改调他的。
- **写本体**：每一类只有一个写入方。
  - 用本人凭证写的，只用斯一的工具：日进展、补齐。
  - 会议由 Nexus 写（设计稿 5.6）。
  - 天枢以服务主体写的，只有新增的提交、跟进得出的状态变化。后一种谁来写还待定（见第 4 节）。
- **内容**：
  - 日进展提到已经在天枢提交或确认过的事，只引用那条事件，不复述。这延续了斯一 16:16 说的「会议结论、周复盘只引用不复述」。
  - 状态变化（完成、延期、改截止、取消）只走天枢那条，要负责人确认；日进展里只写风险。
- **AI 工具主动记录**：天枢 MCP 的「主动记进展、主动建事项」去掉，只在本人明确要求时才做（设计稿第 10 节第 4 问，按停走）。这本身也是一条收集路。
- **安装**：
  - 天枢上手页只装天枢这边；
  - 斯一那套用他的 `tkos-world update` 装；
  - 上手页检查两样在不在，缺哪样就提示哪样。

## 8. 分工

| 斯一 | 天枢（你这边） |
|-|-|
| 日进展 skill：格式、定时、写本体。格式当成稳定约定，改之前告诉天枢 | 四种请求：什么时候发起、请求记录、进度显示、确认界面 |
| 读取脚本：只有这一份，给一个稳定的调用方式（按时间范围、目录、关键词读，输出脱敏后的片段） | 本机收集器：改造现有采集器，按请求叫起本人的 AI |
| 本人凭证的写入工具 | 本人在天枢点头后的事件，由天枢服务端写 |
| 新写入类型的规矩：提交、跟进得出的状态变化 | 每天读日进展给 DRI agent |
| 日进展引用天枢的事件，不复述 | MCP 说明去掉主动记录 |

## 9. 当面和斯一对的（按顺序）

1. **分工按第 3 节**：每天定时的归他，天枢发起的归我们。
   - 你 16:28 跟他说过「新阶段会整体换成他那套」。这份方案保留了天枢的本机收集器，只是改成按请求跑、不定时收，所以要讲清楚为什么。
   - 理由：现状、证据、跟进、补齐都发生在天枢里的某个时刻，他的定时 skill 接不住。
2. **读取脚本只留他那份**，要一个稳定的调用方式。
3. **新写入类型**：交付物提交、跟进得出的状态变化。
   - 我们的提议：照现在天枢会议写入的做法，本人在天枢点头，天枢以服务主体写，带上本人 id。
   - 跟进得出的状态变化和分工会「进展由 Co-Agent 写」可能冲突，这一种要和溪南一起定。
   - 问他批不批，还是要求用本人凭证写。
4. **补齐换成自动发起**：写入仍用他的工具和本人凭证，本人在天枢确认后才写。
5. **日进展的两条约定**：引用天枢的事件、不复述；格式改之前通知天枢。
6. **天枢采集器改造的时间**：先停定时上传，再上按请求收的收集器。

1. **不等斯一**（动手前按第 9 节第 1、6 条跟他说一声）：
