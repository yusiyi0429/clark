## 做了什么

- **左边 Task 卡**：名字、计划日期，加状态小标：
  - 未开始 / 评审中 / 迭代中 · 分数 / 可以交付 / 已交付；
  - 去掉了「已完成 a / b」和进度线。
- **右边交付面板**，从上到下（不套卡片，只用细线分段，只有上传区是虚线框）：
  1. 负责人一行，和「本体 · 验收标准 N 条」（或「本体 · 完成定义」）。
  2. 结论：
     - 评审中显示几步走到哪，和「已用 / 约 N 分钟」；
     - 评完是圆环（几条达到）、一句结论、概况、「比上一版：…」，以及按什么评、读了几份、用时。
  3. 验收标准逐条：
     - ✓ / ◐ / ✗ 加一句理由；
     - 没达到的默认展开「依据 / 怎么补」；
     - 旁边有「我不同意」：写一句为什么，带着这句话重评这一条；还是没达到就标「本人有异议」。
  4. 交付物：
     - 版本切换（v1 · 25、v2 · 已交付）；
     - 文件、图片、链接的小条，后面写已读 · 页数 / 已看 / 读不了的原因；
     - 只写了现状的版本显示那段话。
  5. 交付后：伙伴写这一版的说明（达成了什么、这一版多做到的、为什么变了、经验），可以「改一改」或「不要这段」，不点就算认可；下面是「已交付 · N 分钟」和「撤回」。
  6. 动作：
     - 上传新版本：默认沿用上一版的材料，× 去掉；
     - 说说现状；
     - 「还差 N 条」；
     - 「交付」只有每一条都达到才亮。
  7. 这个 Task 下的执行事项收进底部「▸ 我的事项 N」。
- **能读的材料**：
  - 文件和图片：PDF、Word、Markdown、HTML、图片（单张不超过 5 MB），一次最多 10 个文件、每个不超过 20 MB；
  - 网页链接：一次最多 5 个，会去抓正文；
  - 飞书链接一律标「飞书文档请导出后上传」；抓不到的标「打不开 · 请导出后上传」。
- **后端**：
  - 迁移 219（两张表）；
  - 8 个接口，都在 `/api/plan-tasks/{taskId}/deliverable` 下面；
  - 评审和版本说明走后台队列，重启后会接着做；
  - 权限在收文件之前就查；
  - 下载的文件带 `content-security-policy: sandbox`。

## 已知的问题

- 读本体 Task 有 2.5 秒的时限，本体慢的时候面板会报找不到这个 Task。
- 「约 N」按最近 20 次评审用时的中位数算（最少 30 秒）。「我不同意」那种只重评一条的也算在里面，会把这个数拉低。
- example.com 这种正文太短的页面会被标「打不开」。
- 版本说明的开头措辞每次不一样（「达成了：」/「本版达成了：」），没在界面上固定。
- 本机 API 全量测试跑不完：vitest 进程池报 `ERR_IPC_CHANNEL_CLOSED`，只能分批、单文件跑。
