# 伙伴（Buddy）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 每个人一开始「选择你的伙伴」：起名字，在原来的三种横放胶囊里选一种。名字和样子存在服务端，对话窗顶上显示伙伴的名字，右列那颗胶囊按本人选的样子画，设置里能改；本地运行时的人设带上伙伴名字和短句规矩。

**Architecture:** 新表 `person_buddies` + `GET/PUT /api/me/buddy`，会话响应带 `buddy`（给页面守卫判断「还没选伙伴」）。网页 `components/buddy/` 放 `useBuddy`（读写和广播变化）和 `BuddyPicker`（起名 + 选胶囊，引导和设置共用）；胶囊预览沿用现有 `PresenceCapsule` 和 `SkinPicker` 的写法，不画新形象。引导最前面加 `buddy` 一步，不能跳过；已引导过但没有伙伴的人，下次打开只走这一步。

**Tech Stack:** Fastify + Postgres 迁移、TypeBox 契约 + openapi-typescript 生成客户端、Next.js（apps/web 的 AGENTS.md：写代码前先读 `node_modules/next/dist/docs/` 里相关的那篇）、Vitest。

**Spec:** `.scratch/next-phase/spec.md` 5.5「选择你的伙伴」「伙伴在对话窗上露脸」「说话方式」；第 10 节第 19 问未定，第 20 问已定（先不做 2D）。

## Global Constraints

- 叫法：本人的 Agent 统称「伙伴」；溪南那边站在公司立场的仍叫 Co-Agent。界面上不出现「Co-Agent」指本人伙伴的新字样。
- 外形只有原来的三种横放胶囊，id 和浏览器里记过的一致：`classic`、`alive`、`panda`（孙铭泽 10/29 晚定，先不做 2D 形象）。不画新形象、不加小头像。
- 界面不写说明句；复用 ts-design 组件和 `globals.css` 里的主题变量，不加新颜色。
- 伙伴名字：去掉首尾空白后 1–12 个字（我定的）。新人的名字框是空的，要本人起。
- 迁移编号 218（下一个空号；合并前再核一次有没有被占）。改迁移要同时改 `apps/api/test/migrate.test.ts` 里的文件清单。
- 契约改了先跑 `pnpm --filter @warmap/web gen:client`，生成文件不手改。
- 文案过 `apps/web/src/cards/formalCopy.test.ts`（不用「帮你、看看、啦、哦」这类口语）和 `apps/api/test/promptGovernance.test.ts`（不打招呼、不称呼「X总」）。
- 只动天枢本地运行时的人设；正式环境的人设归人豪，不碰 `chatService.ts`。

## Review Focus

1. 已经走完引导、但还没有伙伴的老用户：下次打开任何页面，先只走「选择你的伙伴」一步，选完回到原来要去的页面，不再重走整套引导。→ Task 3 的测试。
2. 名字全是空格、超过 12 个字：保存、继续按钮不可用，接口返回 400，不存。→ Task 1、Task 2 的测试。
3. 在一个标签页里改了伙伴，同一浏览器另一个标签页的对话窗顶上跟着变（至少刷新后一致）。→ Task 2 的 `buddy-changed` 测试。
4. 本机浏览器里存过胶囊样子（`tianshu.coagent-skin`）的人，第一次选伙伴时默认停在那一种上。→ Task 2 的测试。
5. 选了伙伴以后，会议录音、新人进群时右列那颗胶囊画的是本人选的样子，换设备也一样。→ Task 4 的测试。
