# 伙伴（Buddy）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 每个人一开始「选择你的伙伴」（起名字、选外形），伙伴的名字和外形存在服务端，在对话窗顶上和右列那颗胶囊的位置露脸，设置里能改；本地运行时的人设带上伙伴名字和短句规矩。

**Architecture:** 新表 `person_buddies` + `GET/PUT /api/me/buddy`，会话响应带 `buddy`（给页面守卫判断「还没选伙伴」）。网页一个 `buddy/` 目录：外形登记表、`BuddyAvatar`（画外形和动作）、`BuddyPicker`（起名 + 选外形，引导和设置共用）、`useBuddy`（读写和广播变化）。引导最前面加 `buddy` 一步，不能跳过；已引导过但没有伙伴的人，下次打开只走这一步。

**Tech Stack:** Fastify + Postgres 迁移、TypeBox 契约 + openapi-typescript 生成客户端、Next.js（apps/web 的 AGENTS.md：写代码前先读 `node_modules/next/dist/docs/` 里相关的那篇）、Vitest。

**Spec:** `.scratch/next-phase/spec.md` 5.5「选择你的伙伴」「伙伴在对话窗上露脸」「说话方式」；第 10 节第 19、20 问未定。

## Global Constraints

- 叫法：本人的 Agent 统称「伙伴」；溪南那边站在公司立场的仍叫 Co-Agent。界面上不出现「Co-Agent」指本人伙伴的新字样。
- 界面不写说明句；复用 ts-design 组件和 `globals.css` 里的主题变量，不加新颜色。
- 伙伴名字：去掉首尾空白后 1–12 个字（我定的）。
- 外形 id 固定为：`capsule-classic`、`capsule-alive`、`capsule-panda`、`panda`、`cat`、`whale`、`drop`。2D 形象沿用 `.scratch/next-phase/伙伴候选_2026-10-29.html` 的画法；用户挑完（第 20 问）再删不要的。
- 迁移编号 218（下一个空号；合并前再核一次有没有被占）。改迁移要同时改 `apps/api/test/migrate.test.ts` 里的文件清单。
- 契约改了先跑 `pnpm --filter @warmap/web gen:client`，生成文件不手改。
- 文案过 `apps/web/src/cards/formalCopy.test.ts`（不用「帮你、看看、啦、哦」这类口语）和 `apps/api/test/promptGovernance.test.ts`（不打招呼、不称呼「X总」）。
- 只动天枢本地运行时的人设；正式环境的人设归人豪，不碰 `chatService.ts`。

## Review Focus

1. 已经走完引导、但还没有伙伴的老用户：下次打开任何页面，先只走「选择你的伙伴」一步，选完回到原来要去的页面，不再重走整套引导。→ Task 4 的测试。
2. 名字全是空格、超过 12 个字：保存按钮不可用，接口返回 400，不存。→ Task 1、Task 3 的测试。
3. 在一个标签页里改了伙伴，同一浏览器另一个标签页的对话窗顶上跟着变（至少刷新后一致）。→ Task 3 的 `buddy-changed` 测试。
4. 系统设置「减少动态效果」时，伙伴不眨眼、不点头、不跳。→ Task 2 的 CSS 规则和测试。
5. 本机浏览器里存过旧胶囊样子（`tianshu.coagent-skin`）的人，第一次选伙伴时外形默认停在那一种胶囊上。→ Task 3 的测试。
