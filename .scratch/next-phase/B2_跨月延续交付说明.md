## 2. 接口（契约 `packages/contracts/src/taskContinuity.ts`，OpenAPI 入口 `taskContinuityOpenapi.ts`）

都只给 DRI 工作台视角。延续、到此为止和撤销到此为止只给那件 Task 的负责人：看不到的回 404，能看但不是负责人的回 403。

| 接口 | 体 / 回 | 规则 |
|---|---|---|
| `POST /api/me/tasks/:taskId/continuation` | `{ toTaskId }` → `ContinueTaskResponse { taskId, settlement, moved }` | 新 Task 也要是本人负责的。可以重复调，第二次起 `moved` 全为 0。旧 Task 已经延续到别的 Task 回 409 `ALREADY_CONTINUED`；新 Task 自己已经延续出去回 409 `TARGET_CONTINUED`。 |
| `POST /api/me/tasks/:taskId/stop` | `{ note? }` → `{ taskId, settlement }` | 已经延续出去的回 409 `TASK_CONTINUED`。 |
| `DELETE /api/me/tasks/:taskId/stop` | → 204 | 原来没定过也回 204。 |
| `GET /api/me/months/:period` | → `MonthPageResponse` | 见第 4 节。 |
| `PUT /api/me/months/:period/tasks/:taskId/decision` | `MonthAnswer { choice, note }` → 204 | 选 stop 会同时定到此为止（task_stops）；选 continue 或 revise 会撤销到此为止；只写一句话（choice 为 null）时不动到此为止。两样都空回 400；不是这个月本人负责的 Task 回 404。 |

写入一条延续时，在一个事务里做下面这些事（`taskContinuity.continueTask`）：

- 改挂到新 Task：没做完的卡和事项（已完成、已退回的不挂）、开着的专题、还没进版本的待交付条目、没关的拆卡登记、还没了结的「要开工」、规划员会话（`local_runs` 里 kind 为 plan 的），以及它出的计划和还没处理的派活单草稿。卡、专题、拆卡登记、计划连 Mission 一起换。
- 卡对应的那条标准：按原文在新 Task 的标准里重新找序号，找不到就算「其他」。
- 管线：新 Task 接用旧管线的对话。接了 Chat 的把 `task_pipelines` 这一行改挂到新 Task；没接 Chat 的把 `plan-task:` 对话改到新 Task 的 scope。新 Task 已经开过管线的不动。
- 约定：复制一份给新 Task，`draft_from` 记旧 Task。新 Task 已经有约定的不复制。
- 留在旧 Task 上：做完的卡和交付版本。
- 旧 Task 定过到此为止的，以这次延续为准，撤掉。

规划员还按旧 Task 上报派活单时，`localSync` 会顺着延续接到最后一件新 Task 上，本机程序不用改。

约定接口（`TaskAgreementResponse`）新加了 `draftFrom`：是延续来的草稿时为旧 Task 的 id，否则为 null。

## 4. 给 W2 的月份页数据形状

路径和 W2 的 `useMonthPage.ts` 一致（`GET /api/me/months/:period`，`PUT .../tasks/:taskId/decision`，回 204），choice 的取值也一致。和 W2 现有类型的差别如下，合并时只改 `useMonthPage.ts`：

- `MonthTask` 多了三个字段（W2 现在用不到也不影响）：
  - `missionId`；
  - `settlement`：了结方式，null 表示没了结。kind 为 continued 时，`settlement.to` 是延续去的那件，带 `period`；
  - `continuedFrom`：这件是从哪件延续来的，形状同 TaskRef。
- `done` 只在「本人确认完成」时为 true。已延续、到此为止的 Task 要看 `settlement`：
  - 已延续的，建议写「已延续到 12 月的 X」，不再问怎么办；
  - 到此为止的会同时带 `answer.choice = "stop"`。
- `agreement` 没有标准时为 null；`total` 至少是 1。
- `draft` 现在一律为 null，形状照 W2 的 `MonthDraft` 定在契约里，等溪南。
- 网页客户端已经重新生成（`apps/web/src/lib/api/openapi.json`、`schema.d.ts`），类型名是 `MonthPageResponse`、`MonthTask`、`MonthAnswer`、`MonthDraft`、`TaskSettlement`、`TaskRef`。

## 5. 每天自动载入 Mission

- 代码在 `missionAutoLoad.ts`，接在 `server.ts` 的公共后台任务上，每天一次。
- 每次载入公司时区的本月和下月，调的是现有的 `loadWorldMissions`，用主实例，只读，一个月一个事务。
- 只有 `TIANSHU_AUTO_LOAD_MISSIONS=1` 而且本体配了才会开，默认关。上线时开不开由你定。

## 6. 等溪南的、没做的

- Co-Agent 草稿：`draft` 永远为 null，`MonthDraft` 的形状是暂定的。
- 怎么把复盘答案交给 Co-Agent：答案存在 `task_month_reviews`，交付方式等 10.8 的回答。
- 延续的来源：表和函数都支持 coagent / world，但还没有载入这两种来源的代码，现在只有本人通过接口定（owner）。
- 新 Task 管线里的分隔线「12 月」：没做。网页可以用 `continuedFrom` 判断是延续来的，但 `continuedFrom` 里没带延续的时间。
