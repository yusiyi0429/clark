## 结果摘要

### 2026-09-28

- **契约与迁移**：`monthlyReviews.ts` 契约、044 迁移、ADR-0024、CONTEXT 术语。能力域加负责人（`capability_config.owner_id`）。复盘材料改为走对话附件，不扩展材料区。
- **API**（子代理实现，Claude 审过）：
  - 复盘和复盘项的仓储与投影，12 个 Action（行锁、防重放、锁内权限校验）
  - 三个 Agent（起草、偏差评估、公司汇总），调度在月末倒数第 3 天自动开启
  - LTCO 决定后立即创建下月计划草案，草案输入加 `previousReview`，1 日作为兜底
  - 对话工具 `propose_review_edit`，通知由复盘状态现算
- **Web**：
  - 复盘项页 `/me/reviews/items/[id]` 和 `/reviews/items/[id]`：四栏编辑、Agent 建议的「采用 / 忽略」、提交、偏差评估、确认 / 打回
  - CEO 总览 `/reviews/[period]`：行内确认 / 打回，5 条判断可编辑、确认
  - LTCO 决定页 `/reviews/[period]/ltco`
  - CEO 和成员通知栏的「月末复盘」分组，能力域配置的负责人选择
- **验证**：
  - 契约 72/72，Web 668/668（新增 8 项），API 新增 14 项
  - API 全量串行 753 项，10 项失败都不是这次引入的：deployment 8 项、Windows 下 tsx 超时 1 项、migrate 1 项；migrate 那一项已顺手修好（原本就停在 040）
  - 时间机器另起 4600 / 3600 端口，在浏览器里走完全程：CEO 打开 → 起草 → Agent 建议被采用 → 编辑后直接提交 → 评估 → 打回（带原因）→ 重新提交 → 确认 → 成员在 375 宽下从通知进入并提交 → CEO 在 768 宽下从通知进入，行内确认 → 汇总 → 改判断后确认 → LTCO 修订 → 跳到 11 月计划草案；LTCO 已写入，复盘关闭，通知清空，控制台无报错。
- **验收中顺手修的**：
  - 复盘项对话底部的说明文案
  - CEO 自己负责的项提交后，状态写成「待你确认」
  - 提示框间距
  - LTCO 修订框为空时误报「和现在一样」
- **时间机器**：新增 `review-open` 命令、演示用的复盘 Agent、可配置端口；Method 能力域的负责人设为孙铭泽。
- **没做**：C、D 阶段（见 spec §10）；真实模型下 Agent 输出的质量要在开发环境或上线后看；时间机器里的对话 Agent 不连模型，「提改写建议」是用仓储函数模拟的。
