## 规则（用户委托拟定，ADR-0023）

- **改一个字段，不重开整轮**：确定后发现错，只改某项个人任务的一个字段。
- **谁提、谁定**
  - 卡的主人「申请更正」：写改后的文字和原因。
  - 拍板人（CEO／本战场 DRI）逐条「采纳」或「不采纳」，不采纳要写原因；自己发现的错可以直接「更正」，立即生效。
  - 采纳写回这一个字段，版本加 1。
- **不能直接采纳的申请**：申请之后字段又改过，标「原文已变化」，只能不采纳，或按最新文字直接更正。
- **留痕**：每条更正都记下来，字段标「已更正」，卡的状态写「更正 N 处」。
- **提醒拍板人**：有待处理的申请时，这一轮回到拍板人的通知里。
- **月份过了只读**：月底提前确定的下月卡也能更正；月份过了只读，要改的放进下个月的卡。

## 审查后 Claude 自己改的

1. **月份过后行文案回到「已确定」**
   - 问题：月份过后，拍板人看到的行仍写「N 条更正申请」，催一件已经办不了的事。
   - 处理：先补断言，确认它失败，再改 `missionRounds.ts`。待处理数照实保留。
2. **CEO 通知栏带回待办**
   - 问题：CEO 通知栏把已确定的轮次整个过滤掉了，看不到更正待办。
   - 处理：`NotificationRail.tsx` 改成「已确定且有 todo 才留」。已确定轮次有待办时，也照常每 20 秒刷新。测试先红后绿。
3. **成员战场详情的「下一步」直达申请**
   - 已确定后「查看 N 月个人卡」带 `?correction=`，直达第一条待处理申请。
   - 状态句只认服务端的 `todo`，去掉 Web 自己数申请、判月份的分支。`roundStatusText` 的参数从 `{ applied, closed }` 简化为 `corrected`。
4. **深链焦点被关闭键抢走**
   - 现象：从通知点进来，`?correction=` 和 04c 就有的 `?feedback=`，焦点都在约 300ms 后被工作区的「关闭」键抢回。
   - 原因：工作区在展开动画结束后无条件聚焦关闭键。
   - 三个方案：
     - (a) 关闭键只在焦点不在详情里的深链目标上时才抢；
     - (b) 深链等动画结束再聚焦，靠计时，不稳；
     - (c) 详情向工作区登记首个焦点，要加接口。
   - 采用 (a)，只认 tabindex=-1 的深链目标，所以「在详情里点按钮换卡」时焦点照旧回到关闭键。
   - 实测：通知进入 50／300／800／1500ms 焦点都在那条申请上；普通打开仍聚焦关闭键（`debug-focus*.cjs`）。
5. **只读说明贴着版本行**：外壳的 `p { margin: 0 }` 优先级更高，改为 `.readonly.readonly`。实测间距 24px（`debug-readonly.cjs`）。
6. **ADR 的说法**：卡片私聊的 Agent 读的是本人能看到的整张卡，也读得到更正记录。ADR 照实写，代码不改。

## 同批小修（用户逐条要求）

- **雷达选中胶囊**
  - 蓝色保持 `#3A83F7`：用户的优先级是「蓝色不要太深」。
  - 白字从 500 加粗到 600，补可读性。白字对比度仍约 3.6:1：达到大字号或粗体界面文字的 3:1，没达到正文的 4.5:1。
- **404**：换成天枢的晨光底、磨砂卡片和实心蓝按钮。文案不再写 WarMap，也不写「对象」这类开发用语。
- **引导舞台**：只改 CSS。桌面舞台上下各留 20px 渐隐，手机布局不变。
- **DRI 手机首页**
  - DRI 的事在天枢之外做，来天枢是为了同步和看进展，所以手机上按「先看新的、再推手上的、最后看全局」排：通知 → 执行事项 → 我的本月卡 → 战场 → 雷达 → 个人菜单。
  - 顶部只留时钟胶囊，姓名标题只给读屏。
  - 桌面不变。只改 CSS 顺序，另在首页末尾多放一份只在手机上显示的个人菜单。

## 边界与遗留

- **不做**：申请人收到处理结果的提醒、撤回申请、重开已确定的整轮（ADR-0023「不做」）。
- **引导不提示更正**：「下一件事」不提示待处理的更正。首次登录时正好有待处理更正的情况很少。
- **执行事项与个人任务**：执行事项还没有登记所属的个人任务，首页写不出「这件事推动了哪一项个人任务」（SSOT GAP-19）。
- **待真机验收**：iPhone 上「已更正」小标的点按区域、长文字的编辑体验。
