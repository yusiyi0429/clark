# 03 DRI 首页小组件

Type: feature
Status: resolved（报告见 ../evidence/03/report.md）
Blocked by: 04d（依赖成员外壳、本轮个人卡的数据和小标）
Spec: `../spec.md` §5、§3（美学统一）；产品论证：`../why.md` §（d）

## 目标

DRI 一进首页就能回答两个问题：
- 我的工作服务于哪个本月目标？
- 我从哪里接着做？

顶部是像小组件一样的几块：参与的战场（只写本月目标）、我的本月卡、雷达（开了个人雷达才有）。下面是我的执行事项。

## 范围

1. **数据**
   - 扩展 `GET /api/me/home`，或新增一个成员首页接口，返回：
     - 参与的战场：id、名称、本月目标三种状态的文案与原文
     - 我的本月卡：cardId、状态句、截止时刻
   - 复用工单 01 引导里"你这个月的工作"的服务函数，不写第二份逻辑。
   - "参与"指：本月是这个战场的负责人，或是本轮个人卡的 Owner（包括讨论候选），或在这个战场有 Mission。
2. **战场卡**
   - 只写战场名和本月目标：
     - 还没生成：「本月目标还没出来」
     - 未签发：「本月目标还在协商」
     - 已签发：原文，最多 3 行，多了能展开
   - 措辞和引导里是同一句话。
   - 战场 DRI 的卡头加皇冠（同 CEO 侧的写法）。
   - 点卡进成员战场详情。
3. **我的本月卡**
   - 常驻入口，写状态和截止时刻，点击打开我的卡。
   - 确认后通知退出了，这个入口也还在。
   - 没有卡时写「这个月还没有你的卡」。
4. **成员战场详情页** `/me/battlefields/[id]`
   - 在成员外壳的展开区里打开。
   - 内容：六个月目标、本月目标、本月这个战场的个人卡与负责人（能打开自己的卡；拍板人能打开全部）、本轮状态块（设计 `../design-04-mission-cards.md` §6.5）。
   - 不显示 CEO 的待决策议题。
   - 看不到的战场返回 404。
5. **雷达小组件的位置**
   - 雷达（工单 02）还没做时，不画任何占位。
   - 布局按"有雷达、没雷达"两种都设计好，02 接入时只需要把组件放进去。
6. **页面开头那句说明**：「发给你的信号、你推进和参与的执行事项，都会出现在这里」删掉或改写，不承诺没做的功能。
7. **排版**
   - 顶部几块是同一种卡片外形：宽屏并排，窄屏上下叠。
   - 常用桌面尺寸（1440×900、1280×800）下，执行事项区至少有一部分留在首屏。

## 质量标准

- 这是 DRI 每天打开的第一屏。要紧凑、清楚，能让人一眼找到正在推的事。不要完成率、甘特图、健康判断、演示进度。
- 美学统一（spec §3）：
  - 沿用工作台已有的卡片体系（ts-design），不在工作台里铺引导的画布。
  - 圆角、间距、字号、状态措辞与引导、个人卡页一致。
  - 实心天枢蓝只用在行动上。
- 没有登记资料时写「没有登记」，不写成"没有工作"。
