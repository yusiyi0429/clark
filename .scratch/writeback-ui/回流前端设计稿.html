天枢写进本体（world-02 · tkos.world/0.3）的每个环节，现在有没有前端、缺什么；缺的部分给出可点的样稿。依据是《对话质量联调架构》第 2、4 节和 Content Pact v0.6 的 9 个对象。代码基线 origin/main a7ad0b8。样稿里的界面按「不写解释句」来做，说明都写在右侧。

2　统一的落点标签

每一处写入都用同一种小标签，写清「对象类型 · 名称 · 组件」；右侧的点表示写入状态。它沿用影响卡上已有的「落到」一排（ImpactFace 的 targets），只是从天枢本地对象换成本体的 9 个对象。下面每张样稿都用它。

3　会议链

会议事件写一条（摘要 + 条目 + 挂点），条目里的每条决定再按现有做法各记一条（D-39）。会议页「会上定了」区上面加一条「挂到」，每条决定下面加它的落点；影响卡显示本体落点。

3.1 会议挂点 + 不写进本体

没有会议页「会上定了」区头部 · MeetingDecisions.tsx header；主持人和 CEO 可改

怎么用

  • 挂点默认 = 决定影响到的 Mission ∪ 会议议题关联的 Mission；都没有就挂主持人的单元。
  • 「改」打开对象选择：按 9 个对象搜，列本月 Mission、单元、PO。
  • 主持人确认完（或代判生效）后 30 分钟内写；写之前开关随时可开。
  • 已写入后再开「不写进本体」：在本体记一条撤回更正，原事件不删（本体只能追加）。

要你拍板

  1. 没有 Mission 时挂哪：主持人的单元推荐 / Company
  2. 谁能改挂点、开开关：主持人和 CEO推荐 / 只有 CEO
  3. 已写入后开开关：记撤回更正推荐 / 写入后不能再关
  4. 会议加「关联 Mission」字段：不加，挂点直接存在会议上推荐 / 加到建会表单

3.2 每条决定的落点 + 写入状态

补在已有的行上DecisionRow；契约 TMeetingDecisionView 加 world 状态和落点

会上定了

1 条待确认

    怎么用

    • 落点在主持人点完之后出现（影响分析算出来的），确认之前不猜。
    • 代判拆成两种状态：「Agent 代判 · 定了」已推卡、已记；「Agent 代判 · 没定」什么都没推。两种都还能三选一。
    • 代判之后这条继续留在首页「会上定了」，标「代判」，直到主持人点过。
    • 对不上本体对象的决定不再静默跳过，挂到 3.1 的会议挂点上，标黄点。
    • 写入失败显示红点，自动重试；重试到头进管理员视图（6.2）。

    要你拍板

    1. 落点和状态给谁看：主持人和 CEO推荐，参会人只看落点 / 只给 CEO 和管理员
    2. 代判后是否继续留在首页待办：留到主持人点过推荐 / 只在会议页

      3.4 影响卡：本体落点、「和我无关」原因、更正已同步

      补在已有的卡上ImpactFace、「前因后果」；管理员质量信号读 impact_cards.status='irrelevant'

      怎么用

      • 卡面落点一排不变（Task、验收项，本人看得懂的）；「前因后果」里加一行「本体」，写这条决定挂到的本体对象和状态。
      • 「和我无关」点了先出三个原因，点一个就收起；不点原因也能收（再点一次「和我无关」）。
      • 更正卡加一个「本体已更正」标，说明本体那条已被替代。

      要你拍板

      1. 「和我无关」要不要原因：三个快选，可不选推荐 / 不要原因
      2. 和我无关后改不改本体挂点：不改，只进质量信号推荐 / 去掉他的对象，记一条更正

      4　对话链

      架构页：规则本期定，实现排在会议之后。四类触发（纠错、拍板、要求记下、深聊成型）命中后，在那条回答下面挂一张确认卡；本人点了才往下走。片段按起止规则自动切，在卡里折叠。卡的外框沿用回答后面挂的卡（EntryCards、转议题建议卡）。

      4.1 对话里的确认卡 + 片段预览

      没有回答后面挂的卡 · 复用 entry-cards.module.css、IssueSuggestCard 的三选项

      怎么用

      • 卡上四样：类型、提炼出的一句、替代了哪句（纠错才有）、挂到哪个对象。
      • 「片段 · N 条」折叠，点开看切出来的原文，标出触发句、旧说法、依据三类。
      • 本人对对象有权（DRI、上级、CEO）：主按钮「写进本体」。无权：主按钮变成「交给 林晓 确认」，DRI 确认后才写。
      • 无权的「拍板」不出卡（不算决定）。
      • 深聊成型只出一行候选，本人选是哪一类后展开成上面的卡。
      • 「记一下」里的个人偏好照旧进个人记忆，句尾留记忆小标，不出卡。

      要你拍板

      1. 本期做到哪：规则 + 这版原型，实现排在会议之后推荐 / 本期就实现纠错一类
      2. 二号位也出确认卡：出，对自己有权的对象推荐 / 只给一号位（和转议题卡一致）
      3. 片段原文给谁看：对话本人、CEO、挂点对象的 DRI推荐（架构页待定第 2 条）

      4.2 推给对象 DRI 的待确认

      没有首页左栏通知卡（ActionNoticeCard，和「会上定了」同一种）；点开进二级页看片段

      怎么用

      • 和主持人确认「会上定了」一样在卡上直接办：采纳 / 改一下 / 不采纳。
      • 卡上写提出人和对象；点开是二级页（同一个外壳），显示 4.1 的片段。
      • 采纳后写一条对话事件，提出人在原对话里看到卡变成「林晓 已采纳」。
      • 参照 Mission 卡的「申请更正 → 采纳 / 不采纳」（CorrectionPanel.tsx）。

      要你拍板

      1. DRI 不处理怎么办：两次提醒后保持待办，不代判推荐 / 和会议一样一个工作日后代判

      5　进展链

      日进展现在由 skill 直接写，天枢里看不到。改成经天枢写以后，在本人首页给一个「今天写进本体」的预览：每个目标一行，可以改、可以不写。周复盘在提交区列出要写的对象，提交后显示结果。

      5.1 日进展：写之前能看、能改、能不写

      没有本人首页 /me，20:30 起草后出现；计划外复用 MemberOffPlan.tsx

      怎么用

      • 每个目标一行：落点 + 两三条事实，每条带采集条目的出处。
      • 「不写」只去掉这一行；全部不动，21:30 按草稿写（架构页：不需要确认，读时标「未经确认」）。
      • 对不上目标的工作单独一行，落点是本人所在单元，标「计划外」。
      • 写了以后只能「更正」：本体追加一条更正，不删原条。

      要你拍板

      1. 写之前给不给预览窗口：20:30 起草，21:30 写推荐 / 现在这样直接写，事后可更正
      2. 计划外写不写进本体：写到本人所在单元，标计划外推荐 / 只留在天枢
      3. skill 停写会议事件：本周请斯一停推荐（和「会议事件只由天枢写」冲突）

      5.2 周复盘：提交前列出写到哪，提交后看结果

      补在已有的提交区WeeklyReviewScreen.tsx:167；仿 MonthlyPlanCard 的 SignRecipients

      怎么用

      • 提交区上面一行落点：这次会写到的对象，按「关键进展与 Evidence」里引用到的 Mission、Task 算。
      • 本体里没有的对象标黄点「没对上」，不再算成功。
      • 提交后同一行变成结果；失败的红点自动重试，管理员能看到。
      • 只写进展行和链接，不写全文（D-01），不用另外说明。

      要你拍板

      1. 没对上的对象：挂到本人所在单元推荐 / 只标黄点不写

      6　签发月度计划、写入失败

      6.1 签发月度计划：列出要代确认的 PO

      补在已有的签发区MonthlyPlanCard.tsx:424 的 SignRecipients 下面

      怎么用

      • 「我确认签发」上面加一行：签发时一起确认的 PO。
      • 签发后这一行变成结果；没登记委托导致被拒的显示红点。

      要你拍板

      1. 确认哪些域的 PO：所有已承诺的 PO（含 Method）推荐 / 维持只确认公司和 E&O

      6.2 管理员：本体写入的跳过、失败和重试

      补在已有的管理员视图AdminScreen.tsx 新增一区；admin.ts 读 meeting_decisions.world_status 替掉已停写的 world_meeting_events

      怎么用

      • 按来源列：会议名 / 周复盘 / 签发，而不是原始对象 id。
      • 失败的可以「重试」；跳过的（没对上对象）单列一个数，可以点进去改挂点。
      • 用户侧只看到状态点；错误码只在这里。

      要你拍板

      1. 本体写入失败给不给「重试」：给推荐 / 只能接手、解决
