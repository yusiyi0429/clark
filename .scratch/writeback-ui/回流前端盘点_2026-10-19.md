## 2. 会议链

### M1 主持人确认「会上定了」

1. **前端现状：有。**
   - 会议页的「会上定了」区：`apps/web/src/components/meeting/MeetingDecisions.tsx`。每条一句，带原话和状态，主持人三选一：对 / 改一下 / 其实没定（`:87-92`）。CEO 视图挂在 `apps/web/src/cards/MeetingCard.tsx:1662`，成员视图挂在 `:1581`。
   - 通知栏置顶：`apps/web/src/components/meeting/HostDecisionNotices.tsx`，CEO 和成员两边都挂了（`NotificationRail.tsx:295`、`member/MemberWorkspace.tsx:58`）。卡上能直接点「对」「其实没定」，也能展开「改一下」，还显示「x 月 x 日前」和「Agent 判断没定」。
   - 两处都调 `POST /api/meetings/{id}/decisions/{decisionId}/review`（`meetingDecisionApi.ts:181-191`）。
2. **谁在什么时候确认什么 [事实]：**
   - 纪要整理好后，`sync` 调分层 Agent，挑最多 5 条给主持人，`due_at = addWorkday(分层时刻)`（`meetingDecisions.ts:164-171`）。
   - 只有 `lead_dri_id`（主持人）能确认：别人调用一律 404，CEO 也一样（`:204`）；战略项返回 409「战略项由 CEO 确认」（`:205`）。
   - 提醒：分层当时提醒一次，下一个工作日 9:30 再提醒一次，走飞书通知（`:238-263`）。和设计「散会当天一次、第二天上午一次」基本一致。不一致的地方是：分层如果拖到第二天，第一次提醒也跟着到第二天 [推断]。
   - 确认后，生效的决定入队 `propagate`：先做影响分析，再推影响卡，最后写本体（`:308-421`）。
   - **和设计不一致**：架构页写的是「Host 确认 3–5 条 → 写 1 条会议事件（摘要、条目、挂点）」，代码按 D-39 写的是「一条决定一条事件」，没有会议事件。
3. **缺什么：**
   - 每条决定会写到本体的哪个对象、写没写成，主持人都看不到：`TMeetingDecisionView` 里没有 `world_status`、`world_event_id`，也没有落点（`packages/contracts/src/meetingDecisions.ts:30-56`）。
   - 一场会如果一条可确认的都没有，界面直接不显示这一区（`MeetingDecisions.tsx:28`），主持人也就无从判断这场会会不会进本体。
4. **改的是哪个对象，界面有没有表达：**
   - 写的是**外部事件**，不改对象内容。`subject_refs` 从这一版影响卡的 targets 推出来（`worldDecisionEvents.ts:47-77`）：
     - Task：所属 Mission 的计划块里有 `todo:<id>` 组件时，挂到 `Mission@版本#块/todo:<id>`；没有就挂 Task 对象（world-02 里 Task 是 0 个），再没有就挂 Mission。
     - Mission：挂 Mission 对象。
     - 一个都对不上：主持人是 E&O 负责人时挂 **E&O 责任单元**，否则 `skipped`。
   - 事件正文第一行写谁拍的板：「Host 已确认」「CEO 已确认」「Agent 代判，Host 尚未确认」（`:25`、`:84-90`）；`declaration.human_acceptance.required=false`（`:105`）。
   - **界面完全没有表达**落点，比如「Mission · 企业经营 Context 建模 · Task 全景」这样的标签，也没有「已写进本体」的状态。

## 6. 写入失败或被拒时，谁看到什么

**写入路径 [事实]：** `WorldClient.write`（`apps/api/src/worldClient.ts:255-289`）先 prepare 再 commit，每次尝试在 `world_sync_ledger` 记一行。

- 本体返回非 2xx 时，抛 `WorldError(status, error.code)`（`:183`）。0.3 信封校验失败、权限不足（403）、委托缺失，都在这里落成 `failed`，带 `error_code`。
- `VERSION_CONFLICT`、`STALE_DEPENDENCY`、`PROTOCOL_WRITE_DISABLED`、`PROTOCOL_BINDING_CONFLICT` 会按当前对象重建请求，再试一次（`:143`、`:285`）。
- 网络错误记 `network_error`，交给上层重试。

| 写入点 | 用户（主持人、本人、CEO）看到什么 | 管理员看到什么 |
|-|-|-|
| 会议决定事件 | **什么都看不到**：`meeting_decisions.world_status/world_error` 不进契约 | 只看到 `write()` 里失败的那一次：「失败」列表一行，名称是 `world_record_event`，目标是原始的 `对象id@版本`，加错误码；没有会议名、没有决定，不能重试（`admin.ts:154-158`，`retryable:false`）。**看不到的情况**：① `skipped`（对不上对象）；② 写之前的查找就抛错，比如外部引用对应多个对象、找不到 E&O 单元（`worldDecisionEvents.ts:39`、`worldClient.ts:247`），这种只有日志 [推断]；③ 网络错误重试到 dead 后，只在「后台任务」里显示 `meeting.decision_propagate` |
| 周复盘 | 看不到 | 「人 × 来源」表的「本体」一格：周、状态（已写入 / 写入中 / 失败）、失败对象数（`AdminScreen.tsx:241-247`），可以给本人发提醒，模板是「周复盘没写进本体」。跳过的对象算成功 |
| 代 CEO 确认周期目标 | 看不到 | 台账失败行（`world_confirm_period_goal`）。CEO 映射不到本体主体时在写入前就抛错（`worldPeriodGoals.ts:46`），只有日志 |
| 旧的整场会议事件 | — | `admin.ts:141-145` 还在读 `world_meeting_events`，但这张表已经不写了，是一个死口径 |

- 管理员视图里，「卡住的会议」计数恒为 0，是占位（`admin.ts:204`）。设计 §10 的「会议链路」区、「本体同步」区（契约版本对不上、重试队列）、「本体凭证」一列都还没做。
