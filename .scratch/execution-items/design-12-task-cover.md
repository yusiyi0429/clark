## 1. 一句话

执行事项详情页改成这件事的「封面」：上面是它属于哪项个人任务、标题、截止和参与人；下面三块——**完成标准**、**正在推进**（放进来的文件和链接）、**执行过程**（进展，默认折叠）。状态跟着推进人的动作自动走，完成只能经推进人**验收**。完成后封面换成完成记录：验收记录和结论、交付结果、逐条打勾的完成标准。

## 2. 页面结构

### 2.1 页头（`DetailFrame`，沿用 9/29 定的平铺页头）

一行从左到右：返回 · 眉题「执行事项」· 标题 · **状态** · **材料下拉** · **验收** · **⋯**。

| 位置 | 内容 |
|-|-|
| 状态 | 点 + 字，和任务卡页「● 审核中」同一种写法。未启动：空心灰圈；进行中：蓝点蓝字；有待验收的提交时：推进人看到「等你验收」，协作者看到「待验收」（同进行中的颜色）；完成：`--confirmed`；已退回：judgment 色。手机只留点。 |
| 材料下拉 | 现有 `MaterialMenu`。第一项「封面」（原「事项」改名），见 2.2。 |
| 验收 | 只给推进人；没完成就一直在，未启动也能验收（完成不一定要留下文件，比如「和明华确认方向」）。平时是和材料下拉同款的 32px 低调按钮；有待验收的提交时变成实心主按钮，和任务卡页「确认我的任务」一样。完成后不显示。 |
| ⋯ | 只给推进人：编辑（原页头「编辑」挪进来）、退回（会后分派的才有）、删除（未启动的自建或计划事项，沿用现有条件）、重新打开（完成后）。 |

### 2.2 材料下拉

- 列表：封面 → 各份材料（按放进来的先后）→ 细线 → 上传文件 / 粘贴链接 / 起草文档（原来一项「添加材料」拆成三项；权限同上传，推进人和协作者都有）。会议、议题的材料区不变，仍是一项「添加材料」。
- 每项前面的图标：文档 `FileText`，链接 `Link2`。右侧小字沿用 `hint`：链接写域名；Co-Agent 正在按批注修改的那份写「在改」并带脉冲点。
- 完成后：验收时选为交付结果的排在前面，其余排在一条细线和小字「参考材料」后面（同一张单子，不另做层级）。
- 点封面上的卡片和在下拉里选是同一个动作：左侧阅读区换成那一份，页头下拉显示它的名字。回封面：下拉选「封面」。不在页头下面另起页签。

### 2.3 封面正文

沿用 `task-detail.module.css` 的 `.taskPane` / `.pane` / `.paneBlock`（720 宽，块之间是现有的细线和间距，块标题 13px 600 灰）。

**身份区**（第一块）
- 推进人：所属个人任务链接（现有 `longLink`）；协作者看到的是纯文字（个人任务页协作者打不开，点了会 404）。没有个人任务时是现有徽标「会后分派 · {会名}」或「独立事项」。
- 下一行灰字：`{战场名，没有写「未关联战场」} · 你在推进`（协作者看到 `{推进人}在推进`）。**删掉「第 n 步，共 m 步」和「等上一步：…」。**
- 已退回的，再下一行 judgment 色「已退回：{原因}」。
- 标题 24px / 600。右侧「让 Agent 推进」：secondary 胶囊、天枢标志在前，禁用，悬停和聚焦时提示「Agent 执行接入后可用」。
- 下一行：`{M 月 D 日}前完成`（没有截止写「截止日期待定」）· 有计划开始日的写 `计划 {M 月 D 日}开始` · `参与：{名字}`；推进人后面有现有的「邀请协作」。

**完成标准**
- 用现有 `doneDefinition`，按换行拆成多条（去掉空行和行首的 `-`、`*`、`·`、`•`、`1.`、`1、`、`(1)` 这类记号），每条前一个空心圆。不改字段，最长 500 字不变。
- 没写时：推进人看到「还没写完成标准，验收时会逐条对照。」加一个「写完成标准」（打开编辑）；协作者只看到「还没写完成标准。」

**正在推进**
- 标题后面写份数。网格 `repeat(auto-fill, minmax(min(190px, 100%), 1fr))`，间距 12。
- 一份一张卡：上半是按格式画的示意（文档几行线、PDF 一块图加线、HTML 一个标签框、链接一个小浏览器框），**不生成真缩略图**；左上角小标签写格式（Markdown / Word / PDF / HTML / 链接 · 域名）。下半：名称；一行来源——`{谁} 上传 · {时间}`、`{谁} 放进来 · {时间}`（链接）、`Agent 按{谁}的要求写 · {时间}`（`origin=agent`，和阅读页现有写法一致）；Co-Agent 正在按批注改这份时，这一行换成蓝字「Co-Agent 正在按批注修改」带脉冲点，卡片描边换浅蓝。
- 网格最后一张「添加」卡，点开是同样三项（上传文件 / 粘贴链接 / 起草文档）。一份材料都没有时，换成三张入口卡：上传文件（PDF、Word、Markdown、HTML）/ 粘贴链接（Claude、Figma、飞书里做的东西）/ 起草文档（说要写什么，我的 Agent 写成文档），下面一行灰字「文件也可以直接拖进这一页。」
- 整页可拖入文件。焦点不在输入框时，在页面里粘贴一个 http(s) 链接 = 粘贴链接。

**执行过程**
- 有进展、推进人的判断、会议原话三样里任一样时出现，默认折叠成一行（首页「已完成」折叠行同款样式）：`执行过程 · N 条进展 · 最近：{一句}`。展开后：会议原话（标「会议原话」）、推进人的判断（标「推进人的判断」）置顶，然后是现有进展列表（来源徽标：网页 / Codex / Claude Code / GitHub / 外部工具），最后「写一条进展」。
- 三样都没有时不出现这一块，只留一行「＋ 写一条进展」（推进人和协作者都有，进展的写入权限不变），点了就地展开输入框。进展是本体每周拉取（工单 13）和月度复盘起草读的数据，入口不能没有。
- 原「这件事的判断」不再单独成块，推进人在 ⋯ → 编辑里写。「我的批注」（协作者私人批注）界面去掉，数据保留。

### 2.4 完成后的封面

- 身份区最下面加「验收记录」：底 `--confirmed-wash`，圆角 16。第一行「✓ 已验收」（`--confirmed`）+ `{验收人} · {M 月 D 日 HH:mm} · 比计划早 N 天 / 晚 N 天 / 按期完成`（没截止日期就不写最后一段）；第二行是一句结论（没写就不显示）。
- 交付结果：验收时选中的第一份是大卡（示意 + 名称 + 一行 `{格式} · {谁} · {M 月 D 日}` + 「打开」），其余一行一份。一份都没选就不出这一块。
- 完成标准：达到的条目是实心勾（`--confirmed`），右侧是依据（指向材料的可以点开）；没达到的照实显示空心圈。标题后写 `N / M`。
- 执行过程照旧。参考材料仍在页头下拉里。
- 10/8 之前就完成、没有验收记录的老事项：不出验收记录，完成标准照常列出、不打勾也不写 `N / M`，材料不分交付和参考。
- 右列、输入条不变。

### 2.5 手机（≤959）

同一套结构单列排。页头只留返回、标题、状态点、材料下拉（只剩图标）、⋯；推进人的「验收」放在 ⋯ 的第一项（点通知里的「等你验收」直接打开验收）。入口卡三张一排。遵守仓库已有的手持字号下限（标签、角标 13px，说明性的辅助字 14px，见 `task-detail.module.css` 末尾）。验收弹窗在手机上占满宽度。

## 3. 状态规则

1. 去掉手动报进度：详情页的「报进度」三连按钮、首页卡片底部的三个状态按钮、首页「已完成」里的「改回进行中」都删掉。
2. **未启动 → 进行中只认推进人的动作**：推进人本人（含他连的外部工具、他让 Agent 做的事）第一次做下面任一件时，在 API 里自动发生：放进材料（上传 / 链接 / 让 Agent 起草）；写进展；外部工具提交验收；Co-Agent 按他的批注或对话要求改了材料。协作者做同样的事照常记录、照常显示，但不改状态。「进度只认推进人自报」这条规则不变，推进人的动作本身就是自报。
3. → 完成：只能走验收接口（§4），只有推进人能调。PATCH 的 `status` 不再接受 `done`（返回 400）。
4. 「等你验收」不是新状态：`tasks` 上加 `submission`（谁、从哪个工具、何时、可选的结论 / 逐条判断 / 建议的交付结果）。有 submission 且未完成时，页头显示「等你验收 / 待验收」，验收按钮变实心，推进人收到通知（§7）。
5. 完成 → 重新打开：⋯ 菜单，状态回进行中，清掉验收记录。
6. 退回不变。`TaskStatus` 枚举不变——本体每周拉进展（工单 13）读的就是它。
7. **进展里不写系统记录**：进展只放人和工具写的真实进展。验收、重新打开、外部工具提交验收这三件事，改为由 Co-Agent 在事项群组里说一句（「{推进人}验收了这件事：{结论}」「{推进人}重新打开了这件事」「{推进人}用 {工具} 提交了验收」），协作者也看得到。

## 4. 验收

- 入口：页头「验收」（手机在 ⋯ 里）→ 弹窗，和「连接到外部工具」同一个 `MenuDialog`（宽 560）。点通知里的「等你验收」直接打开封面并弹出它。
- 标题「验收「{事项名}」」，一句说明「你确认之后，这件事才算完成。」（有 Agent 草稿时前面加「Agent 对照完成标准逐条查过了。」）。
- **对照完成标准**：每条一个复选框，下面一行灰字「依据：…」（指向材料的可点，点了关弹窗、打开那份）。标题右边写 `N / M 达到`。没写完成标准时这一块只有一句「没写完成标准，按交付结果和结论验收。」
- **交付结果**：这件事的全部材料，两列复选，说明「没选的作为参考材料留下」。可以一份都不选。没有材料时不出这一块。
- **一句结论**：文本框，最多 200 字，可空。
- 按钮：「验收完成」（主按钮）；有待验收的提交时左边还有「还要继续做」（清掉这次提交、关弹窗）。右上角 × 和 Esc 只关弹窗，不清任何东西。未全勾也能验收，记录如实写 `N / M`。
- **Agent 草稿**：打开弹窗时，提交里带了草稿就直接预填；没有就请我的 Agent 起草（`POST /api/me/tasks/{id}/acceptance-draft`，只读：看完成标准、材料正文摘录和最近进展），给出每条是否达到和依据、一句结论、建议的交付结果。等待时三块里显示「我的 Agent 在对照完成标准」+ 脉冲点；失败或 30 秒没回就留空，手填照样能验收。草稿只是预填（勾选、依据、结论），由人改完再点「验收完成」。
- 接口：`POST /api/me/tasks/{id}/accept`，body `{ version, verdict, standards: [{ index, met, evidence, materialId }], deliverableMaterialIds }`；标准的文字由服务端按当前 `doneDefinition` 拆出来存快照；交付结果必须是这件事现有的材料；版本冲突 409 并带 `latestTask`（同 PATCH）。成功后：状态完成、写验收记录、清掉 submission、这件事的「等你验收」通知标为已读、群里 Co-Agent 说一句；页面派发 `member-tasks-changed`，首页卡片进「已完成」折叠组。
- 「还要继续做」：`DELETE /api/me/tasks/{id}/submission?version=`。重新打开：`POST /api/me/tasks/{id}/reopen { version }`。
- 存储：`tasks.acceptance jsonb`（acceptedBy、acceptedAt、verdict、standards 快照、deliverableMaterialIds）、`tasks.submission jsonb`。重新打开时清空验收记录，不留历史（群里那句就是记录）。

## 5. 材料：链接与起草

- `MaterialFormat` 加 `link`；`object_materials` 加 `url`。`MaterialView` 加 `url`（仅链接）和 `working: boolean`（这份材料有排队中或正在改的批注修改）。改契约后重新生成客户端。
- `POST /api/materials/task/{id}/links`，body `{ url, title? }`。只对执行事项开放（会议、议题返回 400）。只收 http / https，最长 2000 字符。没给标题时用「域名 + 路径最后一段」。**不去抓外部页面**（不取标题、不截图）。权限同上传：群成员都能加，只有放的人能删，计入 30 份上限。
- 阅读区打开一条链接：不嵌 iframe。显示标题、域名、谁放的、何时、「打开 ↗」（新标签页，`rel="noopener noreferrer"`）。
- 链接没有文件：`/file`、`/preview` 返回 404；不能写批注；Co-Agent 不能改；Pi 的 `list_materials` / `read_material` 给出地址和标题（不抓内容）。
- 起草文档：打开右列「我的 Agent」，输入条预填「帮我在这件事里起草一份：」并聚焦（输入条里已有草稿就不覆盖）。沿用现有 `create_material`，不做空白编辑器。
- 上传格式和大小不变（PDF、Word、Markdown、HTML，20 MB）。

## 8. 暂不做：让 Agent 推进

现在按钮只禁用。等 TokenHub 的执行 Agent 接入时，界面按画布第二行做，Agent 需要满足下面的约定（可以直接给 TokenHub 当需求）：

1. 读事项：同 `get_item`。
2. 写进展、加材料、改材料：沿用现有进展、`add_link`、`create_material`、`edit_material` 的权限与留痕。
3. 问人（「需要你」）：一个问题，2–4 个选项，每个选项可附一段可复制或可预览的内容，允许「其他」自由回答，可以「稍后再说」。问的同时不阻塞不受影响的工作。
4. 提交验收：同 `submit_for_acceptance`。完成仍只能由人验收。
5. 运行状态：想思路 / 推进中 / 等你回答 / 已提交验收，供页头状态和「推进思路」页显示。
6. 收回：推进人随时停止，Agent 停止写入。

界面（接入时再实现）：页头状态可点，打开「推进思路」页（复用会议页 `HeaderMaterialToggle` 的做法）；「需要你」是阅读区底部弹出的框，左边选项、右边内容；封面上多一行「正在做什么」，完成标准每条右侧写进度；身份区的按钮变成「收回，我来推进」。

## 9. 验收标准

1. 新建执行事项后打开的是封面：身份区、完成标准、三张入口卡和一行「＋ 写一条进展」；页头下拉只有「封面」和三个添加项；页头有低调的「验收」。
2. 推进人上传一份 Markdown：状态自动变「进行中」，网格出现这张卡，页头下拉多出这一份；点卡和在下拉里选打开的是同一份。协作者上传：状态不变。
3. 粘贴 `https://claude.ai/...`：出现链接卡（标签「链接 · claude.ai」），阅读区打开它是链接页，不是 iframe。`javascript:` 之类的地址被拒。
4. 批注被采用、Co-Agent 在改时，卡片和下拉里都显示「在改」脉冲点；改完消失。
5. 封面、首页卡片、本月计划、任务卡关联事项上都不再出现「第 n 步」「等上一步」和状态按钮。
6. 只有推进人看到「验收」；PATCH `status: done` 被拒（400）。验收后：状态「完成」，封面换成完成记录，首页卡片进已完成组，群里有 Co-Agent 那一句。
7. 验收弹窗在 Agent 草稿失败时仍可手动完成；未全勾时记录如实写 `N / M`；× 不清提交，「还要继续做」清掉提交、页头回到「进行中」。
8. MCP：`update_status(done)` 只提交验收、不完成；`submit_for_acceptance` 让页头显示「等你验收」并通知推进人，协作者调用被拒；`add_link` 的链接出现在封面上。
9. 重新打开后状态回「进行中」，群里有这一句；没有验收记录的老完成事项正常显示。
10. 执行过程三样都没有时只有「＋ 写一条进展」；有内容时默认折叠。
11. 390 / 834 / 1440 宽各走一遍：新建、上传、粘贴链接、验收、完成后的封面。

## 13. 实现时定下的细节（2026-10-08，分支 `feat/task-cover`）

1. **通知不放「去验收」按钮**：通知栏卡片上的按钮是「处理掉」用的（知道了、接下），这条要验收完或点「还要继续做」才算处理，放按钮会让人以为点了就办完了。点通知本身就打开封面并弹出验收（地址带 `?accept=1`，打开后去掉，刷新不再弹）。上面 §2.5、§4、§7 说的「去验收」就是点这条通知。
2. **新手引导一起改**：工作台示意图（`WorkspaceSchematic`）里的执行事项卡原来写「第 1 步，共 3 步」「等上一步」，改成「进行中」「等你验收」；执行事项演示里「所属个人任务」后面的「· 第 2 步」和落地卡片上的「第 2 步，共 3 步」也去掉（§11 第 2 条的连带）。
3. **每周同步**：同步指令和 `claude -p` 放行的工具不再写 `update_status`，换成 `add_link`、`submit_for_acceptance`。已经按旧指令设好的定时任务照常能跑——旧指令里的 `update_status(done)` 现在就是提交验收。
4. **老的已完成事项没写完成标准时**，完成标准这一块不出（「还没写完成标准，验收时会逐条对照」对已完成的事不成立）。
5. **上传**：执行事项可以一次选几份、整页拖几份，按顺序一份一份传；中途有一份失败时，前面传成的照样列出来，并提示失败那份的原因。
6. **验收弹窗**：外部工具带来的草稿一打开就是预填好的；交付结果按材料 id 记，从通知直接打开、材料还没读到时也不丢；人先动了手，Agent 的草稿晚到不覆盖；验收或「还要继续做」之后先换上最新的事项再关弹窗，封面不会先闪一下半新不旧的样子。复选框按 HeroUI 的结构写（`Checkbox.Content` 包住复选框和文字，整行可点）。
7. **手机（≤959）**：材料下拉只剩图标；正在推进的卡两列一排；交付大卡收成一行（小示意、名称和元数据、右边「打开」），同画布「手机 · 完成后」。
8. **⋯ 下拉单**比材料下拉窄（最小 180px），只有一两项时不显得空。
9. **退回时清掉提交**：外部工具提交过验收、推进人又把会后分派的事退回了，提交一并清掉，「等你验收」通知标为已读（否则首页卡片会对一件已退回的事写「等你验收」，通知也永远消不掉）。
10. **外部工具拿到最新版本**：推进人自己的工具写进展、放链接会让未启动的事项变进行中，版本跟着变；`append_progress`、`add_link` 的结果里加一个 `item`（事项此刻的 status 和 version），接着提交验收直接用它，不撞版本。旧指令里先写进展再 `update_status(done)` 的，撞了版本会拿到 `currentVersion`，重试即可。
11. **「在改」会自己消失**：有材料正在按批注改、阅读区又没开着时，每 5 秒重读一次材料清单；改完或没改成，卡片和下拉单上的「在改」就消失。
12. **同一页再点通知也弹出验收**；**编辑表单只交这次改过的字段**（和打开表单时比），别处同时改的其他字段不会被盖回去。
