## 1. 一句话结论

**新建后详情页的重心是一张「下一步卡」。卡里只放两样东西：状态，和此刻唯一该做的事。刚建完时这件事是「开始推进」，进行中时是「记下」一条进展。其余事实各有固定位置，没填的就不显示。**

为什么这样定：执行事项是在天枢外面做的，来天枢只为了如实自报和同步进展（SSOT DRI-01）。所以刚建完的那一刻，页面本身就是回执：刚才三步填的内容整理成几行，可以一眼核对。这时在天枢里唯一有意义的动作，就是自报「开始了」。新建流程里开始日默认今天，正是为这一步准备的。

## 2. 刚创建那一刻（推进人 · 未启动 · 还没有判断和进展）

以截图里那件事为例：挂在 Mission 下，排第 4 步，共 4 步；上一步还没完成；开始日是今天；截止选了「还没想好」；完成时留下「一份文档」；还没有协作者。

### 2.1 工作站（≥960）中栏，自上而下

| # | 区块 | 确切文案 | 规则 |
|---|---|---|---|
| 0 | 页头胶囊（结构不变） | `←` · 眉题 `执行事项` · 标题 `你好` …… 右侧 `📄 事项 ▾` · `编辑` | 「编辑」改成打开弹窗，不再在页面里原地展开 |
| 1 | 归属行 | `让跨人员交接有可核对的完成标准 ↗` | 沿用现有 longLink 样式，点开 Mission 页。独立事项显示徽标 `独立事项`；会后分派显示徽标 `会后分派 · {会议名}`。**这一行不再放状态徽标** |
| 2 | 附注行（paneNote 灰） | `第 4 步，共 4 步 · 等上一步：发布清单并复盘遗漏项` | 写法与概念版一致：第几步和等上一步合成一行。上一步的标题可以点，点了打开那一步。没有在等的上一步时只写「第 n 步，共 m 步」；独立事项没有这一行。不写战场名，也不写「你在推进」 |
| 3 | 元信息行（paneNote） | `今天开始 · 截止待定 · ＋ 邀请协作` | 日期只出现在这一行，任何状态下都不挪位置。开始日不是今天时写 `{M} 月 {D} 日开始`，有截止时写 `{M} 月 {D} 日前完成`。「＋ 邀请协作」是幽灵按钮，打开现有的 CollaboratorsDialog。日期本身不能点，要改走「编辑」 |
| 4 | **下一步卡** | 左：`● 未启动 ▾`；右：`开始推进` | 整页唯一的实心品牌蓝按钮。状态胶囊点开是菜单（未启动 / 进行中 / 完成），aria-label 保留「报进度」。卡里没有标题，也没有说明文字 |
| 5 | 完成时留下 | `完成时留下　一份文档` | 灰色小标签后面直接接正文，正文长了自然换行。没填就整行不显示，要补走「编辑」 |
| 6 | 判断入口 | `＋ 写下这件事的判断` | 一行幽灵按钮。点了在原地变成输入框，占位 `一句话结论，别人打开先看到这句`，配 `保存` / `取消` |
| 7 | 进展入口 | `＋ 写一条进展` | 一行幽灵按钮。点了在原地展开输入框，占位 `做了什么，下一步或卡在哪`，配 `记下` / `取消` |

**下一步卡在三种情况下的变化**
- 开始日在将来：右边换成次级按钮 `提前开始`。此刻没有该做的事，所以不放蓝色主按钮。
- 开始日已经过了，或者根本没填开始日：仍然是 `开始推进`，不标红，也不催。
- 会后分派：`开始推进` 旁边多一个次级按钮 `退回`，见 §3.4。

**此刻隐藏**
- 「报进度」整块：标题、说明「进度只认推进人自报…」和三段按钮。
- 判断块里的只读段、分隔线、常驻的输入框和保存按钮。
- 「还没写过。写下来之后…」「还没有进展。可以在这里写…」「还没有写完成定义。」这几句空状态。
- 「团队协作 · 你在推进」「参与：王路遥」，以及单独一行的「计划开始 10 月 4 日」。
- 页底的「删除执行事项」（挪进编辑弹窗）、页底的「会议来源」块，以及页底的报错和成功提示条。

**主要动作**：`开始推进` 发 PATCH `status=in_progress`。只能本人点，不会因为到了开始日就自动触发。点错了可以从胶囊菜单改回。

**视觉**
- 不新增任何 token。下一步卡用 ts-design 现有的玻璃面和圆角。
- 实测时如果卡片和页头胶囊放在同一屏显得太重，就去掉底色，退成上下留白的一行。
- 块与块之间改用留白隔开，不再画分隔线。
- 首屏只有 8 行左右，1440×900 下全部落在折叠线以上。

### 2.2 右栏（工作站）此刻

- 「我的 Agent」：页头、正中的 `暂无消息`、输入条 `问你的 Agent…` 和频道切换 `[我的 Agent] [事项群组 · 1]`，**全部不变**。依据 SSOT C-02：空态只写「暂无消息」，不放说明，也不放按钮。
- 事项群组：建事项时 API 已经写好一条 Co-Agent 开场，并把推进人标成已读，所以没有未读角标，不弹胶囊，也不自动切过去。
- 右栏底部脚注要不要缩短，见 §8 决定 4。

## 3. 状态演进（只写和「刚创建」相比变了什么）

**总规则**：下一步卡永远只放「状态 + 此刻该做的那一件事」。日期在元信息行，判断在判断块，进展在进展块，这三样的位置任何状态下都不变。

### 3.1 进行中（推进人点了「开始推进」之后）

**下一步卡**
- 状态胶囊变成 `● 进行中 ▾`。
- 卡里变成写进展的输入框，占位 `做了什么，下一步或卡在哪`。工作站上 2 行起、随内容长高；手持上默认单行，聚焦后展开。
- 卡底左边是次级按钮 `完成了`：点了直接报为完成，不弹确认，可以改回。右边是主按钮 `记下`，有字才能点。⌘/Ctrl+Enter 也能提交。

**记下之后**
- 输入框清空，按钮旁显示 `已记下`，2 秒后消失。
- 新条目出现在下面「进展」时间线的最上方。写第一条时，「进展」小标题才出现。

**进展块**
- 不再显示「＋ 写一条进展」，因为卡里已经是入口，避免一页出现两个进展输入框。

### 3.2 写了判断 / 有了进展

**判断块**
- 显示小标题 `这件事的判断`、正文，和一行 `你写于 {时间} · 修改`。
- 点「修改」，同一个位置变成输入框，原文预填进去。同一句话不会出现两次。
- 失焦时不自动保存。判断是别人都能看到的结论，不能误存出去。

**进展块**
- 小标题 `进展`；不在进行中时，标题右侧有 `＋ 写一条进展`。
- 时间线最新的在上。每条的样式沿用现有：来源角标（网页 / Codex / Claude Code / GitHub / 外部工具）、作者、时间、正文、证据链接。

**未启动但已经有进展**（比如外部 Agent 先通过 MCP 写了一条）
- 下一步卡仍是 `开始推进`。
- 进展块照常显示小标题、「＋ 写一条进展」和时间线。

### 3.3 完成

**下一步卡**
- 状态胶囊变成 `● 完成 ▾`，用 success 色。卡里没有按钮，想改回去用胶囊菜单。

**判断块**
- 还没写判断：入口升级成主按钮 `写下这件事的判断`，是此刻全页唯一的实心蓝按钮。点开就是 §2 里那个编辑器，位置不挪进卡里。完成时向上回传的就是这句判断。
- 已经写过：只是展示态，页面上没有主按钮。

**进展块**
- 恢复 `＋ 写一条进展`，完成后还能补证据。
- 不放庆祝，也不放总结。

### 3.4 会后分派与退回

**会后分派（推进人，未退回）**
- 归属行是徽标 `会后分派 · {会议名}`。
- 归属行正下方是引用块 `「{原话}」`，没有原话就不显示。原话就是这件事的「为什么」，所以任何状态下都固定放在这里，页底的「会议来源」块取消。
- 会后分派没有开始日，元信息行是 `{M} 月 {D} 日前完成 · ＋ 邀请协作`。
- 未启动时，下一步卡是 `● 未启动 ▾` · `开始推进`，旁边加一个次级按钮 `退回`。接下还是退回，正是此刻要做的决定，和首页通知上「接下」「退回」并列的做法一致。
- 其他还没退回的状态：胶囊菜单多一项 `退回…`。
- 退回弹窗沿用概念版 TaskActions 的写法：标题 `退回会后分派`，字段 `退回原因`，按钮 `取消` / `确认退回`（填了原因才能点）。一步走完，去掉现在「行内表单 + 二次确认」的两步。
- 编辑弹窗里仍然没有删除，规则不变。
- 语义要说清楚：对会后分派来说，点 `开始推进` 就等于接下并开始。之后 CEO 撤不回，因为 `deleteDispatchedTask` 要求事项处于未启动。不另加确认，交付说明里写明。

**已退回**
- 下一步卡只有一行 `已退回：{原因}`，info 色，没有 ▾，也没有按钮。文案和首页卡片（`MemberTasks.tsx:55`）一致。
- 页头不显示 `编辑`；判断没有「修改」；进展块没有「＋」入口，已有条目照常只读显示。
- **已知限制**：这里的只读只是前端不给入口。API 带 status 的 PATCH 会把 `return_reason` 清空（`apps/api/src/tasks.ts:189`），MCP 的 `update_status` 也能把事项改回去。这个问题现在就存在，另立工单（见 §7 A2），本次不扩范围。

### 3.5 协作者视角

| 区块 | 和推进人相比 |
|---|---|
| 页头 | 没有 `编辑` |
| 归属行 | Mission 名显示成纯文字，不跳转：协作者通常不在 Mission 页的可见范围内，点了会 404。后面跟只读状态徽标，比如 `进行中`，没有 ▾ |
| 附注行 | `王路遥在推进 · 第 4 步，共 4 步 · 等上一步：{标题}`，上一步的标题不能点 |
| 元信息行 | `10 月 4 日开始 · 截止待定 · 协作：你、李四`，没有邀请入口 |
| 下一步卡 | **不显示**。状态只读，「进度只认推进人自报」这条规则靠协作者看不到控件来体现，不写说明，也不靠悬停 |
| 判断 | 推进人写过才显示：`这件事的判断`、正文、`王路遥写于 {时间}`；没写过就整块不显示 |
| 我的批注 | `＋ 我的批注`。展开后输入框旁边有轻提示 `仅你可见`；写过以后显示 `我的批注`、正文和 `仅你可见 · {时间} · 修改` |
| 进展 | 一行 `＋ 写一条进展`，下面是时间线。保留这项已经上线的能力，见 §8 决定 3 |
| 右栏 | 不变，默认停在「我的 Agent」 |

## 6. 与概念版 TaskPane 的差异及处理建议

对照的是 `clark-main/src/components/dri/panes.tsx:196` 的 TaskPane 和 `task-controls.tsx` 的 TaskActions。

**偏离**
1. 删掉「报进度」块（说明加三段按钮），换成下一步卡：状态胶囊菜单加一个随状态变化的主动作。

3. 空字段不显示，或者只留一行「＋」，不再用「尚未填写 / 还没写过」这类句子。

6. 会议原话从页底挪到页首。
7. 已退回时整页只读：隐藏编辑、进展入口和判断的「修改」。
8. 概念版本来就有、天枢一直没移植的「提出方案 / 等你点头的方案」，这次继续不做。

**处理建议**：作为「概念页整体照搬」的一次明确例外，在本文档里留档，写清只动区块结构和文案，不动视觉语言。理由有三：
- 概念版本身没有「刚建完」这个状态，`monthly.tsx:70` 建完同样直接打开 TaskPane。它是给稳定期设计的演示面板，所有表单常开，就是为了演示「这里能写」。
- 截图里的问题（9 个区块、2 个空输入框、3 个「保存」、主动作压在折叠线附近）根源就在平铺结构，对齐概念版治不好。
- 天枢自己加的计划开始、进展、材料、会议来源，又在这个结构上继续往下叠。

## 8. 需要你拍板的决定

**决定 1　同不同意偏离概念版 TaskPane 的区块结构？**
- 范围就是 §6 列的 8 条偏离：去掉报进度块、判断不并排两份、空字段不显示、编辑走弹窗、删除收进弹窗、会议原话挪到页首、已退回只读、推进人不显示战场和「你在推进」。视觉 token 一律不动。
- **推荐：同意。** 截图里「一整页表单、没有重心」就是平铺结构的必然结果，概念版自己也没有「刚建完」状态。不同意的话，只能退回到「删说明、去重复」的微调，主动作仍然压在折叠线附近。

**决定 2　点完「开启执行事项」，还要再点一次「开始推进」吗？**
- A（**推荐**）：保持手动。
- B：第 ③ 步开始选了「今天」时，「开启执行事项」直接把状态报为进行中，需要做 §7 的 A1。
- 推荐 A 的理由：
  - 「开始默认今天」是新建表单替人填的默认值，不是推进人的自报，B 会把默认值当成自报（违背 SSOT C-04）。
  - 多点的这一下可以撤回，而且是这件事在首页、Mission 页、拍板人个人卡上第一条真实的信号。
  - 对会后分派来说，「开始推进」还意味着接下，不能代替用户点。

**决定 3　协作者能不能在页面上写进展？**
- A（**推荐**）：保留一行次级的 `＋ 写一条进展`，同时把 `CONTEXT.md` 执行事项词条里「协作者只在事项群组里说话」改成「协作者能写进展和私有批注，不能改状态」。
- B：隐藏。
- 推荐 A 的理由：D06 第 100、138 行，现有的 `appendTaskProgress`（只校验能不能读到这件事），MCP `append_progress` 描述里的「我推进或协作的事项」，以及 CLAUDE.md 的「同步本周进展」，都允许协作者写进展。只把网页入口藏起来，页面和外部工具的行为就不一致了，等于回退一项已经上线的能力。改 CONTEXT.md 要你确认。

**决定 4　右栏脚注要不要缩短？**
- A（**推荐**）：只把事项页缩成 `仅你可见`，议题页不动。
- B：两个页面都不改。
- C：议题页一起改。
- 推荐 A 的理由：
  - 现在这句长达 30 个字，是写给刚建完的人看的规则说明，和你要的「文案极简」冲突。
  - 用「仅你可见」，和其他所有脚注的前缀一致；SSOT C-02 原文写的是「仅自己可见」，你也可以选这个。

## 9. 评审中被否决的思路

- 「我的 Agent」在右栏用规则生成一句开场，再配几颗建议胶囊（agent-led）：违反 SSOT C-02 的「空态只写暂无消息，不放标题、说明和按钮」和 C-03 的「我的 Agent 只做问答」。而且那句话是规则拼出来的，却以 Agent 的名义出现，会让人误以为是模型在说话。
- 手持端在输入条上方加一排横滑建议：又多一个浮动元素，增加噪音，消融检查时第一个就会被拿掉。
- 「起草判断」之后点「填入判断」：依赖模型恰好只回一句话，状态只存在内存里，刷新就丢。
- 「列个做法」「写完成小结」这类建议：刚建完就推人做计划，接近项目管理那一套；而且依赖 Agent 真的去调 `create_material`，没有实测过。
- 到达时弹 toast「已开启」，之后每个动作都弹 toast：页面本身就是回执，DRI-05a 有不显示回执的先例。成功只在按钮旁边轻提示。
- 邀请成功后自动切到事项群组：`open-thread-channel` 的处理函数会把右列展开，违反「系统不自动展开右列」。
- 协作者打开页面时右栏默认切到事项群组：超出这次「新建后页面」的范围，还要改 DetailGroup 和 ConversationHost。现有的邀请通知打开时走的是 `openTask`，也不带 `?channel=group`。
- 整页就地编辑，鼠标移上去显浅蓝底（calm-brief）：每一行都像能编辑，和「安静」冲突；触屏上不好发现；多个字段各自保存，409 会更频繁，丢稿风险高。
- DetailFrame 支持就地改标题：所有二级页共用这个页头，牵连面太大。
- 战场名统一加「战场」后缀：是不必要的字符串特判，直接不显示更简单。
- 用「⋯」替掉「编辑」，把换 Mission、退回藏进菜单：入口难找。会后分派「接下还是退回」正是此刻要做的决定，不该藏起来。
- 把战场名或「进度只认推进人自报」放进悬停提示：手持上没有悬停，信息等于消失。
- 完成状态下把判断输入框挪进下一步卡、截止日期在卡和元信息行之间来回挪：同一样东西随状态换位置，读起来不可预期。
- 未启动且没有进展时把整个进展区藏起来：想先记一笔准备工作，就得先把状态报成进行中，违背如实自报。
- 隐藏协作者写进展的入口：回退已经上线的能力，页面会和 API、MCP、周同步不一致。
- 默认「开启即进行中」：表单的默认值不等于推进人自报，只作为决定 2 的备选。
- 协作者看到的 Mission 名保留 `↗` 跳转：协作者读不到推进人的 Mission 页，点了会 404。
- 连接提示对所有人显示：已经连上的人会看到无用的提示。要做就带上令牌判断，放到 L1 后做。
- 进展默认只显示最新 3 条、其余折叠：刚建完的页面没有这个问题，按 YAGNI 不做。
- 建事项后让我的 Agent 调模型主动说一段开场：要改 API、花 token、有延迟，也违反 C-02 和 C-03；刚建完的人要的是下一步，不是一段复述。
