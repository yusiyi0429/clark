# 会后确认：开完会到写进本体之前，人在哪里确认

人豪，这是 main 上已经做好的「会后确认」前端，截图来自本机演示环境。

- 用的是脱敏样例会议「co-agent 交互评审」：
  - CEO 周明远，主持人林晓；
  - 参会的有陈一凡、吴桐、许诺；郑可在名单上，但没有实际参会。
- 纪要抽取、分层、影响分析三步的模型输出，都是之前用真实模型跑出来的结果，这里原样回放。
- 演示环境没有连本体，也没有连飞书。

## 链路

1. 拉妙记，抽取纪要。
2. 分层 Agent 从纪要里挑出最多 5 条「会上定了 X」，交给主持人。
   - 改公司方向、LTO、PO，或者跨战场调资源的，算战略项，交给 CEO 确认，不会代判。
3. 主持人对每一条三选一：对 / 改一下 / 其实没定。
   - 散会当天提醒一次，下一个工作日 9:30 再提醒一次。
   - 满一个工作日还没确认，按 Agent 的推荐生效。
4. 每一条生效的决定，都要做影响分析：给受影响的人推一张影响卡，同时在本体里记一条事件。
5. 主持人之后改判，收过卡的人会收到更正卡，本体里记一条更正（correction）。

## 每屏看什么

每屏都有两张：1440 是电脑，390 是手机。

| 屏 | 谁看 | 对应哪一步 |
|---|---|---|
| 01 | 主持人首页 | 左栏「会上定了 3」：散会后推给主持人的待确认。每条写着截止时间，过了时间由 Agent 代判 |
| 02 | 主持人首页 | 在首页直接点「改一下」：展开改写框，在原说法上改 |
| 03 | 主持人会议页 | 「会上定了」：第 1 条是战略项，交给 CEO；其余几条由主持人三选一，Agent 推荐的选项高亮 |
| 04 | 主持人会议页 | 在会议页上「改一下」 |
| 05 | 主持人会议页 | 处理完以后的四种状态：CEO 已确认、已确认（可以改判）、Agent 代判（主持人还能三选一）、其实没定（划掉） |
| 06 | 受影响的人首页 | 左栏「影响 2」：会后推过来的卡 |
| 07 | 影响卡 | 主持人确认过的卡：卡面写影响、要做什么、截止日、落到哪个 Task 或验收项。点开「前因后果」能看到会上定了什么、谁拍板、原话、可以问谁 |
| 08 | 影响卡 | Agent 代判的卡，顶上标着「Agent 代判，Host 尚未确认」 |
| 09 | 影响卡 | 在卡上追问：本人的 Agent 结合这张卡和本人手上的事回答。问答留在卡上，不打扰拍板的人 |
| 10 | 影响卡 | 点了「和我无关」：卡收起，原因留下来作质量信号 |
| 11 | 主持人会议页 | 主持人改判：第 1 条的交稿日从 23 日改成 24 日，下面显示「原：…」 |
| 12 | 更正卡 | 收过卡的人收到「更正」，写清谁把什么改成了什么 |
| 13 | 旧卡 | 原来那张卡标上「已有更正」 |
| 14 | CEO 会议页 | 战略项由 CEO 确认 |

## 跟你那边相关的几处

- 01 和 03：分层 Agent 挑出来的几条对不对、推荐「对」还是「其实没定」，是取用和评测最直接的对象。
- 07、08、10：影响分析是不是落对了人、落对了 Task、验收项或 Mission。用户点的「和我无关」会记下来，可以当负样本。
- 05、08：代判之后，主持人仍然可以改；改了之后，收过卡的人会收到更正卡。

## 走查时看到的问题

- 手机 390 宽下，影响卡的页头没有状态胶囊。电脑上能看到「待处理」「和我无关」，手机上点完「和我无关」只能看出按钮没了（10-390）。
- 首页左栏「改一下」的输入框只有两行高，长一点的说法看不全（02-1440）。
- 卡上的落点是天枢里的 Task、验收项、Mission，不是本体对象。确认时也看不到这条会写进本体的哪个对象。这一点在回流盘点里单独展开。
- main 上的前端没有暗色主题：整站固定 `color-scheme: light`，模拟系统暗色也不会变。所以只截了亮色一套；手机端本身就是深色锁屏风格。
