# 天枢伙伴工作间 UI：已授权的实现设计

用户在2026-11-15要求按上一轮UI评审方向开始，循环改进直到达到标准，自主推进。长期目标仍为团队成员通过伙伴持续承接、协作、会议到交付的完整工作。

本阶段交付实际React内部版及可查看的界面对照。采用现有Next.js/React/TypeScript与设计token，不新增依赖。沿用已隔离工作树，在`codex/partner-ui-20261115`分支实现；原`a1f365a1`和v0源码归档保留。

## 方向与取舍

- 选择：清晰、平静的伙伴工作间。主对话承接工作事件，默认显示变化、进度和下一动作，复杂明细按需展开。
- 曾考虑仅统一颜色/圆角，无法解决结构问题，未选；另建独立工作中心会重复原对象和入口，未选。
- 这是依据用户授权作出的实现选择，不称为用户已认可具体视觉细节。

## 验收标准 v2（契约校正及最终评审补充）

1. 伙伴中的团队来件、已发生会议状态和已确认会议交接进入同一个WorkTimeline，具有稳定key与真实时间；未来预约保留独立折叠安排，不伪装已发生消息。
2. 团队卡首层显示来源、内容、逐人进展摘要和当前可做动作；历史往来默认收起，回复/附件、失败重试和原深链都可到达。收起不能隐藏需要本人回复的入口。
3. 会后变化先显示已确认内容与递送结果；来源/明细次级展开。已递送历史目标退出可选列表后仍能通过原对象路由查看，不恢复派活资格。
4. 运行、等待、验收返工分别汇总；现有failed契约表示重做，不计入实际运行数，也不改写为程序故障。需求排队显示真实已接收/待发送状态，重试或优先/撤回规则保持原意。
5. 沿用语义token、清晰主次按钮和一致卡片层级；新触控主操作最小44px目标，320px布局不能使用固定大宽度；暗色和减少动效遵从原主题。机械检查不冒充实机布局通过。
6. 现有类型检查、相关回归与新增行为检查通过；独立评审针对信息量、深链和状态更新找反例。主界面的真实截图、点击、手机和真人理解没有观察工具时保留未验，不以模型打分宣称“一线水平已达到”。
7. 独立事件在追加、空历史、时间状态切换与分桶变化中保留同一React父级/类型/key路径，避免整合主时间线引入表单状态丢失；元素树证据和真实浏览器生命周期分开记录。

## 模块边界

`usePartnerMeetingFeed()`返回`{blocks:TimedBlock[], notice:ReactNode, scheduled:ReactNode}`；只有非scheduled会议进入blocks，每个key为`partner-meeting:<id>`，时间用原item.at，明确是会议时间。旧PartnerMeetingInbox保留可用包装。

`useMeetingWorkHandoffFeed()`返回`{blocks:TimedBlock[], notice:ReactNode}`；每条已确认变化使用`meeting-handoff:<confirmationRef>`及confirmedAt。旧MeetingWorkHandoffs包装复用同hook，避免双请求与重复显示。

团队沿用`usePartnerTeam().blocks`，不新建数据入口。主会话将所有块、错误提示、未来安排及输入队列接入BuddyView。
