# Nexus → DRI 确认：本地回放步骤

在 worktree `.claude/worktrees/nexus-dri-receiver`（分支 `claude/nexus-dri-receiver`）的根目录下做。两种回放都只用本机：一次性测试库（54329 上的 Docker 容器 `tkos-preview-test-pg-54329`）、127.0.0.1 上的假接收端；不调模型、不发飞书、不写本体、不连外网。

第一次用先装依赖、编契约包：

```bash
pnpm install --frozen-lockfile
```

```bash
pnpm --filter @warmap/contracts build
```

## 一、对样例：一条命令回放一条请求正文（周三用这个）

1. 把溪南发来的请求正文（就是 POST 的那个 JSON 对象，不用改）存成文件，放到 `.scratch/nexus-dri/requests/` 下，比如 `.scratch/nexus-dri/requests/real-1.json`。这个目录和下面的 `out/` 都不进 git。
2. 跑一遍，第二个参数是本人的决定（`confirmed` 确认、`rejected` 拒绝、`amended` 修改，修改时第三个参数是改后的内容）：

```bash
node apps/api/node_modules/tsx/dist/cli.mjs .scratch/nexus-dri/replay-local.mts .scratch/nexus-dri/requests/real-1.json confirmed
```

```bash
node apps/api/node_modules/tsx/dist/cli.mjs .scratch/nexus-dri/replay-local.mts .scratch/nexus-dri/requests/real-1.json amended "改后的内容写在这里"
```

3. 屏幕上依次打印四步的结果，同时存成文件（路径会打印出来，缺省在 `.scratch/nexus-dri/out/<时间>/`，也可以加 `--out <目录>` 指定）：

| 文件 | 是什么 | 发给溪南核什么 |
|---|---|---|
| `receipt.json` | 接收回执，原样 | accepted、receiptId、tenantId、requestId、itemId、revision、fingerprint |
| `confirmation-record.json` | 确认记录，就是他按 confirmationRef 读回的那一份，原样 | 确认人、决定、确认时看到的问题和内容、确认时间、原请求指纹；修改时另有 amendedContent、amendedFingerprint |
| `callback-body.json` | 回调正文，发出去的原始字节 | 字段、callbackId、confirmationRef |
| `callback-headers.json` | 回调的三个头 | x-dri-timestamp、x-dri-signature（HMAC-SHA256 签「时间戳.原始正文」） |

要点：

- 租户、agentId、负责人都照请求正文里的值配，所以真实格式的正文不用改。负责人取 `proposedConfirmers` 的第一位。
- 「现在」缺省按请求的 `createdAt` 加一分钟算，过期的旧样例也能回放；要用真实时间加 `--at now`，要指定时刻加 `--at 2026-11-11T06:00:00.000Z`。确认时间、回调的时间戳都跟着这个「现在」。
- 签名密钥缺省用溪南公开合成样例里的样例密钥。要换成约好的联调密钥，先设环境变量 `NEXUS_DRI_CALLBACK_SECRET` 再跑（脚本不打印密钥）。
- 请求被拒时会打印 HTTP 状态和错误码。指纹对不上（`FINGERPRINT_MISMATCH`）时会把请求里的 fingerprint 和天枢算出来的并排打出来，直接发给溪南对规范化写法。
- 同一条请求想换一种决定再看，重跑一遍就行，每次都是新库。

自测过：`requests/sample.json`（样例包里的 request）跑 `amended`，四个文件都出来了。

## 二、在浏览器里看：时间机器加假接收端

给时间机器（verify-tianshu 技能用的那套）带上接收端的环境变量再启动，通知栏的「会后确认」里就能看到推来的待定事项。

1. 起假接收端（收到回调会验签并打印）。先设 `NEXUS_DRI_CALLBACK_SECRET`（本地用样例密钥就行），再：

```bash
node .scratch/nexus-dri/replay.mjs receiver 4391
```

2. 在同一个 PowerShell 窗口里设好下面几个环境变量，再启动时间机器：
   - `NEXUS_DRI_SERVICE_TOKEN`：本地随便定一个假值。
   - `NEXUS_DRI_TENANT_ID=synthetic-tenant`、`NEXUS_DRI_AGENT_ID=synthetic-dri-agent`（样例里的值）。
   - `NEXUS_DRI_CALLBACK_URL=http://127.0.0.1:4391/callbacks/dri`，`NEXUS_DRI_CALLBACK_SECRET` 和接收端用同一把。

```bash
pwsh -NoProfile -File ~/.claude/skills/verify-tianshu/scripts/verify.ps1 start
```

3. 推一条给孙铭泽（时间机器账号 `browsermember`，本体人员 ID 用仓库里实例配置的那个）。脚本把样例改成「现在创建、一小时后到期」并重算指纹；`NEXUS_DRI_SERVICE_TOKEN` 要和第 2 步一样：

```bash
node .scratch/nexus-dri/replay.mjs push http://127.0.0.1:4580 305ea98d-c0e7-4e3a-8746-1748f7fdcec0
```

4. 用 `browsermember` 登录 `http://127.0.0.1:3580`，通知栏「会后确认」里出现「待定事项」，点确认、拒绝或修改。几秒内假接收端的窗口打印收到的回调和 `signatureOk`。

注意：时间机器的应用时钟从 2026-10-01 起，确认时间和回调时间戳是那个时钟的；要拿给溪南核的东西用第一节的命令出。

## 三、接到本地自己起的 api 上

`apps/api` 读这几个环境变量（见 `docs/guides/environment.md`）：`NEXUS_DRI_SERVICE_TOKEN`、`NEXUS_DRI_TENANT_ID`（都设才开）、`NEXUS_DRI_AGENT_ID`（缺省 `tianshu-dri`）、`NEXUS_DRI_CALLBACK_URL`、`NEXUS_DRI_CALLBACK_SECRET`。人员对应用本体实例配置的 `people`（`TKOS_WORLD_INSTANCE_LOCAL_FILE` 指的文件会合并进来）。推请求照第二节第 3 步，把地址换成那个 api 的。
