# 天枢对话：分段、会话纪要与回看（设计，2026-10-28）

负责：会话管理归天枢这边（用户 10/28 定）。本文是讨论后的设计稿。摸底数据见主会话的 `requirements-doc-review-2500e1/.scratch/tianshu-v1/会话管理_摸底与设计_2026-10-28.md`（下称「摸底」），本文不重复。

## 0. 要解决什么

1. **越聊越重**：首页现在一人一视角一条永久的 Chat 对话。Chat 每轮把上次摘要之后的全部原文（≤8 万字符）重发给主模型，一轮 3–8 步，每步都重发；超过 8 万在首字前当场压缩。量现在还小，一号位一天聊 15–20 轮的话 8–10 天碰到上限。
2. **分段以后会失忆**：只按时间分段，「你记得前几天我跟你聊过 X 吗」就答不上。
3. **两边各记各的**：首页走 Chat 以后，问答不进天枢的消息表，天枢的历史检索看不到首页；对象页（会议、议题、执行事项、任务卡、复盘等）还走天枢自己的运行时，Chat 也看不到它们。

## 1. 原则

- **界面不分段，模型分段**：一号位看到的仍是一条连续的对话（不违背 02d「去掉会话」）。模型每轮只带当前这一段。这和天枢自己已有的「闲置 12 小时模型侧重开」是同一思路。
- **事实每轮重读**：首页卡、World、待办每轮都重新读，分段不丢事实。
- **旧事靠「纪要 + 回看」，不靠个人记忆**：个人记忆存「这个人是什么样的」（偏好、本人自述的背景和决定），每轮都带、可逐条纠正遗忘、只从本人消息学。「哪天聊了什么」是有日期、会过时、含助手结论的记录，单独存成会话纪要，按需回看。
- **天枢做重活，Chat 只加两处取用**：分段、纪要、检索都在天枢；人豪只在 Chat 里把目录放进资料、加一个调天枢检索的工具。

## 2. 分段（首页和二级页面同一套规则，用户 10/28 定）

**换段规则（两条满足一条就换）**：
- 上一次发言距现在 ≥ 12 小时；
- 上一次发言在今天北京时间凌晨 4 点之前（跨天）。

| 情况 | 首页（Chat） | 二级页面（议题、会议、执行事项、任务卡、复盘等，天枢运行时） |
|-|-|-|
| 换段时模型侧 | 天枢在 Chat 新开一段对话 | 模型侧开一个新的 pi 会话，不带上一段的原文和工具往返（替代现在的「闲置 12 小时重开」，触发条件改成上面两条） |
| 自动交接 | 新段的会话目录里带上一段的完整纪要（见 §4） | 新段的会话目录里带**本页面**上一段的完整纪要 |
| 一段很长 | 不切段（切在话题中间最伤），交给 Chat 段内滚动压缩；请人豪把阈值从 8 万调到 4 万并改后台做 | 不切段，沿用天枢现有的后台压缩 |
| 话题切换 | 不自动判断（多一次模型调用、容易切错） | 同左 |
| 「继续」「重新回答」 | 永远进那一轮所在的段，即使已经换段 | 同左（续写接回那一段的模型会话） |
| 附件 | 上传和随后那一句用同一个判段规则；上传触发换段，附件就放进新段 | 附件挂在页面对话上，不受影响 |
| 界面 | 一条连续的对话；拼最近 7 天的几段（最多约 200 条），段之间一行很淡的日期 | 一条连续的对话（本来就是），换段处同样插一行日期 |
| 开关 | `CHAT_SESSION_ROTATION`，默认关，等 Chat 那两处上线再开 | `CONVERSATION_SEGMENTS`，默认开（只依赖天枢） |

日期行用契约里现成的 `kind: "trace"`（`Transcript.tsx` 没有 href 时就是一行淡字），不改契约。首页对话层每 10 秒轮询一次历史，拼接范围必须有界。

**界面**：首页历史拼最近 7 天的几段（最多约 200 条），从旧到新；段与段之间插一行很淡的日期（契约里现成的 `kind: "trace"`，不改契约）。首页对话层每 10 秒轮询一次历史，拼接范围必须有界。

## 3. 会话纪要

**一段 = 两次发言间隔不超过 12 小时的一串问答。** 首页（Chat 的每段对话）和对象页（天枢 `conversation_messages` 按 12 小时间隔切开）用同一个口径。

**表**（迁移 215）：`conversation_digests`

| 字段 | 说明 |
|-|-|
| id | |
| owner_id、viewer_role | 本人；viewer_role 只对首页 Chat 段有值，对象页为空 |
| source | `chat`（首页）或 `tianshu`（对象页） |
| source_ref | Chat 的 conversationId，或天枢的 conversationId |
| scope、scope_label | `global` / `meeting:…` 等，加一个给人看的页面名（「首页」「会议：xxx」） |
| started_at、ended_at | 这一段的起止时间 |
| covered_to | 已覆盖到哪条消息（位置或序号），用于增量更新 |
| title | 一句话主题，≤40 字 |
| digest | 纪要正文，≤1,500 字 |
| keywords | 关键词数组，供检索 |
| status | `ready` / `stale`（有新内容待更新） / `hidden`（原对话被隐藏或本人要求忘掉） |
| model、generated_at | |

**纪要写什么**（沿用 Chat 和天枢现有摘要规则的口径）：
- 用户要解决的问题、后来的纠正；
- 结论和决定，**标明谁定的**：本人确认的 / 助手建议、本人没表态的；
- 没解决的问题、答应要跟进的；
- 读过的资料（名称、版本、日期），不抄正文；
- 开头写「截至 10/27 18:20」。助手的假设保持假设，不写成事实。

**什么时候生成**：后台任务，仿 `personalDistillation.ts` 的 tick。某段最后一次发言已过 15 分钟、且有纪要还没覆盖的新内容，就用轻模型（TokenHub 上的 qwen 快模型）增量更新这一段的纪要。不在回答路径上，慢一点没关系。这样到下一段开始时，上一段的纪要已经是现成的。

**读 Chat 那边的原文**：天枢用本人身份调 Chat 的 `GET /conversations` 和 `/conversations/:id/messages`（#51 现成的客户端）。

## 4. 回看：两种触发

**(b) 模型自己判断**：每轮给模型一份「会话目录」，两部分：
- **上一段**：首页是首页的上一段，二级页面是本页面的上一段。给完整纪要（≤1,500 字），这就是自动交接。
- **近 14 天其他段**：每条一行：日期、页面、主题，最多 10 条，按时间倒序，几百字，跨首页和所有二级页面。
模型看到相关的一段，就自己调工具读它的纪要或原文。

**(a) 用户主动提**：「前几天我们聊过 X」「上次说的那个方案」。模型调检索工具。

**两个工具**（对象页和首页一样的语义）：
- `search_past_conversations({ query?, from?, to?, page? })`：在本人的纪要里按关键词和日期查（标题、关键词、正文），返回最多 5 段：日期、页面、主题、纪要前 300 字、段 id。查不到时退回原文检索：对象页用现有的 `searchOwnConversationHistory`；首页段用纪要已覆盖的内容，不再逐段翻 Chat。
- `read_past_conversation({ segmentId, cursor? })`：读这一段的完整纪要，需要时再分页读原文（每页 ≤8,000 字）。

**放在哪**：
- **对象页（天枢运行时）**：目录放进每轮的上下文包（本轮那条用户消息里，不放 system prompt，利于缓存）；两个工具加进运行时，替代或包住现有的 `search_conversation_history`。
- **首页（Chat）**：天枢新开两个宿主接口，鉴权同现有 `/internal/*`（内部凭据 + X-Owner-Id + X-Viewer-Role）：
  - `GET /internal/conversation-catalog`：近 14 天目录；
  - `GET /internal/conversation-recall/search`、`GET /internal/conversation-recall/:segmentId`：对应两个工具。
  - Chat 那边要做的：每轮读目录放进本轮资料；注册两个工具，转调这两个接口；提示词加一句「用户提到以前聊过的事，或你判断需要以前的讨论时，先查会话目录和回看工具，不要说不记得」。

**范围**：只看本人的。首页段按视角隔离（和 Chat 一致）；对象页的对话属于本人，两种视角都能查到（待定，见 §8 第 3 条）。被隐藏的对话、本人要求忘掉的，纪要标 `hidden`，不进目录、查不到。

## 5. 顺带修的两处（和对话链路有关）

1. **飞书私聊在 Chat 模式下收到「这次回答没有完成」**（按代码推断，没实测）：`feishuChat.ts` 写完后按 runId 去天枢 `conversation_messages` 找回答，Chat 模式下那里没有。改法：转发时把流里的正文累积下来，库里找不到就用累积的正文。
2. **首页问答进不了天枢的历史检索**：纪要表覆盖了首页段，检索就能查到。天枢个人记忆（3f）看不到首页仍是缺口，两套个人记忆统一另议。

## 6. 上线顺序

分段、纪要、回看必须一起上：先分段会让「前几天的事」比现在更想不起来。Chat 那两处没上之前，首页的回看先不可用，所以首页分段的开关在 Chat 那两处上线以后再打开；对象页的目录和工具可以先上（只依赖天枢）。
