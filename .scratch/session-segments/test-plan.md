# 会话分段、纪要与回看：测试计划（2026-10-28）

对应设计：`会话分段与回看_设计_2026-10-28.md`。实现会话做完后，由设计会话（chat-service-connect）按本计划执行；全部通过后再交主会话合并到 `feat/meeting-upload-link`。

## 0. 规矩

- **两个场景都测**：每条标了「G / P」的用例，首页（G，Global chat）和二级页面（P）各测一遍。二级页面至少测**议题**和**会议**两种。
- **证据**：每条用例都要留证据：SSE 事件（工具名、参数）、数据库行、接口返回、截图，或 LangSmith / 运行记录里模型实际收到的上下文。只看回答文字不算通过。
- **判定**：通过 / 不通过 / 受阻（写清卡在哪）。不通过的先修再全量重跑相关组，不只重跑那一条。
- **账号**：本地用 sunm/8989（CEO 和成员两种视角），外加一个成员账号测隔离。预发只用评测账号（chat-ceo-eval、chat-member-eval），不碰别人的真实对话。
- **改时间**：「过了 12 小时」「跨凌晨 4 点」靠把测试数据的时间往前改来模拟：
  - 本地天枢库：`conversation_messages.created_at` 等；
  - 首页的 Chat 段：在单测里用假 Chat；端到端时只改评测账号在预发 Chat 库里那几段的 `updated_at`。
  - 不在业务代码里加只给测试用的时间钩子。
- **不写本体，不发群消息**。凭据不打印。

## 2. 用例

### A 分段

| # | 场景 | 步骤 | 通过标准 | G | P |
|-|-|-|-|-|-|
| A1 | 同一天、间隔短 | 10:00 问一句，11:00 再问 | 同一段；模型上下文里有 10:00 那轮 | ✓ | ✓ |
| A2 | 闲置满 12 小时 | 上一轮改到 12 小时零 1 分钟前，再问 | 新的一段；模型上下文里**没有**上一段原文和工具往返 | ✓ | ✓ |
| A3 | 跨凌晨 4 点、不到 12 小时 | 上一轮改到前一天 23:30，现在 04:30 问 | 新的一段 | ✓ | ✓ |
| A4 | 边界 | 03:59 → 04:01；04:01 → 15:59；间隔正好 12 小时 | 换 / 不换 / 换 | ✓ | ✓ |
| A5 | 换段后续写旧的一轮 | 上一段最后一轮中断；换段后点「继续」 | 续写进**原来那一段**，接着写完；新段不受影响 | ✓ | ✓ |
| A6 | 附件触发换段 | 跨天后先传附件，再发一句引用它 | 附件和这一句在同一个新段；回答读到附件 | ✓ | — |
| A7 | 并发首句 | 网页和飞书私聊同时发出跨天后的第一句 | 只建一段，两句都在里面 | ✓ | — |
| A8 | 开关关闭 | 关 `CHAT_SESSION_ROTATION` / `CONVERSATION_SEGMENTS` | 行为和改动前一致（首页一条永久对话；二级页面老的 12 小时闲置重开） | ✓ | ✓ |
| A9 | 界面 | 有两段以上时打开对话 | 一条连续的对话，段之间一行很淡的日期，没有说明文字；顺序正确；首页最多拼 7 天 | ✓ | ✓ |
| A10 | 轮询有界 | 首页对话层开着 1 分钟 | 每次轮询的请求数和返回条数有上限，不随段数无限增长 | ✓ | — |
| A11 | 段内很长 | 同一段持续追问到很长 | 不换段；首页靠 Chat 段内压缩，二级页面靠天枢后台压缩；不在首字前当场压缩（二级页面） | ✓ | ✓ |

### B 会话纪要

| # | 场景 | 通过标准 | G | P |
|-|-|-|-|-|
| B1 | 生成时机 | 一段最后一次发言过了 15 分钟，后台生成纪要；这一段又有新内容时增量更新；回答过程中不调纪要模型 | ✓ | ✓ |
| B2 | 内容规则 | 对照原文逐条核：开头有「截至……」；问题、纠正、结论与决定、没解决的、读过的资料都在；**决定标明是本人定的还是助手建议的**；没有原文里没有的事实；助手的假设没写成事实 | ✓ | ✓ |
| B3 | 来源 | 首页 Chat 段和二级页面对话都有纪要，页面名正确 | ✓ | ✓ |
| B4 | 隐藏和忘掉 | 原对话被隐藏或本人要求忘掉后，纪要标 hidden，目录里没有，检索查不到 | ✓ | ✓ |
| B5 | 隔离 | 别人的纪要查不到；首页 Chat 段按视角隔离；二级页面的纪要本人在 CEO 视角和成员视角都能查到 | ✓ | ✓ |

### C 自动交接

| # | 场景 | 通过标准 | G | P |
|-|-|-|-|-|
| C1 | 新段第一轮的目录 | 模型收到的会话目录里有「上一段」的完整纪要（首页：首页的上一段；二级页面：本页面的上一段），加近 14 天其他段的目录（≤10 条） | ✓ | ✓ |
| C2 | 「接着昨天的说」 | 跨天后只说「接着昨天的说」，回答准确接上昨天的主线，不要求用户重述 | ✓ | ✓ |

### D 回看

| # | 场景 | 步骤 | 通过标准 | G | P |
|-|-|-|-|-|-|
| D1 | 用户主动、跨页面 | 在议题或会议页聊过 X；隔天在首页问「前几天在<那个页面>聊过 X，最后怎么定的」 | 调了检索工具（看 SSE）；答对，说出日期和页面；必要时读了原文 | ✓ | — |
| D2 | 用户主动、反方向 | 在首页聊过 Y；隔天在议题页问「之前在首页聊过的 Y 怎么说的」 | 同上 | — | ✓ |
| D3 | Agent 自己判断 | 不提时间，只问一个依赖旧讨论的追问（如「那个方案的风险我们之前怎么评估的」） | 模型自己查了目录或调了工具，答对；没有说「不记得」 | ✓ | ✓ |
| D4 | 没聊过的事 | 问一个从没聊过的话题「我们之前聊过 Z 吗」 | 如实说没找到，不编造（否决项） | ✓ | ✓ |
| D5 | 按日期 | 「上周二聊的那个」 | 工具参数带了日期范围，答对那天的那段 | ✓ | ✓ |
| D6 | 要原话 | 「我当时原话怎么说的」 | 调了读原文，引用准确 | ✓ | ✓ |
| D7 | 耗时 | D1–D6 每条记首字和整轮时间 | 记录即可（用户允许回看慢一点）；超过 3 分钟算不通过 | ✓ | ✓ |

### E 回归

| # | 场景 | 通过标准 |
|-|-|-|
| E1 | 全量测试 | §1 全绿 |
| E2 | 飞书私聊（Chat 模式） | 回答完整送达，不再收到「这次回答没有完成」 |
| E3 | 历史检索覆盖首页 | 二级页面的历史检索能查到首页段（经纪要） |
| E4 | 上下文有界 | 换段后第一轮发给模型的历史只有本段（首页看 Chat 新段的消息数；二级页面看运行记录） |
| E5 | 没聊过旧事时 | 新用户、没有任何旧段时目录为空，对话正常 |

### F 回答质量

- 用 C2、D1–D6 的脚本对话，按《质量标准 V2》打分：75 分以上，没有否决项（编造、把待定当决定、把计划当完成）。
- 每条留问答原文和工具调用记录。
