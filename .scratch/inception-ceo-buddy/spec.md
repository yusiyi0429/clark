## 1. 要达成什么

**成功的样子**：CEO 在会议之外，愿意主动花时间跟天枢聊公司经营的事。
- 明华：「从产品角度的指征是，他会愿意开始花时间，在会议之外用这种东西跟天枢聊。做不到这个事，那这个就不太成功」（推动计划 56:34）。
- 明华：「不是被迫而愿意做，我其实愿意跟你天枢聊一聊，就证明这个事我们实现了亲历价值」（推动计划2 05:20）。

**为什么原来不用**（明华，推动计划2 00:22–05:20）：
- 一号位的时间最有限，「我是不想变的」。要工具来适应他，他不会去适应工具。
- 原来不用，是因为有负担：
  - 要打字，还得打得很结构化，像对着搜索引擎敲字；
  - 用电脑是被逼的。
- 能坐上牌桌靠思辨能力；坐得住，靠「对他是工作支持，而不是额外的管理负担」。

**后来愿意用的条件**：
- 不改变他任何工作状态，但嵌进他的工作里：「你看起来……只是一个交互界面的变化，不是，我们在构建一个场景」。
- 他从没体验过「带着持续记忆的 AI 帮他持续做事」，这就是要让他感受到的价值（推动计划2 05:20）。
- 无感，又能感受到 AI 的价值，「我们就赢了」（推动计划2 07:20）。

**这是「最简的产品路径」**（推动计划 57:09）。
- 明华同场说，其他东西（点名包括铭泽那些）都可以弱化掉。
- 推动计划2 16:05 又说：铭泽昨天讲的功能「是 0，不是 1，要把 chat 先调好」，「他的切口也就是聊」。

## 2. 场景

### 2.1 Inception 当天：九步法第一步「看见未来」

推动计划 21:44–31:44、44:12–52:08。

只讲战略，不讲组织范式。两个「显灵」：

1. **战略预演**：
   - 带一份 agent 团队做的战略报告，有洞察，下面列着假设。
   - CEO 读完给意见；讨论时同时录音，后台跑出 V2，让他看到报告变了。
   - 这条线是明华、田田和战略 agent 的，不归天枢伙伴（我的理解）。
2. **协作方式**：
   - 先拉 Nexus 进会（「王总你好，我是 Nexus……」）；
   - 再给他看天枢：一台预装好的 pad 或三折屏，「他直接打开就可以点」。天枢说「我现在对你公司有一定了解，我可以是这么理解的」，他可以用语音或打字随时聊（推动计划 30:36、52:08）。

**天枢这一天要做到**（推动计划 52:08）：
- 随时能聊，语音、打字都行；
- 能给出比较高质量的、对他公司的洞察和理解；
- 内容来自战略报告里假设的预载，现场说明这是 demo。

### 2.2 四周陪跑：「亲历价值」这条线

推动计划 32:25–35:53、53:13–56:34。

- **CEO 选 1–2 个议题**：他真正在持续推动、要靠开会推人干活的事。
- **每次开会**：
  - 会前：天枢出预审，放在 pad 上，他开会前打开看一下。「天枢要刚开始的时候要把预审报告做好」。
  - 会中：拉 Nexus，是固定动作。溪南的建议是从天枢约会议时自动把 Nexus 拉进去（推动计划2 18:47）。
  - 会后：
    - Nexus 做总结、提炼；
    - 记忆要接得上，同一个议题上次和这次都记得；
    - 结果反馈给天枢。
- **CEO 什么都不用变**：
  - 开会时让旁边的人把天枢、Nexus 拉进来，感兴趣就问两句。
  - 前两三轮有人在旁边陪；产品质量过关以后，他或者助理自己拉。
- **天枢可以实时讨论，但都围绕这一两个议题**（推动计划 32:25）。
  - Nexus 当场提了风险：边界一松，客户会把它当通用助手，一问超范围就答不上来（推动计划 33:39）。
- **前四周不连通他的组织**，不接 DRI（推动计划 37:17）。
- **会上还说**：「最开始的第一个版本在 DR Agent 上面，甚至可能前期都不一定会用」（DR 应该是 DRI）。更看重的是语音、随时能交互，一交互就有反馈（推动计划 30:36）。

## 3. 天枢伙伴（CEO 版）要做的事，分门别类

### 3.1 第一次见面：像认识一位新客户

明华给 Nexus 定的口径（推动计划 50:22–52:08），天枢照同样的口径（推动计划 30:36）：
- 带着思考和洞察来，但坦白「我对你们公司没那么了解」，希望之后一起交流、成长起来。
- 不知道就说不知道。内部信息不足，就说不了解内部；外部的就讲外部。
- 能给一些结构性的洞见。问两个问题，一定不成熟，但要让他感觉「开会时有这么一个人跟我聊」。

「每次预装完就能像认识一个新客户一样，跟他交流」（推动计划2 08:05）。
- 这句说的是 Nexus，紧接着说天枢也要能形成一些预先的东西。

**要定**：
- 开场白怎么来：
  - 预装时写死一版；
  - 或者按预装的内容生成。
  - 我的建议：按预装内容生成，结构固定成四步：我是谁 → 我已经知道的三点 → 我还不知道的 → 问一个问题。
- CEO 要不要走「选择你的伙伴」（起名、选外形）：
  - 会上说的是「他的自己的 agent 叫个名字，叫天枢」（推动计划 30:36）。
  - 我的建议：预装时默认叫「天枢」、外形用默认的，第一次打开不让他选，设置里能改。CEO 不想多点一步。

### 3.2 预装：战略预装载、议题记忆，还是客户本体

同一场会前后有两种说法：
- **先不接本体**：明华说这是「取巧」——一份战略预装载，加每个议题一份持续的记忆；「这个事不用接本体，他也可以做得成，也会有价值」（推动计划2 04:21）。
- **一定得有本体**：
  - 后面又说，战略报告第一版「一定得有本体」，用我们同一套结构给客户初始化一套。
  - 开完会沉淀进本体，天枢再读（推动计划2 19:26–20:18，溪南、铭泽附和）。

另一句：报告一改，天枢的内容最好也跟着变；可以一步步来，质量更重要（推动计划2 08:05）。

**要定**：第一个客户先走「预装载 + 议题记忆」，还是一开始就初始化一套客户本体？前后两种说法，要明华确认（待定）。

**我的建议**：
- 先问清第一个客户的本体由谁初始化（斯一？），几天能好。
- 天枢这边两种情况都按「从本体读」做：没有本体时读预装载文件，接口一样。以后换数据源，不改对话。

### 3.3 会前预审

- 归天枢（推动计划 54:25；推动计划2 21:12–21:14 也说「会前肯定是」）。
- 现有：天枢能约会议、出会议卡，但没有「按议题出预审」。

**要定**：
- 预审长什么样、什么时候出、放在哪（pad 上一打开就能看到）。
- 读什么：议题记忆、上次 Nexus 的会后总结、战略报告里相关的假设。

### 3.4 约会议带上 Nexus，会后接住 Nexus 的总结

- 会中、会后归 Nexus，总结反馈给天枢（推动计划 54:25）。
- 明华要你和溪南把「谁依赖谁、整个流程什么样」画清楚（推动计划2 21:01–21:43）。
- 现在 Nexus 和天枢连得不扎实。没连好以前，人工喂会议纪要也可以；溪南说花两三天先把会接上（推动计划2 17:27–17:57）。
- 这和新阶段设计 5.6 一致：会前归天枢，会中、会后归 Nexus。
- 今天这条链路和昨天（DRI 那条）有不少能共用，明华要你们盘出哪些共用（推动计划2 18:15–18:47）。

### 3.5 会议之外的对话：成功指征就在这里

- 围绕 1–2 个议题。
- 不让他打字：
  - 语音能说就说；
  - 伙伴要问他什么，给选项，点一下就答。
- 对话本身的做法和 DRI 共用（spec.md 5.7）。CEO 这边最依赖三样：
  - 选项提问（5.7 D）；
  - 先快速回一句（5.7 A2）；
  - 语音。
    - 现在有火山的语音转文字；10/23 为了微信语音降成了小灰麦克风，代码还在。
    - CEO 的 pad 上要不要把它放回主位（待定）。
- 回答质量是核心：「Chat 的功能是核心……最终输出那个东西、吐东西的质量」（推动计划2 03:26）。回答质量归人豪。
- 要不要主动开口：
  - 会上没说。
  - 我的建议：只在会后总结到了时说一句（「上次会定了 X，下次会前我出预审」），给他一个会外聊的由头；其余时候不打扰。

### 3.6 设备和第一屏

- 「我们给他一个三折屏或者一个 pad，那个 pad 是预装好的，他直接打开就可以点」（推动计划 30:36）。
- 现有：
  - 手机网页；
  - 三折屏双栏（9/28）；
  - 「添加到桌面」（10/26 定）。
- 要定：pad 一打开的第一屏是什么。
  - 我的建议：直接是天枢对话，加上下一场会的预审；不是工作台。

### 3.7 租户和数据延续

- 产品现在没有多租户、多业务（推动计划2 12:29）。
- 四周是 demo，但这一两个议题以后正式部署时必须无缝延续：结构一样，只做一次数据迁移（推动计划2 12:47–13:43）。
- 明华：要记下来、报风险，但不要因此卡住现在的工作（推动计划2 13:54–15:50）。
- 用户只有 CEO，一到两个，各用各的、不连通，但产品要有用户角色（推动计划2 20:24–20:46）。
- 10/20 定过的口径：
  - 按数据归属方分租户；
  - 前期每个租户独立部署，数据库、本体 scope、凭证、资料目录、登录入口各一份；
  - 试用是正式的一个阶段。
- **要定**：第一个客户是谁、什么时候部署。
  - 下周可能问到时间；
  - 也可能直接从房东网（房懂懂）开始（推动计划 12:15；推动计划2 11:38–12:27）。

  - 要不要我们帮着做工具，待定。
- **会中、会后**：Nexus（溪南）。
- **「锚定目标范式」那条咨询线**：咨询团队做，战略确认 1 周、组织范式设计 1–1.5 周、鱼缸规划 1.5 周（推动计划 34:40–35:53）。
- **四周之后全面上 TKOS**：明华来想，现在不泛化（推动计划2 16:05）。
