# 手机与华为三折叠审查（CEO 为主）· 2026-09-28

只读审查，没有改代码。环境是时间机器（localhost:3500，一次性库，代码与 HEAD 82f6d7a 一致）。账号用 `browserceo`，首次引导用 `wangluyao`：只翻页，没有完成引导，也没有保存雷达。
工具是 Playwright 无头 Chrome，模拟触屏与移动 UA。CEO 的 16 个页面各在 5 种视口下截图，并自动检测横向溢出、文字截断、过小的点击区域和过小的字号；另外测了交互态、展开/合上屏幕和横放。证据图在 `evidence/`，其中 A、B 两张是带标注的汇总。

## 视口假设（推断，未上真机）

Mate XT 的物理分辨率：单屏 1008×2232，双屏 2048×2232，三屏 3184×2232。按鸿蒙常见的 DPR≈2.8 换算，再扣掉状态栏和浏览器栏：

| 形态 | CSS 视口 | 落在现有断点 |
|---|---|---|
| 单屏 | ≈360×680 竖 | ≤690 手机版 |
| 双屏 | ≈731×680 近正方形 | 691–759 折叠版 |
| 双屏，「显示大小」调大（DPR≈3） | ≈683×680 | ≤690 手机版 |
| 三屏横放 | ≈1137×680（16:11） | 1001–1250 桌面窄版 |
| 三屏竖放 | ≈797×1040 | 760–1000，带右侧对话列 |

两个结构性事实：
- **三种形态的高度都只有约 680。** 现有布局按「桌面够高」设计，这是多数问题的来源。
- **同一台双屏会因为「显示大小」这个系统设置落到两套布局里。**

## 问题清单

### P0：挡住使用

1. **议题页在单屏几乎没有阅读区**（`/issues/[id]`，证据 A①）。
   - 单屏上从上往下依次是：标题折成 7 行（每行 4 个字）、会议块（日期、10:00、主麦、打开会议空间）、tab 行。它们都固定不滚，剩下的 `.reading` 只有 148px，底部常驻输入框再盖掉约 100px，正文实际可见约 40px。
   - 双屏和三屏也只剩 200–300px。
   - 根因：页头和会议块固定，只有内层区域滚动；高度短时没有降级。
2. **CEO 在手机上看不到公司全局**（设计缺口）。
   - ≤690 时 CEO 的 `.mainArea{display:none}`，首页只有通知。个人菜单里只有雷达设置、修改口令、组织配置、重看引导、退出。
   - 所以战场、Mission 总览、公司能力、雷达信号在手机上都没有入口，只能从某条通知间接点进去。
   - 成员手机首页是「通知 → 执行事项 → 卡 → 战场 → 雷达」一条滚动，CEO 没有对应的版本。

### P2：触屏与精致度

12. **单屏详情页左侧 48px 窄条加边距占掉约 70px**（19%），正文只有 262–290px，一行约 13 个字。
13. **详情页输入框常驻约 100px 高**，按钮文字被截成「我的 Ag… / 事项群…」。
14. **点击区域偏小**：
    - 战场卡「Missions · 2」79×18，「打开会议空间」202×18，材料 tab 高 28。
    - 配置页的编辑和删除都是 24×24，而且紧挨着，有误触删除的风险。
    - 首页战场卡有 10–11px 的字（「尚未收到负责人反馈」等）。
    - 建议在 `pointer:coarse` 下把点击区域放到 ≥40px。
15. **三屏横放高度只有约 680**：
    - 「公司战略议题」空着也占一整块大卡，首屏一半是空的。
    - 右侧「我的 Agent」列 300px 大部分时间只显示「暂无消息」。
16. **软键盘（推断，需真机验证）。** 没有设 `interactive-widget=resizes-content`，也没有 `visualViewport` 处理。Chromium 内核（华为浏览器、ArkWeb）默认只缩视觉视口，弹键盘时对话记录层（`100dvh` 定高）的下半部分可能被键盘盖住。
17. **单屏横放**（797×330）：议题页和任务卡只剩页头，看不到正文。
18. **与手机无关，顺带记下**：
    - 会议复盘页暴露开发术语「Outcome candidate / actionId / confirmed effect」。
    - 用的是原生文件选择框和复选框。
    - 直接打开或刷新详情链接时，关闭键带一圈蓝色焦点环；从首页点进去则没有。

## 系统性根因

1. **断点按屏幕宽度，可用宽度却由外壳决定。** 左窄条 62px 或通知栏 270px，加右侧对话列 300–440px，内页（Mission 总览 1100、Mission 详情 1280、各页头）却按 viewport 切换。
2. **高度不足没有降级。** 多页固定页头和元信息块，只滚内层；遇到 680 高、底部再叠一个常驻输入框，阅读区就塌了。
3. **页头「标题 + 操作」挤在一行，没有换行策略。** 窄了就把标题挤成细柱。
4. **断点不齐。** 外壳 690、对话列和引导 759/760 各切各的；三折叠双屏正好卡在中间。

## 1 / 2 / 3 屏各显示什么（建议）

**单屏（约 360，单手）：处理与速览。**
- **首页一条滚动。**
  - 上面是要我拍板的事和会议（现有通知）。
  - 下面加「公司全局速览」：本月公司目标一句话；每个战场一行（编号、名称、负责人、待决策数、本月进度）；雷达未读数；Mission 总览入口。
- **详情全宽。**
  - 顶部一条「← 标题」，页头随正文滚走，只留一行吸顶；去掉 48px 左窄条。
  - Agent 收成一颗按钮或单行胶囊，点开再从底部升起。
- **单屏不做编辑**：组织配置、战场/Mission/能力管理和宽表。显示只读，或提示「展开屏幕后编辑」。

**双屏（约 731 近正方形，双手捧）：阅读与讨论。**
- 首页两栏：左边通知约 300px，右边公司全局。
- 打开详情时占满右侧，通知收成窄条（沿用现有逻辑）。对话走底部抽屉，不放右侧对话列。
- 683 和 731 必须是同一套布局：手机断点下移到约 600（鸿蒙 md 从 600vp 开始）。引导的断点跟着对齐。

**三屏（约 1137×680 横放，像 11 寸平板）：总览与工作台，最接近桌面。**
- 首页：通知 + 公司全局（战场两列）。空的「公司战略议题」收成一行，让战场卡进首屏。
- 详情：阅读区 + 对话列。
  - 1250 以下没有消息时，对话列默认收起、保留把手。
  - 内页按容器宽度（container query）排版。
- 三屏竖放（约 797×1040）按双屏规则处理：对话走底部抽屉。

**所有形态都要满足：**
- 展开和合上时保持当前对象和阅读位置（现在已经做到）。
- 页头随内容滚走。
- 点击区域 ≥40。
- 弹键盘时输入框不被遮挡。

## 修复方案（选定后再改）

**A. 只修 bug。**
- 范围：P0-1、P1 3–11、P2 16（viewport meta 一行）。
- 副作用：改动小、风险低；但三折叠仍是「桌面被挤扁」的体验，P0-2（CEO 手机看不到全局）没解决。

  - 单屏：首页加公司全局速览，详情改成顶部返回条，输入框收起。
  - 断点改成 600 / 960 两档，对齐引导。
  - 内页改用容器查询。
  - 三屏空卡收起；对话列没有消息时默认收起。
- 副作用：
  - 外壳 CSS 在所有宽度上都会动，要重跑 1440/390 截图回归。
  - `styles/responsive-layout.test.ts` 里断言 `max-width:690px` 规则字符串的用例要跟着改。
  - CEO 手机首页的信息量变多，需要您确认速览里放哪几项。

**C. 只做单屏和双屏，三屏维持桌面窄版。**
- 范围：P0 两项、断点对齐、P1 的显示 bug。
- 副作用：三屏横放时 Mission 总览仍被挤扁，对话列仍占宽。
