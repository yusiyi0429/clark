## 给人豪的说明要点

沿用了你的设计：
- 提炼的证据规则：每条改动必须有本轮（现在是本批）本人原话逐字支持，整批校验、原子写入；`status: apply / noop / needs_clarification` 契约（971274c）；模型调用次数上限 2；按人 advisory lock 串行。
- 「忘掉的不再学回来」：被忘的条目作为屏障交给模型，同义要标出（`matchedForgottenId`），服务端再按原文兜底。
- 本体公司事实的读取：`company.ts` 的投影、按人授权的域、列表—逐个读—再列表核对版本、短句柄分页、续页不许换查询条件，都原样保留；只改了读不到时的处理。
- 记忆正文进轨迹、凭证不进（21e05fe、971274c 的口径）。

改了什么、为什么：
- **没有合并 #12，而是挑两部分移到 main 上**：与 #10 冲突 39 个，迁移编号、trace_threads 表结构、LangSmith 实现两边各一套。轨迹统一用 main 的 `tracing.ts`；迁移从 069 起。
- **存储从 Personal.md 改成逐条存表**：整份覆盖有丢失风险、16 KiB 上限会让整批提炼失败；R4/R5 要的时间、状态、替代、anchor、依据直接是列。
- **记想法，不只记偏好**：用户要的是想法、立场、未决问题、理由（R4）。纠正改成新建 + 替代，不覆盖。
- **「记住 / 忘掉」交给主 Agent 的工具**：原来的同步路径在抢不到锁、超时、校验失败时会把主回答换成「个人记忆修改尚未完成」并清空上下文（R9）。用户的决定是由主 Agent 调工具完成。
- **显式改动不再清空所有会话上下文**：忘掉的意思改成「不再作为记忆带出」，不再让所有对话从空历史重来。
- **提炼按游标增量，不做会话管理**：用户和孙铭泽的判断是超时不在 session 大小，而在每条消息都重读、重算；用户也不要可见的 session。改成只处理游标之后的新消息、窗口有上限、攒批或空闲才跑、失败退避。
- **本体读不到时**：按用户决定，先如实告诉用户没读到本体，再用本地资料作答并注明来源，多记日志（#12 是拒绝用本地资料）。
- **主对话的看板工具不拿掉**：#12 在非任务卡页面去掉了 `get_warmap_overview`、`list_missions` 等，main 上它们是一号位的主力，这次没带这个改动。
- **没带的**：场景 Anchor（`read_anchor`、turnContext 的临时正文）、`peopleDirectory` 拆分、#12 的轨迹与文档整理。是否还需要场景 Anchor，请你说明它在 main 上要解决的问题。
