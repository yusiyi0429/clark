# 记忆接入：没把握、没改的问题

以下都没有改代码，只记下现状、可选做法和各自代价，等孙铭泽或人豪定。

## 1. 内部分批怎么切

现状（3f）：按人一个游标，攒够 6 条或空闲 3 分钟就跑一批，一批最多 20 条、2.4 万字；跨页面的消息按时间排在一起。

没把握的地方：
- 是否该按「话题」或「页面」切，而不是只按时间。按时间切，一个想法在两个页面断续说，可能被切进两批，第二批靠 `earlier`（游标前 4 句）和现有记忆接上；按话题切要先做一次分类，多一次模型调用。
- 6 条 / 3 分钟 / 20 条这几个数是拍的，没有用户真实的对话节奏做依据。
- 上线时游标为空，会从头补整理全部历史对话（每次最多 20 条、每 15 秒检查一次）。历史多时会连续调用 light 模型一段时间。可选：从上线时刻起算、只补最近 N 天、或全部补。现在是全部补。

## 2. R8「基于旧版本」的提示文案

现状（3a）：当前页面对象就是 anchor，检索时只比对象不比版本；钉住的版本比现在旧时，条目带 `basedOnOldVersion: true` 装进对话，系统提示只写了一句「用到时说明它基于旧版本」。

没把握：给用户看的具体说法（例如「这是你在第 3 版时的看法」还是「这个议题后来改过，你当时的看法是…」）、要不要说出旧版本号、改动大小是否影响要不要提。只对「当前页面对象」做了比对，别的对象的新版本没有去查。

## 3. 是否改成向量检索

用户已定先不建向量库。现状：
- 个人记忆选取：中文二字词 + 英文词的重合度，加上「钉在当前对象上」加分、偏好类兜底，总量 8 KiB。
- 历史原话检索（3e）：ILIKE 粗筛 + 命中词数排序，候选 300 行。

已知局限：同义改写（「县城样板」与「下沉试点」）找不到；记忆条目多了以后，按重合度选可能漏掉相关但用词不同的条目。什么时候值得换，取决于实际条目数和漏召回的评测结果（R10），这次没有数据。

## 4. 压缩提示词怎么换

main 的后台压缩（conversationCompaction.ts）沿用原样，没有改。R3 要求「压缩只负责装得下」：现在原话永久保留、可用 `search_conversation_history` 找回，压缩丢掉的细节能查回来。是否要让压缩提示词明确保留「想法、立场、未决问题」原话，或在压缩摘要里注明「细节可检索原话」，没有把握，没改。

## 5. 其他

- **删 = 忘掉**：`DELETE /api/me/memory/personal/items/:id` 只把条目标为 forgotten，正文留着，后台提炼据此不再学回来。要不要再提供「彻底删除」（连正文一起删，代价是之后可能被重新学回来），没定。
- **忘掉之后旧对话里的原文**：3d 之后不再清空模型上下文，所以同一段对话的历史里仍有用户当时说的原话。忘掉的含义现在是「不再作为记忆跨对话带出」，不是「从对话历史里抹掉」。是否需要在当轮告诉模型「这条已被忘掉，别再用」，没做。
- **任务卡私聊不做后台提炼**：沿用 #12。现在任务卡私聊里能读个人记忆、能用工具记住/忘掉，但后台不自动提炼。R1 说「任何页面」，是否放开要看任务卡私聊里的内容是否适合进个人记忆。
- **需要澄清时**：后台提炼返回 needs_clarification 只记日志，不打扰用户，这批照常推进游标。是否要在下次对话里问一句，没定。
- **提炼时限 60 秒**：没有生产实测，按输入规模估的。每批都记 `personal_memory.distilled` 日志（durationMs），上线后按 P95 调。
- **本体公司事实的授权文件**：`query_company` 沿用 #12 的按人授权（`COMPANY_WORLD_ACCESS_FILE`，personId → domain 列表），没有这个文件时一律回报「读不到」并回退本地。部署时要有人配这个文件，或者改成按角色默认授权，需要定。
- **本体公司事实的磁盘投影**：#12 每次读取后把 Company.md 写到 `MEMORY_STORAGE_DIR/company`，读的时候并不用它。保留了人豪的设计没删，是否需要待人豪说明用途。
- **场景 Anchor（read_anchor）没带**：#12 的 sceneAnchor / turnContext（每轮把页面目录装成 anchor、工具结果不进历史）这次没接，main 已有 currentObject / globalContext 那一套。是否还要，需要人豪说明它解决的问题在 main 上是否还在。
