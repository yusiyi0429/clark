# 垂直切片拆票草案

日期：2026-10-15

依据已确认的 Anchor / Reference 与 Company / Personal 设计。旧 issues 的六票按模块分层，本草案改为可单独验证的行为切片；确认后再发布成逐票文件，旧票保留为设计历史，不同时派发两套票。

## 01 — 解耦人员目录，保持登录与授权行为

**What to build:** 身份与权限不再依赖公司认知存储；公司记忆替换过程中，现有成员仍能以相同身份登录、读取本人对象、连接已有个人 MCP。

**Blocked by:** None — can start immediately.

这是 to-tickets 允许的宽重构例外：先 expand 新人员目录接口、迁移身份调用方，旧认知接口暂保留；删除旧形式在 06 contract，不能在本票同时停用旧企业知识。

- [ ] 通过现有登录、会话和本人数据接口验证 personId、角色及可见范围不变。
- [ ] 保持其他 MCP、群组、批注和 M2 的既有行为。
- [ ] 目录缺失仍如实失败，不用 World 业务负责人推导登录权限。

**TDD seams:** 登录/session HTTP 接口、本人对象 HTTP 接口；必要的目录模块公开接口。只验证行为，不通过私有函数或数据库侧查询替代断言。

## 02 — 主私聊使用当前页面 Anchor，保留用户原话

**What to build:** 用户在首页或对象页发送消息时，Agent 获得与可见 Card 一致的有界 Anchor，可展开当前项；当前 Query、显式引用与附件分别处理，换页面后旧 Anchor 不累积。

**Blocked by:** None — can start immediately.

- [ ] 前端选择与 API 契约连通；过期选择返回 409、越权返回 404，失败保留输入。
- [ ] 页面和 Anchor 复用授权投影，先权限过滤再计数，目录分页不泄露隐藏对象。
- [ ] 真实 Pi 首轮、工具后续请求、恢复及压缩使用本轮 Anchor，持久消息保留原话。
- [ ] 本地页面值明确为页面/草稿/历史，不借高场景权重覆盖 World 事实。

**TDD seams:** Web 私聊输入公开交互、messages HTTP、ConversationRuntime.run、read_anchor 工具。复用已有真实 Pi 离线探针，不测 SDK 私有实现。

## 03 — 主私聊按需读取 World 公司事实与 Company

**What to build:** 用户询问公司方向、责任或目标时，主 Agent 能查询 World 并消费可读 Company 片段；读取失败时如实说明，不拿本地旧目标或旧 Markdown 补事实。

**Blocked by:** 01（独立人员目录，避免公司事实查询与身份权限混在旧仓储里）。

- [ ] 从完整 World 响应到有界正文、Company 更新与主聊只读工具形成可验证链路。
- [ ] 不提供 World 写入工具；消除主聊中同用途的本地公司事实工具，页面信息由 Anchor 承担。
- [ ] 不发布部分失败的残缺投影，不跨访问范围消费 Company，不注入协议哈希或来源模板。
- [ ] World 未配置不阻止个人问题与已有页面讨论；明确区分没有对象和覆盖不足。

**TDD seams:** 主 Runtime 的公开 run/工具接口、Company 公开读写治理接口；HTTP transport 是外部桩边界，使用现有响应样例及人工指定预期。

**外部依赖:** 离线可交付与完整契约测试可以执行；真实实例读取授权、覆盖与最新响应形状尚未验证，不能报告生产联通已验收。

## 04 — 本人能查看、纠正、遗忘 Personal，并用于私聊

**What to build:** 每个人拥有独立 Personal.md，能通过本人接口查看和修改；主聊只使用本人相关片段，遗忘后旧运行态和历史召回不能把已删除属性重新带回。

**Blocked by:** 01（稳定人员身份边界）。

- [ ] 本人 GET/修改/遗忘完整贯通到持久文档和主聊 Reference，版本冲突不覆盖新内容。
- [ ] 同人跨 scope 共用、不同人隔离；不接受任意 owner 或文件路径。
- [ ] 文件与版本控制态中断可恢复，记忆不可用时主回答仍能运行。
- [ ] 遗忘失效 Runtime/cache，并阻止旧历史重新召回相同属性；不删除公司事实。

**TDD seams:** 本人记忆 HTTP 接口、PersonalMemory 公开接口、主 Runtime 参考消费；磁盘和 PostgreSQL 使用真实临时资源，模型/远端服务在外部边界受控。

## 05 — 主私聊结束后自然蒸馏个人记忆

**What to build:** 用户自然表达长期偏好或反复的个人情况，无需说“记住”，会在后续私聊中体现；当前回答不被后台蒸馏阻塞。

**Blocked by:** 04（持久存储、版本、遗忘和主聊消费已可用）。

- [ ] 对话成功提交与持久任务排队一致；重启、重复消费和并发更新不丢失或覆盖新纠正。
- [ ] 只依据本人消息蒸馏，不把 Company、Anchor、假设、他人话语或助手推测当本人事实。
- [ ] 支持 add/update/remove/noop，区分明确偏好与谨慎归纳；失败不影响主回答。
- [ ] 明确纠正/遗忘不依赖助手成功回答；旧任务不能复活已遗忘内容。

**TDD seams:** messages HTTP 到下一轮公开记忆读取的完整行为、Personal 蒸馏 worker 的公开任务接口；模型响应在 provider 边界受控，不 mock 内部函数。

## 06 — 停用旧 CompanyMemory MCP，保留共同调用方能力

**What to build:** 旧企业知识端点、专用配置和 Markdown 事实源退出；主聊、雷达、预审等已有调用方使用共同 Company 能力，身份与其他 MCP 保持可用。

**Blocked by:** 01、03（先有独立人员目录和可替代公司读取路径，再 contract）。

- [ ] 没有旧 CompanyMemory MCP 或旧 Markdown 的隐藏公司事实回退。
- [ ] 停用专用端点/Token/启动条件，其他 MCP 和既有服务仍可运行。
- [ ] 配置、健康状态、部署存储与领域文档一致，旧 ADR 明确被替代。
- [ ] 不扩展群消息、任务卡批注或 M2 功能。

**TDD seams:** 应用启动与 health HTTP、旧端点停用、现有雷达/预审公共运行入口、其他 MCP 现有接口。

## 07 — 切换后的历史兼容、集成验收与 PR 级审查

**What to build:** 原有用户进入新主聊后仍保有原始聊天，新的事实与个人记忆链路可靠；所有切片在同一分支组合后没有新旧上下文混用、越权或遗忘回流。

**Blocked by:** 02、03、04、05、06。

这是集成验收票，不再发明新功能；各行为票在本票之前应能独立验证。

- [ ] 仅重建可替换 Pi entries，保留原始聊天，兼容没有新字段的已有客户端。
- [ ] 运行 30 条固定验收场景的机制检查；真实模型/World 未执行项与已通过结果分开报告。
- [ ] 完成相关检查和最终全量检查，区分环境缺失、原有失败与本次缺陷。
- [ ] 对整体差异执行 Standards/Spec 两轴独立 review，修复有效发现后重验并提交。

**TDD seams:** Web → messages HTTP → Pi → 工具/记忆的端到端公共行为；不通过直接数据库读取替代用户可观察断言。

## 并发与 worktree 执行规则

- 首批可并发：01、02。01 完成后 03、04 可并发；04 后启动 05；01+03 后启动 06。
- 每个 ticket 一个 implement subagent、一个独立分支和 worktree。依赖完成后再从包含依赖提交的 integration HEAD 建工作树。
- 相同文件可能被不同切片触及；每票独立提交后逐个集成，冲突按完整行为合并，不整文件覆盖。
- 每票内部按一个公开行为 red → 最小 green 推进，再做 Standards/Spec 两轴独立 code-review。并发槽不足时 reviewer 分批运行，不能跳过 review。
- 集成者固定每票起始提交为该票 review 基线；最终 PR 级 review 对比实现前基线，避免漏掉早期切片。
- 不发布或合并远端 PR；当前授权是实现、提交及 PR 级审查。若创建 PR，按工具要求附加到当前任务。
