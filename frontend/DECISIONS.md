# DECISIONS

Every judgement call made while building the v1 front-end demo, in the format
PRD-FE asks for: **决策 / 理由 / 影响面**. Entries marked ⚠ are places where the
PRD contradicts itself or where I could not fully meet a requirement — read
those first.

Spec of record: [`docs/PRD_FE_v1.0_Clark前端Demo实现规格.md`](docs/PRD_FE_v1.0_Clark前端Demo实现规格.md).

## A · 栈与工程

| # | 决策 | 理由 | 影响面 |
|---|---|---|---|
| A-1 | **Next.js 16.3 / React 19.2**，而非 15 | PRD §3.1 写「15+」。16 是当前稳定版，demo→MVP 的跨度里少一次大版本升级 | 无。App Router 语义一致 |
| A-2 | **TypeScript 5.9**，不用 7.x | TS 7 装上后 `tsc --noEmit` 通过，但 `typescript-eslint` 明确拒绝 TS 7.0（见其 issue #10940），`pnpm lint` 直接崩 | 等 typescript-eslint 支持 TS ≥7.1 再升 |
| A-3 | 状态用 **SWR**，不用 TanStack Query | PRD §3.1 允许二选一。SWR 更轻，且 `mutate(key, newObj, {revalidate:false})` 天然表达 H2「拿到返回对象再渲染」 | 全站读取统一走 `src/lib/use-resource.ts` |
| A-4 | 全站关闭自动重验证（focus / reconnect / stale） | 数据只在用户操作时变化。后台静默重取会让 200–600ms 的 pending 态说谎 | 写操作必须显式 `mutate` 新对象 |
| A-5 | 页面 = 薄服务端组件（只解析路由入参）+ `src/app/_views/*` 客户端视图 | 数据层现在在浏览器里。将来接后端可**逐页**改为服务端取数，而不是一次全局重写 | 新增页面照此分层 |
| A-6 | 移除 `shadcn` npm 包作为运行时依赖，把它提供的 4 个 `@custom-variant` 内联进 `globals.css` | 那是 CLI，不该出现在 `dependencies`；它的样式表里 600 行 scroll-fade / shimmer 工具一个都没用到 | 再用 `shadcn add` 装新组件时，若组件用到别的 data-variant，需补进 globals.css |
| A-7 | 保留 `tw-animate-css` | 纯 CSS 工具集，不是 PRD §12 所指的动画库（framer-motion 之流）。Tailwind 只输出实际用到的规则 | 目前仅少量过渡类使用 |

### P-7 · 换掉非流式之前，长生成的天花板是 300 秒，不是我们设的那个数

**它是从一轮真运行上看见的，不是读代码读出来的**：`RUN-A4-mtievtms-2`（ISS-225）

### P-9 · 缓存不是「丢了」，是一直没发 —— 而这件事写在测试名里绿了一整天

P-5 记的是「换网宿之后提示缓存丢了，而且不可见」。**那句话只对了一半，代价是十几天的

带断点、同一前缀第二次   cached_tokens 9092                                       ← 读到了
不带断点、同一前缀       cached_tokens 0                                          ← 确认它是显式的

**网宿的兼容口一直吃 Anthropic 的 `cache_control`**，在 OpenAI 兼容协议上发 Anthropic
风格的内容块就行。没有自动前缀缓存（逐字节相同的重复调用和改过前缀的调用耗时一样：

人叫醒的路，否则它只是把坏状态钉死。

### P-10 · 第一节串行七分钟，买的是一个五分钟就过期的东西

`stage-write.ts` 原来的形状是「第一节单独跑，把缓存写进去，其余几节并发读」。这个设计
在 Bedrock 上是对的。换到网宿之后它同时被两件事击穿：

1. 断点根本没发（P-9），那个缓存一直是空的 —— 423 秒串行是白付的；
2. 就算发了，缓存活 5 分钟而第一节要跑 7 分钟 —— **等它写完，缓存已经过期。**

修法不是调参数，是把「暖缓存」和「写第一节」这两件被绑在一起的事拆开：用一次
`max_tokens: 16` 的调用（实测 5.5–6.7 秒）把前缀写进去，然后六节一波并发。缓存和并发
两样都拿到。`WRITE_PASS_MS` 因此从 `outline + 2×section + closing + 2×gate` 变成
`outline + warm + section + closing + 2×gate`，410 秒 → 870 秒（分节只算一次，但各项
按实测重标了）。

**这一条的通用形状**：一个设计的成立条件（这里是「缓存的有效期 > 写它那一步的耗时」）
在换供应商时被打破了，而代码里没有任何一处在检查那个条件。它不会报错，只会变慢和变贵。

### P-13 · `docker run --env-file` 会自己去掉行尾的 `\r` —— 别顺着 CRLF 去查 401

2026-09-01 部署前收到一条告警：`.env.local` 是全 CRLF（135/135），而
`deploy/ecs/deploy-release.sh:70` 用 `--env-file` 读它，所以「每一位值尾部会挂一个回车，

记下来是因为这条推断**自洽、可怕、而且会重新被推导出来**：CRLF 确实是真的、`--env-file`
确实是真的、401 也确实是一种真实的失败样子。缺的只有一步——去看那个文件现在是什么样、
以及它现在是不是正在工作。**顺着它去查一个不存在的原因，会走很远。**

## S · 2026-09-05 · 预研 v3：四步、一句话、前提为给定、批判进裁决

### S-1 · 为什么重做

预研存在的目的是让一号位尽快判断这题值不值得花精力，深入在对话里做。v2 是七步（装上下文 / 对靶点 /
外部核验 / 写 / 算影响 / 批判 / 装卡），194 秒，而后四步的产物在屏幕上一处都不显示（`signal-view.tsx`
只读 take / finding / openQuestion / soWhat / status）；批判打回只进 `stages`，从未改过结论。真实样本
ISS-224：一号位写「我们的第一个客户是维信诺」，模型判 `invalid`，理由「当前上下文没有任何证据表明该公司
已与维信诺接触」；批判指出「把流程空转当成世界为空、靶点标反了」，卡照发。一号位看到的不是「它判错了」，
是「它不认识我」。

### S-2 · 改成什么

四步：装上下文 → 对靶点 → 写 → 批判；裁决是纯函数（`a3/ruling.ts`），只有它定最终 status / quality。

- **前提为给定**（`PreResearchDoc.premises`）：议题标题和递上来的原文里一号位陈述的公司事实抽成前提，
  每条带逐字原话（`toPremises` 只收 quote 是输入子串的）；prompt 明写「本体没记录 ≠ 不成立」，
  `invalid` 只许用议题本身的理由；`validate.ts` S02-C p0 拦「上下文/本体没有记录」这类理由。
  前提不升成已核验事实、不写本体（GPT-6 那句表述采用）。
- **一针见血**（`PreResearchDoc.verdict`，≤40 字）：先判后一个理由，屏幕最大的字；A3-20 p0 拦空和
  「进一步研究」这类没立场的话。openQuestion 压到 ≤3 条、每条是对话入口（「就这条追问」进右栏输入框）。
- **批判对象改成预研结论本身**（`CriticSubject`），代号 premiseDenied / targetMismatch / contradiction /
  overclaim；机检在前（前两类不叫模型直接打回）；批判槽位改 synth（gpt-5.6 首包 1.8 秒，Claude 80 秒）。
  裁决：premiseDenied / contradiction → 一次有明确目标的修正 → 只跑机检，过了 `corrected`、没过
  `needsCorrection` 且 status 置 null；targetMismatch → 撤靶点、议题照旧；批判没跑成 → `criticUnavailable`，
  **不当通过**。质量状态固定上屏（`QualityStrip`），不参与篇幅取舍。
- 撤掉：外部核验（`verifyExternally`，预研不取证，证据由深研自己取；生产上 `preEvidence` 本来就没接）、
  算影响（`proposeImpact` 改成 `deriveImpact` 纯推导）。提请卡照旧纯函数装配，`stages` 形状不变。

### U-1 · 出口限速器 `models/gate.ts`

按**出口**管，不按槽位管：`alt`（claude-opus-5）和 `synth`（gpt-5.6）是两个槽位、两个家族，但走同一个网宿网关、

- 令牌桶 + 信号量，每分钟那道闸用**滑动窗口**（固定窗在整点前后会放行两倍）。排队 FIFO，不做优先级。
- 出口五个：`wangsu` / `ark` / `deepseek` / `bocha` / `doubao`。`deepseek` 是交接文档里没有的第五个 ——
  官方直连那条回落（`slots.ts`）是另一个账号、另一个域名、另一份配额，并进 `ark` 会让「方舟满了」把直连也挡住。

  下限，保守猜的；真值要看各家控制台，撞了就用 `TKOS_GATE_*=并发/每分钟` 盖上（在取用时读，不用重启），别改代码。
- 单进程内单例，钉在 `dev-pin` 上（不钉的话一次重编译会出现两个限速器各放各的行，合起来正好双倍）。
  **多实例部署时这一层要换成 Redis。**

接进两个唯一入口：模型调用是 `complete.ts` 的 `callModel`（全仓库只有 `agent/json.ts` 一处调它，对谈的 `callJson`
也经这里，所以挂在这儿不挂在 `Harness` 上，否则对谈那条路会漏）；检索是 `research/search.ts` 的 `searchAll`。

**429 从「失败」改成「位子没了」。** 这是 `complete.ts` 那条「4xx 一律不重发」唯一的例外，理由是那条判据的前提
（重发拿回来的是同一个答案，只是多付一次钱）对 429 不成立。撞上时：整个出口退避（`Retry-After`，压进 1–60 秒）、
**把位子还回去重新排队**、重发一次；仍然 429 就照旧抛，而话指到限额上（该调 `TKOS_GATE_*`，不是去查网宿的开通状态）。
`isTransportFailure` 一个字没动 —— 它答的仍然是「请求根本没走通吗」，429 的答案照旧是「不是」。

排队时间进 `CallResult.queuedMs`，和 `ms` **分开**记进 trace（`harness.ts`，只在真排过队时才出现）：并进去的话
限速器一生效 trace 上每一条都变慢，而那只能被读成「这个模型今天慢」，于是去查出口、去调超时 —— 查的是一件没发生
的事。`ms` 的口径改成「进门到现在减掉 queuedMs」，不是「从拿到位子算起」：位子可以还回去再排一次（429 那一支），
从最后一次算起会把前面几次请求的时间抹掉。**这一处是被一条用例逼出来的**，第一版把退避那一秒整个记成了模型多想一秒。

`TaskStatus` 加 `queued`，`TaskState` 加 `queuePosition`（前面还有几轮，**在跑的那一轮也算**）。`runTask` 收
