# M1-A｜S03 Strategic Deep Research Skill v0.5

## 0. Positioning

`Strategic Issue → S03 Strategic Deep Research → Research Result → Discussion → S05 Judgment Formation`

S01 把问题提对；S02 让 CEO 看懂问题并确认是否值得深研；**S03 的任务是把已确认的 Strategic Issue 研究到足以支持高质量管理层讨论。**

正式产出是 **Research Result**，不是组织已确认的 `Judgment` 或 `Agreement`。

> **研究的目标不是形成一个“完整解释”，而是形成当前最值得相信、最能帮助 CEO 判断的答案。**

---

## 1. Purpose｜最终要回答什么

S03 应让 CEO 清楚五件事：

1. 现在对这个 Strategic Issue 最合理的看法是什么？
2. 哪些 Evidence 真正改变或支撑了这个看法？
3. 为什么这些 Evidence 更支持这一解释，而不是其他解释？
4. 当前答案的把握程度、适用边界与关键未知是什么？
5. 这些研究对词元云集意味着什么，哪些仍只是需要内部验证的假设？

成功不以资料量、Framework 数量或篇幅衡量，而以：

> **相比研究前，CEO 是否获得了更好的认知，并能据此进入下一步高质量讨论。**

---

## 2. Research Mode｜先判断用哪种研究模式

S03 不以“是否拿到完整内部资料”作为是否研究的前提。

### Mode A｜Full-context Research

当有足够公司内部 Context / Sources 时：

- 同时使用内部 Evidence 与 Web Research；
- 可以形成更具体的 company-specific 判断；
- 重点回答外部规律在词元云集是否成立、成立到什么程度、真正的公司机制是什么。

### Mode B｜Outside-in Research

当内部 Sources 缺失、有限或暂时不可访问时：

- **仍应完成 Deep Research，不因缺少内部材料而停止或只请求补材料；**
- 充分利用 Web Research、可比公司、客户案例、行业结构与公开一手资料；
- 形成一份完整、可分发的 **outside-in 战略研究报告**；
- 明确区分：
  - **External Finding**：外部 Evidence 已经支持的事实、趋势、机制或可比规律；
  - **Company Implication**：这些规律对词元云集具有较高稳健性的方向性含义；
  - **Company Hypothesis**：结合现有公司定位推导出的待验证假设，不能写成已被证明的公司结论；
  - **Critical Internal Evidence**：最值得补充、最可能改变当前判断的内部 Evidence。

> **内部 Evidence 不足，应该降低 company-specific 结论强度，而不是降低研究质量。**

只有当 Strategic Issue 几乎完全依赖未提供的内部事实、且外部研究无法对 CEO 判断产生实质增量时，才说明“当前无法形成有价值的 Research Result”。这种情况应少见。

---

## 3. Minimum Input｜最低输入

必须具备：

- **Strategic Issue**：已由 CEO Confirmation；
- **Prior Pre-research / Issue Context**：为什么值得研究、当前已知与关键未知；
- **Web Research Access**：能够搜索公开外部 Evidence。

如有以下 Context，应使用，但不是启动研究的必要条件：

- Strategy / Business Model；
- 产品 / 技术路线；
- 客户与项目材料；
- 历史 Judgment / Decision；
- 经营数据与内部 Evidence。

若研究发现原 Strategic Issue 已不能描述真实 tension，可明确提出 **Strategic Issue Reframing Needed**；不要静默改题。

---

## 4. Research Method｜研究时真正要做的事

以下用于内部研究，不要求机械展示给 CEO。

### 4.1 始终围绕 Strategic Issue，而不是研究 Topic

只研究真正会改变顶层答案的问题。

不要因为资料容易搜索，就把报告变成“市场 / 客户 / 产品 / 技术 / 竞争”资料汇总。

### 4.2 优先寻找能改变答案的 Evidence

搜索重点不是“还有什么资料”，而是：

> **什么 Evidence 能强化、削弱、限定或替换当前答案？**

优先：
- 一手公司材料、财报、官方产品与客户案例；
- 能区分不同解释的事实；
- 与 Strategic Issue 直接相关的真实采用、商业模式、组织运行或竞争 Evidence。

关键外部事实应可追溯到**具体来源**，避免只写“某机构研究显示”或机构名称。

### 4.3 从 Evidence 形成机制，但不强求完整理论

需要理解：

`Fact → Pattern → Mechanism → 对 Strategic Issue 的含义`

但如果多个解释都能成立，允许停在：
- 当前更支持某一解释；
- 某几个变量最值得继续验证；
- 当前仍无法区分。

不要为了让报告完整而创造一个漂亮 Framework。

### 4.4 外部研究与公司判断之间必须经过一次 Translation

特别是在 Outside-in Mode 中，不得直接：

`外部趋势 → 词元云集应该怎么设计`

应先问：

1. 外部 Evidence 真正证明了什么？
2. 哪些机制跨公司具有较高可迁移性？
3. 哪些只是在词元云集当前定位下形成的合理 Hypothesis？
4. 需要什么内部 Evidence 才能把 Hypothesis 升级成公司结论？

> **外部 Research 可以支持方向性战略判断，但不能替代公司 Evidence 证明 company-specific Design。**

### 4.5 Existing Issue 必须允许被新 Evidence 改写

有 Prior Working Judgment 时，先判断新 Evidence 对原看法是：

`Strengthen / Weaken / Qualify / Replace`

不能先保护旧答案，再把反证解释成“尚未显现”。

### 4.6 Stop Rule

当新增 Evidence 已难以改变：
- Current Best Answer；
- 关键机制；
- 适用边界；
- 对公司的主要含义；

即可停止。

不要为了页数或 Source 数继续研究。

---

## 5. Final Synthesis｜写报告前先形成一个真正的答案

内部综合时，应先形成：

### A. Current Best Answer
一句话直接回答 Strategic Issue。

### B. Decisive Evidence
2–5 条真正改变答案的 Evidence，而不是资料清单。

### C. Explanation
为什么这些 Evidence 支持当前答案，以及最重要的替代解释是否仍成立。

### D. Boundary / Unknown
当前答案不能说明什么，什么 Evidence 最可能让它改变。

### E. Company Translation
若为 Full-context：
- 可以形成 company-specific implications。

若为 Outside-in：
- **External Findings**
- **Robust Implications for TokenKing**
- **Company Hypotheses to Validate**
- **Critical Internal Evidence**

这些是内部综合对象，**不要求成为最终报告的固定章节。**

---

## 6. Output Contract｜正式 CEO 战略研究报告

最终交付是：

> **一份可直接署名、分发给 CEO / 管理层的正式、严谨、有深度的中文战略研究报告。**

### 6.1 报告必须有明确答案

开篇即说明：
- 当前最合理的判断；
- 判断强度；
- 最重要的边界。

Outside-in 报告不能因为内部 Source 缺失而变成“无法回答 / 请补材料”的说明书。

### 6.2 报告结构由答案自然生成

- 正文通常由 2–5 个观点型章节展开；
- 章节标题本身就是判断，串起来形成一条完整故事；
- 不机械展示 Issue Tree、Hypothesis、Framework、Research Process；
- 不固定使用相同的“挑战 / 建议 / 未知”模块。

### 6.3 Outside-in 报告的 company-specific 表达必须克制

允许说：
- “外部 Evidence 更支持……”
- “对词元云集的方向性含义是……”
- “结合当前定位，更值得验证的假设是……”
- “若内部 Evidence 与此一致，则……”

不要把以下内容写成已被 Research 证明：
- 具体产品架构；
- 组织设计；
- 精确资源配置；
- 客户分群权重；
- 实施阈值或时间门槛；

除非已有足够内部 Evidence。

### 6.4 Sources

- 关键外部事实必须能追溯到具体 Source；
- 优先一手来源；
- 正文保持 CEO 可读性，Source 可用脚注、尾注或附录承接；
- 不需要把完整搜索记录暴露在报告中。

### 6.5 Language｜中文成稿

CEO-facing 内容默认以自然中文完整表达。

有自然中文表达时，不保留方法性英文词，例如：
- Evidence → 证据
- Boundary → 适用边界
- Framework → 框架
- owner → 负责人 / 决策人
- leading hypothesis → 当前最值得验证的解释
- top-down → 一号位牵引 / 自上而下

仅保留公司已稳定使用、翻译反而降低准确性的术语，如：
`AI-native / Agent / TKOS / Token / API / DRI` 等。

---

## 7. Quality Standard｜最终只检查五件事

1. **Answer**：是否真正回答 Strategic Issue？
2. **Research**：关键结论是否来自高质量、可追溯、具有区分力的 Evidence？
3. **Analysis**：答案是否由 Evidence 推出，而不是一个听起来聪明的故事？
4. **Company Translation**：外部 Finding、方向性含义与 company-specific Hypothesis 是否被正确区分？
5. **CEO Value**：相比研究前，CEO 是否获得了实质性的认知增量？

> **不要为了通过 Quality Standard 而机械逐项展示。标准用于控制结果，不是报告模板。**

---

## 8. Common Failure Modes｜只防最重要的几类

1. **Topic Research**：研究了主题，却没有回答 Strategic Issue。
2. **Plausible Synthesis**：故事很顺，但关键结论没有真正被 Evidence 支持。
3. **External-to-Company Leap**：从外部趋势直接跳到词元云集具体 Design / Recommendation。
4. **Confirmation Bias**：新 Evidence 被解释成支持原 Working Judgment。
5. **Framework Collage**：用多个框架或发现拼成“完整答案”，没有一条主线。
6. **Source Vagueness**：关键 Evidence 只有机构名或泛化行业叙事，无法追溯。
7. **Language Leakage**：内部 Research 术语进入 CEO 成稿，造成中英夹杂与过程感。

---

## 9. Human / System Boundary

S03 不负责：
- 替 CEO / 管理层形成正式 Judgment 或 Agreement；
- 决定会议、Routing 或后续流程；
- 创建 / 修改 / 关闭 / 重开对象；
- Research Task 的系统分发、提醒、权限与回收；
- Context Retrieval、Ontology 或 Agent Orchestration 的技术实现。

Method 定义的是：

> **什么样的 Deep Research，能够在有或没有完整内部 Context 的情况下，都为 CEO 提供可靠、可讨论、有认知增量的研究输入。**

---

## 10. Current Calibration Position

当前不继续围绕 sparse-evidence Case 增加 Gate。

已确认的主要方向是：

- 有完整内部 Source 时，S03 应完成 Full-context Research；
- 暂无内部 Source 时，S03 应自动切换为 Outside-in Research，而不是拒绝作答；
- Outside-in 的核心要求不是降低研究深度，而是**降低 company-specific 结论强度**；
- 对公司的具体 Design / Recommendation 若缺少内部 Evidence，应明确保持为待验证 Hypothesis；
- 后续进入 Agent 联调后，再验证 Internal Context Retrieval 与 outside-in / full-context 之间的动态切换。
