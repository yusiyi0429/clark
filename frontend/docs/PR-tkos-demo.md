# 服务端数据层 + 四个 Agent + 访问门 + demo 内容包

自 `origin/main` 起的五次提交。主线只有一条：**把 TKOS 从一份前端演示，变成一个真的会自己研究、自己给判断、并且把判断持久化的系统**；最后一次提交把王总那场 demo 的内容按 Word 包原文装了进去。

## 为什么这些改动要一起进

`a3d6e80` 把数据层搬到服务端之后，Agent 才有地方跑；Agent 跑出来的东西要落到判断板上，才需要 `types.ts` 里那组新对象；判断板有了内容，首页右栏才有东西可显示。中间任何一步单独合进去都是一个既不能演示、也不能自测的中间态。

## 1｜数据层搬到服务端（`a3d6e80`）

`client.ts` 从 2900 行缩到 138 行：它现在只是一个 RPC 客户端，54 个方法一字未改地打到 `POST /api/data`。实现全部搬进 `lib/data/store.ts`（server-only）。

- **一个 RPC 端点，不是 54 条 REST 路由。** 这不是公开 API，只被我们自己的前端调用。1:1 映射让 `client.ts` 的调用点真正做到一个字不改；铺 54 条路由只是把同一件事写 54 遍。
- 安全边界：方法名必须命中白名单（白名单就是 `api` 自己的键），参数必须是数组，不接受任意属性路径，不做 eval。
- `lib/data/persist.ts`：对象库落盘到 `.data/store.json`，防抖合并。**种子指纹只哈希数据集的身份**（议题 id+标题、判断 id+陈述、人、域），不哈希整个 store —— 哈希整个 store 的那一版里，`TODAY` 一变指纹就变，快照被判定为「种子已变」丢弃，一号位周一用完周二回来发现对话和报告全没了，而日志里只有一句「种子已变」。
- `lib/agent/models.ts`：火山方舟多模型槽位（PRO / FLASH / ALT）。ALT 刻意选**不同家族**的模型 —— 同一家族的第二次调用不是独立第二源，是同一个偏见说两遍。

## 3｜A4 深研 / A2 定题 / A10 写回 / A6 观测（`457d8a3`）

四个 Agent 加两个共享模块。共享模块存在的理由是三个坑每个 Agent 都会踩：

- `lib/agent/json.ts` —— `response_format: json_object` 挡住裸引号；`finish_reason === "length"` 当成失败而不是当成结果；剥 ```json 围栏。**结构保证胜过求模型别那么干。**
- `lib/agent/rules.ts` —— 确定性的质量规则写成代码（p0 拦截 + 修复，p1 只记录），需要判断力的那些才交给模型。

## 4｜判断板 + A6 观测 + 访问门（`5320a1c`）

- `components/advisor/judgement-board.tsx` 取代 `probe-map.tsx`。上下两层：**上半层是参谋给的、还没经过一号位的；下半层是他确认过的公司口径。** 层由 `confirmed` 在不在决定，没有「基本确认」这种中间态 —— 留了中间态的地方最后都会堆满中间态。
- 下半层每条必须带 `support`：只记「07-15 会上确认」，半年后回头看只知道**确认过**，不知道**凭什么**；而真要重新打开一条判断时，要检查的恰恰是那个「凭什么」还成不成立。
- `lib/access.ts` / `proxy.ts` / `/access`：演示环境的口令门。Next 16 把 `middleware` 改名 `proxy`，跑在 Node runtime 上，所以 `node:crypto` 可用。三态错误：401 是密码错，503 是服务端没配（这条过去被渲染成「暂时无法验证，请稍后再试」—— 把配置问题说成临时故障，等于让人一直重试一件永远不会成功的事）。

### 一道缝，不是一个分支

`TKOS_MODE` 是 demo 版与 MVP 版之间**唯一**的开关（默认 `demo`，`live` 走真模型）。分支或者第二个仓库看起来更干净，代价是两边会各自长出对方没有的修复 —— 而演示前一天发现的那个 bug，永远是在另一边修的。

缝只在两处张开：内容从哪份种子来；以及 demo 下 `ensureDeepResearch` 直接返回、一次模型都不叫。

### 快捷条走剧本，输入框走真模型

点包里那几句原问题 → 逐字吐出包里的原答案（`AdvisorPreset.scripted`）；自己打字 → 真的 deepseek。这两件事必须同时在，否则演示要么像录像，要么在关键一问上翻车。

走不走剧本由**数据**决定而不是环境变量：那是这一组问答的性质，不是整个进程的性质。

### Oasis 种成潜在议题，不是已升级

Package 01 的对谈结尾是一号位说「把它作为一个战略议题继续研究」，Package 02 的首页清单里它已经是当前战略议题 —— 后者是前者那次升级**之后**的状态。所以种成潜在议题，报告与判断板预先备好，演示时当场按下去。种成已升级会省事，代价是把演示里最重要的那一下变成一张截图。

## 顺手改掉的四处假话

1. **`IssueResearchStatus` 加了 `idle`。** 原来没报告就一律算「进行中」—— 屏幕上一个转着的圈，代表的却是一件没有人在做的事，而一号位会一直等它。
2. **承接人不再默认回落到域 DRI。** 回落的那一版里，这个域下每一件议题都长出一行「等刘明华回传」，包括从来没交给过任何人的 —— 一个人同时「欠」着九件事，而他其实一件都没被要求过。
3. **已部署的议题不再显示研究进度**，改显示部署之后的当前状态。它的研究早就结束了。
4. **`Candidate` 不进「进行中」。** 它还是潜在议题，归左上角那扇窗。混在一起之后，「我手上到底有几件事」这个问题就再也没有答案了 —— 而那一列存在的全部意义就是回答它。
