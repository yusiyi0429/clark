## 0｜这一版是什么

- 读者是**词元云集的 CEO 刘明华**。业务域是本体里他自己的那八个（D-01…D-08），DRI
  那一栏现在写的是**岗位**（「CEO」「产品负责人」）—— 本体是故意把具名 DRI 换成岗位的，
  六个岗位的说明里都写着「在位人待确认」。屏幕上照实写岗位，不替他填人。
  AIDC / 词元云集 / 房懂懂那三块是王总那一层的集团生意，只在 `mode=demo` 那一档出现。
- **上线第一天是空屏：一件议题、一张卡都没有，连潜在议题那一屏也是空的。这是对的。**
  首页两个页签空着、八个域的计数全是 0、提请台上什么都没有 —— 不是数据没导进来，
  别当故障排查（`store.candidate.test.ts` 钉住的就是这几条）。
  理由是来路：进这份清单只有三条路 —— 雷达按公司布下的靶点抓回来的、DRI 押上名字
  递上来的、他自己提的（「+ 我自己有一件事」，在同一屏上）。预置几条「已经摊在提请台上」
  的卡，等于替这三条来路各编了一次来历，而屏幕上分不出哪一条是编的。
  本体那九条议题仍然生成在 `seed-tokenking.ts` 里（生成器照本体如实生成，那是它的职责），
  只是 `store.ts` 不装进来；`mode=demo` 那一档照旧摊满，王总那一场要的就是一屏内容。
- **第一天实际能进来的只有他自己提的那一件。** 雷达（自动抓取）还没接；A1a 的立案
  写回也还没接（`agent/a1a/apply.ts` 现在只接了「判为噪音」那一条），所以 DRI 那条路
  也要等。他在潜在议题那屏按下三个键之一，那件事才进入某个域 —— 域是卡片带过去的
  （`disposeCard`），本体里没有「议题属于哪个域」这层关系。
- **两处模型调用是自动起的，不用他点任何按钮**（2026-08-19 改成这样）：
  - 一条潜在议题被建出来 → 立刻一轮 **A3 预研**（`ensurePreResearch`）。所以他敲下
    「+ 我自己有一件事」那一下就是一次模型调用；A1a 的立案写回接上之后，雷达抓回来的
    每一条也走这里。
  - 他在潜在议题那屏按下「聊聊」（转成战略议题）→ 立刻一轮 **A4 深研**
    （`ensureDeepResearch`），深研落库后接着一轮 **A5 读成判断**（`ensureJudgements`）。
    卡上那句「深度研究进行中 · 报告就绪后提醒您」从这一刻起是真的 —— 原来它要等他点进
    「议题研究」那一页才真有东西在跑。
  三处都**失败不自动重开**（重试烧钱，而且会把失败藏起来），也都**在 demo 那一档完全
  不跑**（`store.triggers.test.ts` / `store.triggers.demo.test.ts` 钉的就是这两头）。
  他要重来：预研没有重试入口（等下一条议题），深研走「打回重研」。
- 用户规模：**自己人，三五个**。没有账号体系，一道共用口令挡在所有页面前面。
- 单进程单写者：对象库在内存里，落盘到一个 JSON 快照。**不能开多副本**，两个
  副本会各写各的快照，后写的覆盖先写的，而屏幕上看不出任何异常。
- 图谱、模型都是外部依赖，都会挂。挂了的表现在下面第 4 节。

## 1｜上线前必须做的四件事

### ① 把种子冻起来

`TKOS_SEED_FROZEN=1`。**上线那一刻就是冻结点。**

不冻的规则是：种子文件的指纹跟快照里那份对不上，就丢弃快照从种子重建。这条规则在
开发期是对的（改了种子却看不到变化，会排查很久）。上线之后它反过来杀人：谁动一下
种子文件（改个示例文案都算），下一次重启就把一号位真正录进去的议题、判断、决定
**全部抹掉换回示例数据**，而日志里只有一行 warn。

冻结之后种子改动不生效，`/api/health` 的 `seed.drift` 会变成 `true` —— 那句话的
意思是「种子文件跟快照对不上，冻结着所以没重建，但你那次改动没进去」。真要换种子：
先把快照文件挪走，再放开开关。

`TKOS_KEEP_SNAPSHOT=1` 不是它的替代品，那是开发期「这一次先别重建」的临时开关。

### ② 确认跑的是真模型，不是罐头

`TKOS_MODEL_MOCK` **不能是 1**，`TKOS_MODE=live`。

一台跑罐头答案的机器从外面看和真机一模一样。真出过一次：「怎么不花 token」
「产出怎么每次一个字都不差」被查到了别的地方去。所以 `/api/health` 里有
`upstream.modelMock`，发布后先看这一项。

`TKOS_MODE` 不是 `live` 时，A1a 那条链路走预置内容不叫模型（`store.ts` 里的 `DEMO`）。
给王总演示时要的就是这个；MVP 要的不是。

### ③ 决定图服务这条链路防不防中间人

现在图服务是 **IP + 自签证书**，所以 `TKOS_GRAPHKNOWLEDGE_VERIFY_TLS=0`。它的代价
写清楚是这一句：**这条链路不校验证书，公司的战略议题、判断全文在传输中不防中间人。**
内网私有网络里可以接受，走公网不行。

行动项（Sean / 运维侧，不在前端仓库里）：图服务换域名 + 正式证书，或者把这一跳收进
私有网络。做完之后**把这个变量删掉**，不要留着「反正现在能跑」。

它现在露在 `/api/health` 的 `upstream.graphknowledge.verifyTls` 上，就是为了不让它
变成一个没人记得的开关。

### ④ 生成访问口令，不要手填

跑 `deploy/ecs/configure-demo-access.sh <密码>`，它会自己生成 `TKOS_ACCESS_SECRET`。
两项缺任何一项 = 谁都进不去（`/access` 会直说并且不显示输入框）。

这道门的代价见第 2 节，先读完再定密码。

## 2｜共用口令这道门，代价是什么

只有一道口令，没有账号。三五个自己人用，这个取舍是划算的 —— 但它的性质要写明白，
不能等出事的时候才发现没人知道：

- **一份泄漏等于全量泄漏。** 谁把密码转给了谁、谁的电脑上留着，都查不出来。台账
  （Run 记录）里也没有「是谁点的」这一栏 —— 这一版不区分人。
- **撤销只能全员换口令。** 要踢掉某一个人，唯一的办法是换 `TKOS_ACCESS_SECRET`
  （已登录的人全部掉线，cookie 签名对不上），然后把新密码发给其余人。
- **登录后那个 cookie 本身就是凭据。** 它是 HMAC 签名的，拿到 cookie 值的人不需要
  密码就能进，对着云上那份也一样能进。所以：不要在截图、日志、聊天记录里带上它。
- 没过门的接口一律 401，页面重定向到 `/access`。公开的只有三条：`/access`、
  `/api/access`、`/api/health`（存活探针，无鉴权、无副作用）。

真要按人管控（谁看得见哪条议题、台账里记得住是谁），那是账号体系那一轮的事，不是
给这道门加参数能解决的。

## 3｜环境变量：缺了会怎样

完整清单以 [`.env.example`](../.env.example) 为准（`docker-compose.yml` 是本机验证
用的同一份清单）。这里只列**这一版会咬人的那几个**：

| 变量 | 缺了/配歪了的表现 |
| --- | --- |
| `ARK_API_KEY` | pro / flash / seed 三个槽位没模型。启动日志里 `[tkos:models] 没有可用的 pro 槽位`。深研那一排页签同时少两栏（「DeepSeek」和「豆包」）—— 它们共用这一把 |
| `BEDROCK_API_KEY` | **一把 key 撑两条链路**（ALT 与 SYNTH），所以缺了是**一次少两栏**：深研那一排页签剩下「DeepSeek」「豆包」。而判断板的主源本来是「ChatGPT」那一份，主源顺位会落回 DeepSeek 那一条。**这是正常降级**，屏幕上和这一轮的运行记录里都写明换了谁 |
| `TKOS_GRAPHKNOWLEDGE_BASE_URL` | 没配时请求压根发不出去，异常里会明说「地址是空的」，不要读成「服务挂了」 |
| `TKOS_GRAPHKNOWLEDGE_AUTH` | 401/403 报的是「拒绝认证」，跟「服务不可达」是两条排查路径。形式必须是 `user:password`（按**第一个**冒号切，密码里可以带冒号） |
| `TKOS_ACCESS_PASSWORD` / `_SECRET` | 缺任何一项谁都进不去 |
| `TKOS_DATA_DIR` | 容器里是 `/app/.data` 且**必须挂卷**。不挂卷 = 容器一重建，一号位录进去的东西全没 |
| `TKOS_CODE_SHA` | `/api/health` 的 `commit` 是 `dev`，线上跑的是哪一版答不出来 |
| `OPERATOR_TOKEN` | 缺了 `POST /api/signals/inbox` 一律 503，抓取作业推不进来；和作业那边 `TKOS_INBOX_TOKEN` 不一致则 401。两种都在 `[tkos:inbox]` 前缀下 |
| `TKOS_SEARCH_PROVIDER` + 对应的检索 key | 「主动开始扫描」这一轮**在容器里跑**，检索是它的第一步。一家都用不上时那一轮直接失败，屏幕上写清是缺哪个变量 —— 不会假装在扫。（这个键原来是去实验台起 run 的，靠 `TKOS_LAB_BASE_URL` / `_PASSWORD` / `_FROM_RUN` 三位；2026-08-31 整条搬回本仓库，那三位删了） |

方舟这边只剩一个出口了（模型广场：`ARK_API_KEY` + `/api/v3`，出 pro / flash / seed）。
套餐那个出口（`ARK_AGENT_API_KEY` + `ARK_PLAN_BASE_URL`）2026-08-25 起没有模型走它，
两个变量一起删了 —— **配着却没有任何代码去读的 key 是个陷阱**：控制台里看着开通了，
产品上一个字都不经过它。已经配了的机器把它们从环境里删掉，留着不会报错也不会生效。

模型 id 的覆盖变量跟着别名走：`ARK_MODEL_DEEPSEEK_PRO` / `ARK_MODEL_DEEPSEEK_FLASH` /
`ARK_MODEL_DOUBAO_SEED`。老名字 `ARK_MODEL_PRO` / `_FLASH` / `_ALT` **已经没有任何代码
读它们**，配了不生效。

SEED 那个槽位（深研那一排里的「豆包」）就在这把 `ARK_API_KEY` 上，**不需要第二把 key**：
同一条 `/api/v3`、同一套请求体，多出来的成本只有 token。默认发的模型名是
`doubao-seed-evolving`；账号里开通之后叫什么（带不带日期后缀、要不要换成推理接入点
`ep-xxxxxxxx`）是部署期才知道的事，走 `ARK_MODEL_DOUBAO_SEED` 覆盖 —— 填错的表现是那一栏
404（`ModelNotOpen` 或 `InvalidEndpointOrModel.NotFound`），别的几栏照跑。

ALT 与 SYNTH 两个槽位都在 Bedrock 上（Claude Opus 5 与 GPT-5.6），**同一个账号、
同一把 `BEDROCK_API_KEY`、同一个域名，但是两个口**：

- `BEDROCK_REGION` —— **拼进域名**的（`bedrock-runtime.<region>.amazonaws.com`），
  不是请求参数。不填走 `us-east-2`。一处改，两个口一起走。
- `BEDROCK_BASE_URL` —— GPT 那个 OpenAI 兼容口的整条地址覆盖（带 `/openai/v1`）。
  要的是 **`bedrock-runtime`**：`bedrock-mantle.<region>.api.aws` 那个域名答得出话，
  但对这个账号里 Claude 与 GPT 的每一个模型 id 都回 404，最容易让人以为是 id 写错了。
- `BEDROCK_ANTHROPIC_BASE_URL` —— Claude 那个口的整条地址覆盖，**只到域名为止**
  （剩下的路径由 SDK 自己拼）。和上面那个是两个变量：共用一个的话，配一条带
  `/openai/v1` 的网关地址会把 Claude 这一条一起打歪，而它回的 404 看起来像 id 写错了。
- `BEDROCK_MODEL_GPT56` —— 默认 `us.openai.gpt-5.6-sol`。
- `BEDROCK_MODEL_OPUS5` —— 默认 `us.anthropic.claude-opus-5`。

两个默认值都是「推理配置」那种 id（`us.` 前缀）。不带前缀的基础模型 id 在这个账号上是
INFERENCE_PROFILE-only：GPT 那边直接发回 404，Claude 那边回 400 并在原话里点名要换成
推理配置的 ID 或 ARN。

深研 2026-08-26 当天还短暂有过第五条（OpenRouter 上的 Ox Alpha），同一天整条撤掉了 ——
撤的时候连 `OPENROUTER_API_KEY` / `_BASE_URL` / `_MODEL_OX_ALPHA` 三个变量一起撤，理由和
上面套餐那一段是同一条：**配着却没有任何代码去读的 key 是个陷阱**。已经配过的机器把这三个
从环境里删掉。

四条链路**各跑一整套深研框架**：各自编命题、各自联网取证、各自写报告、各自过出口对账，
同时跑、同时显示、各自计时。所以少一条链路少的是那一栏，不是报告本身；几条全跑不成
这一轮才算挂。

★ 这几条必须**互不同模型家族**。理由不是「要用不同厂商」，是自己判自己会通过自己的失败
模式 —— 几条同家族的话，那几份报告会一起漏掉同一个来源，而屏幕上仍然摆着几栏，看起来像
互相印证过。配歪了启动日志会告警（只告警不阻断）。

## 4｜三个口子，出问题先看哪一行

### `GET /api/health` —— 无鉴权，判活 + 判「这台跑的是什么」

```bash
curl -s http://127.0.0.1:3120/api/health
```

一次答五个问题：`commit`（哪一版）、`mode`（真数据还是演示内容包）、
`upstream.modelMock`（是不是罐头）、`upstream.graphknowledge.verifyTls`（防不防中间人）、
`seed.{frozen,drift}`。

`mode` 默认 `live`。**`demo` 那一档整套内容是王总那一场的原文**（时间停在 7 月 15 日，
预研深研全预置，一次模型都不叫），而屏幕上没有一处说这是示例 —— 所以要从外面问得出来。

`seed.drift` 三态：`false` 种子与快照一致；`true` 对不上（冻结着，没重建，那次改动
没生效）；`null` 这个进程还没读过快照 —— 探针不碰对象库，所以刚起来时是 `null`，
这不是故障。

### `GET /api/graphknowledge/check` —— 图谱这条链路的主验收口，不调模型

```bash
curl -s "http://127.0.0.1:3120/api/graphknowledge/check?recipe=S03"
```

要过访问门（带 cookie）。逐层往下走到锚点与整条配方装配，哪一层断的写在
`stoppedAt` 上。`?recipe=S01|S02|S03` 换成整条配方装配；不给就只验最后一跳。
不认识的参数一律 400（曾经 `?recipe=S03` 被静默忽略，于是台账上记着「S03 已验」，
实际跑的是另一组参数）。

**它不会回显任何凭据。** 认证只报「配了 / 没配」—— 这个结构是暴露在 HTTP 上的。

### 日志前缀 —— 按链路 grep

`[tkos:models]` 槽位与计费告警 · `[tkos:persist]` 快照与种子指纹 ·
`[tkos:graphknowledge]` 图谱 · `[tkos:access]` 访问门 · `[tkos:task]` 后台任务 ·
`[tkos:a1a]` `[tkos:a3]` `[tkos:a4]` `[tkos:a5]` `[tkos:a6]` `[tkos:a6x]` `[tkos:a10]`
各条链路（`a6x` 是 A6 萃取的文本卫生违规，只记不挡）。`[tkos:a5]` 除了 p0 还会记
一种情况：**这次一条判断都没上板**（模型交了几条但全被板上的去重挡下，或整形后为空）
—— 屏幕上那时是一块空板，原因只在这一行里。

### `POST /api/signals/inbox` —— 抓取作业的收件口，机器专用

受 `x-operator-token` 保护（值 = `OPERATOR_TOKEN`），**在访问门的白名单里**（见
`src/proxy.ts`：推它的是机器，没有访问 cookie）。按 `dedupe_key`（归一化后的 URL）
幂等：同一条 URL 再来一次只更新研判，不新增，也不动一号位已经做过的处置。

日志一行一批：`[tkos:inbox] run <run_id>（扫描于 …）收到 N 条 → 新增 x / 更新 y`。
排查顺序：401 就是口令不一致（不是网络）；400 那句话会点名是第几条的哪个字段，
契约破了在这里看得见；503 是这台机器压根没配 `OPERATOR_TOKEN`。

**这一侧不做任何过滤**：作业给什么就收什么、就显示什么。阈值只在实验台调
（`docs/superpowers/specs/2026-08-19-catching-signal-rollout-design.md` §9）。

## 5｜台账（Run 记录）怎么读

每条链路跑完落一条 Run 记录。三个 `status` 的意思不一样，**混着数会得出错的结论**：

- `ok` —— 跑完了，有产出。
- `ignored` —— 判完了，什么都不该动：A1a 判信号是噪音、A6 判这一轮没有动摇判断。
  **产出为空就是正确结果。** A6 那条链路唯一要看的指标（「十四轮聊下来落了几轮图」）
  就是从这里算出来的。
- `failed` —— 图服务不可达，就地停住。屏幕上是一次失败，台账里数得到。

`contextMode` 三态同理：`anchored` 装了公司上下文；`external_only` 开了但图里没有
对应议题（**正常分支，不是故障**）；空串 = 这条链路从来没开过上下文（A6 和 A5 是
这一支 —— A5 读的深研报告装配时已经带过公司上下文，为同一批材料再打一次图服务是
多花一次钱加一条失败路径）。

`external_only` 里面还分两档，**看 trace 里那条「转纯外部」的 `companyStateChars`**：
非 0 表示这一次仍然装上了【公司经营状态】（本期 Outcome、八个域的在版判断这些，跟锚点
无关，一次调用就拿得到），只是没有这条议题的既有认识；0 才是真的什么公司材料都没有。
两次运行的产出差得远时，先看这一栏 —— 它是唯一看得出「手上材料一样厚吗」的地方。
屏幕上对应的两句话是「只有公司经营状态，没有这条议题的既有认识」和「本次无公司上下文」。

质量门那两个字段**问的不是同一件事**，A3/A4 才有：

- `violations` = 最后一轮还剩的违规。带 `degraded: true` 的那种是重修两轮都没救回来，
  产出照样落盘，看得见才修得掉。
- `firstRoundViolations` = **第一轮**被挡下来的违规原文，**重修成功也留着**。要问
  「哪条规则老是被违反、prompt 该调哪一句」，靠的是这一个 —— 绝大多数违规是第一轮犯、
  第二轮改对的，只看 `violations` 那部分全看不到。一轮就过的运行**不写这个字段**
  （不是写空数组）：空数组和「没记」在统计时分不开。

窗口：Run 记录留最近 200 条，上下文快照留 64 份。老记录里的快照取不回来时，那条
记录上是 `snapshotEvicted: true` —— 「取不回来」和「本来就没有」要分得开。
