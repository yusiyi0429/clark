## 我自作主张的地方（你没说过，我按判断做了）

这一节是重点。以下都是我在没有依据的情况下自己定的，**每一条都可能被你推翻**：

**1. 视觉语言：墨/纸/琥珀 + 衬线标题 + 等宽溯源。**
理由是 Clark 不该看起来像聊天软件或资讯客户端（四个"不是"的前两条），我往"内参/呈报件"的方向做了。**这是审美判断，没有依据，你觉得不对就换。**

**2. 溯源徽章作为全局记忆点。**
四类来源（外部事实/内部事实/人的判断/Agent 推演）在每一屏都出现，视觉上很吵。我认为这个吵是对的——它是 Clark 区别于任何 chatbot 的东西。但如果王总觉得烦，第一个该砍的就是它。**这是全原型里我最不确定、但最舍不得的一个决定。**

**3. 议题内容我编了一个。**
用的是「AIDC 私有化诉求 vs 产品通用化路线」，因为它符合 MC-5 说的"跨业务资源配置类最有感"。**这不是真实议题**，只是形状对。⚠8/15 议题池确认后要换成真的——用真数据做线框是 v0.1.1 第 7 节自己写的下一步。

**4. 我把"建议动作"做成了 Agent 推演徽章。**
即：Clark 的建议本身也标了来源类型，不享有特权。这是我加的，文档里没有。理由是如果 Agent 的建议不标来源，"每句话带出处"就是选择性执行。

**5. 交接包的"披露我的倾向"开关默认关但可见。**
文档只说了"默认脱敏、可选披露"，没说这个开关长什么样、放哪。我把它放在升级按钮正上方——**藏起来等于产品替 CEO 做了判断**。

**6. Issue 列表按"需要你判断的"排序，不按时间。**
文档没说。这是从注意力契约倒推的。

**7. 校对工位未标说话人时禁用提交。**
文档没说。理由：分歧归属错会直接污染 Decision State 四分类，进而污染 Brief 的三分类标注，是链路上最早的污染源。

**8. 影子评审台的"归因"字段是我加的。**
MC-2 风险栏写着"精度不达标 → 复盘归因（靶点质量 vs 管道质量）"，但没有任何 Feature 承接"归因"这个动作。没这个字段，那条风险处理是空话。
