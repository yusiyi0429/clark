# 相一：秘书空间 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `/access` 上加一个 CEO / 秘书滑块，建起 `/sec` 这个秘书空间，把编排会议
搬过去，并给纪要审阅建一个原来没有的列表页。

**Architecture:** `/sec` 是纯页面层的新分区——`proxy.ts` 里一号位那把口令一过就
`next()`，对路径不做判断，所以 `/sec/*` 天然进得去；`scope.ts` 那张表分的是调用者的
真实身份（`actor.role`），而秘书用的就是一号位那把共享口令，所以两个文件这一相**一个
字不改**。座位（seat）只决定验完口令落到哪一页，是一个 httpOnly cookie，只在服务端读。
"CEO 侧只读"不靠读 cookie，靠**路由蕴含座位**：`(tkos)` 下渲染的那一份传 `readOnly`
（那件事在相二做）。

**Tech Stack:** Next.js App Router（`src/app`）、React 客户端组件、Tailwind v4、
CSS Modules（`access.module.css` 的既有做法）、vitest（只测纯函数）。

**Spec:** `docs/superpowers/specs/2026-09-02-两个空间与动态面板-design.md`

新建 `src/lib/seat.ts`：

```ts
/**
 * 座位 —— 验完口令之后，这个人坐在哪一侧。
 *
 * ## 它不是权限
 *
 * 这一版一把共享口令开两个空间（`src/proxy.ts` 里一号位那把口令一过就放行，对路径
 * 不做判断）。所以座位答的是「你现在坐在哪个位置上」，不是「你有没有资格」——
 * 坐在秘书位上的人只要知道 `/` 这个地址，照样进得去一号位那一侧。
 *
 * 把这句话写在这里，是因为下一个人看到一个叫 `seat` 的 cookie 时最自然的假设恰好
 * 是反的。真要立边界时的落点不在这个文件：给秘书发独立口令、人表里加一个
 * `role: "secretary"` 的人、`METHOD_SCOPE` 加一档、`api/data/route.ts` 那句
 * `scope !== actor.role` 改成按角色集合判。
 *
 * ## 为什么 httpOnly
 *
 * 屏幕上没有任何一处需要在浏览器里读它：一号位那一侧的页面全在 `(tkos)` 下、秘书
 * 那一侧全在 `/sec` 下，**路由本身就蕴含了座位**。所以它只在服务端被读一次
 * （`/access` 那一页拿它把滑块拨到上次的位置），拿不到 JS 那一侧去。
 */

export const SEAT_COOKIE_NAME = "tkos_seat";

/** 一个月。它只是个偏好，过期了重新选一次就是，不必和口令那 12 小时同寿。 */
export const SEAT_COOKIE_MAX_AGE = 60 * 60 * 24 * 30;

export type Seat = "ceo" | "sec";

/**
 * 把任意一个值收敛成座位。**入参一律不可信** —— 它来自 cookie 和 POST body。
 *
 * 不做大小写宽容、不 trim：这个值是我们自己写进 cookie、自己从滑块发出去的，
 * 两头都只会是那两个字符串。宽容会让「读到了一个我们没写过的值」这件事悄悄消失，
 * 而那件事本身就是信号。
 */
export function seatFrom(candidate: unknown): Seat {
  return candidate === "sec" ? "sec" : "ceo";
}

/** 这个座位验完口令之后落到哪一页。 */
export function landingFor(seat: Seat): string {
  return seat === "sec" ? "/sec" : "/";
}
```

```ts
  /*
   * 座位跟着口令一起写。**它不是第二把钥匙** —— 见 `lib/seat.ts` 开头那一节：
   * 这一版一把口令开两个空间，这个 cookie 只决定验完之后落到哪一页。

   * 不跟 access cookie 共用一次 set：那一个是 12 小时的凭据，这一个是一个月的偏好，

  response.cookies.set({
    name: SEAT_COOKIE_NAME,
    value: seatFrom(seat),
    httpOnly: true,
    secure: request.headers.get("x-forwarded-proto") === "https",
    sameSite: "lax",
    path: "/",
    maxAge: SEAT_COOKIE_MAX_AGE,
  });
```

```ts
/** 只接受站内路径，挡掉 `//evil.com` 这种开放重定向。没带就回 `null` —— 那时滑块说了算。 */
function safeNextPath(candidate: string | undefined): string | null {
  if (!candidate) return null;
  if (!candidate.startsWith("/") || candidate.startsWith("//")) return null;
  return candidate;
}
```

- [ ] **Step 1: 视图**

新建 `src/app/_views/sec-debriefs-view.tsx`：

```tsx
"use client";

import { AsyncBoundary } from "@/components/async-boundary";
import { DebriefColumn } from "@/components/agenda/debrief-column";
import { api } from "@/lib/data/client";
import type { DomainSummary, IssueSummary, MeetingSlot } from "@/lib/data/types";
import { useResource } from "@/lib/use-resource";

/**
 * 纪要审阅 —— 秘书那一侧的整页。
 *
 * ## 它是把首页右栏那一叠搬了过来，不是重做一份
 *
 * 同一件事在屏幕上只该有一套做法：按会分组、摞着、展开才铺开、两颗键（无需再议 /
 * 还需再议）。所以这一页直接用 `DebriefColumn`，一行都不抄。它本来就是自足的——
 * 判据只有 `debrief` 一个，外面传一份「全部的」还是一份「会开完的」都不影响它的内容。
 *
 * ## 为什么审纪要在这一侧
 *
 * 「这场会谈拢了没有、要不要再开一次」是一个读完材料就能判的事实问题，不是一次拍板。
 * 摆在一号位面前，他每天要先从一堆不用他管的事里把要拍板的那几件挑出来 —— 而挑
 * 这一下正是这个系统本来要替他省掉的东西。
 *
 * ## 那一栏要一个有界高度的父块
 *
 * `DebriefColumn` 自己是 `grid-rows-[auto_minmax(0,1fr)]`，里面那一格靠
 * `overflow-y-auto` 滚。父块不给高度的话它会一直长，页面整体滚 —— 那时抬头那一行
 * 会跟着滚走，而他正是靠抬头认出「这几张是同一场会」的。
 */
export function SecDebriefsView() {
  const issuesRes = useResource<IssueSummary[]>("issues", () => api.listIssues());
  const slotsRes = useResource<MeetingSlot[]>("slots", () => api.listSlots());
  const domainsRes = useResource<DomainSummary[]>("domains", () => api.listDomains());

  const refresh = async () => {
    await Promise.all([issuesRes.mutate(), slotsRes.mutate()]);
  };

  return (
    <div className="mx-auto flex w-full max-w-[900px] flex-col px-6 py-6">
      <h1 className="mb-4 text-md font-medium text-ink">待审的会议纪要</h1>
      <AsyncBoundary resource={issuesRes} skeleton={<ColumnSkeleton />}>
        {(issues) => (
          <section className="h-[calc(100vh-11rem)] overflow-hidden rounded-2xl bg-list-ground [--r:1rem]">
            <DebriefColumn
              issues={issues.filter((i) => i.debrief)}
              slots={slotsRes.data ?? []}
              domains={domainsRes.data ?? []}
              today={api.today}
              onRefresh={refresh}
            />
          </section>
        )}
      </AsyncBoundary>
    </div>
  );
}

function ColumnSkeleton() {
  return (
    <div aria-live="polite" className="space-y-2 p-2">
      {[0, 1, 2].map((i) => (
        <div key={i} className="list-block concentric px-3.5 py-3">
          <span className="skeleton block h-2.5 w-24" />
          <span className="skeleton mt-2 block h-4 w-[82%]" />
        </div>
      ))}
    </div>
  );
}
```
