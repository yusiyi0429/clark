# 议事对话层 v2 验收记录

这一份是**空表**，等真模型那一轮跑完再填。发起那一轮要 `.env.local` 里的模型与检索 key，
所以由他自己起：在界面上挑一条已经有报告的议题进对谈，连着压、给论据、按下确认，
把下面每一行照实填。

**机器答不了的那几行，谁也别替它填**：

- **§8-2 的盲测** —— 与 ChatGPT 同题各 10 轮，找评审辨认哪个是套壳流程。这是一次人做的
  对照实验，写不成断言，本轮十五个任务里也没有它的实施者。
- **§7 的跨 session 预判** —— 要在 session A 里真挑战三次口径，再开 session B 看首轮回应。
  跨 session 这件事本身可以造夹具，但「首轮回应主动写清口径」是模型行为，只有真模型答得了。
- **真模型的漂移对照** —— §7 的红线那一条要的是「带用户卡」与「不带用户卡」两组的结论方向
  一致。两组都得是真模型跑出来的，罐头脚本里两组回应都是人写的，比出来的是写脚本的人。
- **§8-1 的两个秒数、§3 的 20 轮模板句统计** —— 机检只证明埋点被真的填上了、脚本里一句套话
  都没有，秒数和 20 轮那个统计都要真模型那一轮出。

## §3 的三条：与上面 §8-2 分开写

§3 的验收有三条，**一条都不是机检能答的**。`e2e.test.ts` 里那条按 §3 编号命名的机检守的是
另一件事，别把它读成 §3 已验收。

| 项目（照规格 §3 抄） | 谁来跑 | 这一轮实测 | 过没过 |
| --- | --- | --- | --- |
| 回应形状测试：对 10 类典型输入（问事实/要解释/反驳/挑战/提假设/引证据/要判断/修正/确认/否定）各构造 3 例，回应长度方差显著（一句话到千字都应出现），无固定三段式痕迹 | 人跑，30 例 |  |  |
| 模板句检测：连续 20 轮中"更新后的判断是""仍会改变结论的未知"类句式出现 ≤2 次 | 人跑，真模型连着 20 轮 |  |  |
| 表态率：挑战类输入的回应 100% 含明确裁决（成立/部分/不成立） | 人跑 |  |  |

**`e2e.test.ts` 里那一条机检（三套脚本 15 轮一句套话都没有）守的是「脚本作者别把套话写进夹具」**：
阈值是 0 不是规格那个 2 —— 那个 2 是给真模型 20 轮定的合格线，拿它来量人写死的夹具，
等于允许脚本作者往里写两句套话还照旧全绿。
那 15 段回应是人写死的，模型一次都没开口。它跑绿只说明夹具干净，与上面这三行无关。
`system.test.ts` 里那几条反模板断言同理 —— 检的是提示词里没有固定三段式，不是模型的输出。
