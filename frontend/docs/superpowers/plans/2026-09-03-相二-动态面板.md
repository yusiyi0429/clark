# 相二：动态面板 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把一号位首页右栏从「待确认的会议纪要」换成原型里那块 iOS 锁屏式动态面板，
只装会后归他的 action item；顺带把 rail 挪到中栏左缘、中栏底色换成 `#F4F4F5`。

**Architecture:** 六个互不重叠的文件组并行做，最后一个任务把它们接到 `home-view` 上。
面板自己是纯客户端组件，数据走一个新的只读取数口 `listActionItems()`——**它不按
`confirmedAt` 过滤**，因为审纪要的人已经是秘书了（相一），秘书按下「无需再议」不该让
一号位自己的事从面板上消失。

**Tech Stack:** Next.js App Router、React 客户端组件、Tailwind v4、CSS Modules、vitest。

**Spec:** `docs/superpowers/specs/2026-09-02-两个空间与动态面板-design.md`（相二那一节）

## Global Constraints

- **原型是唯一依据。** CSS 变量名保持原型的 `--glass / --glass-hi / --glass-border /
  --dark-glass / --sheet / --on-glass / --on-glass-2 / --on-glass-3 / --shadow /
  --wp-base / --wp-a / --wp-b / --wp-c / --wp-d`，类名保持原型的，以便逐条对照。
- **原型里的示例内容一律不搬。** `ITEMS` / `FEEDS` / `SCRIPTS` / `KIND_G` 的具体条目、
  演示条、换壁纸按钮、角色切换，一个都不要进仓库。
- **卡片没有主动作 pill。** 这一版右栏装什么还没定完，一颗按下去会改数据的键不该先长出来。
- **两层之间不写标签。** 原型那三条小字（实时 / 待处理 / 参考）不要，只用间距分开。
- **`prefers-reduced-motion` 下关掉壁纸与球的动画。**
- 注释照仓库写法：中文、完整句子、说清**为什么**和上一版错在哪，不复述代码在做什么。
- 不造新词。用产品已有的词：一号位、秘书、议题、会后提炼、action item、座位。
- **有产出就记账**：`src/lib/changelog.ts` 最前面加一条 + `package.json` 版本号跟着改。
  本相收口 **v0.126.0**。**只有 Task 7 碰这两个文件。**
- **共享工作目录**：另有几个 Claude 会话在改同一份 `src`。永远用显式路径提交，
  绝不 `git add -A`；暂存前用 `git diff --cached` 确认只有自己的 hunk。
  并行提交时若撞上 `index.lock`，等一两秒重试一次。
- 命令：`pnpm lint`、`pnpm test`、`pnpm vitest run <path>`。

## Ruling — `assignedTo` 从相三挪到相二

规格把 `assignedTo` 写在相三，但同一份规格又说相二「面板这时只有『点了你名的』那一层
有内容」——那一层正是靠 `assignedTo` 算出来的。两句话对不上。

**判：`assignedTo`（确定性的人名比对，不叫模型）连同取数口一起放进相二；
`principal`（要不要拍板，模型判断）留在相三。** 否则相二交出来的是一块永远空的面板，
验收无从谈起。成本（如果判错）：相三少一个字段要加，不影响已落的代码。

### A 组产出（C、D、G 组消费）

```ts
// src/lib/data/types.ts
/** 一条 action item 归了谁。`confidence` 现在只有一档，留着是为了将来推给别人时能分档。 */
export interface TodoAssignee {
  personId: string;
  name: string;
  confidence: "explicit";
}

// DebriefTodo 上新增一个可选字段（其余字段不动）
assignedTo?: TodoAssignee;

/** 面板上一张卡的全部内容。**这是一份读出来的投影，不是库里的对象。** */
export interface ActionItem {
  /** 就是 `DebriefTodo.id`，全库唯一（`TD-<slotId>-<issueId>-<n>`）。 */
  id: string;
  text: string;
  assignedTo?: TodoAssignee;
  due?: string;
  issueId: string;
  issueTitle: string;
  slotId: string;
  /** 人话的会次（`周三 9/3 · 上午`）。取不到那一场会时是 `已开完的会`。 */
  slotLabel: string;
  /** 这场会在这件议题上的第一行。sheet 上半用。 */
  debriefSummary: string;
  /** 同一场会同一件议题的其他 action item。sheet 的「它想到的」用。 */
  siblings: { id: string; text: string }[];
}
```

```ts
// src/lib/data/store.ts 的 api 上新增；client.ts 转发；scope.ts 定 "ceo"
listActionItems(): Promise<ActionItem[]>
```

**它按当前视角过滤，调用方不再筛。** 服务端拿 `viewer()` 的 `personId` 比
`assignedTo.personId`，只回这个人的。这样面板里没有一处「我是谁」的判断——那句话
在服务端只说一次。

 * 把会后待办上那个自由文本的 `owner` 解析成「这是不是一号位」。

 * 值得单测的是**它拒绝什么**，不是它认得什么。这条链路上最坏的错是把一件事安到一个

import { resolveTodoAssignee } from "./todo-assignee";

  it("「CEO」这个词不认 —— 人表里那是一个岗位占位符的名字", () => {
    expect(resolveTodoAssignee("CEO")).toBeUndefined();
    expect(resolveTodoAssignee("ceo")).toBeUndefined();

    expect(resolveTodoAssignee("问一下刘明华")).toBeUndefined();
  });
});
