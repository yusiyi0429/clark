# 深研解耦：可调开关/参数清单，与本体召回点

2026-08-31 勘察。对象是 `runDeepResearch` 默认那一支——`a4/pipeline.ts` 的**七步链**
（`TKOS_DR_V2=0` 的四链路旧支不在本文范围，它只用来拿同一议题两边各跑一遍作对比）。

写给要把这条链单独部署、并从实验台调参的人。**每一条都标了它今天是什么状态**：
环境变量 / 入参 / 硬编码。没标"可调"的，就是今天改不动，要动得先改代码。

---

## 0. 三条必须先知道的

### ① `depth` 今天在这条链上等于没有

`Harness` 有一张 `DEPTH` 表（`searchK` / `maxProps` / `maxRounds` 三个量），
但**深研这条链从来不传 `depth`**——`pipeline.ts` 那句 `new Harness({agent:"A4", slot:"pro", …})`
没有这一栏，调用方 `store.ts` 也没传。所以它恒为 `DEFAULT_DEPTH = "high"`。

就算把它接通，三个量里也只有一个真起作用：

| 量 | high 档的值 | 在七步链上的实际效果 |
|---|---|---|
| `searchK` | 5 | **真起作用**：每条检索式向每一家取几条 |
| `maxProps` | 4 | **无效**。N2 算的是 `max(2, ceil(maxProps/8))`，而 `maxProps` 最大档才 6，`ceil(6/8)=1`，所以**任何档位都是每维 2 条** |
| `maxRounds` | 2 | **无效**。`sweep` 调 `gatherEvidence` 时写死 `{...h.budget, maxRounds: 1}` |

**要在实验台上拧规模，`depth` 是错的旋钮。** 直接给 `search_k` / `props_per_dim` /
`max_waves` 三个独立量，比修 `depth` 诚实。

### ② 一轮的时长装不进一次 HTTP 函数

默认时限 `DEFAULT_DEADLINE_MS = 25 分钟`（`TKOS_A4_DEADLINE_MS` 可改）。而且这不是
"最坏情况"——是**排期表算出来的下限**：

```
WRITE_PASS_MS    = outline 95s + 4×section 90s + closing 95s + 2×anchorGate 20s = 590s
WRITE_RESERVE_MS = reconcile 100s + 590s = 690s ≈ 11.5 分钟
```

也就是说，**光成稿那一段就要 11.5 分钟**，前面 N0+N1+N2 还要约 9.3 分钟。
单次请求—响应的形态装不下，Vercel 上必须是**起一轮 + 轮询/回调**，不能是一次同步调用。

### ③ 这条链有三处进程内副作用，解耦时要替掉

| 在哪 | 干什么 | 解耦后 |
|---|---|---|
| `openContext` → `freezeContext` | 把装配好的上下文冻结进 `contextSnapshotPut` | 要么给一个可注入的快照存储，要么允许关掉（代价：这一轮不可复现） |
| `Harness.progress` → `tasks.ts` | 往进程内任务表上报"走到第几步" | 换成回调 / SSE / 轮询端点 |
| 返回的 `run: AgentRunRecord` | 由调用方 `agentRunPut` 落库 | 原样回给调用方即可，这一处本来就没耦合 |

`A4Result` 本身是自足的（`doc` / `violations` / `evidencing` / `run` 全在返回值里），
所以真正要动的只有上面两条。

## 2. 逐节点

每个节点标三样：**模型槽位 / 输出额度 / 有没有本体召回**。

### 装配（N0 之前）· ★ 全链唯一一次本体召回

```
openContext("S03", input.title)  →  h.contextBlock
```

**这是深研全链唯一一处碰本体的地方。** 四个探针：

| 探针 | 端点 | 参数 | 今天可调？ |
|---|---|---|---|
| P0 公司经营状态 | `GET /api/v1/context/static` | `viewer`, `as_of` | viewer 走 `TKOS_GRAPHKNOWLEDGE_VIEWER`（默认 `PSN-01`）；`as_of` **有意不给环境变量** |
| P1 议题卡 | `GET /api/v1/entities/{code}?view=latest` | 锚点编号 | 锚点由检索选出，或 `anchorCode` 钉死（复现旧运行用；S03 **不认** `judgmentCodes`） |
| P2 判断演进链 | `GET /api/v1/entities/{code}?view=chain` | 议题挂着的每条判断 | 逐条串行 |
| P3 语义召回 | `GET /api/v1/context/dynamic` | **双路**：core question `k=10 / budget=6000`，议题标题 `k=5 / budget=3000` | **硬编码，由配方固定** |

拼出来的段落顺序：公司经营状态 · 议题 · 判断演进链（全版本 + `status`）· 既有共识与边界 ·
既有研究 · 双路语义召回。总预算 `MAX_CONTEXT_CHARS = 16000`，超了在装配里就抛。

**P3 的 k/budget 不随任何旋钮变，这是有意的**：改了它，"同一议题不同深度"拿到的公司
上下文就不一样，两次结果不可比。要在实验台上拧它，得先接受这条代价。

**三态**（结构保证，不是约定）：
- 命中 → `anchored`
- 锚点没找到 → `external_only`，**不是故障**；P0 照取，正文里明写"没有这条议题的既有认识"
- 图服务连不上 → 抛 `AgentRunFailed`，**整轮就地失败**（这是全链唯一会就地失败的一句）

**产物的形状**：一整段 Markdown（`renderedMarkdown`）+ 一个编号集合（`memberIds`）。
每条的认知状态（判断版本上的 `status`）被 `renderVersions` 渲染成 `v2[confirmed] …` 一行字，
**结构在这一层蒸发**。要把本体的分类信息喂进后面的节点，得先改这一层。

需要的环境：`TKOS_GRAPHKNOWLEDGE_BASE_URL` / `_AUTH`（`user:password`）/ `_VERIFY_TLS` / `_VIEWER`。
**单独部署时这台机器要能连到图服务**——连不上不是降级，是整轮失败。

### N0 锚定主体

- 槽位 `pro`，额度 `ANCHOR_MAX_TOKENS = 8000`
- **无本体召回**
- 入参只有 `title` / `scope` / `preTake`
- 硬编码：`DEFAULT_WINDOW = "当前时点 ± 未来 3 年"`、`GENERIC_MAX = 11`（主体名太泛的判据）、`LIFECYCLES`

### N1 先验草稿

- 槽位 `alt`（Opus），额度 `DRAFT_MAX_TOKENS = 8000`，`json:false` + `jsonlContinue:1`
- **无本体召回**。v0.94.0 起会收在版判断（`A4Input.judgments`），但那来自 clark 自己的库，不是图
- 硬编码：`THESIS_MAX = 150`、`ANNOTATION_FLOOR = 0.9`（标注率下限）、`UNKNOWNS_FLOOR = 5`、
  `HEDGES`（骑墙词表）、`PREMISE_PER_BUCKET = 5` / `PREMISE_CHARS = 80`（在版判断那一段的封顶）
- 四态标签 `E* / P / P! / X`，这一步一律 `P`
- 八个维度 `D1…D8` 写死在 `dims.ts`

> **额度含思考。** 2026-08-31 在 N2 上真发生过：思考吃掉九成额度 → JSON 截断 → 命题归零
> → N3 整段被跳过，**而这一轮照旧报 ok**。加长输入会静默挤掉正文。

### N2 抽命题、排检索计划

- 槽位 `pro`，额度 `PLAN_MAX_TOKENS = 8000`，`json:false` + `jsonlContinue:1`
- **无本体召回**。入参只有 N1 的草稿
- 硬编码：`MIN_PROPS_PER_DIM = 2`（实际决定条数的就是它，见 §0①）、`MIN_SOURCE_KINDS = 2`、
  `SOURCE_KINDS`（行业机构/公司披露/监管与政策/媒体线索）、`DIM_SHARE_CAP = 0.3`（单维预算上限）
- 优先级 = 承重 × 时效敏感 × 低置信，阈值 `MATERIAL_THETA = 0.7` / `FRESH_URGENT = 0.7`（`props.ts`）

### N3 分维度取证

整条链的时间大头。旋钮最多，**全部硬编码**：

| 常量 | 值 | 管什么 |
|---|---|---|
| `CHAINS` | 4 条（需求与供给 / 技术与上游 / 格局 / 政策·风险·主体） | 八维怎么分组 |
| `CHAIN_CONCURRENCY` | 2 | 同时跑几条链 |
| `MAX_WAVES` | 3 | 一条链最多几波 |
| `MAX_EVIDENCE_PER_CHAIN` | 24 | 一条链最多攒几条证据 |
| `PAGES_PER_ROUND` | 5 | 一波抓几页 |
| `EXTRACT_CONCURRENCY` | 5 | 几页并着抽 |
| `RESUPPLY_K` | 4 | 补旁证时每条种子取几条 |
| `REWRITE_TRIGGER` | 0.5 | 共源率过半就改写问法再发一波 |
| `MIN_GROUPS` | 2 | 几组独立来源才算闭合 |
| `NEAR` | 6 | simhash 距离，判转载 |
| `MIN_TRIED_FOR_NOT_FOUND` | 4 | 试过几个问法才算"已搜未得" |
| `PAGE_CAP` | 8000 | 单页正文截断字数 |
| `TIMEOUT_MS` | 30_000 | 单页抓取超时 |
| `searchK` | 5（=depth high） | 每条检索式向每家取几条。**唯一受 depth 影响的量** |

- 抽取走 `flash`（调用次数最多的一段，便宜跑量）
- 不可归属域名表（自媒体/文库农场/电商/内容农场/低信任站）写死在 `coverage.ts`
- 时窗 → 检索端 `freshness` 桶（oneDay/oneWeek/oneMonth/oneYear/noLimit），**向上取整**
- **无本体召回**

### N4 证据与草稿对账

- 槽位 `synth`，额度 `RECONCILE_MAX_TOKENS = 16000`，`jsonlContinue:1`
- **无本体召回**
- 四态 `证实 / 修正 / 矛盾 / 未验证`
- `CONTRADICTION_ABORT = 0.3`：矛盾占比过线就中止

### N5 分层成稿

- 槽位 `alt`，三次调用（大纲 + 逐节 + 收口），额度各 `16000`，`effort:"high"`、`verbosity:"high"`
- **这里是 `companyContext` 唯一被使用的地方**——装配那一次取回的整段 Markdown 在此进材料
- 节数由大纲决定（要求 3–6 节，排期按 4 节估）

### N6 出口机检

- 七条规则 `A4-N01…N07`，各自标着打回哪个节点
- `MAX_AUDIT_ROUNDS = 1`（2026-09-04 从 2 压下来）：出口对账只检不整段重写，**一轮重写 = 又一整遍 N5**，四轮里只兑现过一次、499 秒换回一条
- 锚点相关性检查走 `synth`，额度 `ANCHOR_GATE_MAX_TOKENS`
  - ⚠️ 名字里有"锚点"，但**它不回图查**：判的是判断块里模型自己写的那几条内部锚点跟这次研究有没有交集，是一次纯模型调用
- 区块支（`TKOS_DR_BLOCKS=1`）另有一套 `blocks/lint.ts` 的结构违规，与 `validateReport` 两套规则各自成立

## 4. 建议给实验台的接口

按"改动量 / 收益"排。默认值一律等于现状。

### 第一批：改字符串就能通

| 字段 | 取值 | 落到哪 |
|---|---|---|
| `search_provider` | `""` / `bocha` / `doubao` / 逗号分隔 | `providers(spec)` 已经收参数，只差一路传下去 |
| `deadline_ms` | 整数 | `deadlineMs()` 已经读环境变量，改成入参 |
| `blocks` | `on` / `off` | `blocksOn()` 同上 |
| `mock` | `on` / `off` | `modelMockOn()` 同上 |
| `graph` | `on` / `off` / `anchor_code` | 关掉 = 跳过装配走纯外部；钉死锚点 = 复现旧运行 |

### 第二批：要把硬编码提成参数

| 字段 | 默认 | 落到哪 |
|---|---|---|
| `search_k` | 5 | `h.budget.searchK`。**别用 `depth` 代替它** |
| `props_per_dim` | 2 | `MIN_PROPS_PER_DIM` |
| `max_waves` | 3 | `sweep.MAX_WAVES` |
| `pages_per_round` | 5 | `evidence.PAGES_PER_ROUND` |
| `rewrite_trigger` | 0.5 | `cosource.REWRITE_TRIGGER` |
| `min_groups` | 2 | `coverage.MIN_GROUPS` |
| `audit_rounds` | 1 | `MAX_AUDIT_ROUNDS`，`1` = 只检不整段重写（按块返修照旧） |
| `p3_k` / `p3_budget` | 10/6000 + 5/3000 | 配方里的双路召回。**开放它就放弃了跨深度可比性**，要写在实验记录里 |
| `slots` | pro/flash/alt/synth 四个别名 | 换模型做对照 |

### 不建议开放

- `MAX_CONTEXT_CHARS`（超了在装配里直接抛，不是软约束）
- `CONTRADICTION_ABORT`、`MATERIAL_THETA`、`FRESH_URGENT`（判据阈值，动了之后两轮结果的含义就不一样了）
- 不可归属域名表（它是"哪些站不算来源"的口径，不是规模旋钮）

### 形状建议

对齐实验台已有的那套（`/api/runs` + `RunIn` + `agents.SWITCHES`）：

- **开关清单要机器可读**，由服务自己声明（对应 lab 的 `/api/meta → switches`），台子照它长界面，不照文档抄一份会漂的抄本
- **给了不读的旋钮要 422**，不许静默吃掉——最坏的失败模式不是报错，是一整批真钱 run 跑完才发现自变量没接上
- **起一轮 + 轮询**，不是一次同步调用（§0②）

## 5. 部署前要解决的

1. **函数时长**：成稿一段就要 11.5 分钟，必须任务化
2. **图服务可达**：连不上是整轮失败，不是降级。要么保证网络可达，要么给一个显式的 `graph=off` 走纯外部
3. **快照落地**：`freezeContext` 今天写进程内的库，解耦后要给存储或允许关掉
4. **进度上报**：`tasks.ts` 是进程内的，换成回调或轮询端点
5. **并发与限流**：`CHAIN_CONCURRENCY=2` × `EXTRACT_CONCURRENCY=5` = 一轮里最多十个模型调用同时在飞，多轮并跑要先算清出口的限流
