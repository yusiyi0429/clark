# 目标与产出改成树 + 会议式交互的方向 · 设计稿

2026-08-10 · 已与 Sean 确认范围。明天向王总演示，今晚落地的是 §2–§5；§6 是方向说明，写给方法论团队看，不写代码。

## 1. 为什么改

两个出发点：

1. **目标与产出现在是列表，看不出结构。** 总 Outcome、八个域各自的 Outcome、每个域下的 Mission，本来是一棵树；列表把这棵树压平了，一眼看不出「公司赌的一件大事是怎么分到八个域、每个域又拆成哪几件可执行的事」。
2. **真实的大企业 CEO 在会议里做决策。** 他的信息来源是新闻、务虚会、业务汇报、专家交流、战略调研；看完之后在会上几轮提问、当场下判断、当场通知下去。他的日常是开会，不是坐在某个电脑工作台里。产品的交互要跟这个工作方式对上，而不是要求他改变工作方式。

## 2. 目标与产出：纵向的树

替换现在 `/outcomes` 页里「八个域各自赌什么」那个列表；页头的总 Outcome 原文和页尾的「一周一格」保留。

### 结构

```
公司总 Outcome（原文照录，期号 + 定稿日 + 剩余天数）
 │
 ├─ 01 战略转型 · 刘明华          ← 域一层
 │   Domain Outcome 原文 · Commitment 状态 · n/m 判断已确认
 │   （有判断在晃时：红侧线 + 那句「什么在动摇它」）
 │    ├─ 01-1 确认公司 8 月战略 Outcome   · 进行中 · 8 月上旬   ← Mission 一层
 │    ├─ 01-2 完成八 Domain 授权          · 进行中 · 8 月上旬
 │    └─ …
 ├─ 02 …
 └─ 08 …
```

- 一根主干从总 Outcome 垂下来，八个域挂在主干上，每个域的 Mission 挂在域下面。连线全部用发丝线，不用箭头。
- 每个域可以折叠；默认全部展开（demo 时一眼看到整棵树）。折叠行上仍写着「4 条 Mission」。
- 域节点点击进 `/domains/xx`（现有页面）。Mission 保持只读——那是 03 Method 的边界，树上不提供任何编辑入口。

### 节点上写什么

- **域节点**：编号、名字、DRI；Domain Outcome 原文照录；Commitment 状态（纲领原话）；`n/m 条判断已确认`；有判断在晃时加红侧线和那句具体的话（沿用现有 shakingNotes）。
- **Mission**：编号、结果命名（M2 标准）、状态、里程碑。状态用文字（进行中 / 已确认 / 待启动），不用进度条。DRI 与域 DRI 不同时才显示人名。

### 不做什么

- 不做进度条、百分比、健康度——一个 Outcome 走到哪儿只有一号位自己能判断（原则不变）。
- 不做平移缩放的画布。窄栏（380px）里树必须直接可读。宽屏的横向展开留作后续。
- 不做 Mission 编辑。

### 数据

`OutcomeScreen.domains[]` 增加 `missions: MissionCard[]`（数据层从 `missionCards` 按域填充）。这是 §6 之外唯一的类型改动，按惯例记 EXT。

## 3. 会前一页纸：加一行

Brief 页尾部、发丝线下加一行小字：

> 若今天拍板：04-J1「……」v1 将翻版或放弃 · 已布控的 2 条重开条件将重估

内容从议题的 `judgmentRefs` 解析出来（数据层已有活对象），点击进判断页。作用：进会议室之前，这场会赌的是哪句话已经在桌上。

## 4. 提请：底部加一个折叠行

`/pending` 每日提请的底部加一行（默认收起）：

> 另有 N 件事没打扰您

展开后每件一行：来源、一句话、以及不出卡的理由（「单一来源」「不动摇任何在版判断」「等 8/15 的会一并议」）。数据加在种子里，内容取自现有世界的真实信号（05-2 的对比、非产品化工时上升这类），不编样例。

作用：证明 Agent 懂得什么时候**不**打扰，并且把没打扰的账摊开给一号位看。每天 3 张的预算制因此变得可信。

对任意一行可以说「这个我要看」——这个动作本身被记下来，是最直接的纠错反馈（见 §7）。

## 5. 改名景略 + 品牌字 + mark

- 界面上所有可见的 `Clark` 换成 **景略**：左栏和页头的品牌字、对话栏署名、「Clark 的提请」眉题、各页 `title`、aria-label、种子数据里的 actor 字段。代码标识符（`sendToClark`、`role: "clark"`、组件名）不动。
- 「景略」两字用抖音美好体（DouyinSansBold）。整包 2MB 不能进首屏（H8），用 fonttools 子集出只含这两个字的 woff2（约 4KB），`next/font/local` 加载，只用于品牌字。
- mark 的几何已经是新版（两片 K 形）；颜色统一到 Sean 更新的 `assets/clark-mark-brand-color.svg`：`#075CCB / #1684FF`。改三处：`globals.css` 的 brand token（含暗色档）、`src/app/icon.svg`（favicon）、保持「静止随文色、悬停显双色」的现有行为。

## 6. 会议式交互的方向（不写代码，给方法论团队的输入）

四个独立视角推演后收敛出的同一个结构：

> **会议是唯一的写入时刻；工作台是会与会之间的面；会中产品不出声；判断仍是坐标系，但「会」要升格成一等对象。**

产品现有的动线（提请 → 聊聊 → 交给 DRI → 会前一页纸 → 会后 Closure 补录 → 写回判断台）本来就是「会前准备、会中拍板、会后写回」的骨架——要改的不是流程，是叙事方向和入口：

- **会前**：一页纸自动带上「这场会要动哪条判断」（§3 今晚就上）；再往后，每场会自动汇一份会前材料：要动的判断、待决议题的一页纸、当日提请、上次会议的承诺回执，长度以手机上十分钟读完为上限。
- **会中**：产品不出声。没买 ASR，也不该有录音转写——拍板发生在人嘴里。
- **会后**：Closure 补录 + 确认写回（已有）。后续方向：写回确认的同时生成一份给 DRI 的通知文本（一号位口吻、附七要素），「当场下判断、当场通知下去」在产品里合成一次确认；再往后，收到通知的 DRI 的 Agent 回一句自己的复述，复述里走样的词被划出来供一号位当场纠正。
- **判断台**在月度会前可以汇编成「本月哪些判断动了」，季度会前汇编成「哪个域的目标押在动摇中的判断上」，年会前汇编成全年判断版本史。都是现有对象的重新组卷，不是新数据。
- **手机端**（远期）：每天一条消息，像秘书的日报——昨天定的事的回读确认 + 今天的提请。一号位的日常触点不必是这个工作台。

**对方法论团队的四条反向要求**（交互要成立，方法论得先答应这些）：

1. 四种节律会（推进/月度/季度/年会）要有成文的受理范围——什么会有权动什么层级的对象；
2. 每个 Domain Outcome 显式标注它押在哪几条判断上（数据契约加一个字段）；
3. Closure 七要素成为唯一合法的决定记录格式，取代自由体会议纪要；
4. 重开条件必须写成可观测的外部事件（「竞品降价超 15%」而不是「情况变化时」），否则 Agent 盯不住。

其中 1 和 4 是方法论从「写给人读」走向「可被 Agent 执行」的分水岭。

## 7. 反馈收集：行为的副产品，不是问卷

按落地顺序：

1. **不看了 + 理由**（已有）——归因到四段式里哪一段失效；
2. **「这个我要看」**（§4 今晚上）——从「没打扰您的」清单里捞回一件，等于指出一次分诊漏判；
3. **Closure 草稿的改动**——一号位对预填七要素改了哪几个字，是对 Agent 理解力最直接的批改，改得越少说明拟得越准（记录即可，先不展示）；
4. **翻开倾向的时机**——听完反证才翻开被遮的倾向，还是一上来就翻（私有信号，不外显）；
5. **复述纠正**（远期）——传达走样被纠正的过程本身就是校准数据。

现有的评分浮层保留，但只挂在写回这类重时刻上，不加频。

## 8. 明天不动的

首页不换成会议列表；不做会中投屏页；不做手机端；不做通知直发（先当文书员，后当信使）；不做登录、角色、秘书席。这些都在 §6 的方向里，按方法论团队的回应再排。

## 9. 验收

- `pnpm build`、`pnpm lint`、`tsc --noEmit` 全绿；
- 树在 380 / 580 / 1200 三档面板宽度下可读，折叠展开顺滑；
- 界面上搜不到可见的「Clark」（代码标识符除外）；
- 品牌字体文件 < 10KB，首屏无布局跳动；
- favicon、mark、token 三处同色。
