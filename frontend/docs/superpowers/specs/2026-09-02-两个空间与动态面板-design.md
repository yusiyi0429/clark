# 两个空间与动态面板

2026-09-02 · 设计

## 一句话

把这个产品拆成 **CEO 空间**和**秘书空间**两个入口，会后提炼出来的每一条 action item
由系统判去向；CEO 空间的首页右栏换成锁屏式的动态面板，只装归他的那两层。

## 为什么

现在这一屏假设只有一个人用：一号位既要拍板，又要排会，还要逐份确认会议纪要有没有
形成共识。**后面两件不是他的活。** 排会是秘书的活，审纪要是秘书或 DRI 的活；把它们
摆在他面前，他每天要先从一堆不用他管的事里把要拍板的那几件挑出来——而挑这一下正是
这个系统本来要替他省掉的东西。

同时，会后提炼出来的 action item 现在没有去处：它们躺在 `MeetingDebrief.todos` 里，
屏幕上只在议题详情页出现过一次。谁该做、谁该拍板，没有人判。

## 已有的地形（不要重建）

翻仓库时确认的四样，这份设计全部建在它们上面：

| 已有 | 在哪 | 是什么 |
|---|---|---|
| 分区守卫 | `src/proxy.ts` | 一号位口令开全站；签名身份只开 `/dri` 区，敲一号位地址弹回 `/dri` |
| 方法分档 | `src/lib/data/scope.ts` | `Scope = "ceo" \| "dri" \| "both"`，`Record<RpcMethod, Scope>`——加方法忘定档编译不过 |
| 口令门 | `/access` + `src/lib/access.ts` | 口令、HMAC cookie、12 小时、挡开放重定向 |
| 角色空间的先例 | `/dri` + `src/app/dri/layout.tsx` | 自己的外壳、自己的入口 `/dri/enter` |

**所以"输密码进不同空间"里的密码那一半不用做。** 门已经在了，滑块决定的是进哪个空间。

考虑过但否掉的另一条路：不分路由，一个壳里按角色换导航。它和 `proxy.ts` 那层守卫对
不上——往后真要按角色关数据时得推倒重来，而那张 `METHOD_SCOPE` 表存在的理由正是不
让这种事发生。

## 目标

1. 两个入口：CEO / 秘书。`/access` 上一个滑块选，口令照旧。
2. 编排会议、纪要审阅搬到秘书空间。CEO 保留会议细节页的**只读**权。
3. 会后每一条 action item 都被判一次去向，**一条都不许没人管**。
4. CEO 首页右栏换成动态面板，按 `tianshu-dynamic-panel.html` 还原。

## 非目标

- DRI 侧的交互面板（还在设计中）。这一轮 DRI 那一区一个字不改。
- 真正的权限边界。这一轮的分区是**分路**，不是安全边界：一号位那把口令仍然开全站。
  往后要按角色关数据时，落点是 `METHOD_SCOPE` 和 `proxy.ts`，两处都已经留好了。
- 语音识别。本机 `.env.local` 里没有 `DASHSCOPE_API_KEY`，那条线验不到握手之后。

## 相一：秘书空间

### 路径与外壳

新区 **`/sec`**，自己的 layout，骨架照 `src/app/dri/layout.tsx`（顶栏只有品牌位和导航，
不套 `StageNav`——那条导航只认"议题 / 会议"两个大类，秘书这一侧没有这两个大类）。

**`proxy.ts` 和 `scope.ts` 这一相一个字不改。** 这一条是后来翻代码翻出来的，
和这份设计的初稿相反，记在这里免得下一个人照初稿去改：

- `proxy.ts` 里一号位那把口令 `isAccessCookieValid` 一过就 `next()`，对路径不做任何
  判断。所以 `/sec/*` 拿同一把口令天然就进得去，不需要加 zone；DRI 的签名身份仍然
  只开 `/dri` 区，敲 `/sec` 会被弹回 `/dri`——这正是想要的。
- `scope.ts` 那张表分的是**调用者的真实身份**（`actor.role`，从人表里解出来的 `ceo` /
  `dri`），而这一版秘书用的就是一号位那把共享口令，`actor.role` 就是 `ceo`。所以
  每一个方法都照旧能调，一行都不用动。（另：给 `Scope` union 加一档并不会强迫
  重新定档——`Record<RpcMethod, Scope>` 要的是每个键有值，已有的 `"ceo"` 仍然合法。
  真正会红的是 `api/data/route.ts` 里那句 `scope !== actor.role` 的比较。）

**代价写清楚**：这一相的分区因此**只是分路，不是数据边界**。坐在秘书位上的人只要
知道 `/` 这个地址，照样进得去一号位那一侧。这和"非目标"那一节说的是同一件事，
不是漏掉。真要立边界时的落点是：给秘书发独立口令 → 人表里加一个 `role: "secretary"`
的人 → `Scope` union 加一档 → `api/data/route.ts` 那句比较改成按角色集合判。

### 门上的滑块

`/access` 那一页加一个两档滑块：CEO / 秘书。口令验过之后按滑块落到不同的落地页
（CEO → `/`，秘书 → `/sec`）。滑块的选择跟着 cookie 走，下次进来记得上次选的是哪一档。

**滑块不是权限。** 这一版一把口令开两个空间，选错了退回去重选就是。它答的是
"你现在坐在哪个位置上"，不是"你有没有资格"。

### 谁在哪一侧

| | 秘书 | CEO |
|---|---|---|
| 编排会议 `/schedule` | 主入口 | 进不去 |
| 纪要审阅（见下） | 主入口 | 进不去 |
| 会议全家 `/meetings` `/recordings` 会中 | 操作 | **只读** |
| 首页、议题、判断、已部署、档案、决策确认 | 看得到 | 主场 |
| 其余 | 两边都能进 | 两边都能进 |

这张表说的是**三相全部落完之后**的样子。相一结束时纪要审阅两边都还看得到——
CEO 右栏那一叠要等相二换面板时才下架。

**「只读」是什么意思**：那几页在 CEO 侧照常打开、照常读，但**会改东西的键不渲染**——
上传纪要、开始录音、标未召开、以及 `/meetings/[slotId]/[issueId]` 上的「无需再议 /
还需再议」。他点名要保留的是"看得到会议细节"，不是"在那儿替秘书按键"。
把键留着而让它报错是更坏的做法：屏幕上有一颗按不动的键，比没有这颗键难解释得多。

「决策确认」（`/decisions`）留在 CEO 侧——那一页是七要素的**签发**，是一号位的动作，
和"这场会谈拢了没有"不是一回事。翻代码时确认过：`decisions-view` 读的是
`listDecisions` / `listQuickDecisions`，和 `MeetingDebrief` 无关。

### 纪要审阅这一页要新建

**这里有一笔原来没算到的账。** 现在"审纪要"这件事只有两个落点：首页右栏那一叠
（`DebriefColumn`）和逐件的详情页 `/meetings/[slotId]/[issueId]`。**没有一个把待审的
全部摊开的列表页。** 右栏一换成动态面板，那一叠就没了。

所以秘书空间要有 `/sec/debriefs`：把现在 `DebriefColumn` 那一栏的内容（按会分组、
摞着、无需再议 / 还需再议两颗键）搬成一整页。组件本身基本可以直接搬——它已经是
自足的，只是从半栏宽变成整页宽。

## 相二：动态面板

CEO 空间首页右栏换成 `tianshu-dynamic-panel.html` 里那块面板。原型是唯一的还原依据，
下面只记**和原型不一样的地方**和**仓库这一侧的落点**。

### 布局

- **左栏一个像素都不改。** 潜在议题卡片、业务域列表、底部品牌区，结构配色尺寸全不动。
- **中栏底色换 `#F4F4F5`**，其余不动。
- **右栏整体替换**，宽度沿用现在右栏的宽度。
- **`DeployedRail` 从右边缘挪到中栏左缘**，垂直居中。`console-shell.tsx` 的 `pr-9`
  换成 `pl-9`。样式按原型 `.rail` 重画：常驻小白板、点在左标签在右、hover 展开、
  **点击后 `blur()`**（不要 `:focus-within`——那会让点完之后标签收不回去）。
  这一改动 `/` 和 `/deployed` 两屏一起，只有一套 rail。

### 组件

新建 `src/components/panel/`：

```
panel.module.css     原型 CSS 原样搬，变量名保持 --glass / --glass-hi / --glass-border
                     / --dark-glass / --sheet / --on-glass-* 以便逐条对照
dynamic-panel.tsx    壁纸 + hero + feed + sheet 容器 + banner + dock
panel-card.tsx
panel-sheet.tsx
panel-dock.tsx
```

仓库里已有 CSS module 的先例（`access.module.css`、`tianshu-mark.module.css`），
所以这一档不是新起的做法。

### 和原型不一样的三处

1. **卡片没有主动作 pill。** 原型每张卡右下有一颗（「完成」「无需再议」）。这一版
   不要——右栏装什么还没定完，一颗按下去会改数据的键不该先长出来。卡片只是可点开。
2. **两层不写标签。** 原型是「实时 / 待处理 / 参考」三条小字。这一版两层之间只用间距
   分开，不写标签。
3. **没有换壁纸按钮。** 默认 `noon` 配色，`prefers-reduced-motion` 下关掉壁纸和球的动画。

### hero

小字状态行 + 大号时间（`font-weight:300`、tabular-nums）。状态行默认只显示日期
（「周三 9月2日」）；打开 sheet 时变「正在看 {ref}」；会议进行中变计时 + 「会议进行中 · …」。
**不显示「N 件等你」。** 时间每秒刷新。

### sheet

- 点任何卡片 → 右栏起一层 sheet（`top:58px`，顶部留一条 feed）。
- **只有一层。** 再点别的，旧 sheet 加 `.recede` 后移除，新的滑入。没有返回按钮，
  右上角只有 ×。点顶部那条 feed、Esc 也关。
- 上半是这件事本身，下半「它想到的」先显示「在想…」再填相关项（同一场会的其他
  action item / 来源议题）；没有就显示「暂时没想到相关的。」

### dock

原型那一套完整还原：「对话」按钮（150×46）→ 点开变 76px 圆球（三态动画）→ 再点收回；
键盘按钮 → 输入框（`min(520px, 100% - 110px)`，56px 高）→ × 收回；隐形占位让「对话」
真正居中。球上方一条 caption，点开「对话记录」sheet。

**dock 的模式名不许写成 class `bar`**——原型上出过这个事故：`.bar` 是主按钮自己的类，
dock 继承了它会跑到顶部去。无模式时 dock 只有 `dock` 一个 class。

**后端**：文字输入接现有 `/api/chat`。那条路由已经在走今天换的本体叙述接口
（`ontologyLookupForChat` → `POST /v1/context-graph/narrative`），所以接它就是接上本体，
不另开通道。按那个接口的两条限制，caption 和回复里**不许出现 `ISS-xxx` 这类短码**，
也不许说"没有这条记录"。语音只做 UI 状态机 + 一处显式的「本机没配语音」出口，
不搬原型的假脚本。

### 横幅

实时层的新卡片在 sheet 打开时以横幅从顶部压下来（6.5s 自动收回，点它关 sheet 并打开
对应卡片）。这一版没有实时数据源，机制做出来，留一个开发用的触发。

## 相三：action item 的去向

### 判什么

A7 提炼那一次**多判一样**（同一次模型调用，不额外花钱）：这条 action item
**要不要一号位拍板**。判据是这件事的性质——它是一个需要拍板的选择，还是一件照着做
的执行。带一句理由。

### 落到哪

`DebriefTodo` 上加两样：

```ts
/** 会上点了谁的名。事实判断——只有转写里明说了才有。 */
assignedTo?: { personId: string; name: string; confidence: "explicit" };
/** 要不要一号位拍板。模型判断，带理由。判不出来时 needed 为 true（见兜底）。 */
principal?: { needed: boolean; reason: string };
```

`assignedTo` 未来推给别人也用这个字段，所以是存的、不是算的。

### 怎么判是不是一号位

纯函数 `resolveTodoAssignee(owner)`，只认三种：

1. 一号位的真名（`CEO_ACTOR.personId` → `PSN-01` 刘明华）
2. 第一人称「我 / 我来」
3. 「一号位」

**不认「CEO」这个词。** 人表里 `PSN-04` 名字就叫「CEO」但 `role` 是 `dri`——那是
"以 CEO 岗位作为直接责任承担方，在位人待确认"的岗位占位符。认它就会把事安到一个
占位符头上，而屏幕上那一行和真派过一模一样。这个坑写进函数注释。

**A7 的提示词要加一句**：一号位说「我来做 X」也算点了名，`owner` 照原话写「我」。
现在的提示词只说"点了名才填"，模型很可能把第一人称整个漏掉——不加这一句，
"跑一场带明确「我来做 X」的转写"这条验收跑不出来。

落库时算一次（`store.ts` 那段 `todos.map`）；读取时对**缺字段的老记录**用同一个纯函数
补算一次（不写回），这样库里已有的提炼也能点亮。

### 一条都不许丢

- **CEO 面板两层**：上层是要他拍板的，下层是点了他名的执行项。
- **判不出来的一律进上层**——宁可多给他一条，不许一条静静消失。所以
  `principal.needed` 的默认是 `true`，不是 `false`。
- **全集在秘书那儿**：`/sec/debriefs` 上摊的是**全部** action item，每条标着它去了哪儿
  （「等一号位拍板」/「已归 XXX」/「待分派」）。所以"某件事没人去判断"这件事在结构上
  发生不了：秘书那边永远是全集，CEO 面板是它的子集。
- DRI 面板还没有，所以"非战略、又没点一号位名"的那些这一轮**停在秘书的清单上**，
  标「待分派」。这是一笔明账。

### 一个必须改的读法

`listDebriefs` 和议题上那份 `debrief`（`pendingDebriefOf`）**都只返回没确认过的**。
现在审纪要的人是秘书——秘书按下「无需再议」的那一刻，**一号位自己的 action item 会
跟着从面板上消失**，而那一下的意思恰恰是"这些结论认了"，事情这时才算真的落到他头上。

所以面板不能读这两个口。加一个只读的取数口：`listActionItems()`，返回归当前视角的
action item（连着来源议题标题、会议时间、同场其他条目），**不按 `confirmedAt` 过滤**。
`METHOD_SCOPE` 里定 `both`。

## 顺序

三相分开落，每一相之间都是可交付的状态：

1. **相一**：秘书空间立起来 + 门上的滑块 + `/sec/debriefs` + 排会搬过去。
   **CEO 右栏这一步原样不动**（纪要审阅暂时两边都看得到），中间状态完整。
2. **相二**：右栏换动态面板，`DebriefColumn` 从 CEO 侧下架，rail 挪到中栏左缘，
   中栏底色换 `#F4F4F5`。面板这时只有「点了你名的」那一层有内容。
3. **相三**：A7 加拍板判断，面板上层填满；`/sec/debriefs` 加"这条去了哪儿"的标注。

## 验收

**相一**
- `/access` 上滑块两档，选完输口令分别落到 `/` 和 `/sec`；带 `?next=` 进来的仍然
  回原地址（滑块不许劫持它）。
- 秘书空间里排会和纪要审阅都能用；`/sec/debriefs` 上待审的一份不少。
- CEO 侧不再有编排会议的入口。
- `proxy.ts` / `scope.ts` 的 diff 为空。

「会议详情页在 CEO 侧只读」**不在相一，在相二**：相一结束时纪要审阅两边都还看得到，
他从首页右栏那张卡按「无需再议」仍然是正当的；等相二把那一叠撤掉，只读才有意义。

**相二**
- 左栏截图与改造前逐像素一致；中栏底色 `#F4F4F5`；rail 在中栏左缘，hover 展开、
  点击后能收回。
- 右栏：壁纸 + 时间 + 状态行；没有内容时显示「会后归你的事会落到这里。」
- 点卡 → sheet 滑入；点另一张 → 旧的后退消失、新的进入；× / Esc / 点顶部 feed 关闭。
- 「对话」→ 球 → 再点收回；键盘 → 输入框 → × 收回。三种状态下 dock 的
  `getBoundingClientRect().top` 不变。

**相三**
- 跑一场带明确「我来做 X」的转写，提炼后右栏出现这一条；「小张来做 Y」不出现在
  CEO 面板，但出现在 `/sec/debriefs` 上并标「已归小张」。
- 判断逻辑有单测（参考 `store.debrief-assign.test.ts` 的写法：走真链路造数据，
  假模型，不开后门）。
- `pnpm lint && pnpm test` 过。

## 已知的账

- **准确性后期再调。** 拍板判断这一版只保证"不丢"，不保证"判得准"。
- **分区不是安全边界。** 一号位那把口令仍然开全站（见非目标）。
- **同目录还有三个会话在改同一份 `src`**（`clark-main-72`、`clark-main-63`、`后续修改`）。
  跑全量测试时红的可能不是这条线的；`changelog.ts` 最前面那条和版本号大概率会撞。
