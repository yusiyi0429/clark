# Clark 工作台 · 设计规格

2026-08-10 · 作者：Claude（按刘明华 2026-08-09/10 两次口述框架整理）

这份文档取代 `PRD_FE_v1.0` 的 §4.5（阅读栏宽度）、§7 的页面框架与 H3（无导航）三处。
其余 PRD 条款继续生效。凡本文与 PRD 冲突处，本文为准，理由写在各节里。

---

## 0. 这次改的是什么

上一版 Clark 是一叠**页面**：判断台、决策卡、判断详情、问一句，各自一个地址，
互相之间靠 breadcrumb 回去。它读起来像一份写得很好的报告，用起来像一个 2010 年
的后台 —— 全站零动效、全屏 11–15px 灰字、每次点击都是硬切。

这一版 Clark 是一个**工作台**：三栏常驻，中间那栏是一号位跟他自己 Agent 的对话，
永不卸载；右边那栏是可以同时开多个标签的检视区；左边是导航与两个队列。
判断、提案、文档、溯源链都在右栏里以标签的形式并列存在。

一句话：**从"读一份报告"变成"在一张桌子上工作"。**

### 质量目标

对标 Codex / Cohere North / LibreChat 的手感。可验收的定义是这四条：

1. **没有硬切。** 任何内容出现、消失、切换都有 90–320ms 的过渡。
2. **没有空等。** 任何等待都有骨架或流式，且骨架的形状等于最终内容的形状。
3. **层级一眼可辨。** 每屏有且只有一个"最响"的东西，其余按 4 级灰度退下去。
4. **键盘能走完全程。** ⌘K 搜索、数字键定卡、⌘Enter 发送、Esc 收起。

## 1. 布局

```
┌────────────┬─────────────────────────┬──────────────────────────────┐
│ 导航栏      │  对话栏（常驻，不可关）    │  检视区（多标签）              │
│ 232px      │  flex, min 420px         │  可拖拽, min 380px            │
│            │                          │  ┌──────────────────────┐    │
│ Clark      │  Sean                    │  │判断台│目标与产出│溯源 ×│    │
│            │  ┌────────────────────┐  │  ├──────────────────────┤    │
│ 判断台      │  │ 灯塔的定制需求要不要 │  │  │                      │    │
│ 文档库      │  └────────────────────┘  │  │  panel body          │    │
│ 搜索  ⌘K   │                          │  │                      │    │
│            │  您的 Agent               │  │                      │    │
│ 目标与产出   │  这跟您 5 月那条决定冲突… │  │                      │    │
│ 等待决策 ③  │  ┌ 装配清单 12 项 ─────┐  │  │                      │    │
│            │  └────────────────────┘  │  │                      │    │
│ 业务域      │                          │  │                      │    │
│  # 01 战略  │  ┌────────────────────┐  │  └──────────────────────┘    │
│  # 04 产品 ●│  │ 说点什么…      ⌘↵  │  │                              │
│  …         │  └────────────────────┘  │                              │
│ ▪ ▪ +      │                          │                              │
└────────────┴─────────────────────────┴──────────────────────────────┘
```

三栏宽度可拖拽，存 `localStorage`。导航栏可折叠成 52px 图标条（⌘B）。

**为什么中间栏永不卸载：** 一号位在这个产品里唯一的沟通对象是他自己的 Agent。
他读着判断台上某一行忽然想问"人豪 9 月准备推到哪一步"，如果问一句要先跳走一个
页面，他就不问了 —— 而那个念头恰恰是 Clark 最该接住的东西。把对话做成常驻栏，
是把 PRD 里那个"问一句"的入口从一个链接升级成一件家具。

**中间栏的技术形态：** 它在 `(workbench)/layout.tsx` 里。App Router 的 layout 在
路由切换时不重挂载，所以右栏换标签、开新面板时，对话的滚动位置、正在流式输出的
那半句话、输入框里没发出去的草稿，全都不动。这不是优化，是这个布局能成立的前提。

### H3 的处理

PRD H3 写"除返回外不提供导航"。这一条作废，理由：H3 是为"一叠页面"写的约束，
用来防止产品长成一个有菜单有头像有设置的通用后台。工作台的导航栏里只有
**对象**（判断台、文档、目标、队列、业务域、项目），没有一个是功能菜单 —— 没有设置、
没有头像、没有模型选择、没有主题切换。H3 想防的东西一样没有，所以约束本身可以退休。

## 2. 左侧导航栏

自上而下五段，段间以 hairline 分隔：

| 段 | 项 | 点击行为 |
|---|---|---|
| 品牌 | Clark 标志 | 回判断台。默认 `--ink-faint` 灰，hover 渐变到品牌蓝（220ms） |
| 入口 | 判断台 / 文档库 / 搜索 ⌘K | 前两个在右栏开面板；搜索开命令面板 |
| 队列 | 目标与产出 / 等待决策 ③ | 在右栏开面板。等待决策带未答数量 |
| 业务域 | # 01 战略转型 … # 08 运营保障 | 展开该域的对话历史；点域名在右栏开域面板 |
| 项目 | ▪ ▪ + | 项目切换器，只有一个 Project 时隐藏 |

### 判断台放在哪：放在入口第一项

一号位口述的框架里没有判断台，但它是 demo 第一屏、也是这个产品唯一能在三秒内
说明"我管的是什么"的一屏。它不属于"队列"（它不是等他处理的东西），也不属于
"业务域"（它是八个域的横切）。所以它是入口的第一项，且是 Clark 标志的落点 ——
点标志回判断台，和点 Linear 的图标回 Inbox 是同一个肌肉记忆。

### 业务域留不留：留，但改成"域下的对话历史"

一号位自己提的两个方案里选**方案一**（Codex Project 模型），四条理由：

1. **他自己说的那个理由是真的。** 人的短期记忆装不住八个域，导航栏是他的
   reference。删掉之后他要 @ 某个域，得先想起来有哪些域。
2. **对话必须有家。** 一个决策产品里，"我们上次聊灯塔那事是哪条对话"必须答得出来。
   平铺的对话列表到第 40 条就废了；挂在域下面，八个抽屉永远只有八个。
3. **它教会 @。** 看见 `# 04 Product` 就知道 `@04` 能用。不写在屏幕上的语法等于
   不存在的语法。
4. **它零成本。** 域、编号、DRI 本体里全都有（`seed-ontology.ts` 的 `domains`）。

改进一处：每个域名右边挂一个**状态点** —— 该域有判断在动摇时显示 `--counter` 小点，
有等您定的事时显示 `--solid` 小点。导航列表顺手变成状态面板，代价是零。
Codex 的项目列表没有这一层，因为它的项目没有状态；Clark 的域有。

### 等待决策：队列在左栏，卡片在右栏

一号位问"决策提案放哪儿"。答：**左栏放入口和计数，右栏放队列面板，单张卡是右栏的
一个标签。**

- 左栏 `等待决策 ③` —— ③ 是未答数量，答完一张就变 ②。这个数字是他每天打开 Clark
  的第一个理由，必须在导航上常驻。
- 点它 → 右栏开"等待决策"面板：卡片列表，每张卡折叠成三行（问题 / 谁在等 / 动摇哪条判断）。
- 点单张卡 → 右栏开一个**新标签**，标签名是卡的短标题。这就解决了他说的"没想好可以
  暂时关闭、随时回来" —— 关标签不等于放弃，卡还在队列里；而"今天不处理"是一个
  有后果的显式动作（会告知等的人），两者不能混。
- 附件：卡的自由指示框支持附文件（文件 chip，不真上传）。
- 派研究：卡上"先去研究"展开 `DispatchPanel`（已存在），三档阶梯不变。

## 3. 右侧检视区（标签）

### 标签模型

标签 = `{ id, label, href, closable }`。**路由驱动**：右栏的内容就是当前路由的
`children`，标签栏是一份客户端记住的"开过哪些地址"的清单。切标签 = `router.push(href)`，
所以每个标签都是一个真地址，能分享、能刷新、能回退。

只有当前标签的内容挂载。切回去会重新渲染，但 SWR 缓存命中 → 无骨架、无闪。
放弃"每个标签保留 DOM"的方案：那要么用 parallel routes 把地址变成笛卡尔积，要么
把整个右栏做成单页假路由 —— 前者复杂度爆炸，后者丢掉地址，而 PRD 说"一件被定下来的事
必须留在一个能回头点开的地址上"。

最后一个标签不可关。⌘W 关当前标签，⌘1…⌘9 跳标签。

### 面板清单

| 面板 | 地址 | 内容 |
|---|---|---|
| 判断台 | `/` | 八域 × 判断 × 动摇它的东西 × 挂在下面的队列项 |
| 目标与产出 | `/outcomes` | 顶部 `Outcome ⇄ Missions` 分段控件；公司总 Outcome + 八个域 Outcome + 设立日期；可翻历史周期 |
| 等待决策 | `/pending` | 提案队列 |
| 决策提案 | `/decide/[id]` | 单张卡：问题 / 他的方案 / 最强反证 / 选项 / 自由指示 / 派研究 |
| 判断详情 | `/judgments/[id]` | 现在是什么、怎么来的、什么在晃它、版本历史 |
| 业务域 | `/domains/[code]` | 域 Outcome、判断、Mission、议题 |
| 议题 | `/issues/[id]` | 这条议题的一生（时间线） |
| 会前一页纸 | `/issues/[id]/brief` | DRI 方案 + 最强反证独立区块 + 分歧三色 |
| Closure | `/issues/[id]/closure` | 七要素 + 写回回执 |
| 文档库 | `/docs` | 镜像自飞书/云盘的共享文档树 |
| 文档预览 | `/docs/[id]` | 正文 + "被哪些判断引用过" |
| 溯源 | `/trace/[id]` | 一句话的祖先链，逐层到最初出处 |

`/ops/*`（Shadow 审核、会议校对）留在工作台之外，它们是内部工具，不该有对话栏。

`/ask` 与 `/ask/[id]` 删除：问一句从此是中间栏，不再是页面。

## 4. 对话栏

### 形态

无气泡。说话人标签在上（`Sean` / `您的 Agent`），内容在下，全宽左对齐 —— Codex 与
Claude 的做法。用户轮次给一层极淡的 `--neutral-wash` 底并留左边距，Agent 轮次是
裸正文。气泡在中文长句里会把行长压到无法阅读，而这个产品的 Agent 一次要说三段话。

### 流式输出

**这是"丝滑"最大的单一来源。** Agent 回复逐字显现（rAF 分块，约 55 字/秒，标点处
微停顿），末尾一个呼吸光标。等待期间不给转圈：先出说话人标签，再出第一块内容。

数据上这是假的（种子数据里答案是现成的），但它不是装饰：一号位读到第三句时第五句
还没出来，他的阅读节奏和 Agent 的产出节奏就对上了，这正是真接后端之后的样子。
到 MVP 换成真 SSE，这一层组件不用改。

### 消息块

复用已有的 `MessageBlock`（text / manifest / challenge / question），新增三种：

- `receipt` —— 第二档交换回执（带过去了什么、遮掉了什么、对方依据什么答的）
- `escalate` —— 第三档：只有本人能答，附预拟问题，须 CEO 按下才发出
- `proposal` —— 内联一张决策提案的引用，点开在右栏成标签

每一块都是**可检视的物件**，不是聊天蒸汽：装配清单点得开，挑战带出处，
问题带建议 DRI 和期限。这条来自一号位自己的 UI rule：
"AI outputs must be inspectable artifacts, not chat vapor"。

### 输入框

自增高（1→8 行）。Enter 发送，Shift+Enter 换行，⌘Enter 强制发送。
左下 `+` 附件（chip 展示，不上传）。右下写"您的 Agent" —— **不是模型选择器**，
PRD 明确禁止；这里写的是"谁在答"，是权限信息不是配置项。

`@` 唤出提及菜单：八个域 + 七个人。选中后插入 `@04 Product` 的 chip。
提及一个人不等于跟他对话 —— 提及的是话题范围，回答仍然来自一号位自己的 Agent，
它自己去跟对方的 Agent 握手。这条边界要在菜单里写一行小字说明。

### 后端

`api.sendToClark(threadId, text)` 内部走已有的 `api.ask()`：关键词打分命中已登记
判断 → 按三档阶梯给答案 + 回执；命中不了就说"这个问题在已登记的判断里没有依据 ——
我不替它编一个答案"。**不新写一套回复生成器**，因为 `ask()` 里已经写着这个产品最
重要的诚实性约束。

新增数据：`Thread`（对话，可挂 `domainId`）与 `ChatMessage`。种子给五条真实对话，
分挂在 01/03/04/05 域下。

## 5. 溯源

一号位描述得最细的一块，也是这一版新增的最高价值交互。三个入口，一个终点。

### 5.1 代号 chip（hover / 点击）

Agent 说到 `MC-3`、`04-J1`、`M1-A`、`04-2`、`D-04` 时，文本自动识别成 chip。
hover 300ms 出浮层：该对象的原话 + 状态 + 出处一行 + "在右栏打开"。

理由是他自己写的那句：人的记忆记不住代号。屏幕上出现一个他记不住的编号而不能
当场翻译，这个编号就是噪音。识别用一张正则注册表（`lib/provenance.ts`），
解析走本体，**认不出来的代号不做成 chip** —— 一个点开是空的 chip 比纯文本更糟。

### 5.2 框选 → 查找出处 / 引用

在 Agent 消息里框选一段文字，浮出一个两键小条（他的截图里就是这两个）：

- **查找出处** → 右栏开溯源面板
- **引用** → 把这段话插进输入框，带引用样式

### 5.3 溯源面板：逐层到底

一层一张卡，从这句话开始往上走，直到最初出处：

```
① 这句话        “灯塔 7 月定制占研发人力 62%”        Agent 输出
② 它引的        04-J2 的依据第 2 条                  判断依据
③ 那条依据引的   Commitment v0.1 · Mission 3          内部文档
④ 文档引的      7 月研发工时表（飞书表格）             外部来源  ← 到底
```

每层带 `TraceKind` 徽章（外部/内部/人/Agent/判断/同僚），点层级展开原文段落，
最后一层标明"到底了"或"这里断了" —— **链断了要说出来**。一条查不到底的溯源链
如果假装完整，比没有溯源更危险。

数据基础已存在：`Statement.traces: Trace[]`。新增 `lib/provenance.ts` 把它组装成链。

## 6. 排版与动效系统

### 6.1 字体：不破 H8，改打法

PRD H8 禁止任何 web font（中文字体动辄 5–10MB，会毁掉 demo 唯一的第一印象）。
**H8 保留。** 排版的问题改用另外三件事解决：

1. **sans 栈重排**，Win11 上优先 `Segoe UI Variable Text`，中文落到
   `Microsoft YaHei UI`（不是老的 `Microsoft YaHei`）；mac 上 `-apple-system` +
   `PingFang SC`。
2. **mono 栈补中文兜底。** 现在 `.meta` 里的中文会掉进等宽 CJK 字面，又宽又丑。
   栈尾补 `"Microsoft YaHei UI"`，并把字号从 11px 提到 11.5px、字距放到 0.02em。
3. **`.report` 衬线只用在真正编辑部的地方** —— 判断原话、Outcome 原文、Closure 正文。
   字号 +1px（衬线中文在同字号下视觉更小）。其余全部走 sans。

Win 上退到 SimSun 的风险仍在。一行开关留着：`--font-serif: var(--font-sans)` 就全站
换回 sans。这是可逆的，不值得为它破 H8。

### 6.2 字号阶梯

| token | 值 | 用途 |
|---|---|---|
| `--text-micro` | 10.5px | 徽章 |
| `--text-meta` | 11.5px | 编号、时间、计数、出处（mono） |
| `--text-sm` | 13px | 次要正文、列表副行 |
| `--text-base` | 14px | 正文 |
| `--text-md` | 15px | 强调正文、判断原话 |
| `--text-lg` | 17px | 面板标题 |
| `--text-xl` | 21px | 卡片主问题 |

字重只有 400 与 500。灰度只有四级（`--ink` / `--ink-muted` / `--ink-faint` /
`--ink-faint/60`）。**每屏一个最响的东西**：判断台是"今天三件事等您定"，
决策卡是那个问题，对话栏是正在输出的那一轮。

### 6.3 动效

| token | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 90ms | hover、底色 |
| `--dur-snap` | 140ms | 按下、chip、徽章 |
| `--dur-base` | 220ms | 内容进入、标签切换 |
| `--dur-slow` | 320ms | 面板换入、抽屉 |
| `--ease-out` | `cubic-bezier(.2,0,0,1)` | 进入（Linear 的曲线） |
| `--ease-brand` | `cubic-bezier(.22,1,.36,1)` | 强调进入（已存在） |
| `--ease-snap` | `cubic-bezier(.4,0,.2,1)` | 交互反馈 |

规则：

- **列表进入** 6px 上升 + 淡入，按 index 阶梯延迟 18ms，最多累到 8 项后不再递增。
- **面板换入** 淡入 + 4px 位移，220ms。
- **hover 永不只改文字颜色** —— 至少同时改底色或下划线。原来全站只有文字变色，
  这是"廉价"感最直接的来源之一。
- **按下** `scale(.99)`，90ms。
- **骨架** 形状等于最终内容，淡出而非直接替换。
- **滚动条** 6px、透明轨道、hover 才显形。
- `prefers-reduced-motion` 全部归零（已存在）。

性格取向：**偏 Linear 的快而利落**，不取 Notion 的柔缓。一号位一天要过几张卡，
每次 320ms 的柔缓叠起来就是拖沓。只有面板换入用到 320ms。

## 7. 不做的东西

一号位划的红线，界面上连入口都不留：

- 任何暗示卡片是 Agent 自动生成的措辞（8 月验的是"卡片这个形态有用"）
- 录音上传、会中实时（ASR 没买）；Closure 走事后补录
- 秘书控制台、对齐循环、Decision Memory 编辑页
- 登录页、角色切换（没有鉴权和数据隔离）
