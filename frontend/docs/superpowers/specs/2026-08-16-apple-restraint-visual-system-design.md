# 视觉系统：中性轴收敛与取消卡片

日期：2026-08-16
分支：`ui/apple-restraint`
前置：`27c75eb`（取消卡片，深度收敛到一处）—— 那一版只落到 3 个视图

## 一句话

把「半拟物」的实现从**容器立体化**换成**颜色承担身份 + 单处深度**，并把这套处理
从 3 个视图铺满全站。同时修掉 4 个在调研过程中量出来的缺陷。

## 为什么不是给卡片加阴影

调研的结论推翻了最初的方向，也推翻了立项时举的例子：

- **Apple 时钟的三根指针互相没有阴影。** 官方 @2x 截图 12 倍放大逐边缘检查过每一处
  交叠和中心帽下方：零灰晕，硬抗锯齿边。天气那颗太阳没有，80° 那个大字既没阴影也没压底。
  ——「内容立体」这个说法本身也不成立。
- **Apple 示例工程 Backyard Birds 全工程只有两处 `.shadow(`。** 卡片的边是
  `strokeBorder(.separator, lineWidth: 0.5)`，半个点的描边，不是投影。
- **WWDC25 原话**：*"Instead of relying on decoration, hierarchy should be expressed
  through layout and grouping."*
- 唯一一处真阴影是体能训练圆环的端点，而它成立的关键是那个阴影被 `context.clip()`
  裁在环带里 —— 它永远落不到背景上。

所以精致感的承重顺序是：**颜色承担身份 → 一束光（共享色相轴）→ 安静的几何 → 单处深度**。

## 决策

### D1 中性轴收敛（修改 PRD §4.2）

12 个中性色（明暗各 6）移到 **H=286.3°、C≤0.008**，对齐 Apple systemGray 家族
（实测全线落在 286.2–286.3°，方差 <0.2°；C≈0.0065）。

**理由是 §4.2 自己那条规矩**：*颜色即含义，不许挪作装饰*。原来 `--ink-faint`
的 C=0.0351 是 `--factual`（C=0.1193）的 24%，两者色相只差 14° —— 每一个时间戳
都是一层淡淡的「外部事实」蓝。中性色在偷用产品唯一的信号通道。收敛后中性与语义色
的彩度差从 3.4 倍拉到 15 倍，色相离开 `--factual` 44°。

| token | 原 | 新 |
|---|---|---|
| `--paper` | `#f9fafd` L.985 C.0041 H271 | `#fafafb` L.985 C.002 H286.3 |
| `--surface` | `#fdfdff` L.995 C.0026 H286 | `#fdfdfe` L.995 C.001 H286.3 |
| `--ink` | `#0f172a` C.0398 H266 | `#17171b` C.008 H286.3 |
| `--ink-muted` | `#475569` C.0374 H257 | `#535358` C.008 H286.3 |
| `--ink-faint` | `#94a3b8` L.711 C.0351 | `#6b6b70` **L.5295** C.008 |
| `--rule` | `#e2e8f0` C.0126 | `#e7e7ed` C.008 |
| `--solid` / `--solid-fg` | `#0f172a` / `#fafaf9` | `#17171b` / `#fafafb` |

深色一侧同样处理（原来偏得更狠：`--ink-faint` C=0.0216、`--surface` C=0.0154，
那块面在深底上是肉眼可读的蓝，不是「深灰面板」）。

副产物：`--rule`（`#e7e7ed`）与 `--hairline`（ink 9% 合成 `#e6e6e7`）现在只差
一个通道级差，`@layer base` 里 `* { border-color: var(--rule) }` 的兜底和新发丝线
自动一致，不需要额外处理。

### D2 `--ink-faint` 明度上抬（无障碍缺陷，与 D1 无关）

原 L=0.711 在纸上 **2.46:1**，低于 UI 文字 3.0 的下限，而它有 **221 处调用**，
装的是章节标题、时间戳、ID、placeholder —— 全是要读的东西。单改彩度救不了：
明度没动，对比度一个数都不会变。

新 L=0.5295：纸上 5.08:1、白面上 5.21:1、`--neutral-wash`（ink 4%）上 4.74:1、
行悬停底（ink 6%）上 4.62:1。深色一侧 L=0.66，纸上 6.18:1。

**取值条件是「在全部中性底上都 ≥ 4.5」，不是「在纸上 ≥ 4.5」。** 这一步在浏览器
实测里被打回两次：

1. L=0.56（`#747479`）在纸上是 **4.457:1** —— 手算按两位小数记成「4.46，过了」，
   实际差 0.043。4.5 是硬门槛，不是四舍五入后的门槛。
2. L=0.554（`#727277`）过了纸和白面，却在 wash 底上掉到 4.28 / 4.17。这个色不只
   出现在纸上（主页准备度条、卡片脚注都是 wash 底）；按最亮的底调，等于只验了
   最容易过的那一档。

L=0.5295 是满足全部底色的最浅值。

**只用一个 token，不拆。** 拆成「装饰用 3.79:1 / 内容用 5.08:1」要对 221 处逐个
判断归属，收益是一档很微妙的区别，不值。参照：Apple 自己的 systemGray 是 3.12:1，
守 3.0 那一档 —— 但他们不拿这个色装要在投影上读的章节标题。

### D3 取消卡片，铺满全站

`.card` / `.row` / `.row-link` / `.concentric` 四个 utility 在 `27c75eb` 就写好了，
但只接了 `home-view` 和 `domain-nav`。这一版接完剩下的。

- **8 个视图**是老的 `rounded-lg border border-hairline bg-surface` 卡片列表
  → 转成 `.card` 容器 + `.row row-link concentric` 行。`px-4` 改 `px-3.5`，
  因为分隔线内缩量 `--row-pad: 0.875rem` 是按这个值对齐的。
- **3 个视图本来就没有卡片**，不用动：`judgment-view`（规则线 + 状态点）、
  `outcomes-view`（树干）、`doc-view`（ruled list）。`docs-view` 结构上已经接近 `.row`。
- **留着卡片的**：`advisor-view` 左右两栏（真的是两块面）、`card-four-part`
  （digest 里一条一张，不是齐平列表）—— 但边都从 1px 换成半个物理像素的发丝线环。
- **边是语义的不动**：`closure-view` 的单选态 `border-judgment`、风险块
  `border-counter/25`、写回回执左沿 4px `border-l-confirmed`。
  回执外面那圈中性 1px 去掉 —— 那块面的身份由它自己的色底说。

不可点的行不加 `.row-link`：hover 淡底是「这里能点」的承诺。

### D4 材质与渐变的边界

- **磨砂只给 chrome**（顶栏胶囊、弹层、菜单、遮罩），内容层一处都没有。
  非浮动面上的模糊是装饰，还要付真实的绘制代价。
- **渐变只走色相，不压明度**，低差值必配抖动。理由是量的：一道通道差 16、
  高 110px 的明度渐变是 6.9px 一带，必然起带。

### D5 语义色按「底」作用域化，不按「配色方案」

`.solid-panel`（主页雷达窗）是浅色方案里**唯一一块常驻深底**。四个语义色是按纸面
调的，压在 `#17171b` 上全部不及格：factual 3.01、confirmed 3.27、judgment 3.56、
counter 2.84。

修法不是逐处换类名，而是在 `.solid-panel` 里**重声明那四个变量**为 `.dark` 那边
已经调好的同名色（factual 6.94、judgment 8.64、confirmed 7.89、counter 5.84）。
`text-factual` / `bg-confirmed` 这些类名一个字都不用改，靠 CSS 继承自动取到对的值。

这一条同时是 B3/B4 的根治版。那两处（七个 `text-white`）是同一个病的另一种症状：
「这块底是深的」这件事，之前要靠每个写 className 的人记住，忘一处就是一处
对比度缺陷。现在交给 CSS 作用域。

**规律：颜色该由它压在哪块底上决定，不是由全局配色开关决定。**

## 缺陷修复（调研中量出来的，独立于视觉改造）

| # | 位置 | 问题 |
|---|---|---|
| B1 | `home-view.tsx` ProgressRing | `uid` 只由 `pct` 拼（`pr${pct}`）。SVG 的 id 是整篇文档共享的命名空间，首页一屏多个议题、两个 0% 的环拼出同一个 `pr0`，后出现的同名 id 按规范被忽略 —— 第二个环引用的是第一个环的 clipPath。改用 `useId()`（并剥掉冒号，`url(#…)` 里非法）。 |
| B2 | 同上 | 阴影在 22px 上根本不显示。MKRingProgressLayer 那组比例（偏移 w/10、模糊 w/3）来自 w≈20px 的表盘环；比例无量纲，渲染结果不是 —— 抗锯齿有绝对下限。w=3 时偏移 0.3px、模糊 1.0px，**模糊是偏移的 3.3 倍**，白付一个 filter 的代价。改 `max(w/10, 0.6px)` + 模糊 w/4（比值压到 1.25）。w=20 时 `max()` 自动失效，回到原比例。 |
| B3 | `card-four-part:87`、`closure-check:295`、`issue-header:221` | 硬编码 `text-white` 压在语义色上。深色模式下 `--judgment` 反成浅琥珀 `#f0a93b`，白字 **2.01:1**；`--confirmed` `#35c2af` 上 **2.21:1**。都低于 4.5。换 `text-solid-fg`（本来就跟着方案反），变成 9.55:1 / 8.67:1。 |
| B4 | `closure-check:482` | 长按签发的进度条用 `bg-white/25` 压在 `bg-solid` 上。深色下 `--solid` 反成浅面，白色 25% 合成 `#efeff1` 压在 `#eaeaec` 上 —— 进度条直接看不见。换 `bg-solid-fg/18`。 |
| B5 | `selection-cue:62`、`code-ref:219` | 阴影里烤死了 `rgba(15,23,42,…)`，那是旧的浅色 `--ink`。这两个是真的浮层，有权用高度 —— 换成 `shadow-e2` / `shadow-e3`（墨色、跟随方案）。 |
| B7 | `globals.css` `.scroll-edge` | **主定义整个缺失。** class 在 `stage-nav.tsx` 里照写，三处媒体查询（reduced-transparency / prefers-contrast / forced-colors）照覆盖，唯独没有 `.scroll-edge { position: absolute }` 那条基础规则 —— 从 `5320a1c` 起就没有过。后果不是「没有模糊」：那个 88px 高的装饰 div 留在正常流里，把顶栏胶囊往下顶 88px，header 从 64px 变成 152px，屏幕上就是顶栏上方一大片空白。CSS 少一条规则不报错，build / tsc / lint 全过，只有一个类名指向空气。 |
| B6 | `home-view:393` | `text-factual/80` 压在常驻深底上只有 **2.37:1**。由 D5 一并修掉。静态检查看不见它：类名和 token 都合法，错的只是「这个 token 在这块底上不合格」—— 只有在浏览器里合成过才量得出来。 |

## 遗留：字栈（PRD §4.3）

`27c75eb` 把 `--font-serif` 变成了 `--font-sans` 的别名，全站 0 处 `font-serif`。
PRD §4.3 写的是「serif 用于议题标题和 Decision 正文（呈报感）」—— 这一版**删掉了一个
PRD 指定的信号**，而且是在注释里悄悄删的。

理由不算无据：Songti SC 在 Windows 落到新宋体，UI 字号下（<16px）渲染很差；一屏三副字
在一份要当正式材料读的东西里也确实不严谨。但这是 §4.3 的取舍，不是实现细节。
**本设计不替这一条做决定，只把它记成一个显式待决项。**

同一条负面结论：Apple 那张 tracking 表（12pt 归零、17pt 收到 −26/1000）没有套用。
它是拉丁字体的光学补偿，负字距加在全角汉字上会把整行挤死。中文的对应杠杆是行高和
版式，不是字距。

## 验收

静态检查（build / tsc / eslint / grep）：

1. `npx next build` 通过，`npx tsc --noEmit` 无新增错误，`npx eslint src` 无新增警告。
2. 内容层 `shadow-*` 计数为 0（唯一例外：进度环那处裁在环带里的阴影）。
3. 16 个视图无硬编码颜色字面量（`text-white` / `bg-white` / hex / `slate-*`）。

运行时检查（`scripts/verify-visual.mjs`，CDP 读**计算后**的样式，8 条路由逐页跑）：

4. 中性色 OKLCH 色相全部 286.3°，C ≤0.008 —— 读计算值，不读源码。
5. `.row + .row::before` 真的画出来了（有高度、有颜色），且 `left` 等于 `--row-pad`
   的**计算值**（separatorInset 规则）。
6. 发丝线 = 1 物理像素（CSS 高度 × dppx）。
7. 正常流元素零阴影（浮层按 `position` 排除，不按 class）。
8. 每个可见文字节点按字号取 4.5 / 3.0 门槛，全部达标 —— 底色半透明时先合成再算。
9. **顶栏高度 = 64px，装饰层 `position` 是 absolute/fixed。**

第 9 条是 B7 之后补的，因为前八条**一条都没拦住它**：颜色对、发丝线对、对比度对 ——
东西全在错的位置上。验收只验了「长什么样」，没验「在哪儿」。
64 是个有下游的数字（各页 `calc(100vh-4rem)` 按它算），装饰层一旦回到正常流就会
推走真正的内容。加断言之前先注入 `position: static` 复现过一次，确认它真会 FAIL
（header 152px、胶囊 top=96）—— 不然它只是个永远绿的装饰。

**为什么必须有运行时那一半：** 清单是客户端取数后才渲染的，服务端 HTML 里只有骨架屏，
静态 grep 永远验不到那条相邻兄弟选择器。而且这一轮两个真缺陷（B6、以及 `--ink-faint`
在 wash 底上 4.17:1）都**只在运行时可见** —— 类名和 token 各自都合法，错的是它们的组合。

**验收本身也踩了三个坑，记下来免得重犯：**

- 只验一条路由（`/issues`）时是 6/6 全过；铺开到 8 条立刻抓到主页那两处。
  缺陷长在组合上，不长在 token 上。
- 用「骨架屏归零」当水合完成的判据会**假成功**：导航刚开始时 React 还没水合，
  `.skeleton` 本来就是 0，脚本在空 DOM 上跑完全部检查报一片 PASS。
  正确判据是「先见到骨架屏，再见到它消失」。
- 颜色不能自己解析字符串。这套设计大量用 `color-mix(in oklab,…)`，Chrome 序列化成
  `oklab(L a b / α)`；按 `rgb()` 抓数字会把 0.99 当成通道值，算出来纯属噪声。
  交给 1×1 canvas 解析，顺带把半透明层真的叠一遍。

深色一套在这一版是**休眠**的（`layout.tsx` 里那段加 class 的首屏脚本随口述模式封存，
产品代码 0 处 `dark:`），所以运行时验收只跑浅色。试过脚本强行加 `.dark`：token 会翻，
但读浅色变量的地方不会跟着翻，量到的是一个产品里不存在的中间态。
深色重启时把它加进 `SCHEMES` 即可。
