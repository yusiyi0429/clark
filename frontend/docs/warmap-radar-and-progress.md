# CEO 雷达与月度进展

## 入口与边界

首页右上雷达 → 信息流 → 原文摘要、战略关联、未知与出处；右侧为当前材料对话，共用全局输入。左侧始终是通知。

目标与 Mission 目前来自明确标注的演练快照；外部新闻来自真实检索。不要把这两种来源混淆。正式 Mission 台账中的 `MissionCard.status` 只有 running / confirmed / pending，其中 confirmed 并不等于完成验收，所以本次没有错误地把旧字段直接当作完成状态。

## 雷达实现

- `/api/warmap-radar`：访问控制沿用 `src/proxy.ts` 的 CEO 门禁。
- POST `scan` 开始后台任务；重复开始返回同一个进行中的扫描。GET 为状态/信号/锚点快照，扫描期间客户端每 2 秒拉取。
- 检索复用 `research/search.ts` 的博查、豆包适配器和限流；通义配置可用时复用 `qwen-research.ts` 补充来源。通义未配置不会伪装成调用成功；渠道部分失败显式提示。
- 当前默认锚点取自原型目标草案，并明确标注来源。可以在“战略锚点”粘贴生效战略的原文节选、填写出处和战场关联。历史信号保留扫描当时的锚点快照，后续编辑不改写历史。
- 外部内容仅作材料，不执行其中指令。信息流展示检索摘录的摘要，不宣称已抓取/阅读完整原文。
- 七天窗口；无可靠发布时间的材料明确显示日期缺失。URL 规范化去重；相同标题的决策不重复创建。自动归类不机械继承锚点，而按研判的实际影响战场归类。
- 自动升级门槛：关联性/影响/可行动性加权达到 4.2/5，影响与可行动性各至少 4；至少两个不同选项，原文摘录必须包含研判引用，必须有有效战场归属。没有达到门槛可以保留信号，不强行凑议题。
- 红色需有来源中的行动时间原话与具体后果。红色通知和首页议题使用同一信号下的 issue 对象；确认处理后同步移出待决策，重新讨论可恢复。跨战场进入公司战略区；单战场进入该战场。
- 已读、收藏、忽略、恢复和处理结果持久化在 `.data/warmap-radar.json`，不改旧版公司本体，不发消息，不新建组织任务。
- 本地 Node 单进程任务 + 原子文件写入；适合本次 localhost 原型。多实例/无服务器正式部署需改用持久化作业与共享事务存储。进程重启中断的扫描会提示重新开始，不显示假完成。

## 月度进展

- 数据：`lib/warmap/mission-progress.ts`，两个战场独立的 Mission 快照。样本组数是 Mission 内部进度，不是 Mission 数量。
- `/api/warmap-progress` 使用已有 flash 模型评估每项 1–5 权重、0–100 本项完成度与依据，代码计算 `Σ(权重×本项完成度)/Σ权重`。
- 圆环大字为加权百分比，小字为已验收 Mission 数/总数。TokenOps 的部分样本核验可产生部分进度，即使该 Mission 尚未整体验收。
- 校验完整 ID 集合、无重复、权重/完成度范围、完成状态的一致性；不采用模型直接输出的总百分比。
- 缓存键包含评估规则版本及完整快照摘要，同一快照刷新不会重新花费模型调用或产生漂移。证据变化应产生新快照和新评估，不覆盖旧的台账验收定义。
- 服务不可用时显示待评估并允许重试，保留数量；不回填假百分比。六个月目标仍待确认衡量口径，不用月度完成度冒充长期进度。

## 验证

`src/lib/warmap/radar.test.ts` 覆盖归类、升级门槛、引用对齐、输入校验、加权算术。浏览器回归覆盖阅读、收藏、信号归入首页、红色通知联动、明确确认后才提交、撤回恢复、深色气泡、专属对话上下文、翻转与输入框动画、移动端无横向溢出。
