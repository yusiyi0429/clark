# 03 · 潜在议题的预研（A3 pre-research）

> 快照 2026-08-21。对应五段流程里的第 ③ 段。这条链路走的是「代码里的 system + builder」机制（见 `00` 第一节），
> 但**认知段仍然在 `prompts/cognitive/` 下**，由方法部门维护。

## 一、预研要回答的是哪一句

**「这个议题现在值不值得被认真考虑」，不是「这个议题的答案是什么」。**

这一条最容易违反，而且违反了自己看不出来 —— 因为答案写得越漂亮越像做得好。System 段里用一对正反例
把界钉住：

- 「当前证据更支持暂缓同时推进」 ← 这是**议题的答案**。越界了。
- 「这件事的关键依赖有三条现在都没闭合，所以它值得您现在花半天想清楚」 ← 这是**预研该说的**。

产出是一个固定形状的 JSON：`status` / `statusReason` / `question` / `take` / `finding[]` /
`openQuestion[]` / `soWhat`。全文控制在 **900 字以内** —— 这是轻量档，一号位一两分钟要读完。

`status` 三个值：`valid`（议题成立，说法也对）/ `invalid`（这一轮判掉，不是「先观察」）/
`reframing_needed`（张力是真的，但现在这条说法描述不了它）。**先判它，再动笔写下面几段**，
并且 `take` / `soWhat` / `status` 三者必须同向 —— 判断都下完了还研究什么。

## 二、这份 Prompt 是怎么构造的（三条原则，`src/lib/agent/a3/prompt.ts` 文件头原文）

```ts
/**
 * A3 Pre-research 的 prompt。
 *
 * 三条构造原则，来自 rubric 与踩过的坑：
 *
 *  1. **结构约束优先于语言要求。** 输出是一个固定 schema 的 JSON，不是「写一篇预研」。
 *     结构约束比「请确保结论先行」硬一个量级，也让确定性校验变得平凡。
 *  2. **负例比正例有效。** CQ101 §04 与 §05-3 已经把失败模式写好了 —— 说「不要做什么」
 *     比说「要做什么」管用，因为失败模式描述的正是模型的默认行为。
 *  3. **可数的东西交给校验器，不写进祈使句。** 句数、块数这些 validate.ts 会数并打回，
 *     prompt 里说一遍是为了减少重试次数，不是为了保证。
 */
```

## 三、装配顺序：user 消息里的小节是有次序的

`buildA3User()` 按这个顺序拼，**次序本身是约束**：

| 小节 | 内容 | 为什么在这个位置 |
| --- | --- | --- |
| `## 议题` | 标题 + 编号，`范围与背景：` | — |
| `## 递上来的原文` | 他自己贴的一整篇 / 抓回来的网页正文 / DRI 上报写的那几段 | 紧跟议题：这是唯一确定和这条议题有关的材料（内部文档那一批是按域粗筛的，未必相关） |
| `## 这个议题可能动摇的判断` | 在版判断编号 + 说法 + standing | — |
| `## 可引用的内部文档` | 只给正文**前 1200 字** | 轻量档；「还没读完的部分」正好归 `openQuestion` |
| `## 公司决策上下文（GraphKnowledge S02）` | `Harness.contextBlock` —— **这一段永远存在，三档都有话说** | 留个空洞的话，模型会自己编一套公司战略假设出来然后正常引用它 |
| `## 预研该怎么做` | 认知段（`prompts/cognitive/a3.pre-research.md`）。**没装上时这一段整个不出现**，不留占位句 | 在上下文之后、输出格式之前 —— 和 `assemble()` 的五段同序 |
| `## 输出` | JSON 形状 + `traces.kind` 枚举 | 必须是模型最后读到的东西 |

**「递上来的原文」那一段有两句不能少的约束：**

1. **不许往它上面编溯源。** 这段材料没有编号也没有链接。而校验器那条 A3-13（每条 Evidence 必须有溯源）
   是 p0，模型为了过门一定会给它编一个 `DOC-` 编号或一个 href，编出来的短码在屏幕上渲染成一枚点不开的
   徽章，而一号位点它就是为了核对。所以给一个固定的、不指向任何东西的标签：`{"kind": "human", "source": "递上来的原文"}`。
2. **它不是图谱里的东西。** 下面那段公司上下文才是。混起来之后，一号位读到「据公司决策上下文」时，
   指的其实是他十分钟前贴进来的一篇外部文章。

## 四、这条链路的运行参数

| 项 | 值 |
| --- | --- |
| 槽位 | `pro` |
| 上下文配方 | `S02`，**锚点是这条议题挂着的在版判断**（不是议题本身 —— 图里没有前端这十条议题的 Issue 对象，按标题检索一次都命中不了） |
| maxTokens | 4000 |
| 步数 | 2（`装配上下文` / `写这一轮预研`） |
| 重修 | 最多 2 轮，走 `buildA3Repair` |
| 质量门 | `src/lib/agent/a3/validate.ts` + `src/lib/agent/rules.ts` |

```ts
export async function runPreResearch(
  input: A3Input,
  /** 往任务表报进度。见 `HarnessInit.progress` —— 不给就不报。 */
  opts?: { progress?: { kind: string; id: string } }
): Promise<A3Result> {
  /*
   * 上下文源是 M7 的 S02 配方，**锚点是这条议题挂着的在版判断**。
   *
   * 原来是按 `issue.title` 检索 `ISS-*` 自动选锚点，实跑下来一次都命中不了：图谱
   * 里没有前端这十条议题的 Issue 对象（前端的编号是种子生成脚本自己编的），于是每
   * 份预研都走纯外部。而这些判断号（`01-J3` 这一类）在图里是真实存在的，前端每条
   * 议题也已经挂着它们，所以直接用这条已知的对应关系。代价是这一档的「锚点」含义
   * 从议题变成判断 —— 装出来的正文里如实写明这一点。
   *
   * 判断号为空（有议题确实不动摇任何在版判断）就照旧走检索。`q` 里**不含任何指令
   * 样板**：P3 的 q 上限是 100 字符（服务端约束），前 100 字全是「以下内容来自…
   * 请执行…」的话，拿去检索的等于模板文字。
   *
   * `GraphKnowledgeUnavailable` 不接：图服务挂了要是被当成「图谱里没有这条
   * 议题」，每一次预研都会悄悄降级成纯外部，还照样产出一份格式漂亮的报告。
   */
  const h = new Harness({
    agent: "A3",
    slot: "pro",
    ...(opts?.progress ? { progress: { ...opts.progress, total: STEP_TOTAL } } : {}),
  });
  const judgmentCodes = input.judgments.map((j) => j.id);
  h.step(STEPS.context);
  await h.openContext("S02", input.title, { judgmentCodes });
  // 直接取 getter：它自己判了 externalOnly，两支都回落到 NO_COMPANY_CONTEXT。外面再
  // 判一次的坏处不是多一行，是它暗示 getter 不可信 —— 于是这个三元会被抄到第四、第五处。
  const companyContext = h.contextBlock;

  const assembled: ManifestItem[] = [];
  if (h.externalOnly) {
    // 原因照抄下来。「图谱里没有这条议题」和「它挂着的判断图谱里也没有」是两回事，
    // 而这一行是一号位在屏幕上唯一看得到的解释。
    //
    // 两句分开写，因为手上的材料不一样：装上了 P0 的那次，公司整体状况是真的；没装
    // 上的那次什么都没有。合成一句「无公司上下文」，前一种就被说轻了 —— 一号位会
    // 以为这份预研连本期要达成什么都不知道，而它其实知道。
    assembled.push({
      label: h.companyStateOnly
        ? `只有公司经营状态，没有这条议题的既有认识（${h.noAnchorReason || "图谱里没有对应锚点"}）`
        : `本次无公司上下文（${h.noAnchorReason || "图谱里没有对应锚点"}）`,
      kind: "agent",
    });
  } else {
    const b = h.bundle!;
    assembled.push({
      label: judgmentCodes.length
        ? `GraphKnowledge S02 · 锚点是在版判断 ${b.anchorCode} · ${b.memberIds.length} 个对象`
        : `GraphKnowledge S02 · ${b.anchorCode} · ${b.memberIds.length} 个对象`,
      kind: "int",
    });
  }
  for (const d of input.docs) assembled.push({ label: d.title, href: `/docs/${d.id}`, kind: "int" });
  for (const j of input.judgments) assembled.push({ label: `${j.id} · 在版判断`, href: `/judgments/${j.id}`, kind: "judgment" });

  /*
   * 第 ③ 段认知指令。A3 的 user 段是手写的一整份，不走 `assemble()`，但取值要和
   * A1a 同一条路径 —— 所以直接用 `cognitiveFor`，运行时给了就用运行时的。
   * `cognitiveSource` 跟着模型调用记进 trace：事后要能查出「这一轮到底带没带方法标准」，
   * 否则一份没带标准跑出来的预研和带了的在结果页上长得一模一样。
   */
  const cog = await cognitiveFor("a3.pre-research", h.cognitive["a3.pre-research"]);

  const messages = [
    { role: "system", content: A3_SYSTEM },
    { role: "user", content: buildA3User({ ...input, companyContext, cognitive: cog.text }) },
  ];
  const callDetail = { promptKey: "a3.pre-research", cognitiveSource: cog.source };

  h.step(STEPS.write);
  let raw = (
    await h.callMessages(
      "模型调用 · a3.pre-research",
      messages,
      { maxTokens: 4000 },
      callDetail,
      "a3.pre-research"
    )
  ).text;
  let doc = shape(raw, input, assembled);
  let violations = validatePreResearch(doc);
  let attempts = 1;

  /*
   * 第一轮的违规在这里就留下来，因为下面那个 while 会把 `violations` 覆盖掉。
   *
   * 只落最后一轮的话，台账上就只剩「重修都没救回来」那几条 —— 而绝大多数违规是
   * 第一轮犯、第二轮改对的，那部分全没了，「哪条规则老是被违反」也就答不出来。
   */
  const firstRoundViolations = violations.map(fmt);

  while (blocking(violations).length && attempts <= MAX_REPAIR) {
    messages.push({ role: "assistant", content: raw });
    messages.push({ role: "user", content: buildA3Repair(summarize(blocking(violations))) });
    // 序号不动，只在原话后面接一句轮次 —— 重修是这一步内部再跑一遍，不是第 3 步。
    h.substep(`重修第 ${attempts} 轮`);
    raw = (
      await h.callMessages(
        `模型调用 · a3.pre-research 重修第 ${attempts} 轮`,
        messages,
        { maxTokens: 4000 },
        { ...callDetail, repairOf: summarize(blocking(violations)) },
        "a3.pre-research"
      )
    ).text;
    doc = shape(raw, input, assembled);
    violations = validatePreResearch(doc);
    attempts += 1;
  }

  const degraded = blocking(violations).length > 0;
  return {
    doc,
    violations,
    attempts,
    degraded,
    run: h.finish({
      status: "ok",
      input: input.title,
      output: doc as unknown as Record<string, unknown>,
      violations: violations.map(fmt),
      // 一轮就过时不落这个字段：全过的运行留一个空数组，和「没记」在统计时分不开。
      ...(attempts > 1 ? { firstRoundViolations } : {}),
      degraded,
    }),
  };
}
```

# Prompt 原文

## 五、System 段 · `src/lib/agent/a3/prompt.ts` → `A3_SYSTEM`

```text
你是这家公司一号位的参谋。现在做的是**预研**——在一号位决定要不要把认知资源投进一个议题之前，先帮他判断「这值不值得继续想」。

## 预研不是什么

**不是这个议题的答案。** 这一条最容易违反，而且违反了自己看不出来 —— 因为答案写得越漂亮越像做得好。

分清楚这两句话的区别：

- 「当前证据更支持暂缓同时推进」 ← 这是**议题的答案**。越界了。
- 「这件事的关键依赖有三条现在都没闭合，所以它值得您现在花半天想清楚」 ← 这是**预研该说的**。

你要回答的是「这个问题现在值不值得被认真考虑」，不是「这个问题的答案是什么」。真正需要深入回答的部分留给后面的深研。

**take 和 soWhat 必须指向同一个方向。** 如果 take 已经把判断说死了，soWhat 又说「还不值得深研」，那是自相矛盾 —— 判断都下完了还研究什么。反过来，如果 soWhat 说值得升级，take 就不能已经给出结论。

**status 和 soWhat 也必须指向同一个方向。** 判了 invalid，soWhat 就要落在「不值得 / 不足 / 搁置」上，不许再写「值得升级」；判了 reframing_needed，soWhat 要落在「这条议题的说法先要改」上。

不是资料综述。不要把背景都搬进来，不要按「市场 / 技术 / 竞争」分类罗列。

## 你要产出什么

一个 JSON 对象，字段固定：

- status：这一轮的定性结论，三个值之一。**先判它，再动笔写下面几段。**
  - valid：议题成立，说法也对。
  - invalid：查完之后它不值得继续投入认知。不是「先观察」，是这一轮判掉。
  - reframing_needed：背后的张力是真的，但现在这条说法描述不了它 —— 对象、分类轴、
    因果前提、层级，某一处不对。
- statusReason：判 invalid 或 reframing_needed 的那一句理由，要说清**哪一处**不对，
  不写「综合考虑」。status 是 valid 时留空串。
- question：这轮预研真正要回答的那一句。疑问句，落在「这个议题值不值得投入认知资源」上。
- take：给一号位的那段话。它在屏幕上是对话里的第一条回复，不是摘要面板——所以像人在跟他说话，不像文档。
- finding：查到了什么。每条两个字段：`label` 是一句判断式短标题，`text` 是关键事实加它的含义。各带溯源。
- openQuestion：这一轮答不上来的。也就是「如果升级深研，会去查什么」。
- soWhat：一句话，落在值不值得升级上。不是内容总结。

## take 怎么写

三段，段与段之间空一行：

第一段——先说你的判断，再说依据。不要先铺垫背景。
第二段——为什么是现在。有具体时间点或正在发生的事就写出来。
第三段（可选）——反问。以「反问：」开头，**只问一句**。连着问三句那是审问，不是参谋。

前两段合起来 3 到 4 句。多了就是在写文档，不是在说话。

## finding 怎么写

每条是 `label` + `text` 两个字段，它们是一句话的两半：

- **`label` 是一句判断式短标题** —— 它自己就得给出一个判断，不是给这一条起个类目名。
  「瓶颈正在换层」是判断；「技术进展」「市场情况」「关于成本」是类目名，等于没写。
  一行以内，不带句号也行，屏幕会补。
- **`text` 是关键事实加它的含义** —— 先事实再含义，一到两句。事实要具体到能被核对；
  含义要说清它改变了哪一个判断，不写「值得关注」。

判据很简单：**只读这几条 label 能不能读出你的判断**。读不出来，说明判断还在 text 里，
label 只是标签。同一个意思不要在两条里各说一遍。

`label` 里**不要写星号** —— 加粗是屏幕做的，写了 `**` 只会显示成两个星号。

## 硬规矩

- **屏幕不渲染 markdown。** 不要写 `**`、`##`、`- ` 这些记号，它们会原样显示成星号和井号。
- **只用递给你的事实。** 上下文里没有的数字一个都不许出现。编一个数字出来的代价是他在会上被人当场纠正。
- **数字要服务观点。** 写「7 次里有 6 次指向架构」是因为它改变判断；写「共有 33 人」只是在报数。
- **结论强度要匹配依据。** 依据不足就写「当前更支持」「初步支持」「尚不足以证明」，不要无依据地绝对化。
- **不用中性语言回避。** 「机会与挑战并存」「建议持续关注」「值得持续观察」——这些等于什么都没说。
- **每条 finding 必须有溯源**，从递给你的文档和判断编号里挑，不要编来源。
- 编号照原样写（如 01-J2、ISS-003、DOC-05），屏幕会把它们变成可点开的。
- **只有短码可以写进 traces。** 上下文里如果出现「member:」开头的那种编号，那是本体内部
  编号，屏幕认不出来、点不开 —— 不要把它当来源写进去，改写成它对应的那句话或文档标题。
- 称呼一号位用「您」。不用感叹号。不说「好问题」「让我们」「赋能」「闭环」「抓手」这类空词。
- **引号一律用「」**，不要用 ASCII 的双引号 —— 输出是 JSON，裸的 " 会把它弄坏。
- **中英文与数字之间加空格**：写「产品 1.0」「CEO Agent 收到」，不写「产品1.0」「CEO Agent收到」。屏幕上其余文字都是这个排版，不一致会很显眼。
- **全文控制在 900 字以内。** 这是轻量档 —— 一号位一两分钟要读完。写长了不是更充分，是没抓住重点。
- **Fact、Interpretation、Hypothesis 要分开。** 事实就写事实，推论要让人看得出是推论，别把初步发现包装成结论。

## 有重要反向信号时必须主动说

如果手上的材料里有削弱这个议题重要性的东西，写进 finding。把它藏起来，一号位在会上被别人指出来的代价，比你现在说出来大得多。
```

## 六、User 段的构造 · `src/lib/agent/a3/prompt.ts` → `buildA3User`

注释是 Prompt 的一部分 —— 每一句约束旁边写着它挡的是哪一种失败。

```ts
export function buildA3User(input: A3Input & { companyContext: string; cognitive: string }): string {
  const parts: string[] = [];
  parts.push(`## 议题\n\n${input.title}（编号 ${input.issueId}）`);
  if (input.scope) parts.push(`范围与背景：${input.scope}`);

  /*
   * 递上来的原文。
   *
   * 两句约束缺一不可。
   *
   * **一是不许往它上面编溯源。** 这段材料没有编号也没有链接 —— 它不在本体里，是刚刚
   * 递进来的。而 `validate.ts` 那条 A3-13（每条 Evidence 必须有溯源）是 p0，模型为了
   * 过门一定会给它编一个 `DOC-` 编号或一个 href，编出来的短码在屏幕上渲染成一枚点不开
   * 的徽章，而一号位点它就是为了核对。所以给一个**固定的、不指向任何东西的标签**：
   * 从这段材料读到的话就写「递上来的原文」，不编编号、不编链接。
   *
   * **二是它不是图谱里的东西。** 下面那段公司上下文才是。混起来之后，一号位读到「据
   * 公司决策上下文」时，指的其实是他十分钟前贴进来的一篇外部文章。
   *
   * 位置在最前面（紧跟议题）：它是这一轮唯一确定和这条议题有关的材料，内部文档那一批
   * 是按域粗筛出来的，未必相关。
   */
  const material = (input.material ?? "").trim();
  if (material) {
    parts.push(
      `## 递上来的原文\n\n` +
        `这是这条议题被提出来时附着的材料（一号位自己贴的，或者这条信号带进来的）。` +
        `读它是为了知道这件事在说什么。\n\n` +
        `它没有编号也没有链接：**不要为它编一个文档号或 href**。从它读到的话，溯源就写` +
        ` {"kind": "human", "source": "递上来的原文"}，不写别的。它也**不是**公司上下文，` +
        `下面那一段才是。\n\n` +
        material +
        (input.materialTruncated ? `\n\n…（原文更长，预研只读了这一段 —— 没读完的部分归 openQuestion）` : ""),
    );
  }

  if (input.judgments.length) {
    parts.push(
      `## 这个议题可能动摇的判断\n\n` +
        input.judgments.map((j) => `- ${j.id}（${j.standing}）：${j.statement}`).join("\n")
    );
  }
  if (input.docs.length) {
    /*
     * 预研只给正文开头。它是轻量档 —— 全文塞进来既超预算，也会诱使它写成综述。
     * 「还没读完的部分」正好属于 openQuestion：升级深研会去读全文。
     */
    parts.push(
      `## 可引用的内部文档\n\n` +
        input.docs
          .map((d) => {
            const body = (d.body ?? "").trim();
            if (!body) return `- ${d.id}：${d.title}（只有标题，本体没存正文 —— 不要从标题反推内容）`;
            const head = body.slice(0, 1200);
            return `- ${d.id}：${d.title}\n  正文开头：${head}${body.length > 1200 ? "…（预研只读了开头）" : ""}`;
          })
          .join("\n") +
        `\n\n溯源写文档标题，href 写 /docs/<编号>。`
    );
  }
  // 这一段**永远存在**，三档都有话说（见 `Harness.contextBlock`）：锚上了是装好的
  // 正文；锚没上但取到【公司经营状态】的，是 `wrapCompanyStateOnly`；连它都没有的
  // 是 `NO_COMPANY_CONTEXT`。后两档都把「引用必须为空」写成硬约束 —— 留个空洞的话
  // 模型会自己编一套公司战略假设出来然后正常引用它，那种产出格式全对、引用看着也有，
  // 只是全是假的。
  parts.push(`## 公司决策上下文（GraphKnowledge S02）\n\n${input.companyContext}`);

  /*
   * 第 ③ 段认知指令，来自 `prompts/cognitive/a3.pre-research.md`（方法部门的 S02 技能）。
   * 位置在上下文之后、输出格式之前，跟 `assemble()` 的五段顺序一致 —— 输出格式和硬
   * 规矩必须是模型最后读到的东西，技能里那套文本块式的 Output Contract 才压不过它。
   *
   * 没装上时这一段整个不出现，而不是留一句占位。A3 的 system 段自己是完整的，凭空
   * 多一句「标准尚未提供」只会让模型以为它可以自己定标准。装没装上看 Run 记录里的
   * `cognitiveSource`。
   */
  const cognitive = input.cognitive.trim();
  if (cognitive) parts.push(`## 预研该怎么做\n\n${cognitive}`);

  parts.push(`## 输出

只输出 JSON，不要用代码块包裹，不要写任何解释。形状：

{
  "status": "valid",
  "statusReason": "",
  "question": "……？",
  "take": "第一段。\\n\\n第二段。\\n\\n反问：……？",
  "finding": [
    { "label": "判断式短标题", "text": "关键事实。它的含义。", "traces": [{ "kind": "int", "source": "文档标题", "href": "/docs/DOC-05" }] }
  ],
  "openQuestion": [
    { "text": "……", "traces": [{ "kind": "agent", "source": "您的 Agent · 预研未答" }] }
  ],
  "soWhat": "……"
}
```

## 八、认知段 · `prompts/cognitive/a3.pre-research.md`

第一行 `{{SKILL:m1a-s02-pre-research}}` 在装配时被替换成技能全文（`skills/m1a-s02-pre-research.md`），
`---` 之后是这一次的落法：Phase A 的结论落在哪个字段、技能里那五块内容对应哪几个字段、
以及这条路上最容易违反的两条。

```markdown
{{SKILL:m1a-s02-pre-research}}

---

## 这一次怎么落到给一号位的那份产出上

上面那份技能是 S02 的完整标准。下面三件事是它在这个系统里的落法 —— 冲突的地方
**以这一段为准**，因为字段形状和句数是下游按字段取值、并且由确定性质量门去数的。

### 一、Phase A 的结论是一个字段，不是一种语气

技能要求先定 `Valid / Invalid / Reframing Needed`，再决定写什么。这一步照做：**先在
心里判完，再动笔**，不要一边写正文一边决定值不值得继续 —— 那是技能里的
**Status Gate Bypass**。

判完的结果写进 `status`，理由写进 `statusReason`（判 Valid 时留空串）。这两个字段
屏幕要用，所以它们和正文必须一致：

- **Valid** → `status: "valid"`。正常写，`soWhat` 落在「值得继续投入认知」上。
- **Invalid** → `status: "invalid"`。`soWhat` 要落在「不值得 / 不足 / 搁置」上，
  不许再出现「值得升级」；`take` 里直说为什么原来的担心已经被削弱。
  **不要为了把字段填满造一个未知出来**（技能里的 **Forced Unknown**）——
  `openQuestion` 这时写的是「什么证据出现时它会重新值得看」，那是重启条件，
  不是研究任务。
- **Reframing Needed** → `status: "reframing_needed"`。**不要自己改题**（技能里的
  **Silent Reframing**）：按现有说法写，`statusReason` 说清错在哪一处（对象 /
  分类轴 / 因果前提 / 层级），`soWhat` 落在「这条议题的说法先要改」上。改不改、
  改成什么，是一号位那一步的事。

`statusReason` 会原样显示在一号位的屏幕上，跟在「参谋判这条不值得继续投入」
或「参谋认为这条议题的说法要先改」后面。所以它要说清哪一处，不写「综合考虑」
「多方面因素」这种等于没说的话。

### 二、技能里那五块，对应哪个字段

| 技能里的块 | 这里的字段 |
|---|---|
| Sharp Title | `question` —— 疑问句，落在「这个议题值不值得投入认知资源」上 |
| 核心观点 | `take` 的前两段 |
| 发生了什么 / 这意味着什么 的**判断式短标题** | 每条 `finding` 的 `label` |
| 同一条里的关键事实 + 含义 | 同一条 `finding` 的 `text` |
| 还需要搞清楚什么 | `openQuestion` |
| Make the Case 的落点 | `soWhat` —— 一句话，值不值得升级 |
| Source | 每条 `finding` 的 `traces` |

**技能里的 `- **<判断式短标题>** <关键事实>。<含义。>` 在这里是两个字段，不是一行
markdown。** 屏幕按纯文本渲染，`-` 和 `**` 写出来就是一个减号两个星号；**加粗由屏幕
负责**，你只管把短标题和正文分开放。拆成两格的好处是它变成可数的：`label` 空着看得见，
而写成一行时短标题被省掉只表现为「这条读起来有点闷」。

`label` 是**判断**，不是类目名。「瓶颈正在换层」是判断；「技术进展」「市场情况」是
类目名 —— 技能 §5.1 要的「判断式小标题本身应提供 insight」说的就是这个区别。判据：
只读这几条 `label`，能不能读出你的判断。

**句数按这边的预算，不按技能里的。** 技能写「核心观点默认 2 句」，这里 `take` 的前
两段合起来是 3 到 4 句（不含反问那一段）—— 因为 `take` 在屏幕上是对话里的第一条
回复，不是一张卡片上的一栏。`finding` 2 到 3 条（技能的默认值），全文 900 字以内，
`label` 也算在这 900 字里。

`take` 的第三段是「反问」，技能里没有这一块：它是这个系统里参谋对一号位说话的
方式，只问一句，问的是技能里那个 decisive unknown 逼出来的取舍。

### 三、技能里最容易违反的两条，在这里的具体形态

- **Make the Case for the Question, not for an Answer.** `take` 里写「当前证据更支持
  暂缓推进」就是在给议题的答案，越界了；写「这件事的关键依赖有三条现在都没闭合，
  所以值得您现在花半天想清楚」才是预研。`take` 和 `soWhat` 必须指向同一个方向：
  判断都下完了，就没有什么可研究的了。
- **Compression may remove words, but must not increase certainty.** 压到 900 字以内
  是这里的硬预算，所以这条格外要紧：仍然出现在 `openQuestion` 里的那个解释，不许在
  `take` 或 `finding` 里被写成「直接决定 / 失去支撑 / 必然 / 唯一」。要删的是重复和
  抽象词，不是证据边界。

技能 §6.3 那条在这里也是硬约束：内部编号、检索命中与否、方法自述一律不进正文，
`member:` 开头的本体内部编号更不许当来源写进 `traces` —— 屏幕认不出来，点不开。
```

## 附录 · 质量门原文（`src/lib/agent/a3/validate.ts`）

Prompt 里说「一到两句」「每条必须有溯源」是为了减少重试次数，**不是为了保证**。真正数句子、
数块数、查溯源的是这一份；没过就把违规原样贴回去让它逐条改。

```ts
/**
 * A3 Pre-research 的确定性质量门。**不调模型。**
 *
 * 规则来自 tkos_quality_rubric_v0.1.yaml 的 A3 组里 kind=deterministic 的那些，
 * 加上前端渲染带来的两条硬约束。每条都标了 rubric 编号，改规则时两边一起改。
 *
 * 为什么这一层必须存在：CQ101 §04 的要求里有一半是可数的（Key Takeaway 几句、
 * Evidence 几块、有没有回到去留判断）。**这些绝不能靠 prompt 祈祷** —— 写进
 * prompt 然后指望模型每次都数对，是这类项目最常见的失败。可数的就去数。
 *
 * 违反 p0 的直接打回重生成；p1 只记，不挡。
 */
import type { PreResearchDoc, Statement } from "@/lib/data/types";
import {
  CATEGORY_HEAD,
  chars,
  commonViolations,
  isRhetorical,
  paragraphs,
  sentences,
  type Violation,
} from "@/lib/agent/rules";

export type { Violation } from "@/lib/agent/rules";

const traceOk = (t: Statement) => Array.isArray(t.traces) && t.traces.length > 0;

export function validatePreResearch(doc: PreResearchDoc): Violation[] {
  const v: Violation[] = [];
  const push = (rule: string, severity: "p0" | "p1", message: string) => v.push({ rule, severity, message });

  // ---- status（方法域 S02 的 Phase A）----------------------------------
  //
  // 这一组是**一致性检查**，不是措辞检查：status 是屏幕和统计要用的字段，soWhat 是
  // 一号位读到的那一句。两者打架的时候，屏幕上会出现「参谋判它不值得」压着一句
  // 「值得升级」—— 而这种自相矛盾模型自己看不出来，因为两句单独看都通顺。
  const status = doc.status;
  const reason = (doc.statusReason ?? "").trim();
  if (status === null) {
    push("S02-A", "p0", "没给这一轮的定性结论（status 只能是 valid / invalid / reframing_needed）。");
  }
  if (status !== null && status !== "valid" && !reason) {
    push("S02-A", "p0", `判了 ${status} 却没说理由；这一句要说清哪一处不对。`);
  }
  if (status === "valid" && reason) {
    push("S02-A", "p1", "status 是 valid 就不需要 statusReason，这一句屏幕上不会显示。");
  }

  // ---- take ----------------------------------------------------------
  const paras = paragraphs(doc.take ?? "");
  const body = paras.filter((p) => !isRhetorical(p));
  const rhetorical = paras.filter(isRhetorical);
  const n = body.reduce((a, p) => a + sentences(p).length, 0);

  // A3-01 3–4 句。反问不计入 —— 它是独立的一段，不是 Key Takeaway 的一部分。
  if (n < 3 || n > 4) {
    push("A3-01", "p0", `Key Takeaway 应为 3–4 句（不含反问），实际 ${n} 句。`);
  }
  if (rhetorical.length > 1) {
    // instructions.ts：反问一次只问一句，连着问三句那是审问不是参谋。
    push("A6-01", "p0", `反问只能有一段，实际 ${rhetorical.length} 段。`);
  }
  if (rhetorical.some((p) => sentences(p).length > 1)) {
    push("A6-01", "p0", "反问一次只问一句。");
  }
  if (!doc.take?.trim()) push("A3-03", "p0", "Key Takeaway 是空的。");

  // 前端 AgentText 按空行分段、逐段渲染纯文本 —— markdown 会原样显示成星号井号。
  if (/\*\*|^#{1,6}\s|^[-*]\s/m.test(doc.take ?? "")) {
    push("FE-md", "p0", "take 里有 markdown 记号；屏幕不渲染 markdown，会原样显示。");
  }

  // ---- finding（Evidence block）---------------------------------------
  const f = doc.finding ?? [];
  // A3-04 取 2–4：正文写「2–3 个」而标准表与 §09 checklist 都写「2–4 个」，
  // 两处对一处。见 rubric open_questions.Q1。
  if (f.length < 2 || f.length > 4) {
    push("A3-04", "p0", `Evidence block 应为 2–4 个，实际 ${f.length} 个。`);
  }
  f.forEach((s, i) => {
    if (!traceOk(s)) push("A3-13", "p0", `第 ${i + 1} 个 Evidence 没有溯源。`);
    if (CATEGORY_HEAD.test(s.text.split(/[，。：:]/)[0] ?? "")) {
      push("A3-05", "p1", `第 ${i + 1} 个 Evidence 以分类词开头，应该直接写 synthesis。`);
    }

    /*
     * S02-B：方法域 S02 §5.1 要求每条 Evidence 带一句判断式短标题。
     *
     * **少一句短标题是 p0，不是 p1。** 它不是排版偏好：屏幕上这几条是一号位扫得最快的
     * 地方，短标题是他决定要不要读下面那句的唯一依据。缺了之后这一栏退化成三段等长的
     * 灰字，而这件事在结果页上看起来一切正常 —— 正是必须由这一层来数的那种。
     *
     * 「是不是判断而不是类目名」数不出来，所以这里只数三件能数的：有没有、是不是
     * 分类词、有没有长到不像标题。剩下那件写在 prompt 里（见 `A3_SYSTEM` 的
     * 「finding 怎么写」）。
     */
    const label = (s.label ?? "").trim();
    if (!label) {
      push("S02-B", "p0", `第 ${i + 1} 个 Evidence 没有判断式短标题（label 字段）。`);
      return;
    }
    if (CATEGORY_HEAD.test(label.replace(/[。，、；;]+$/, ""))) {
      push("S02-B", "p1", `第 ${i + 1} 个 Evidence 的短标题「${label}」是类目名，不是判断。`);
    }
    if (chars(label) > 20) {
      // 它在屏幕上是加粗后接着正文往下读的一句，长了就不是标题而是第一句话。
      push("S02-B", "p1", `第 ${i + 1} 个 Evidence 的短标题 ${chars(label)} 字，超过 20 字就不像标题了。`);
    }
  });

  // ---- openQuestion ---------------------------------------------------
  const q = doc.openQuestion ?? [];
  if (q.length === 0) {
    // CQ101 §04：Key Takeaway 必须连上「关键不确定性」，一条都没有说明没在做预研。
    push("A3-02", "p0", "没有列出这一轮答不上来的问题。");
  }
  q.forEach((s, i) => {
    if (!traceOk(s)) push("A3-13", "p1", `第 ${i + 1} 个未答问题没有标注来源。`);
  });

  // ---- soWhat ---------------------------------------------------------
  const so = doc.soWhat ?? "";
  if (!so.trim()) push("A3-11", "p0", "结尾没有回到「值不值得继续」。");
  else if (!/(升级|值得|不值得|不足|继续|搁置|观察)/.test(so)) {
    push("A3-11", "p0", "结尾没有落在去留判断上，只是内容总结。");
  }
  if (sentences(so).length > 2) push("A3-11", "p1", "结尾超过两句；它应该是一句判断。");

  // status 与 soWhat 的一致性。两句单独看都通顺，所以只能靠这里对。
  if (status === "invalid") {
    /*
     * 前面那个否定字要看 —— 「不值得升级」里含着「值得升级」，不看的话一份判得
     * 完全正确的 invalid 反而被打回，而正确的写法只有这一种。
     */
    if (/(?<![不没未难])(值得升级|值得继续|应当升级|建议升级)/.test(so)) {
      push("S02-A", "p0", "判了 invalid，结尾却在说值得升级 —— 两句自相矛盾。");
    } else if (!/(不值得|不足|搁置|暂不|先不)/.test(so)) {
      push("S02-A", "p0", "判了 invalid，结尾要落在「不值得继续」上。");
    }
  }
  if (status === "reframing_needed" && !/(说法|框架|问错|重新框|重新定义|改题)/.test(so)) {
    // 屏幕上会显示「这条议题的说法要先改」。结尾那一句不提这件事，一号位读到的
    // 是一句去留判断，而屏幕在说另一件事。
    push("S02-A", "p1", "判了 reframing_needed，结尾要落在「这条议题的说法先要改」上。");
  }

  // A3-08 不强迫 recommendation —— 完整的行动方案是 Deep Research 的活。
  if (/^\s*(建议|行动建议|下一步建议|对策)[:：]/m.test(so)) {
    push("A3-08", "p1", "结尾写成了行动建议；预研只回答「值不值得继续想」。");
  }

  // ---- 全局 -----------------------------------------------------------
  // statusReason 也算进来：它是要显示在屏幕上的一句，空词、markdown、member: 死链
  // 那几条对它一样成立，字数也一样占预算。
  //
  // **每条 Evidence 的 label 也算进来。** 它和 text 一样是屏幕上的正文，所以两件事都
  // 成立：一是里面写了 `**` 照样要被 FE-md 挡下来（加粗是屏幕做的），二是它占 900 字
  // 预算 —— 不算的话，三条短标题等于给了一份四五十字的免费额度。
  const all = [
    doc.take,
    ...f.flatMap((x) => [x.label ?? "", x.text]),
    ...q.map((x) => x.text),
    so,
    doc.question,
    reason,
  ].join("\n");
  // G-* 组（回避式措辞、空词、markdown、member: 死链）全部走共用原语 ——
  // 这几条对 A3/A4/A10 是同一套要求，各写一份就一定有一份会漏掉后来加的规则。
  v.push(...commonViolations(all, "预研"));
  // A3-12 1–2 分钟读完。
  const total = chars(all);
  if (total > 900) push("A3-12", "p1", `全文 ${total} 字，超过 900 字的轻量档。`);

  if (!doc.question?.trim()) push("A2-06", "p0", "没写这轮预研要回答的那一句。");
  else if (!/[？?]$/.test(doc.question.trim())) {
    push("A2-06", "p1", "「要回答的那一句」不是疑问句。");
  }

  return v;
}

export { blocking, fmt, summarize } from "@/lib/agent/rules";
```
