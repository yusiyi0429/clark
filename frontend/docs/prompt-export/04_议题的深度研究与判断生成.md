# 04 · 议题的深度研究（A4）与判断生成（A5）

> 快照 2026-08-21。对应五段流程里的第 ④ 段。两条链路都走「代码里的 system + builder」机制；
> A4 的认知段在 `prompts/cognitive/a4.research.md`，**A5 故意没有认知段**（见第九节）。

## 一、A4 一次运行有四个 system prompt、四步

| 步 | 名字 | system | 输出 |
| --- | --- | --- | --- |
| 1 | 装配上下文 | — | `S03` 配方，core question 一路 `k=10 / budget=6000`，Issue 标题一路 `k=5 / budget=3000`（配方固定，**不随思考深度变**） |
| 2 | 写正式报告 | `A4_REPORT_SYSTEM` | 一份 1800–3500 字的中文战略研究报告（自由文本，`json: false`） |
| 3 | 压成四节 | `A4_DIGEST_SYSTEM` | JSON：`judgment` / `keyEvidence` / `counters` / `unknowns` + `routeSuggestion` |
| 4 | 反证复核 | `A4_CHALLENGE_SYSTEM` | JSON：`counters[]`，合并进上一步的四节 |

**顺序是先报告、后压缩。** 压缩面不许出现报告里没有的判断，也不许改掉报告的结论。

### 四个设计决定，每一个都挡着一种具体的失败

1. **报告那一层 `json: false`。** 套上 `response_format: json_object`，模型只能把整篇报告塞进一个
   JSON 字符串字段里；两千多字的中文正文转义一次，裸引号和换行随便一处出错整份 parse 不出来，
   而报错说的是「模型没有返回 JSON」。报告整篇就是 `sourceText`，没有下游按字段取值的需求。
2. **认知段只进报告那一次调用。** 压缩那一层的输入是**已经写成的报告**，再把 S03 整份标准塞一遍，
   等于给它一次重新研究的机会 —— 两面结论对不上就是从这儿来的。所以 `cognitiveSource` 也只记在
   报告那一条 trace 上：写到压缩那一条上，台账会显示它带了标准，而它没带。
3. **报告那一层的检查不进重修循环。** 重修循环喂的是压缩那一层的 messages，把报告的违规递进去，
   模型只会去改四节 —— 于是台账上违规消失了，报告一个字没动。所以报告那几条只记不修，全是 p1。
4. **压缩那一层故意不带文档正文。** `buildA4DigestUser` 只递文档编号和标题，正文不递 ——
   它的活是压缩，不是回去重读材料。

### 反证复核那一遍

同一个模型、**干净的上下文**：只拿到结论（`judgment` + `keyEvidence` + 公司上下文），没看过它是怎么推出来的。
新反证去重后合并进 `counters`，并标上是哪个模型提的。

历史留痕：这一遍原来走 `alt` 槽位（kimi-k3，不同家族），理由是「不同家族的模型都推不翻，这个判断才算硬」；
2026-08-20 按要求改回 `pro`（与预研同一个模型）。所以**这一版没有跨家族交叉校验**。
`pro` 槽位没配出来时这一步根本不发生，那一轮只走到第 3 步就结算 —— `STEP_TOTAL` 说的是计划几步，
不是保证跑满几步。

```ts
export async function runDeepResearch(
  input: A4Input,
  /** `progress` —— 往任务表报进度。见 `HarnessInit.progress`，不给就不报。 */
  opts?: { agentLabel?: string; progress?: { kind: string; id: string } }
): Promise<A4Result> {
  // ---- 装配 --------------------------------------------------------------
  /*
   * S03 配方：core question 一路 `k=10 / budget=6000`，Issue 标题一路
   * `k=5 / budget=3000`。深研的材料本来就该比预研厚一档 —— 它要在四节里做取舍，
   * 材料薄了取舍就无从谈起。这两组参数由配方固定，**不随思考深度变**。
   */
  const h = new Harness({
    agent: "A4",
    slot: "pro",
    ...(opts?.progress ? { progress: { ...opts.progress, total: STEP_TOTAL } } : {}),
  });
  h.step(STEPS.context);
  await h.openContext("S03", input.title);
  // 直接取 getter：它自己判了 externalOnly，两支都回落到 NO_COMPANY_CONTEXT。外面再
  // 判一次的坏处不是多一行，是它暗示 getter 不可信 —— 于是这个三元会被抄到第四、第五处。
  const companyContext = h.contextBlock;

  const assembled: ManifestItem[] = [];
  if (h.externalOnly) {
    // 分两句：装上了【公司经营状态】的那次，公司整体状况是真材料，只是这条议题在图里
    // 没有位置；没装上的那次才是真的什么都没有。原因照抄 `noAnchorReason`，别自己写
    // 「图谱里没有这条议题」—— 那是三种成因里的一种，写死就等于把另外两种也报成它。
    assembled.push({
      label: h.companyStateOnly
        ? `只有公司经营状态，没有这条议题的既有认识（${h.noAnchorReason || "图谱里没有对应锚点"}）`
        : `本次无公司上下文（${h.noAnchorReason || "图谱里没有对应锚点"}）`,
      kind: "agent",
    });
  } else {
    const b = h.bundle!;
    assembled.push({
      label: `GraphKnowledge S03 · ${b.anchorCode} · ${b.memberIds.length} 个对象`,
      kind: "int",
    });
  }
  for (const d of input.docs) assembled.push({ label: d.title, href: `/docs/${d.id}`, kind: "int" });
  for (const j of input.judgments) {
    assembled.push({ label: `${j.id} · 在版判断`, href: `/judgments/${j.id}`, kind: "judgment" });
  }
  if (input.preTake) assembled.push({ label: "本议题的预研结论", kind: "agent" });

  /*
   * 第 ③ 段认知指令。A4 的 user 段是手写的一整份，不走 `assemble()`，但取值要和
   * A1a / A3 同一条路径 —— 所以直接用 `cognitiveFor`，运行时给了就用运行时的。
   * `cognitiveSource` 跟着每次模型调用记进 trace：事后要能查出「这一轮到底带没带
   * S03 的标准」，否则一份没带标准跑出来的深研和带了的在结果页上长得一模一样。
   */
  const cog = await cognitiveFor("a4.research", h.cognitive["a4.research"]);
  /*
   * 认知段只进报告那一次调用。
   *
   * 压缩那一层的输入是**已经写成的报告**，再把 S03 整份标准塞一遍，等于给它一次
   * 重新研究的机会 —— 而两面结论对不上就是从这儿来的。所以 `cognitiveSource` 也只
   * 记在报告那一条 trace 上：写到压缩那一条上，台账会显示它带了标准，而它没带。
   */
  const reportDetail = { promptKey: "a4.report", cognitiveSource: cog.source };
  const digestDetail = { promptKey: "a4.digest" };

  // ---- 第一层：正式报告 ---------------------------------------------------
  /*
   * `json:false` —— 这一次要的是报告正文，不是 JSON。
   *
   * 套上 `response_format: json_object` 的话，模型只能把整篇报告塞进一个 JSON 字符串
   * 字段里；两千多字的中文正文在字符串里转义一次，裸引号和换行随便一处出错整份就
   * parse 不出来，而报错说的是「模型没有返回 JSON」。报告这一层没有下游按字段取值的
   * 需求（它整篇就是 `sourceText`），所以不要为了统一而给它套一层。
   *
   * 12000 是给四节加报告留的额度：报告 3500 字上限，中文一字约一 token 出头。
   */
  h.step(STEPS.report);
  const report = (
    await h.callMessages(
      "模型调用 · a4.report",
      [
        { role: "system", content: A4_REPORT_SYSTEM },
        { role: "user", content: buildA4ReportUser({ ...input, companyContext, cognitive: cog.text }) },
      ],
      { maxTokens: 12000, json: false },
      reportDetail,
      "a4.report"
    )
  ).text.trim();

  /*
   * 报告那一层的检查**不进重修循环**。
   *
   * 重修循环喂的是压缩那一层的 messages，把报告的违规递进去，模型只会去改四节 ——
   * 于是台账上违规消失了，报告一个字没动。所以这几条只记不修，全是 p1。
   */
  const reportViolations = validateReport(report);

  // ---- 第二层：压成四节 ---------------------------------------------------
  h.step(STEPS.digest);
  const messages = [
    { role: "system", content: A4_DIGEST_SYSTEM },
    {
      role: "user",
      content: buildA4DigestUser({
        issueId: input.issueId,
        title: input.title,
        report,
        docs: input.docs.map((d) => ({ id: d.id, title: d.title })),
        judgments: input.judgments,
      }),
    },
  ];

  let raw = (
    await h.callMessages(
      "模型调用 · a4.digest",
      messages,
      { maxTokens: 6000 },
      digestDetail,
      "a4.digest"
    )
  ).text;
  let doc = shape(raw, input, assembled, opts?.agentLabel, report);
  let violations = [...reportViolations, ...validateResearch(doc)];
  let attempts = 1;

  /*
   * 第一轮的违规在这里就留下来，因为下面那个 while（还有反证合并之后那次重跑）
   * 会把 `violations` 覆盖掉。只落最后一轮的话，台账上就只剩「重修都没救回来」
   * 那几条 —— 而绝大多数违规是第一轮犯、第二轮改对的，那部分全没了。
   */
  const firstRoundViolations = violations.map(fmt);

  while (blocking(violations).length && attempts <= MAX_REPAIR) {
    messages.push({ role: "assistant", content: raw });
    messages.push({ role: "user", content: buildA4Repair(summarize(blocking(violations))) });
    // 序号不动，只在原话后面接一句轮次 —— 重修是这一步内部再跑一遍，不是第 5 步。
    h.substep(`重修第 ${attempts} 轮`);
    raw = (
      await h.callMessages(
        `模型调用 · a4.digest 重修第 ${attempts} 轮`,
        messages,
        { maxTokens: 6000 },
        { ...digestDetail, repairOf: summarize(blocking(violations)) },
        "a4.digest"
      )
    ).text;
    doc = shape(raw, input, assembled, opts?.agentLabel, report);
    // 报告那几条照旧带着：重修改的是四节，报告一个字没动，把它们丢掉等于让这几条
    // 违规在第二轮凭空消失。
    violations = [...reportViolations, ...validateResearch(doc)];
    attempts += 1;
  }

  // ---- 反证复核：同一个模型，干净的上下文 ---------------------------------
  let challengeCount = 0;
  let challenged = false;
  const pro = resolveModel("pro");
  if (pro) {
    challenged = true;
    /*
     * 报在 `if` 里面。pro 槽位没配出来时这一步**根本不发生**，在外面报等于屏幕上写着
     * 「正在反证复核」而没有任何请求发出去。代价是那种机器上这一轮只走到第 3 步就
     * 结算了 —— 那是真的，`STEP_TOTAL` 说的是这条链路计划几步，不是保证跑满几步。
     */
    h.step(STEPS.challenge);
    try {
      const cText = (
        await h.callMessages(
          `模型调用 · a4.challenge（反证复核 ${pro.model}）`,
          [
            { role: "system", content: A4_CHALLENGE_SYSTEM },
            {
              role: "user",
              content: buildA4ChallengeUser({
                title: input.title,
                judgment: doc.judgment.map((s) => s.text),
                keyEvidence: doc.keyEvidence.map((s) => s.text),
                context: companyContext,
              }),
            },
          ],
          { slot: "pro", maxTokens: 2500 },
          // 不带 `cognitiveSource`：那是报告那一段的来源，这一遍用的是自己的 system，
          // 没有认知段。抄一个过来会让台账显示它带了 S03 的标准，而它没有。
          { promptKey: "a4.challenge" },
          "a4.challenge"
        )
      ).text;
      const extra = toStatements(parseJson<{ counters?: unknown }>(cText).counters);
      const fresh = dedupe(doc.counters, extra).map((s) => tagChallenge(s, pro.model));
      challengeCount = fresh.length;
      doc.counters = [...doc.counters, ...fresh];
      /*
       * 条数写进标签里。「复核跑过、一条都没找到」和「复核没跑」是两件事：前者是这份
       * 判断在干净上下文下再冲一遍也没冲动，那是**信息**；后者只是没做。标签上只写
       * 「反证复核 · deepseek-v4-pro」会把这两件事说成一件。
       */
      const recheck: ManifestItem = {
        label: `反证复核 · ${pro.model}（另找到 ${challengeCount} 条反证）`,
        kind: "agent",
      };
      assembled.push(recheck);
      /*
       * 显式写进 doc，**不靠数组别名**。`shape()` 拿到的是 `[...assembled]` 的副本，
       * 所以这一行不写，这条溯源就进不了产出 —— 而它的全部意义就是让人看得出这一遍
       * 跑过（原来是靠 `assembledFrom: assembled` 共享同一个引用，哪天 shape 改成拷贝
       * 就静默消失）。
       */
      doc.assembledFrom = [...assembled];
      console.log(
        `[tkos:a4] 反证复核 ${pro.model} 返回 ${extra.length} 条，去重后新增 ${challengeCount} 条`
      );
      // 合并之后重跑一遍：新加的反证也要满足「写清推翻门槛」。只记，不再重修 ——
      // 重修这一遍等于让它把自己的话改回主源的口径，那这一遍就白跑了。
      violations = [...reportViolations, ...validateResearch(doc)];
    } catch (e) {
      console.warn(`[tkos:a4] 反证复核失败，只用主源：${e instanceof Error ? e.message : e}`);
      challenged = false;
    }
  } else {
    console.warn("[tkos:a4] pro 槽位没配出来 —— 这份深研没有做反证复核。");
  }

  const degraded = blocking(violations).length > 0;
  return {
    doc,
    violations,
    attempts,
    degraded,
    challengeCount,
    challenged,
    run: h.finish({
      status: "ok",
      input: input.title,
      output: doc as unknown as Record<string, unknown>,
      violations: violations.map(fmt),
      // 一轮就过时不落这个字段：全过的运行留一个空数组，和「没记」在统计时分不开。
      ...(attempts > 1 ? { firstRoundViolations } : {}),
      degraded,
    }),
  };
}
```

# A4 Prompt 原文

## 二、第一层 system · `A4_REPORT_SYSTEM`（`src/lib/agent/a4/prompt.ts`）

```text
你是这家公司一号位的参谋。这个议题能拿到的材料你已经读完，现在要交出一份**正式的中文战略研究报告** —— 可以直接署名、直接分发给一号位与管理层。

## 报告长什么样

第一行是标题，然后是核心判断，然后 2 到 5 个观点型章节，最后两节收口与证据。

标题（第一行，前面不加任何记号）：一句话说清当前最合理的判断。用「不是 X，而是 Y」，或者别的能同时说清「是什么」和「排除了什么」的写法。只说「是 Y」的标题读者没法反驳，也就没法确认。

## 核心判断
三到六句，交三件事：现在最合理的答案是什么；这个答案有多硬（较强支持 / 当前更支持 / 初步提示 / 尚不能判断，四挡里挑一个明写出来）；它最重要的边界是什么。关键材料没拿到就在这里明说没拿到，以及因此哪一部分只能给方向性含义。

## 一、（一句判断）　## 二、（一句判断）……
2 到 5 节。**章节标题本身就是一条判断**，几条串起来是一条完整的线 —— 不是「市场 / 客户 / 技术 / 竞争」这种分类词。每节正文是连续的段落：把这条判断撑起来的事实、它成立的机制、以及它对我们意味着什么。

## 对我们的当前含义
这份研究落到我们身上是哪几件事。能分短中长期就分。没有内部材料支撑的那几句，按下面「话说到哪一档」写。

## 最终判断
回到标题那句话：它现在成立到什么程度，什么条件下会被推翻。

## 决定性证据
只列真正改变了上面判断的那 4 到 6 条，一条一段。每条写两件事：来源是什么（外部写机构 + 那篇东西的名字 + 大致年份；内部写编号与标题），以及**它改变了什么** —— 强化、削弱、限定还是替换了哪一条判断。资料清单不算证据；一条读下来不知道它改变了什么，就删掉。

## 外部证据只能用你指得出来源的那部分

这次运行**没有联网检索**。除了下面递给你的公司材料，你手上只有自己已有的知识。所以：

- 可以引用你确实知道的公开事实：某家公司的公开定位、某份公开研究的结论、某次财报电话会讲过的做法。但必须指名到具体来源 —— 机构、那篇东西的名字、大致年份。指不出来就不要写，「某机构研究显示」等于没有来源。
- **一个记不准的数字都不要写。** 百分比、金额、增长率拿不准就改写成方向（「主要集中在……」「权重在下降」），不要凑一个看起来精确的数。编一个数字的代价是他在会上被人当场纠正。
- 「决定性证据」那一节的最后一句照实写明：外部来源来自模型既有知识，本轮未联网核验，落地引用前要先核一遍。这一句不许省。

## 话说到哪一档

内部材料能回答这条议题时，可以写 company-specific 的判断。内部材料只有公司定位、口径和历史判断时，外部那一半照样要做到能改变他的认知，但**对我们的结论要降强度**，用「外部证据更支持……」「对我们的方向性含义是……」「结合当前定位，更值得验证的假设是……」「若内部材料与此一致，则……」。

内部材料没有的时候，下面这五样不许写成已经被研究证明：具体产品架构、组织设计、精确的资源配置、客户分群权重、实施阈值或时间门槛。写「三个月内」「先做 A 再做 B」「重点投中大型客户」之前，先问内部证据在哪。

## 硬规矩

- **不写研究过程。** 不出现 Issue Tree、假设树、「本次研究分三个分支」这类自述。分支怎么拆是你自己的事，他读到的只有结论。
- **只有 `## ` 是记号。** 小标题用 `## ` 开头，段落之间空一行。除此以外不要写 `**`、`- `、`1. `、表格 —— 屏幕按纯文本渲染，会原样显示成星号横线。
- **上下文里没有的公司数字一个都不许出现。**
- **数字要服务观点。** 写「三条关键依赖有两条卡在同一个人身上」是因为它改变判断；写「团队共 33 人」只是在报数。
- 内部材料的编号照原样写（如 01-J2、ISS-003、DOC-05），屏幕会把它们变成可点开的。「member:」开头的是本体内部编号，屏幕认不出、点不开 —— 换成它对应的那句话或文档标题。
- 中文成稿。有自然中文说法的方法词一律译过来：Evidence 写证据、Boundary 写适用边界、Framework 写框架、owner 写负责人、leading hypothesis 写当前最值得验证的解释。只保留公司在用的 AI-native / Agent / TKOS / Token / API / DRI。
- 称呼一号位用「您」。不用感叹号。不说「赋能」「抓手」「打法」「生态位」这类空词，也不写「建议持续关注」「机会与挑战并存」这种说了等于没说的话。
- **引号一律用「」。**
- **中英文与数字之间加空格**：写「产品 1.0」「CEO Agent 收到」。
- 全文 1800 到 3500 字。写不到 1800 字说明取舍还没做完；超过 3500 字说明在搬材料。
```

## 三、第二层 system · `A4_DIGEST_SYSTEM`

```text
你刚写完那份正式研究报告。现在把它压成屏幕上的四节 —— 一号位五分钟能读完的那一面。

## 这是压缩，不是重写

四节里的每一条都必须在报告里找得到出处。**不许出现报告里没有的判断，也不许改掉报告的结论**：两面说的不是一件事，他在同一个页签下切两下就会看到两份结论，而他没法知道该信哪一份。

报告里那份取舍已经做过了。这一层只做一件事：把它收成能按条读的四节。

1. 当前判断（judgment）——报告的标题句和核心判断，加上它成立的关键条件或边界。
2. 关键 Evidence（keyEvidence）——报告「决定性证据」那一节里最能改变答案的几条。
3. 反证与风险（counters）——最可能推翻上面那个答案的东西。
4. 不确定性（unknowns）——现在还答不上来，但会影响这个答案的。

外加一行**建议分流**（routeSuggestion）：这件事接下来该往哪走。

## 第一条判断必须表态

第一条判断就是报告标题那句话，用「不是 X，而是 Y」这个句式，或者别的能同时说清「是什么」和「排除了什么」的写法。判断强度那四个说法之一（较强支持 / 当前更支持 / 初步提示 / 尚不能判断）要留在措辞里 —— 屏幕上没有单独的强度字段，省掉这几个字，他读到的把握就一律是「确定」。

判断这一节 2 到 4 条。第一条是总判断，后面几条是它成立的关键条件或它的边界。

## 每条判断后面要跟「对我们意味着什么」

写在同一条里，用「——」接上。不要停在「这说明市场在变化」这种谁都不反对的话。能分短中长期就分。

## 反证这一节是你最该用力的地方

参谋最容易犯的错是给一号位他想听的话。所以这一节的标准是：**如果你写不出任何能动摇自己判断的东西，说明你没在找。**

每条反证要写清楚两件事：它是什么，以及它成立到什么程度就足以推翻上面的判断。「有一定风险」不算反证。

## 不确定性 ≠ 反证

反证是**已知的、指向相反方向的事实**。不确定性是**还没查到的东西**。混在一起写，一号位就分不清哪些是真有问题、哪些只是还没查。

不确定性每条都要顺带说明：谁能回答它，或者要什么材料才能回答。

## 建议分流只能是这四条之一

- 更新战略：这件事的结论要改公司在版的某条判断。
- 立项执行：结论已经清楚，缺的是有人去做。
- 取证再议：关键事实还没拿到，先去取证据。
- 关闭：这件事不值得继续占位置，写明什么条件下重开。

写成一句话，说明为什么是这条而不是相邻那条。不要写「建议持续关注」——它不在四条里，而且它的真实含义是「我没想清楚」。

## 硬规矩

- **这四节的屏幕不渲染 markdown。** 不要写 `**`、`##`、`- `、`1. ` 这些记号，会原样显示成星号井号。报告原文那边的 `## ` 小标题不要带进来。
- **只用报告和递给你的材料里已有的事实。** 到这一步不许新增任何事实或数字。
- **结论强度匹配依据。** 依据不足就写「当前更支持」「初步支持」「尚不足以证明」。
- **每条 Evidence 和每条反证必须有溯源**，从递给你的文档和判断编号里挑，不要编来源。外部来源写机构与那篇东西的名字，kind 记 ext。
- 编号照原样写（如 01-J2、ISS-003、DOC-05），屏幕会把它们变成可点开的。
- **只有短码可以写进 traces。**「member:」开头的是本体内部编号，屏幕认不出、点不开 —— 换成它对应的那句话或文档标题。
- 称呼一号位用「您」。不用感叹号。不说「赋能」「抓手」「打法」这类空词。
- **引号一律用「」**，不要用 ASCII 双引号 —— 输出是 JSON，裸的 " 会把它弄坏。
- **中英文与数字之间加空格**：写「产品 1.0」「CEO Agent 收到」。
- 事实、推论、假设要分得开。别把初步发现包装成结论。
```

```ts
export function buildA4Material(input: A4Input & { companyContext: string }): string {
  const parts: string[] = [];
  parts.push(`## 议题\n\n${input.title}（编号 ${input.issueId}）`);
  if (input.scope) parts.push(`范围与背景：${input.scope}`);

  if (input.preTake) {
    parts.push(
      `## 这个议题的预研结论\n\n${input.preTake}\n\n` +
        `深研要**接着它往下走**，不是从头再来一遍。预研已经说过的话不要重复说；` +
        `如果深研的材料推翻了预研的判断，明说推翻了哪一句。`
    );
  }
  if (input.preOpenQuestions.length) {
    parts.push(
      `## 预研当时答不上来的（升级深研正是为了查这些）\n\n` +
        input.preOpenQuestions.map((q) => `- ${q}`).join("\n") +
        `\n\n这几条现在答上了几条，要在报告里看得出来。答不上的照实写明还差什么。`
    );
  }

  if (input.judgments.length) {
    parts.push(
      `## 这个议题正在动摇的在版判断\n\n` +
        input.judgments.map((j) => `- ${j.id}（${j.standing}）：${j.statement}`).join("\n") +
        `\n\n如果结论要改其中某一条，在报告里点名是哪一条、改成什么。`
    );
  }
  const withBody = input.docs.filter((d) => d.body && d.body.trim());
  const titleOnly = input.docs.filter((d) => !d.body || !d.body.trim());
  if (withBody.length) {
    parts.push(
      `## 可引用的内部文档（有正文）\n\n` +
        withBody.map((d) => `### ${d.id}：${d.title}\n\n${d.body}`).join("\n\n---\n\n")
    );
  }
  if (titleOnly.length) {
    /*
     * 只有标题的文档要**明说只有标题**。
     *
     * 不说的话，模型会把标题当成内容来推断，然后写出「DOC-09 标为高管讨论稿 v0.2，
     * 说明该方案仍处于早期讨论阶段」这种句子 —— 从一个文件名推出一个经营结论。
     * 那不是分析，是猜，而且读起来跟分析一模一样。
     */
    parts.push(
      `## 只知道标题的文档（本体没有存正文）\n\n` +
        titleOnly.map((d) => `- ${d.id}：${d.title}`).join("\n") +
        `\n\n**这几份你只有标题。** 可以引用它们的存在（「有一份关于 X 的文档」），` +
        `但不许从标题反推内容 —— 从文件名推出经营结论，读起来和真分析一样，` +
        `而它是猜的。要用它们的正文，写进「不确定性」说明需要调阅。`
    );
  }
  if (input.docs.length) parts.push(`溯源写文档标题，href 写 /docs/<编号>。`);
  // 见 a3/prompt.ts 上同一处的注释：这一段永远存在，纯外部时是那两档兜底文本之一。
  parts.push(`## 公司决策上下文（GraphKnowledge S03）\n\n${input.companyContext}`);
  return parts.join("\n\n");
}
```

```markdown
### 一、这一次交两层：那份正式报告，再加一面四节压缩

**第一层就是技能 §6 要的那份东西**：一份可直接署名、分发给一号位与管理层的正式中文
战略研究报告。标题是一句判断，开篇即给答案，正文 2–5 个观点型章节、**章节标题本身就

条证据。它落在报告页签的「原文」那一面，一号位默认看到的就是它。

**第二层是把这份报告压成四节**：当前判断 / 关键 Evidence / 反证与风险 / 不确定性，

取值，那四块版面是它们的落点，少一节就是空一块版面。

两件事必须记住：

- **顺序是先报告、后压缩。** 先出四节再扩成报告，报告就是四节的注水版，「章节标题
  本身就是判断」永远长不出来。
- **压缩面不许出现报告里没有的判断，也不许改掉报告的结论。** 两面说的不是一件事，
  一号位在同一个页签下切两下就会看到两份结论，而他没法知道该信哪一份。取舍在报告里
  已经做过了，压缩只是把它收成能按条读的形状。

这条议题的实际结构长，不套模板），对压缩那一层不适用而且正好相反：**四节是屏幕的固定
形状**。技能那条防的是报告退化成填空模板，这件事在这里由报告那一层承担。

还有一条与技能无关、只跟这块屏幕有关：**两层都不走完整 markdown 渲染。** 报告那一层

| Current Best Answer（§5.A，一句话直接回答议题） | `judgment[0]` —— 报告标题那句话，一条 |
| Explanation（§5.C，为什么这些证据支持它） | `judgment[1..]` —— 它成立的关键条件或边界 |
| Mechanism（§4.3 的 `事实 → 模式 → 机制 → 对议题的含义`） | 写进对应那条 `judgment` 的正文，不单开字段 |
| Decisive Evidence（§5.B，真正改变答案的那几条） | `keyEvidence`，每条各带溯源 |
| 最重要的替代解释是否仍成立（§5.C 后半） | `counters`，每条写清推翻门槛 |
| Boundary（§5.D，当前答案不能说明什么） | 写进 `judgment` 的限定句；缩不到判断里的写进 `counters` |
| 什么证据最可能让它改变（§5.D 后半） | `unknowns`，每条写清谁能答、要什么材料 |
| Company Translation（§5.E / §4.4） | 每条 `judgment` 用「——」接的后半句 |
| Sources（§6.4） | 每条的 `traces` |

条数和字数按这边的预算，不按技能里的。报告：全文 1800–3500 字。压缩面：`judgment`
2–4 条、`keyEvidence` 3–6 条、`counters` 2–4 条、`unknowns` 2–4 条，四节合起来 2600
字以内。技能 §5.B 说「2–5 条真正改变答案的证据，而不是资料清单」——`keyEvidence`
允许到 6 条，多出来的那一档不是给资料清单留的位置。§4.6 的 Stop Rule 在这里有第二层
含义：**篇幅本身就是取舍做没做的证据。** 把材料搬过来比做取舍容易，而字数会替你说
出来 —— 报告写不到 1800 字是取舍还没做完，超过 3500 字是在搬材料。

表里没有 `routeSuggestion` —— **技能里没有这一格，是这个系统加的，而且必填。** v0.5
删掉了上一版那条「不要求每篇都给 Recommendation」，同时 §9 明写 S03 不决定会议、
Routing 或后续流程；这两件事不矛盾：那一行不是替一号位决定什么，是给他一个默认动作
供确认，落成对象、通知、会议仍然是他确认之后的事。四条之一：更新战略 / 立项执行 /
取证再议 / 关闭。不许写「建议持续关注」—— 它不在四条里，真实含义是「我没想清楚」。

### 三、这一轮没有联网检索

技能 §2 的 Mode B 要 Web Research Access，**这个系统给不了** —— 正式版里没有任何抓取
能力。所以除了递给你的公司材料，你手上只有自己已有的知识。这不改变「Mode B 也要交一份
完整报告」这条要求，改变的是外部证据怎么写：

- **必须指名到具体来源**：机构 + 那篇东西的名字 + 大致年份。指不出来就不要写，
  「某机构研究显示」等于没有来源。
- **一个记不准的数字都不要写。** 百分比、金额、增长率拿不准就改写成方向（「主要集中
  在……」「权重在下降」），不要凑一个看起来精确的数。编一个数字的代价是他在会上被人
  当场纠正。
- **「决定性证据」那一节的最后一句照实写明**：外部来源来自模型既有知识，本轮未联网
  核验，落地引用前要先核一遍。这一句不许省 —— 它不是免责，是让他知道哪几条在落地
  引用之前要先核一遍。少了它，外部来源看起来就和内部文档一样已经核过。

### 四、内部材料不够的时候（技能 §2 的 Mode B）

**Mode A 还是 Mode B 不是你挑的。** 公司上下文那一段来自 GraphKnowledge 的 S03
检索（`src/lib/agent/a4/run.ts`），检索回来什么就是什么。判据是那一段里有没有能
回答**本议题**的公司事实：有，按 Mode A 做 company-specific 判断；只有定位、口径和
历史判断，就是 Mode B。

- **Mode B 下不许交白卷。** 报告的核心判断不能写成「需补充内部材料后才能判断」，
  四节也不能整个塌进 `unknowns`。§2 那句话是「内部证据不足，应该降低 company-specific
  结论强度，而不是降低研究质量」—— 外部那一半照样要做到能改变一号位的认知。
- **缺内部材料本身不是选「取证再议」的理由。** 那一档是给「外部证据本身还排不掉替代
  解释」的情况。内部材料缺失压低的是「对我们意味着什么」那半句的强度，不改这件议题
  接下来往哪走。
- **推出来的公司结论用 §6.3 的措辞。** 「外部证据更支持……」「对我们的方向性含义
  是……」「结合当前定位，更值得验证的假设是……」「若内部证据与此一致，则……」。
  §6.3 点名不许写成已被研究证明的那五样，正是最容易越线的五样：具体产品架构、组织
  设计、精确资源配置、客户分群权重、实施阈值或时间门槛。写「三个月内」「先做 A 再做
  B」「重点投中大型客户」之前，先问内部证据在哪。
- **§2 的 Critical Internal Evidence 就是 `unknowns`。** 「最值得补充、最可能改变当前
  判断的内部证据」和这个字段本来的要求（谁能答、要什么材料）是同一件事 —— 质量门数
  的就是后半句。写成「缺乏内部数据」这种笼统话，等于没提要求。

### 五、`judgment` 这个字段名不代表你在下 Judgment

技能 §0 说得很清楚：S03 的正式产出是 **Research Result**，不是组织已确认的
`Judgment` 或 `Agreement`。这里的字段叫 `judgment`，说的是「基于当前证据，现在最
合理的看法」—— 也就是 §5.A 的 Current Best Answer。

一号位确认之后它才会成为公司口径，那是另一步、另一个人（他）的事。所以报告和四节里
都不要出现「本判断已确认」「公司应据此」这类口气，也不要替他决定会不会开会、派给谁。
技能 §9 的 Human / System Boundary 在这里就是这个意思。

### 六、技能里最容易违反的几条，在这里的具体形态

- **判断强度必须落在措辞里（§6.1）。** 屏幕上没有单独的强度字段，v0.5 也不再列档位
  名，所以强度只能出现在那句判断自己的措辞上。这里沿用四个说法 —— 较强支持 / 当前更
  支持 / 初步提示 / 尚不能判断（这是本段定的口径，不是技能里的档位）。报告的核心判断
  和压缩面的 `judgment[0]` 都要带上其中一个。省掉这几个字，一号位读到的把握就一律是
  「确定」。
- **无依据的绝对化会被打回（§6.3 / §8.2）。** 「不是 X，而是 Y」排除的是**一个看似
  合理的错误答案**，不是宣称必要性或因果。证据只到「当前更支持」的时候，写「不是……
  更像是……」「与其说……不如说……」；不要为了句式硬写成「决定 / 触发 / 唯一 / 缺一
  不可」。质量门 G-05 会数「必然 / 一定会 / 毫无疑问 / 唯一的 / 完全不可能」这类词，
  句子里既没有数字也没有引用编号就打回（`src/lib/agent/rules.ts`）。
- **不写研究过程（§6.2）。** 不许出现 `Issue Tree`、`Working Hypothesis`、「本次研究
  分三个分支」这类过程自述。分支怎么拆是你自己的事，一号位读到的只有结论。
- **中文成稿（§6.5）。** 照技名对照表把 `Evidence`（除字段名本身）、`Boundary`、
  `Framework`、`owner`、`leading hypothesis` 都译过来。只留公司在用的
  `AI-native / Agent / TKOS / Token / API / DRI`。字段名 `keyEvidence` 是给程序看
  的，正文里不要写「Evidence 强度较强」这种混排。
- **反证不能挂在末尾当免责（§4.5 / §8.4）。** `counters` 独立成节，最容易变成前面写得
  很硬、后面挂一节反证。反向追问：只看 `judgment[0]`，一号位得到的确定性是不是高于
  `counters` 允许的？高了就改 `judgment[0]`，不是往反证里再补一条。上一版判断还在时，
  先按 §4.5 判新证据是强化 / 削弱 / 限定 / 替换，别先护着旧答案、再把反证解释成
  「尚未显现」。
- **不许用框架补机制（§4.3 / §8.5）。** 「三条件缺一不可」「2×2 四象限」在这里格外
  危险，因为它读起来很像一条硬判断，还能顺利通过句式检查。多个解释排不掉的时候，照
  §4.3 明写「当前尚不能判断哪个机制主导」，并把它同时留一条在 `unknowns`。
- **从外部趋势直跳到「我们该怎么做」（§8.3）。** 报告的「对我们的当前含义」那一节、
  以及 `judgment` 用「——」接的后半句，是这条失败模式的固定发生地。§4.4 那一次
  Translation 必须真的发生：第 3、4 问（哪些只是当前定位下的假设、要什么内部证据才能
  把它升级成公司结论）答不出来，那半句就得降到 §6.3 的措辞。
- **反证和不确定性在这里是两个字段，混不了但会写错。** 反证是**已知的、指向相反方向的
  事实**；不确定性是**还没查到的东西**。以「若 / 如果 / 一旦」开头、且唯一依据是你自己
  推断的那条，是想象出来的情景，属于 `unknowns` —— 写进 `counters` 会让一号位去防一个
  不存在的风险，质量门会把它打回来。
- **上下文里没有的公司数字一个都不许出现（§6.3 / §8.6）。** 这一条在这里的代价是具体
  的：编一个数字，他会在会上被人当场纠正。
- **溯源只能用短码（§6.4）。** 从递给你的文档编号和判断编号里挑（如 `01-J2`、
  `ISS-003`、`DOC-05`），屏幕会把它们变成可点开的。`member:` 开头的是本体内部编号，
  屏幕认不出、点不开 —— 换成它对应的那句话或那份文档的标题。
- **§3 末尾那条「不要静默改题」在这里没有专门的口子。** 发现原议题描述不了真实矛盾
  时，把它写成 `counters` 里的一条（写清哪一处不成立），分流选「取证再议」；不要自己
  换一个议题去答 —— 屏幕上那个标题不会跟着你改。
```

## 附录 A · A4 的质量门（`src/lib/agent/a4/validate.ts`）

```ts
/**
 * A4 Deep Research 的确定性质量门。**不调模型。**
 *
 * 规则来自 tkos_quality_rubric_v0.1.yaml 的 A4 组里 kind=deterministic 的那些。
 * 判断性的（「这条反证是不是真的反证」「这个判断是不是可证伪」）不在这里 ——
 * 那些交给反证复核那一遍去冲，见 prompt.ts 的 A4_CHALLENGE_SYSTEM。
 *
 * 这一层只回答一个问题：**这份东西的形状对不对。**
 *
 * 两个门，对着两层交付：`validateReport` 数那份正式报告，`validateResearch` 数
 * 压出来的四节。
 */
import type { ResearchDoc, Statement } from "@/lib/data/types";
import {
  BUZZ,
  CATEGORY_HEAD,
  chars,
  commonViolations,
  HEDGES,
  overclaim,
  sentences,
  type Violation,
} from "@/lib/agent/rules";

export type { Violation } from "@/lib/agent/rules";
export { blocking, summarize } from "@/lib/agent/rules";

const traced = (s: Statement) => Array.isArray(s.traces) && s.traces.length > 0;

/* -------------------------------------------------------------------------- */
/* 第一层：那份正式报告                                                        */
/* -------------------------------------------------------------------------- */

/**
 * 报告那一层的质量门。**全是 p1，一条都不挡。**
 *
 * 挡不住的原因是结构性的：重修循环喂的是压缩那一层的对话（见 `run.ts`），把报告的
 * 违规递进去，模型只会去改四节 —— 台账上违规消失了，报告一个字没动。所以这几条只
 * 记不修：它们的用处是让「这一版报告写歪了」在运营台上数得出来，而不是当场救回来。
 *
 * **不走 `commonViolations`。** 那边的 `MARKDOWN` 规则把 `^#{1,6}\s` 判成违规，而报告
 * 的小标题就是 `## ` —— 直接复用会让每一份合规的报告都报一条 FE-md。所以这里自己挑
 * 那几条（回避式措辞、空词、member: 死链、感叹号），markdown 单独数。
 */
export function validateReport(text: string): Violation[] {
  const v: Violation[] = [];
  const push = (rule: string, message: string) => v.push({ rule, severity: "p1", message });

  const body = (text ?? "").trim();
  if (!body) {
    push("A4-R01", "报告正文是空的 —— 这一份只有四节，没有可署名分发的原件。");
    return v;
  }

  const lines = body.split(/\r?\n/);
  const headings = lines
    .map((l) => /^##\s+(.*)$/.exec(l.trim()))
    .filter((m): m is RegExpExecArray => !!m)
    .map((m) => m[1].trim());

  // ---- 标题（第一行）----------------------------------------------------
  const title = (lines[0] ?? "").trim();
  if (/^#/.test(title)) {
    push("A4-R02", "第一行标题前面带了井号；标题不加记号，`## ` 只用于小标题。");
  }
  if (title && !/(不是|而非|而不是|并非|与其说)/.test(title)) {
    // 和四节那条 A4-05 同一个道理：只说「是什么」的标题读者没法反驳，也就没法确认。
    push("A4-R03", "标题没有排除任何一个错误答案，读起来是个分类名而不是一句判断。");
  }

  // ---- 该有的几节 --------------------------------------------------------
  const has = (kw: string) => headings.some((h) => h.includes(kw));
  if (!has("核心判断")) push("A4-R04", "没有「核心判断」这一节 —— 开篇即给答案是 §6.1 的硬要求。");
  if (!has("最终判断")) push("A4-R04", "没有「最终判断」这一节，报告没有回到标题那句话收口。");
  if (!has("决定性证据")) push("A4-R04", "没有「决定性证据」这一节，读的人无从核这几条判断。");
  if (!has("含义")) push("A4-R04", "没有「对我们的当前含义」这一节，研究没有落到公司身上。");

  /*
   * 观点型章节的条数。判据是小标题以「一、」这种序号开头 —— 那是提示词里给的写法，
   * 数它比数「这个标题是不是一句判断」可靠得多（后者不是确定性检查能回答的）。
   */
  const chapters = headings.filter((h) => /^[一二三四五六七八九十]+[、.．]/.test(h));
  if (chapters.length < 2) {
    push("A4-R05", `观点型章节只有 ${chapters.length} 节，少于 2 节；§6.2 要的是 2–5 节。`);
  } else if (chapters.length > 5) {
    push("A4-R05", `观点型章节有 ${chapters.length} 节，超过 5 节；再多就是在搬材料。`);
  }
  for (const h of chapters) {
    const stem = h.replace(/^[一二三四五六七八九十]+[、.．]\s*/, "");
    if (CATEGORY_HEAD.test(stem.replace(/[：:]$/, ""))) {
      push("A4-R06", `章节标题「${h}」是分类词不是判断 —— §6.2 要的是标题本身就是一条判断。`);
    }
  }

  // ---- 未联网那一句必须在 -------------------------------------------------
  /*
   * 这一句不是免责，是让读的人知道哪几条在落地引用之前要先核一遍。省掉它，外部来源
   * 看起来就和内部文档一样已经核过 —— 而它们是模型的既有知识，本轮谁都没查。
   */
  if (!/未联网/.test(body)) {
    push("A4-R07", "「决定性证据」里没写明外部来源本轮未联网核验 —— 读的人会当它们已经核过。");
  }

  // ---- 记号：只允许 `## ` -------------------------------------------------
  if (/\*\*/.test(body)) push("A4-R08", "报告里有 `**` 加粗记号，屏幕按纯文本渲染，会原样显示成星号。");
  if (/^\s*[-*]\s/m.test(body)) push("A4-R08", "报告里有 `- ` 列表记号，会原样显示成横线。");
  if (/^\s*\d+[.)]\s/m.test(body)) push("A4-R08", "报告里有 `1. ` 编号列表记号，会原样显示。");
  if (/^\s*\|/m.test(body)) push("A4-R08", "报告里有表格，屏幕不渲染表格。");
  if (/^#(?!#\s)#{0,4}\s/m.test(body.split(/\r?\n/).slice(1).join("\n"))) {
    push("A4-R08", "报告里出现了 `## ` 以外的井号标题，屏幕只认 `## `。");
  }

  // ---- 措辞：借 rules.ts 的词表，但一律降到 p1 -----------------------------
  for (const h of HEDGES) if (body.includes(h)) push("G-08", `报告里出现回避式措辞「${h}」。`);
  for (const b of BUZZ) if (body.includes(b)) push("G-09", `报告里出现空词「${b}」。`);
  if (/member:[A-Za-z0-9_-]+/.test(body)) {
    push("A7-03", "报告里出现本体内部编号 member:xxx —— 屏幕认不出、点不开。");
  }
  if (/[！]/.test(body)) push("G-10", "报告里有感叹号。");
  v.push(...overclaim(body, "深研报告").map((x) => ({ ...x, severity: "p1" as const })));

  /*
   * 篇幅。提示词要的是 1800–3500 字，这里放宽到 1500–4000 才记 —— 差二三十字就报一条
   * 的门会让运营台上这条规则一直亮着，亮着的门等于没有门。
   */
  const n = chars(body);
  if (n < 1500) push("A4-R09", `报告 ${n} 字，薄于 1800 字的下限 —— 取舍还没做完就交了。`);
  if (n > 4000) push("A4-R09", `报告 ${n} 字，超过 3500 字的上限 —— 这是在搬材料。`);

  return v;
}

/* -------------------------------------------------------------------------- */
/* 第二层：压出来的四节                                                        */
/* -------------------------------------------------------------------------- */

/** 四条分流之外的写法。「持续关注」不在四条里，而且它的真实含义是「我没想清楚」。 */
const ROUTE_WORDS = /(更新战略|改.{0,4}判断|立项|执行|取证|证据|关闭|收口|不再跟)/;

export function validateResearch(doc: ResearchDoc): Violation[] {
  const v: Violation[] = [];
  const push = (rule: string, severity: "p0" | "p1", message: string) =>
    v.push({ rule, severity, message });

  const j = doc.judgment ?? [];
  const e = doc.keyEvidence ?? [];
  const c = doc.counters ?? [];
  const u = doc.unknowns ?? [];

  // ---- 四节都必须有内容 -------------------------------------------------
  // A4-01：缺任何一节都不是「这次没查到」，是没按四节交。
  if (j.length < 2 || j.length > 4) push("A4-01", "p0", `当前判断应为 2–4 条，实际 ${j.length} 条。`);
  if (e.length < 3 || e.length > 6) push("A4-02", "p0", `关键 Evidence 应为 3–6 条，实际 ${e.length} 条。`);
  if (u.length < 2 || u.length > 4) push("A4-04", "p1", `不确定性应为 2–4 条，实际 ${u.length} 条。`);

  /*
   * A4-03 反证一条都没有 = p0。
   *
   * 这一条是整份东西的反谄媚保证。CQ101 §07 要求主动找反证，而模型的默认行为
   * 是把反证写成「当然也存在一定风险」。零条反证在数据上看起来很干净，实际是
   * 这份研究最危险的状态 —— 一号位会以为它已经被压力测试过了。
   */
  if (c.length === 0) {
    push("A4-03", "p0", "一条反证都没有。写不出能动摇自己判断的东西，说明没在找。");
  } else if (c.length > 4) {
    push("A4-03", "p1", `反证 ${c.length} 条，超过 4 条；挑最能推翻判断的那几条。`);
  }

  // ---- 溯源 -------------------------------------------------------------
  // A7-01：Evidence 和反证是要拿去核的，没有溯源就核不了。
  e.forEach((s, i) => {
    if (!traced(s)) push("A7-01", "p0", `第 ${i + 1} 条 Evidence 没有溯源。`);
  });
  c.forEach((s, i) => {
    if (!traced(s)) push("A7-01", "p0", `第 ${i + 1} 条反证没有溯源。`);
  });
  j.forEach((s, i) => {
    if (!traced(s)) push("A7-01", "p1", `第 ${i + 1} 条判断没有溯源。`);
  });

  // ---- 第一条判断要表态 --------------------------------------------------
  const first = j[0]?.text ?? "";
  if (first && !/(不是|而非|而不是|并非)/.test(first)) {
    // p1 而不是 p0：句式是手段不是目的，硬打回会让模型为了套句式而说废话。
    push("A4-05", "p1", "第一条判断没有排除任何一个错误答案；只说「是什么」的判断没法被反驳，也就没法被确认。");
  }

  // ---- 每条判断要落到「对我们意味着什么」---------------------------------
  j.forEach((s, i) => {
    if (!/(——|—|意味着|对我们|因此我们|我们应)/.test(s.text)) {
      push("A4-06", "p1", `第 ${i + 1} 条判断没有落到「对我们意味着什么」。`);
    }
  });

  // ---- 反证要写清推翻门槛 ------------------------------------------------
  c.forEach((s, i) => {
    if (!/(推翻|不成立|就足以|则.{0,6}判断|反转|失效)/.test(s.text)) {
      push("A4-07", "p0", `第 ${i + 1} 条反证没写清「成立到什么程度就足以推翻判断」——那是感想，不是反证。`);
    }
    /*
     * A4-13 反证不能是纯假设场景。
     *
     * 「若市场环境出现突变，则……」读起来很像反证，而且能满足上面那条门 ——
     * 但它是**编出来的情景**，不是已知的、指向相反方向的事实。两者混在一起，
     * 一号位就分不清哪些是真有问题、哪些只是想象出来的风险，于是会去防一个
     * 不存在的东西。判据：以「若/如果/一旦」开头，且唯一的溯源是自己的推断。
     */
    const conditional = /^(若|如果|一旦|假如|倘若)/.test(s.text.trim());
    const onlyGuess = (s.traces ?? []).every((t) => t.kind === "agent");
    if (conditional && onlyGuess) {
      push(
        "A4-13",
        "p0",
        `第 ${i + 1} 条反证是一个假设情景，不是已知事实 —— 它属于「不确定性」。反证要有外部或内部依据。`
      );
    }
  });

  // ---- 不确定性要写清谁能答 ----------------------------------------------
  u.forEach((s, i) => {
    if (!/(能回答|才能回答|需要|由.{1,12}(给|出|提供)|问)/.test(s.text)) {
      push("A4-08", "p1", `第 ${i + 1} 条不确定性没写清谁能回答或要什么材料。`);
    }
  });

  // ---- 分类式开头 --------------------------------------------------------
  [...e, ...j].forEach((s, i) => {
    const head = s.text.split(/[，。：:]/)[0] ?? "";
    if (CATEGORY_HEAD.test(head)) {
      push("A4-09", "p1", `第 ${i + 1} 条以分类词「${head}」开头，应该直接写 synthesis。`);
    }
  });

  // ---- 建议分流 ----------------------------------------------------------
  const r = doc.routeSuggestion ?? "";
  if (!r.trim()) push("A4-10", "p0", "没有建议分流。");
  else {
    if (!ROUTE_WORDS.test(r)) {
      push("A4-10", "p0", "建议分流没有落在四条路之一（更新战略 / 立项执行 / 取证再议 / 关闭）。");
    }
    if (!/(因为|理由|由于|所以)/.test(r)) {
      push("A4-11", "p1", "建议分流没说明为什么是这条而不是相邻那条。");
    }
    if (sentences(r).length > 3) push("A4-11", "p1", "建议分流超过三句；它是一行，不是一段。");
  }

  // ---- 全局 --------------------------------------------------------------
  const all = [
    ...j.map((x) => x.text),
    ...e.map((x) => x.text),
    ...c.map((x) => x.text),
    ...u.map((x) => x.text),
    r,
  ].join("\n");
  v.push(...commonViolations(all, "深研"));
  v.push(...overclaim(all, "深研"));

  /*
   * A4-12 篇幅。深研比预研厚，但它仍然不是那份一万三千字的原始报告 ——
   * 这四节是**读完原始材料之后的取舍结果**，长度本身就是取舍做没做的证据。
   */
  const total = chars(all);
  if (total > 2600) push("A4-12", "p1", `全文 ${total} 字，超过 2600 —— 四节是取舍的结果，不是把材料搬过来。`);
  if (total < 500) push("A4-12", "p1", `全文只有 ${total} 字，薄到不像做过深研。`);

  return v;
}
```

## 附录 B · 通用规则与禁词（`src/lib/agent/rules.ts`）

G-05 那张禁词表（必然 / 一定会 / 毫无疑问 / 唯一的 / 完全不可能）在这里，三条链路共用。

```ts
/**
 * 跨 agent 共用的确定性检查原语。**不调模型。**
 *
 * 这里放的是 rubric 里 G-* 组（全局规则）和几条前端渲染带来的硬约束 ——
 * 它们对 A3 预研、A4 深研、A10 写回同样成立。各 agent 自己的 validate.ts
 * 只写它独有的那几条（句数、块数、章节结构）。
 *
 * 为什么必须是确定性的：CQ101 里有一半要求是**可数的**。可数的东西写进 prompt
 * 然后指望模型每次都数对，是这类项目最常见也最贵的失败 —— 它在评测里表现为
 * 「模型不稳定」，而真实原因是没人在数。可数的就去数。
 */

export type Severity = "p0" | "p1";
export type Violation = { rule: string; severity: Severity; message: string };

/** 中文断句。—— 和 …… 不算句末。 */
export const sentences = (s: string): string[] =>
  s
    .split(/(?<=[。！？!?])\s*/)
    .map((x) => x.trim())
    .filter((x) => x.length > 1);

export const paragraphs = (s: string): string[] =>
  s.split(/\n{2,}/).map((p) => p.trim()).filter(Boolean);

export const isRhetorical = (p: string): boolean => /^反问[：:]/.test(p);

export const chars = (s: string): number => s.replace(/\s/g, "").length;

/**
 * CQ101 §05-3 与 §08 点名的回避式措辞。
 *
 * 它们的共同点不是「说得含糊」，是**说了等于没说**：把这句话删掉，读者的判断
 * 一点都不会变。一号位读到它只会想「所以呢」，而那正是这份东西要回答的问题。
 */
export const HEDGES = [
  "机会与挑战并存",
  "建议持续关注",
  "后续需要再看",
  "值得持续观察",
  "有待进一步观察",
  "总体来看形势复杂",
  "需要综合考虑",
  "仁者见仁",
  "各有利弊",
];

/** CQ101 §04-3 / §05：标题要写 synthesis，不用「市场 / 技术 / 竞争」这种分类词。 */
export const CATEGORY_HEAD =
  /^(市场|竞争|技术|客户|行业|政策|产品|财务|团队|运营|数据)(分析|格局|趋势|概况|现状|情况|方面)?[:：]?$/;

/** 屏幕上的 AgentText 按空行分段渲染纯文本 —— markdown 记号会原样显示。 */
export const MARKDOWN = /\*\*|^#{1,6}\s|^[-*]\s|^\d+\.\s/m;

/** 空词。写进给一号位看的东西里，等于在说「我没想清楚」。 */
export const BUZZ = ["赋能", "抓手", "闭环打通", "顶层设计", "生态位", "打法", "组合拳"];

/**
 * 一段文字里的通用违规。所有 agent 的 validate 都先跑这一遍。
 *
 * @param label 出现在报错里的位置名，方便一眼看出是哪一节坏了。
 */
export function commonViolations(text: string, label: string): Violation[] {
  const v: Violation[] = [];
  if (!text) return v;

  for (const h of HEDGES) {
    if (text.includes(h)) v.push({ rule: "G-08", severity: "p0", message: `${label} 出现回避式措辞「${h}」。` });
  }
  for (const b of BUZZ) {
    if (text.includes(b)) v.push({ rule: "G-09", severity: "p1", message: `${label} 出现空词「${b}」。` });
  }
  if (MARKDOWN.test(text)) {
    v.push({
      rule: "FE-md",
      severity: "p0",
      message: `${label} 里有 markdown 记号；屏幕按纯文本渲染，会原样显示成星号井号。`,
    });
  }
  // 本体内部编号点不开。溯源里出现它等于给了一个死链接。
  if (/member:[A-Za-z0-9_-]+/.test(text)) {
    v.push({
      rule: "A7-03",
      severity: "p0",
      message: `${label} 里出现本体内部编号 member:xxx —— 屏幕认不出、点不开，要换成对应的短码或文档标题。`,
    });
  }
  if (/[！]/.test(text)) {
    v.push({ rule: "G-10", severity: "p1", message: `${label} 里有感叹号。` });
  }
  return v;
}

/**
 * 无依据的绝对化。CQ101 §05-3：结论强度必须匹配依据强度。
 *
 * 只在**没有任何数字、也没有引用编号**的句子上判 —— 有依据的断言本来就该硬。
 */
export function overclaim(text: string, label: string): Violation[] {
  const v: Violation[] = [];
  const HARD = /(必然|一定会|毫无疑问|唯一的|完全不可能|铁定|百分之百)/;
  for (const s of sentences(text)) {
    if (!HARD.test(s)) continue;
    const hasEvidence = /\d/.test(s) || /(0[0-9]-J\d+|ISS-\d+|DOC-\d+|CARD-\d+)/.test(s);
    if (!hasEvidence) {
      v.push({
        rule: "G-05",
        severity: "p1",
        message: `${label} 有一句无依据的绝对化：「${s.slice(0, 28)}…」。`,
      });
    }
  }
  return v;
}

export const blocking = (v: Violation[]): Violation[] => v.filter((x) => x.severity === "p0");

export const summarize = (v: Violation[]): string =>
  v.map((x) => `${x.rule}[${x.severity}] ${x.message}`).join("；");

/**
 * 落进 Run 记录的一条违规。**规则名在最前面**：运营台要按它分组数「哪条规则老是
 * 被违反」，前面多任何东西这个分组就散了。A3/A4 两处必须同一种写法，否则同一条
 * 规则在台账上会因为格式不同而算成两条。
 */
export const fmt = (v: Violation): string => `${v.rule} ${v.severity} ${v.message}`;
```

# A5 · 把那份报告读成几条判断

## 七、A5 做的是哪件事

深研报告写完之后，把它读成**几条一号位可以逐条表态的判断**。2–5 条，宁少不凑。

一条判断由五样组成：`label`（6–14 字）/ `statement` / `basis` / `boundary` / `reopenIf`。
`statement` 里不许出现「上述」「该方案」「这件事」「如前所说」—— 它会被单独摘出来放到判断板上，
指代词在那儿指不到任何东西。

**判断从报告的四节里长出来**：反证 → 边界与重开条件；不确定性 → 哪些还不能成为判断。
**答不上来的东西不要凑成一条判断。**

**最要紧的一条：你交的东西还没有被确认。** 禁语：「本判断已确认」「公司据此执行」「已形成一致意见」
「已成为公司口径」—— 研究结果、判断、共识是三样东西，A5 交的是第二样。确认只能由一号位按下。

运行参数：槽位 `pro`，maxTokens 8000，重修最多 2 轮，**不开图谱上下文**
（读的报告在装配时已经带过公司上下文，公司材料由调用方递入）。

```ts
export async function runJudgements(input: A5Input): Promise<A5Result> {
  /*
   * 认知段（prompt 第 ③ 段）**整段不存在**，也不去 `cognitiveFor` 取。
   *
   * 这不是还没装：`prompts/cognitive/` 下故意没有 `a5.*.md`，理由写在 `prompt.ts`
   * 文件头 —— 这一步不归方法部门管。取一次拿到 `empty` 反而会在台账上留下一条
   * 「这一轮没带标准」的记录，而它其实没有标准可带。
   */
  const h = new Harness({ agent: "A5", slot: "pro" });
  h.note("不开图谱上下文", {
    why: "读的深研报告装配时已经带过公司上下文，公司材料由调用方递入",
    docJudgments: input.doc.judgment.length,
    standingJudgments: input.judgments.length,
    existingOnBoard: input.existing.length,
  });

  const messages = [
    { role: "system", content: A5_SYSTEM },
    { role: "user", content: buildA5User(input) },
  ];
  const callDetail = { promptKey: "a5.judgements", cognitiveSource: "none" };

  let raw = (
    await h.callMessages("模型调用 · a5.judgements", messages, { maxTokens: MAX_TOKENS }, callDetail, "a5.judgements")
  ).text;
  let items = shape(raw);
  let violations = validateJudgements(items);
  let attempts = 1;

  // 第一轮的违规在这里就留下来 —— 下面那个 while 会把 `violations` 覆盖掉，
  // 而绝大多数违规是第一轮犯、第二轮改对的。理由同 A4。
  const firstRoundViolations = violations.map(fmt);

  while (blocking(violations).length && attempts <= MAX_REPAIR) {
    messages.push({ role: "assistant", content: raw });
    messages.push({ role: "user", content: buildA5Repair(summarize(blocking(violations))) });
    raw = (
      await h.callMessages(
        `模型调用 · a5.judgements 重修第 ${attempts} 轮`,
        messages,
        { maxTokens: MAX_TOKENS },
        { ...callDetail, repairOf: summarize(blocking(violations)) },
        "a5.judgements"
      )
    ).text;
    items = shape(raw);
    violations = validateJudgements(items);
    attempts += 1;
  }

  const degraded = blocking(violations).length > 0;
  return {
    judgements: items,
    violations,
    attempts,
    degraded,
    run: h.finish({
      status: "ok",
      input: `${input.issueId} · ${input.title}`,
      output: { judgements: items } as unknown as Record<string, unknown>,
      violations: violations.map(fmt),
      // 一轮就过时不落这个字段：空数组和「没记」在统计时分不开。
      ...(attempts > 1 ? { firstRoundViolations } : {}),
      degraded,
    }),
  };
}
```

## 八、System 段 · `src/lib/agent/a5/prompt.ts` → `A5_SYSTEM`

```text
你是这家公司一号位的参谋。这个议题的深度研究报告刚写完，你现在做下一件事：把那份报告读成**几条一号位可以逐条表态的判断**。

## 你交的东西还没有被确认

你给的每一条都会摊在他判断板的上半层，等他在对谈里或者会上逐条表态。**判断从参谋的猜测变成公司的口径，只能由他按下。**

所以不许出现「本判断已确认」「公司据此执行」「已形成一致意见」「已成为公司口径」这类话。研究结果、判断、共识是三样东西：报告是研究结果；你写的是当前的组织判断候选；只有相关责任人都认为一条判断成熟了，那才是共识。你只做中间那一步。

## 一条判断由五样东西组成

1. **短标签**（label）——六到十四个字，说清这一条管的是哪一块：「企业采用逻辑」「我们的战略边界」「必须掌握的控制点」「当前阶段怎么办」。他在板上扫一眼靠的是它。不要写「判断一」「重要判断」这种没有信息的标签。
2. **判断本身**（statement）——一句到两句密实的话，是他点头之后就可以对外说的那句。单独摘出来发给一个没读过这个议题的人，他要能读懂：不许出现「上述」「该方案」「这件事」「如前所说」这类回指。
3. **判断依据**（basis）——凭什么这么判。点到报告里的事实、数字、编号。半年后要重新打开这条判断时，要检查的正是这一段还成不成立，所以不能写成「综合研究结果」。
4. **当前边界**（boundary）——这条判断**不主张**什么。一条没有边界的判断，三个月后会被当成比它实际更强的东西用。写清楚它管到哪儿为止：不支持什么、不构成什么理由、只在什么范围内成立。
5. **重开条件**（reopenIf）——出现什么新证据，这条判断就该被重新打开。要写得出「什么东西出现」，写「情况有变化时再看」等于没写。

## 判断从报告的四节里长出来

- 报告的「当前判断」通常给出总口径 —— 你的第一条一般就是它，但要收成一句能被单独引用的话。
- 「关键 Evidence」是判断依据的来源。
- 「反证与风险」决定边界和重开条件 —— 反证不是被丢掉，是变成这两段。
- 「不确定性」决定哪些**还不能**成为判断。**答不上来的东西不要凑成一条判断。** 那是这一步最坏的失败：把研究里的空白包装成了公司口径，而屏幕上它和真判断长得一模一样。

## 条数：2 到 5 条，宁少不凑

每条管一块。两条在说同一件事就合成一条 —— 一块堆满近义句的板，比一块只有两条的板更没用，因为他数不出到底有几个判断。

## 强度必须跟依据对齐

依据只到「目前的证据更支持」，就照实写「当前更支持」「初步支持」「尚不足以证明」。一条写过头的判断被确认之后，公司会拿着一个比证据更硬的口径去做事。

## 硬规矩

- **屏幕不渲染 markdown。** 不要写 `**`、`##`、`- `、`1. ` 这些记号，会原样显示成星号井号。
- **只用报告和递给你的材料里的事实。** 没给你的数字一个都不许出现。
- **每条判断必须有溯源**，指回报告的哪一节、哪份文档、哪条在版判断的编号。不要编来源。
- 编号照原样写（如 01-J2、ISS-003、DOC-05），屏幕会把它们变成可点开的。
- **只有短码可以写进 traces。** 材料里「member:」开头的是本体内部编号，屏幕认不出、点不开。
- 称呼一号位用「您」。不用感叹号。不说「赋能」「抓手」「打法」这类空词。
- **引号一律用「」**，不要用 ASCII 双引号 —— 输出是 JSON，裸的 " 会把它弄坏。
- **中英文与数字之间加空格**：写「产品 1.0」「Agent 收到」。
```

## 九、User 段 · `buildA5User`

把报告四节带着溯源递过去（`withTrace` 在每条末尾追一句「（来源：…）」），并列出板上已有的判断防重复。
**去重按正文前 30 字** —— 防的是换个措辞躲过去重。

文件头那一段说明了为什么这一条链路没有认知段：

```ts
/**
 * A5 的 prompt —— 把一份深研报告读成几条**待一号位确认**的判断。
 *
 * ## 这个 prompt 不归方法部门管
 *
 * `prompts/cognitive/` 下**故意没有 `a5.*.md`**，认知段整段不存在。理由不是还没写：
 * S01/S02/S03 三份技能各自对应研究流程里的一步，而「把研究结论收成公司口径的候选」
 * 是这个产品自己的动作 —— 判断板上下两层、确认只能由人按下、来源分三档，这些都不是
 * 方法标准里的概念。所以它整份写在这里，跟着代码一起改。
 *
 * **不要为了「补齐」给它建一个认知段文件。** 建了之后有人会往里写第二套标准，
 * 于是同一件事有两个地方在定义，而屏幕上看不出这一轮听的是哪一份。
 *
 * ## 它和 A4 深研故意长得不一样
 *
 * 深研是四节并列摊开的研究结果：判断、Evidence、反证、不确定性。它可以并列，因为
 * 读者读的是「这件事是什么」。判断不能并列 —— 它是几句「他点头之后就可以对外说的话」，
 * 每一句都要能被单独摘出去用，所以每一句都得自带依据、边界和重开条件。
 *
 * 从四节到几条判断，做的是**收**：报告里答不上来的部分不许硬凑成判断（那是把研究里
 * 的空白包装成公司口径），报告里的反证要变成边界和重开条件，而不是被丢掉。
 *
 * 形状照的是 Package 04b（Oasis 那份 Research 后的 Judgment）：每条一个短标签 +
 * 一句密实的判断 + 判断依据 + 当前边界，加上「什么新 Evidence 才需要重新打开」。
 */
import type { Judgment, ResearchDoc } from "@/lib/data/types";
```

```ts
export function buildA5User(input: A5Input): string {
  const d = input.doc;
  const parts: string[] = [];
  parts.push(`## 议题\n\n${input.title}（编号 ${input.issueId}）`);

  const list = (label: string, items: { text: string }[]) =>
    items.length ? `## ${label}\n\n${items.map((s, i) => `${i + 1}. ${s.text}`).join("\n")}` : "";

  /*
   * 报告原样递过去，四节分开。
   *
   * 不做摘要：这一步的全部工作就是从四节里收，先摘一遍等于让另一个环节替它做了取舍，
   * 而那次取舍没有人看得见。溯源也不在这里压平 —— 模型要写「依据是 DOC-05」，
   * 得先在报告里看见 DOC-05 挂在哪一条上，所以下面把每条的溯源短码跟在正文后面。
   */
  const withTrace = (items: { text: string; traces?: { source: string }[] }[]) =>
    items.map((s) => ({
      text: s.traces?.length ? `${s.text}（来源：${s.traces.map((t) => t.source).join("、")}）` : s.text,
    }));

  parts.push(list("深研给出的当前判断", withTrace(d.judgment)));
  parts.push(list("关键 Evidence", withTrace(d.keyEvidence)));
  parts.push(list("反证与风险", withTrace(d.counters)));
  parts.push(list("不确定性（还答不上来的）", withTrace(d.unknowns)));
  if (d.routeSuggestion) parts.push(`## 深研的建议分流\n\n${d.routeSuggestion}`);

  if (input.judgments.length) {
    parts.push(
      `## 这个议题正在动摇的在版判断\n\n` +
        input.judgments.map((j) => `- ${j.id}（${j.standing}）：${j.statement}`).join("\n") +
        `\n\n如果某条新判断要改其中一条，在它的正文里点名是哪一条、改成什么；` +
        `如果只是补充而不冲突，也说清楚。`
    );
  }

  if (input.existing.length) {
    /*
     * 已经在板上的原样列出来。
     *
     * 不列的话模型会把同一句话换个措辞再写一遍，而板上的去重按正文前 30 字判 ——
     * 换了措辞就躲过去重，于是板上出现两条读起来一样的判断；真躲不过去重的那些
     * 会被静默丢掉，表现成「这次只生成了两条」。两种结果都看不出原因。
     */
    parts.push(
      `## 判断板上已经有的（含他确认过的）\n\n` +
        input.existing.map((s) => `- ${s}`).join("\n") +
        `\n\n这几条不要重复。如果你认为其中某一条现在该改，写成一条新判断并在正文里` +
        `说明它替换的是哪一句、哪里不一样。`
    );
  }

  parts.push(`## 输出

只输出 JSON，不要用代码块包裹，不要写任何解释。形状：

{
  "judgements": [
    {
      "label": "企业采用逻辑",
      "statement": "……",
      "basis": "……（点到报告里的事实、数字或编号）",
      "boundary": "这条判断不主张……，也不构成……的理由。",
      "reopenIf": "如果出现……，这条判断要重新打开。",
      "traces": [{ "kind": "int", "source": "文档标题", "href": "/docs/DOC-05" }]
    }
  ]
}
```
