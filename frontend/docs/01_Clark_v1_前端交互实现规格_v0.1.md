## 0. 定位、范围与边界声明

**这份文件不是 MC-1 边界里排除的"完整 PRD"。** 它只覆盖 ⚠8/22 轨 A 闭环必需的界面，是**执行规格**而非设计扩张。判据很简单：这里写的每一条，都能指回一条 Mission Card 的成功证据；指不回去的，不写。

**服务的验收条款**：

| Mission Card 成功证据 | 本规格对应界面 |
|---|---|
| MC-2 ③ 卡片 ≤3 张/日、四段式、事实断言 100% 可溯源 | FE-0 晨报 |
| MC-2 ④ ≥1 个进入 CEO 讨论的问题来自卡片 | FE-0 三动作处置 → FE-2 对谈 |
| MC-2 ⑤ Discuss 自动继承全部 Context（**装配清单可查**） | FE-2 装配清单 |
| MC-2 ② 影子模式评审精度达门槛 | FE-4 影子评审台 |
| MC-3 ② Brief 含最强反证 + 分歧三分类标注 | FE-3 Decision Brief |
| MC-3 ③ 上传后 ≤30 分钟产出复盘与 Closure 草案 | FE-5 校对工位 → FE-3 Closure |
| MC-3 ④ CEO 确认后完成写回 | FE-3 Closure 确认 |
| MC-5 ① 全程数据落库可回放 | FE-1 Issue 时间线 |
| MC-5 ② 以使用行为与两项评分为证 | 跨界面 · 评分机制 |

**明确不在本规格内**：Outcome 对齐循环全部界面（J2，9 月）、一句话调度、准备队列、协作账单、异步深研的进度界面、弃用降级模式、会中实时、周度回看、Watchlist 自动重提。

## 1. 六条设计原则（用于裁决实现期争议）

这些不是口号，是可以用来否决具体实现方案的判据。开发期有分歧时按此裁决，裁不了再找我。

**P1 · 判断优先于信息。** 每一屏只回答一个问题：你现在要不要做一个判断。凡是不导向判断的信息，折叠或删除。这是四个"不是"里"不是资讯流"在界面上的具体形态。

**P2 · 每句话带出处。** 事实性断言必须挂溯源徽章，四类可视区分：外部事实 / 内部事实 / 人的判断 / Agent 推演。**没有来源的内容必须显式标"推断"**。这是 M06 FR2 在前端的执行点，也是 Clark 区别于任何聊天产品的视觉记忆点。

**P3 · 结构化优先于自由文本。** 全产品**不引入任何富文本编辑器**（不用 TipTap / Slate / ProseMirror）。Closure 七要素、DRI 条目修订、校对工位都是字段化交互。理由：给了自由文本框，写回就无法解析，Decision 当场退化为会议纪要——正中四个"不是"的第三条。这一条会被反复挑战，写死。

**P4 · 空报是合格输出。** 空态不是错误态，不用灰色插图和"暂无数据"。文案要有主语和判断："今天没有需要您看的变化。"

**P5 · 前端不持有业务状态。** 所有状态迁移都是「调接口 → 后端状态机校验 → 返回新状态」。**不做乐观更新。** 因为 M02 FR2 要求非法迁移在存储层拒绝；前端本地先改会让代理动作审计和版本链出现空洞。

**P6 · 预算是硬约束，不是建议。** 晨报 ≤3 卡/日、确认点 ≤3 次/周。**超限时系统自己排序并顺延，不询问、不上报、不"要不要再看一条"。**

## 3. FE-0 · 晨报与三动作处置

### 3.1 目标

让一个每天只给 5 分钟的人，在这 5 分钟里完成 0–3 个判断，并且**不产生"我是不是漏了什么"的焦虑**。

### 3.2 载体与两套形态（A-2 待定，两套都实现）

| 载体 | 卡片形态 | 降级点 |
|---|---|---|
| 飞书（能力上界） | 单卡承载四段式 + 三按钮 + 「展开溯源」折叠区 | — |
| 企微（模板制） | 主标题 = 发生了什么；副文本 = 为何现在重要（≤160 字）；三按钮；「看详情」跳 H5 | 四段式压成两段，战略影响与建议动作移入 H5 |

**不论哪种载体，三动作按钮必须在 IM 卡片内直接可点**，不允许"全部跳 H5 再操作"——那会把 3 次点击变成 6 次，破 M11 非功能要求。

### 3.3 卡片结构（四段式）

```
① 发生了什么      —— 事实陈述，每条挂溯源徽章
② 为何现在重要    —— 时效性论证（为什么是今天不是上周）
③ 影响哪条判断    —— 必须命名具体的 Strategy / Hypothesis 对象，答不出的不出卡
④ 建议动作        —— 三选一的默认建议（系统的推荐，不是命令）
```

**硬约束**：③ 是出卡门槛。前端应当假设后端不会送来③为空的卡片；如果收到，**渲染为异常并上报运营台**，不要静默隐藏——这是精度门失效的信号。

### 3.4 三动作

| 动作 | 迁移 | 后续 |
|---|---|---|
| **Discuss** | Candidate → Exploring | 直接进入 FE-2 对谈，Context 已装配完毕 |
| **Watch** | Candidate → Watching | 入 Watchlist，无二次确认 |
| **Dismiss** | Candidate → Dismissed | 弹四个预设原因标签（不相关 / 已知 / 时机不对 / 判断错了），可补一句，**可跳过**（B-4） |

三个动作**都不弹确认框**。Dismiss 的原因收集是回喂去噪的输入，不是防误操作的门。误 Dismiss 的补救是 Issue 列表里能找回，不是加一道确认。

### 3.5 空态

一行文本，不发卡片：**「今天没有需要您看的变化。」** 下面一行小字给退路：「有事随时找我 →」（点击进入自由对谈）。

不发插图，不发"系统运行正常"，不发本周统计。

### 3.6 待决点

- **B-1 卡片密度**：折叠（默认）vs 全展开。原型两版可切。
- **B-5 空报是否发消息**：默认发。

## 4. FE-1 · Issue 列表与时间线

### 4.1 定位

**Issue 详情页 = Context 时间线。** 这不是一个"带附件的详情页"，页面主体就是这个对象从出生到现在的全部事件。MC-5 证据①「全程数据落库可回放」的举证界面就是它。

### 4.2 事件类型（8 类，B-7 待与 05 冻结）

| 类型 | 徽章 | 折叠默认 |
|---|---|---|
| 状态迁移 | 时间轴主干节点 | 展开 |
| Signal 进入 | 外部/内部事实 | 折叠 |
| 对谈 | 人的判断 + Agent | 折叠（显示轮次与摘要） |
| 深研完成 | Agent 推演 | 折叠 |
| DRI 交接发出 | 组织动作 | 展开 |
| DRI Judgment 回传 | 人的判断 | 展开 |
| Decision 固化 | 组织动作 | 展开 |
| Re-open Trigger 命中 | 系统 | 展开 |

**折叠规则的依据是 P1**：组织动作和状态迁移导向判断，过程性内容不导向判断。

### 4.3 关键交互

- 时间线倒序（最新在上）。CEO 打开时想看的是"现在到哪了"，不是"当初怎么来的"。
- 每个事件可展开到原文/溯源。
- 顶部固定条：**当前状态 + 下一个需要你做的动作**。如果没有需要 CEO 做的，明说"目前不需要您做什么"。
- 列表页按"需要你判断的"排在最前，其余按状态分组，不按时间排序。

### 4.4 不做

不做看板视图、不做筛选器矩阵、不做标签体系。v1 的 Issue 数量是个位数到十几个，任何筛选 UI 都是过度设计。

## 5. FE-2 · 对谈页（Advisor）

### 5.1 这一页的两个非标准之处

它看起来像 chat，但有两个东西是标准聊天 UI 没有的，也正是它的价值证明：

**（一）装配清单（MC-2 证据⑤ 的举证界面）。** 进入对谈时，Clark 的第一条消息必须交代**"我带了什么进来"**：原 Signal、相关 Strategy/Hypothesis、历史 Decision、Decision Memory 条目、过往对谈。这是"王总永远不需要从头介绍背景"的可见证明，也是这条验收唯一能举证的地方。

**（二）挑战必须带来源。** Red Team 的每条挑战渲染为：冲突点 + 依据来源 + 替代解释三段式，来源不可省略。前端应当把无来源的挑战渲染成告警——那是"表演性抬杠"，是 MC-2 复盘沉淀里评估集要抓的东西。

### 5.2 装配清单的三个变体（B-2）

| 变体 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **① 首条消息内折叠**（默认） | 作为 Clark 开场白的一部分，一行摘要 + 可展开明细 | 语义正确——这是开场白不是设置项；零额外 UI | 滚上去之后看不见了 |
| ② 顶部常驻条 | 页面顶部固定一条"本次对谈基于 N 项 Context" | 随时可查 | 占掉手机屏顶部空间，且大部分时间无用 |
| ③ 侧拉抽屉 | 右上角图标唤出 | 不占空间 | 藏太深，验收时演示要额外解释 |

**推荐 ①**，理由是它同时满足"可查"和 P1：装配清单在开场时是判断材料，之后就是审计材料，审计材料该沉到时间线里去（FE-1 也能查）。

### 5.3 四模式的前台呈现

**不暴露模式切换器。** Explore / Research / Challenge / Frame 是后台 Worker 的分工，前台只体现为对谈能力——这是基线「一个前台 Agent，后台 Worker 不暴露」的直接要求。

唯一的例外是 **Frame 的出口**：当 Clark 判断问题已经收敛，在对话流里给出一张**结构化的 Decision Question 卡**（不是一段文字），带「升级并交给 DRI」按钮。这是从对谈跳到组织动作的唯一入口。

### 5.4 升级确认

点「升级」→ 展示交接包六要素预览 → **默认脱敏状态可见**（"CEO 关注的问题"而非"CEO 的倾向"），下方一个开关：「同时告诉 DRI 我的倾向」，默认关。

这个开关是评审张力 3（组织层面锚定）的落地点。默认关很重要，但要让 CEO 知道它存在——藏起来就变成产品替他做了判断。

### 5.5 待决点

- **C-4 异步深研 8 月不做**：对谈内的"深研"请求 8 月按同步阻塞处理，前端显示进行中状态，不做 IM 回推。

## 6. FE-3 · Decision Brief 与 Closure 确认

### 6.1 Decision Brief（会前，只读）

七个区块，**分歧标注是这一页的核心**：

```
当前问题 / DRI 推荐 / 关键 Evidence / 最强反证
开放分歧  ← 每条标注属于【事实】【假设】【价值】
建议追问  ← 每条附"不同答案分别意味着什么"
```

**分歧三分类用颜色语义固定下来**，全产品一致：事实类 = 中性灰蓝（可查证）、假设类 = 琥珀（需验证）、价值类 = 深色实心（只能拍板）。CEO 扫一眼颜色就知道"哪几条只能我来定"。

「最强反证」区块必须独立成块且视觉上不弱于 DRI 推荐——它是防迎合的产品形态，缩成脚注就等于没有。

### 6.2 Closure 确认（会后，可编辑）

七要素：Choose / Not Choose / Why / Key Hypothesis / Risk Accepted / Commitment / Re-open Trigger。

**两个变体（B-3）**：

| 变体 | 交互 | 点击数 |
|---|---|---|
| A · 逐字段确认 | 每个要素独立确认按钮，全部确认后写回 | ≥7 次 |
| **B · 整体审阅 + 局部改**（默认） | 全文呈现，任一字段点击即改，底部一个「确认并写回」 | 1 次（不改的话） |

**推荐 B**。理由：MC-5 要回答"CEO 是否愿意持续使用"，而 A 方案是 7 次点击——它把治理正确性直接变成了摩擦，正中评审张力 7（人工确认不能复活秘书工作）。治理要求的是"CEO 确认过"，不是"CEO 点了七次"。

**编辑交互严格字段化**（P3）：每个字段是 textarea 但**有明确的字段边界和长度提示**，Re-open Trigger 是结构化条件而非自由描述。绝不做成一个大富文本框。

### 6.3 写回后

确认成功后**不跳转、不弹庆祝**，就地把页面转为已固化状态，显示：写回了哪几个对象、布控了什么 Trigger。这是"同一版本认知"的可见证明。

## 7. FE-4 · 影子评审台（内部）

### 7.1 目标

这是 8/11 就要用的界面，也是 MC-2 证据②的数据产生现场。**功能不能缺，视觉可以粗糙。**

### 7.2 结构

左侧候选卡片队列，右侧评审面板：

- 卡片四段式全文 + 溯源链接（评审员要能一键跳到原文核对）
- **精度评分**：这一张卡该不该发给 CEO？→ 该发 / 不该发 / 边缘
- **归因**（不该发时必填）：靶点问题 / 关联判定错 / 事实错 / 重复 / 时机不对 / 表述差
- 动作：放行 / 退回 / 改写后放行（改写内容入训练数据）
- 顶部：本周精度、放闸门槛（≥70%，A8 待定标）、距离门槛还差多少

**归因字段是这一页最重要的设计**。MC-2 风险栏写着"精度不达标 → 复盘归因（靶点质量 vs 管道质量）"，没有归因字段这条风险处理就是空话。

## 8. FE-5 · 会议校对工位（内部）

### 8.1 为什么它是 P0

MC-1 把秘书卡降为辅助，但明确说"降的是验收地位，不是工作本身"。MC-3 关键路径原文：「会后批处理管道 = 采购 ASR + **秘书校对工位** + 结构化抽取」。**没有这个界面，30 分钟 SLA 不成立。**

### 8.2 结构

逐段列表：时间戳 / 说话人下拉 / 转写文本（可编辑）/ 音频跳转。

- 说话人标注是**下拉选择**，不是输入框——会议参与者是已知的封闭集合。v1 说话人分离可以全人工（M08 FR3）。
- 提交后触发结构化抽取，页面转为"抽取中"，完成后跳 Decision State 复盘。
- 顶部显示 SLA 倒计时：上传时刻 + 30 分钟。**这是给操作员的压力表**，不是装饰。

## 9. 跨界面机制

### 9.1 溯源徽章（全局，signature 元素）

四类，视觉必须可区分且在小屏上仍可辨：

| 类型 | 含义 | 可点 |
|---|---|---|
| 外部事实 | 公开信息 | 跳原文链接 |
| 内部事实 | 投喂材料 | 跳材料片段 |
| 人的判断 | CEO / DRI 说过的 | 跳原始语境 |
| Agent 推演 | 无外部来源的推断 | 展示推演依据 |

**无来源的断言必须显式标"推断"**，不允许裸露。

### 9.2 注意力预算执行（P6）

前端持有并显示预算状态，但**不做超限提示给 CEO**：

- 晨报卡片超 3 张 → 系统排序后顺延，界面上不出现"还有 N 条未显示"
- 确认点超 3 次/周 → 攒批，队列里排序
- 预算消耗对 CEO 不可见，对运营台可见（用于陪跑期校准 A7）

**反模式**：任何形式的"您今天还有 2 条未读""要不要再看一条"。

### 9.3 评分（MC-5 证据②的举证来源）

关键输出后（卡片处置、对谈结束、Brief 阅读、Closure 确认）弹非阻塞浮层：两项 1–5 星 + 差距大时追一句"最大的问题是什么"。**可跳过，跳过不追。** 10 秒完成。

## 10. 前端对后端的接口期望（给 05 的输入）

不是 API 设计，是前端渲染必须拿到的东西：

| 需要什么 | 为什么 | 对应模块 |
|---|---|---|
| 每个生成物附 citation manifest | 溯源徽章渲染 | M06 FR2 |
| 每次对谈附 assembly manifest | 装配清单（MC-2 证据⑤） | M03 FR4 |
| Issue 时间线 API 返回按时序的异构事件流，每个事件带类型 | FE-1 主体 | M02 FR4 |
| 状态迁移接口返回**迁移后的完整对象**，不只是成功标志 | P5 前端不持有状态 | M02 FR2 |
| 分歧条目自带三分类字段 | Brief 颜色语义 | M08 FR4 |
| 交接包字段级可见性由后端判定后下发 | 脱敏不在前端做 | M01 FR6 |

**最后一条要强调**：脱敏必须在生成层执行，前端只渲染它收到的东西。前端做隐藏 = 数据已经到了客户端 = 脱敏是假的。
