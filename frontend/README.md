# 天枢 · 一号位的战略决策系统（MVP）

给公司一号位用的战略参谋。它的主体不是对话，是一个叫 **议题**（Strategic Issue）的持久
对象——公司的判断被沉淀成可版本、可回放的对象，而不是散落在聊天记录里。

代码里的标识符仍然叫 `clark`（仓库名、容器名、脚本名），屏幕上的名字是**天枢**。

## 这一版不是 demo 了

上一版 README 写的是「v1 纯前端 demo：无后端、无鉴权」。那三个字全部不成立了：

| | demo 那一版 | 现在 |
|---|---|---|
| 数据 | `seed.ts` 一份假数据 | 落盘的对象库（`TKOS_DATA_DIR`），一号位录进去的东西活过重启 |
| 模型 | 不调 | 真调。预研、深研、读成判断、信号研判都是真实的模型调用，**真的花钱** |
| 外部信息 | 没有 | 真检索（博查 / 豆包）+ 真抓页 |
| 进门 | 谁都能进 | 一道共用口令挡在所有页面前面；DRI 走各自的签名链接 |
| 部署 | 本机 `pnpm dev` | ECS 上的 docker 容器，蓝绿发版 |

**它现在要在公司内部真的被人用。** 用户规模是自己人三五个：一号位一个，DRI 六个岗位。
没有账号体系——这不是欠账，是按这个规模选的。

### 上线第一天是空屏，这是对的

首页两个页签空着、八个域的计数全是 0、潜在议题那一屏也是空的。**不是数据没导进来。**

进这份清单只有三条路：雷达按公司布下的靶点抓回来的、DRI 押上名字递上来的、他自己提的
（「+ 我自己有一件事」）。预置几条「已经摊在提请台上」的卡，等于替这三条来路各编了一次
来历，而屏幕上分不出哪一条是编的。

演示那一档（`TKOS_MODE=demo`）另说：那一档摊满内容、不出网、不调模型。

## 跑起来

```bash
pnpm install
cp .env.example .env.local   # 然后把值填进去，说明都在那个文件里
pnpm dev
```

`.env.local` 里至少要有：模型那几位（`ARK_*`）、检索那几位（`TKOS_SEARCH_PROVIDER`
加对应的 key）、进门那两位（`TKOS_ACCESS_PASSWORD` / `TKOS_ACCESS_SECRET`）。
缺哪一位、缺了会怎么样，`.env.example` 里逐条写着——**照实说，不假装能用**是这个仓库
的一条硬规矩。

```bash
pnpm test            # 全量单测，不出网、不调模型
pnpm lint
pnpm cost:report     # 这一段时间的模型调用花了多少，按链路分
```

## 五个环节

一件事从进来到落地，屏幕上是这么走的：

| 环节 | 路由 | 它回答什么 |
|---|---|---|
| 感知 | `/signals` | 今天有什么值得注意。三个来源汇到同一份清单，他在这里决定哪几件值得占自己的时间 |
| 立案 | `/` | 我手上有哪些事、哪几件已经定了时间。这一屏是驾驶舱 |
| 研究 | `/issues/[id]` | 参谋把这件事研究成什么样了，以及当面追问 |
| 开会 | `/sec/schedule` · `/meetings` | 排到哪一天的上午/下午，谁到场 |
| 收口 | 首页右栏 · `/decisions` | 会后要点确认，判断落库、布控重开条件 |

其余入口：`/sensors`（雷达在盯什么，可以交代一句「这一轮多盯着点什么」）、
`/signals-scans` 与 `/signals-log`（扫描与处置的台账）、`/deployed`（交出去还在跑的）、
`/changelog`（每一版改了什么）。DRI 那一侧在 `/dri`，只能通过签名链接进来，
看不到一号位的提请台、对谈记录和判断本体。

秘书那一侧在 `/sec`：编排会议（`/sec/schedule`）、纪要审阅（`/sec/debriefs`）从
一号位手上搬了过来——排哪天开会、纪要谈没谈拢，不是他该管的事。进门还是 `/access`
那一把共用口令，验完之后多一步：口令上方一个两档滑块（一号位 / 秘书），选哪一档
决定落到 `/` 还是 `/sec`。**滑块分的是路，不是权限**——这一版一把口令两侧都开得
进，坐在秘书位上的人知道 `/` 这个地址照样能进一号位那一侧（`src/lib/seat.ts` 有
细账，落权限边界的路也写在那儿）。

## 哪些地方会花钱

这是内部推行时最容易被问的一件事，所以写在这儿：

- **提一件潜在议题** → 自动起一轮预研。他敲下「+ 我自己有一件事」那一下就是一次模型调用。
- **把一件潜在议题转成战略议题** → 自动起一轮深研，深研落库后接一轮「读成判断」。
  一件议题走完这一段目前**约 ¥9**，其中绝大部分在深研那一段。
- **主动开始扫描** → 十几次检索加三四次模型调用，一轮三四分钟。
- 打开一件议题的页面会自动起一轮判断——**所以逐个点开二十件议题 = 二十轮模型调用**。

三处都**失败不自动重开**（重试烧钱，而且会把失败藏起来），也都在演示档完全不跑。
`pnpm cost:report` 出的是真账，不是估算。

## 代码结构

```
src/
  app/
    (tkos)/            # 一号位那一侧的全部页面
    dri/               # DRI 那一侧（签名链接进来）
    sec/               # 秘书那一侧：编排会议、纪要审阅（同一把口令，/access 滑块选）
    access/            # 共用口令那道门
    api/               # data（对象库 RPC）· chat · agent · signals/inbox · listen/speak …
    _views/            # 客户端视图 —— 页面的实际内容都在这里
    globals.css        # 设计 tokens 与全站画法。颜色一律走变量，组件里不许写死颜色
  components/
    agenda/            # 驾驶舱的壳、议题栏、日程板、会后那一栏
    advisor/           # 议题研究页：报告、对谈、判断板
    brand/             # 字标与标记
  lib/
    agent/             # A1a 立案 · A3 预研 · A4 深研 · A5 判断 · A7 复盘 · 对谈
    data/              # types（对象模型）· store（对象库）· client（api，前端只认它）
    scan/              # 「主动开始扫描」：靶点策略 → 检索式 → 研判 → 收进待挑列表
    research/          # 深研自己的取证：检索、抓页、入账、独立性折叠、覆盖判定
    models/            # 模型接入、槽位、重试、成本计量
    graphknowledge/    # 公司本体（只读）
```

## 改东西的规矩

1. **每一次有产出的改动都要记账**：往 [`src/lib/changelog.ts`](src/lib/changelog.ts)
   最前面加一条，`package.json` 的 `version` 跟着改。漏记的兜底是 `pnpm changelog:check`。
   日志是**写给用它的人看的**，不是写给 git 看的——说清屏幕上有什么不一样了、为什么，
   文件名和函数名不进去。
2. **拿不准的判断记进 [`DECISIONS.md`](DECISIONS.md)**：决策、理由、影响面三栏。
   被后来推翻的条目划掉、注明被谁推翻，不删——推翻的理由和当初的理由一样值钱。
3. **组件只认 `api`**（`lib/data/client.ts`），不许直接 import 对象库或种子。
4. **不许写死颜色**，全部走 CSS 变量。
5. **不许假装能用**：一条链路没配好、没跑成、拿不到数据，屏幕上就照实说是哪一种，
   不给一个按了没反应的键，也不拿「加载中」盖住一个永远不会来的东西。这一条在这个
   产品里是硬规矩——它卖的就是可核对。
