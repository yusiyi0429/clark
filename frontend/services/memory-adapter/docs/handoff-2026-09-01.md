## 一、`spawnsOf` 和 `spawns` 名字对不上 —— 数据是有的，只是接不上

M7 在 `ISS-D1` / `ISS-D2` 上发的是：

```json
{"belongsTo":["TK"],"shakes":["01-J12"],"spawnsOf":["CARD-D1"]}
```

clark 的配方读的是 **`spawns`**，读到的是 `undefined`，走 `?? []` 变成空数组。
**不报错，那一段直接空掉。**

这不是缺数据，是命名不一致，一边改一行就好。**该改哪一边我判断不了** —— 如果
`spawnsOf` 是本体那边正式的关系名，clark 改；如果是投影时写岔了，本体改。麻烦定一下。

顺带把六个关系的现状摆齐（`shakenBy` 那一列是新 adapter 上的，M7 上没有）：

| clark 的配方读 | M7 | 新 adapter |
| --- | --- | --- |
| `hasJudgement` | ✅ | ✅ |
| `shakes` | ✅ | ✅ |
| `resolvedBy` | ✅ 指向 `AGR-D8` / `AGR-D9` | ❌ |
| `shakenBy` | ❌ | ✅（8-31 那轮补上的） |
| `spawns` | ⚠️ 发的是 `spawnsOf` | 待查 |
| `researchForOf` | ❌ | ❌ |

**两版各有各的缺口，没有哪一版是另一版的超集。** 切过去之前这张表得先填平，否则是
拿一组缺席换另一组缺席。

## 二、`view=chain` 回 200，但 `versions` 是 0 条

```
GET /api/v1/entities/ISS-D8?view=chain  →  200，versions: []
```

`latest` 是好的（当前版取得到）。缺的是**它怎么变过来的**。

对 clark 的影响：判断的版本链是「在版判断」那一段的骨架 —— 一条判断被什么摇动过、
改过几次、每次改了什么。拿不到版本链，屏幕上就只剩一个当前值，看不出它是刚立的
还是被推翻过三次的。**这一层不报错，报的是 200 加一个空数组。**

想知道的是：是这批 Issue 本来就只有一版（那就是正常的，clark 这边该把「只有一版」
和「取不到版本链」分开显示），还是版本没被投影出来。

## 三、`researchForOf` 两版都没有

这件事我判断不了」。今天在 M7 上复核，仍然没有。**如果本期就是没有，希望在 README

现在它和「装配正常但内容为空」在屏幕上长得一模一样。

## 四、不是 bug，但你应该知道：本体里的议题和 clark 跑的议题不是同一批

P3 回来的种子，命名空间是这样的：

```
CANON-ST-02  01-J3  D-01  D-01:outcome  AGR-D9  BJ-D4  DOC-19  ISS-D4  AIDC:outcome
```

clark 的锚点只认 `ISS-` / `CARD-` 前缀（A3/A4 认前者，A1a 认后者）。实测五个不同的
问法、共 40 条种子，**能被认作锚点的只有 4 条**。

而库里的议题是 `ISS-D1`…`ISS-D9` 九件，全是词元云集自己的经营事务；clark 本机跑的
深研是 `ISS-110`…`118` 和 `ISS-201`…`225`。**除了题目恰好撞上的少数几件，深研这条路
上本体用不到。**

举一件真的：`ISS-225`「AI 时代企业管理该自顶向下还是从执行层切入？」跑深研时，
P3 池子里确实出现了 `ISS-D4`，但 clark 的「池子拉不开」那道闸把它挡了
（最低/最高 = 0.9098 ≥ 0.9）。我去核了 `ISS-D4` 的原文是「Agent 规模化进入企业后，
企业敢不敢把权力交给 AI」—— 和 ISS-225 相邻但不是同一件事。**那道闸判对了。**

这条写在这里不是要谁改什么，是说明一件事：**「四层全绿」和「本体真的喂进了深研」
之间还隔着「库里有没有那件议题」。** 现在 P1/P2 和三条配方在真实链路上仍然基本
走不到 —— 8-31 那一轮记的是因为 P3 挂着，今天 P3 通了，卡点换成了这个。
